# Issue #111: PCの再生音を加工するセットアップ（段階1）

## 実装と判断

- 既存4用途を保ち、PCの音楽・動画を加工する5番目の用途を追加した。選択だけでは目的も音づくり設定も保存・変更しない。
- 再生アプリ → CABLE Input（Windows・アプリ出力）→ CABLE Output（Auralyn入力）→ VST → 物理ヘッドホンの経路を表示する。Windows・アプリ側の再生先は利用者が設定する。入力候補のケーブルが一つなら選択し、複数なら選択を待つ。musicへの切替時は以前の入力・出力候補を消し、既知の仮想出力を選ばせず自己循環を避ける。名前による判定のため、すべての他社仮想機器を識別できる保証はない。
- musicではマイク試聴・送り先テストを出さず、明示的な保存・開始で適用する。Homeの入力・音の表示と導線を変更し、44.1 kHzを音楽専用と表記しない。準備判定は既存の試聴用途を使用し、条件変更時もmusicの保存目的を保つ。
- 明示開始時、未起動エンジンの統計は実設定を保証しないため、既存APIでストリームを開始してから現在のNR・内蔵設定を取得する。revision付きの内蔵声処理をOFFにし、観測したモード・強度・voice guardを保持してNRをOFFにする。preset・amount・歌設定・残響パラメータも保持する。残響のenabledは独立した設定として変更しない。NR失敗時には内蔵設定のrevision付きundoを試みる。NRには比較付き更新がないため古い値を無条件に復元しない。
- NR設定と内蔵snapshotを読み戻し、ストリーム稼働中・OFF・保持対象の一致・内蔵処理のpending/errorなし・appliedRevision一致を確認してから保存する。稼働状態が停止または不明な場合は保存しない。これは制御側の状態確認であり、最終的な音や機器・受信先までの確認ではない。並行変更、応答不明、条件付きundo失敗では設定が一部変わる可能性がある。その場合は完了せず、設定を確認してから再試行するよう表示する。
- musicの用途・音声設定・ウィザード完了・表示設定を保存後に読み戻す。保存失敗時には今回書いた値と一致するものだけ条件付きで復元する。ストレージ自体の障害や並行更新により完全復元できない場合がある。IPCとストレージをまたぐ原子的な処理ではない。
- Windows自動ループバックは未実装。段階2の調査は [PLAYBACK_CAPTURE_RESEARCH.md](PLAYBACK_CAPTURE_RESEARCH.md) を参照。エンジン実装と実機・OBS検証は残件。
