# 歌枠の回帰確認（#219、#211）

NR・内蔵処理の変更PRでは、以下の4線を確認し、[記録様式](templates/singing-regression.md)に版、条件、証拠、結果と未実施を残す。自動試験や測定準備だけでは実機の合格にならない。未実施や判定不能は未確認としてPRに明記し、解消まで守る線を確認済みとしない。

初回は同じ機器・配線・素材・設定で現行版を測り、結果とばらつき、聴取者の判断を記録する。その後、変更版を測る前に各条件の許容差・判定方法を決めて記録する。結果を見てから閾値を都合よく変更しない。機器や素材を変更した場合は比較可能性を確認し、必要なら新たに基準を取り直す。[評価軸](EVALUATION_CRITERIA.md)の比較先同等以下や1時間0回は評価上の目標であり、今回の実測値や確立済みの回帰許容差ではない。

## 事前準備と素材

- ビルド識別子、OS、機器・driver、実rate、要求bufferと実callback長、配線・clock、入力／出力、NR・内蔵処理・VSTの状態と値を記録する。比較版間は対象の変更以外を揃える。変更途中や条件未取得は比較不能として扱う。
- プロジェクト所有者に、伴奏や他者の権利物を含まない無伴奏の自声を依頼する。長く伸ばす音、ビブラート、弱く消える語尾を複数含め、区間と意図を記録する。別人の素材は収録・比較・保存の用途と期間を伝えて個別に許諾を得る。音声と特定可能な情報はリポジトリ外にアクセス制限して保管し、同意期限または撤回時に削除する。記録には匿名IDと保管・削除状況だけを記載し、音声をcommitしない。
- A-3用の固定非無音信号は歌唱素材とは別に用意する。再生・録音経路やファイルの識別子を記録し、同じ信号を1時間以上使用する。素材も物理配線も未準備なら測定しない。

## A-1：自分用モニターの遅延

[配線前の計画・解析](LATENCY_MEASUREMENTS.md)の #211 手順を使う。ASIOの対応する128 sample前後を含め、実callback長を記録する。`prepare` が生成する固定信号と条件表を使い、フィードバックを遮断した安全な配線で、同一ADC clockの参照・処理後を同時収録し、各条件5回を `a1` で解析する。直結などの校正と配線図を残し、波形・競合peakも確認する。相対lagは校正なしに端子間往復遅延やOBS同期値にはならない。相関不能、clock不明、校正不足は未確認とする。

実際の歌唱者が自分用モニターで歌えるかも同条件で確認し、数値と聴感を別々に記録する。初回値も歌える遅延の目標も未取得である。

## A-3：1時間の欠損

固定非無音信号を1時間以上流し、同一録音の左に参照、右に処理後を収録する。実際の経路・設定と開始／終了、キュー診断を記録し、上記 #211 手順の `a3` で解析する。`suspectedIntervalCount` と `digitalZeroIntervalCount` は重複し得る疑いで、確定欠損数や `glitchCount` ではない。未解析時間、unknown／partial、疑い区間の波形・聴感を残す。両ch同時欠損、削除frame、短い変化や正当なNR減衰を区別できないため、検出0だけでは欠損なしと断定しない。固定信号試験と実際の1時間歌唱は別の証拠である。

## A-5：歌声の保持

同一素材・設定で基準版と変更版を収録し、伸ばす音、ビブラート、語尾ごとに欠けや不自然な変化を比較する。NR OFFの参照も用意し、版の提示順を入れ替えた目隠し対比較で、聴取者数、順序、区間、判断と理由を残す。素材不足や判断不能は未確認とする。

ボイスチェックの加工前は入力ゲイン・チャンネル選択後のFX前、加工後はFX後・出力ゲインと全体ミュート前である。分離時の加工後は配信用経路であり、自分用出力やOBS最終ミックスの収録ではない（`src-tauri/src/audio_engine/core/commands.rs`）。独立した試聴先を使い、OBS等への混入がないことを実際の経路で確認する。試聴時の任意の音量合わせは減衰のみで通常出力や保存WAVを変更しない。比較で用いた方法と値を記録する。A/Bは同じ再生位置を使うが、DSPの遅延差を完全補正しない。必要な時間合わせは手法・補正量を別記し、原本を保持する。自動相関が歌声や残響で誤る可能性を確認し、合わせられない区間は判定不能とする。

## 二系統と処理分離

同一入力から配信用と自分用の出力先を確認し、それぞれを独立に収録・試聴する。片側の処理だけを変え、意図した側に変化し、他方の処理設定・出力が保たれることを確認する。出力先、変更内容、各収録位置と結果を記録する。ボイスチェックの配信用タップだけでは両出力の到達や分離を証明できない。実機で未確認なら分離維持も未確認とする。
