# 用途別ウィンドウの方針（Issue #109）

## 寸法候補

| 表示用途 | 通常時の下限（論理px） | 保存値がない場合 |
| --- | --- | --- |
| 配信・通話 | 960×640 | 既存のウィンドウ状態を使用。完全な初期起動は既存の1024×768 |
| 音楽鑑賞 | 900×600 | 同上 |

この寸法は現在の主要操作、入出力表示とVSTラックの表示候補である。配信側では送出と分岐の情報が増えるため、音楽側よりも余裕を取る。実DPI・実Windowsウィンドウでの受入は未確認で、設計した表示での主要操作の到達性を確認し、必要なら寸法を再調整する。

設定済みユーザーのウィンドウは既存のwindow-stateプラグインが復元する。用途別の保存値がない最初の起動では、現在の寸法・位置を基本にして不足分だけ拡大し、既存値を無条件に初期寸法へ戻さない。既定値1024×768は変更していない。

## 保存と画面内復元

- 表示用途ごとに、通常時の位置・寸法と最大化状態を保存する。最大化した画面全体の寸法を、通常時の寸法として保存しない。
- 起動時にその用途の保存値があれば使用し、切り替え時は現在の寸法と位置を維持する。下限を満たさない場合は不足分だけ拡大し、音楽表示に戻すだけで縮小しない。切り替え後の実寸を新しい用途の状態として保存する。
- 用途別保存値がない場合、既存window-stateプラグインによる復元値を優先する。OSが既に最大化しており、通常時の寸法が不明なら復元用の通常寸法は1024×768を候補とする。
- モニター位置は物理px、ウィンドウ内容のサイズは論理pxで保存する。起動時・移動後・DPI変更後は表示可能な作業領域とウィンドウ装飾を考慮する。接続されなくなったモニター上の保存位置は最も近い表示領域へ補正する。
- 高DPIや小さい画面では、利用可能な作業領域を超える最小サイズを強制しない。位置とサイズは表示領域に収まるように補正し、最大化中の通常寸法は維持する。
- 保存値が壊れている場合やネイティブAPIが利用できない場合は安全に無視する。表示用途の変更によって音声機器、エフェクト、音量、ミュートなどは変更しない。

## 検証と限界

自動テストは、用途切替時の拡大・非縮小、保存済み寸法／最大化、消失したモニターの位置、混在するスケール、小画面、壊れた保存値、古い非同期応答、ブラウザー環境を対象とする。

Windowsの実ウィンドウ、最大化解除のOS固有挙動、100%／125%／150%／200%の実DPI、マルチモニター移動・切断、タスクバーや画面領域の変更は未確認。実機での確認は #72 に記録し、モック成功だけで実ウィンドウの合格にしない。寸法候補を製品保証とは扱わない。
