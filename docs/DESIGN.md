## 1. 製品の約束と利用者

### 1.1 何のためのアプリか

**いつものマイクの音を整え、聴いて確かめてから、配信や通話へ送る。**

利用者が行う作業は、次の4つに集約されます。画面の順序・名前・強調は、この流れに合わせます。

| 段階 | 利用者の目的 | 主な画面 |
| :--- | :--- | :--- |
| 1. つなぐ | マイクと送り先を決め、音が届くようにする | セットアップ、オーディオ設定、接続チェック |
| 2. 整える | ノイズを減らし、声を聞きやすくする | 音づくり、VST ラック |
| 3. 確かめる | 加工前後を聴き比べ、音量を確認する | ボイスチェック、VST を外して比較、音量チェック |
| 4. 本番中に守る | 事故を止め、すぐ戻す | 緊急ミュート、VST を外して比較、出力音量 |

### 1.2 誰に向けるか

| 利用者 | 主に使うもの | 前提にしてよい知識 |
| :--- | :--- | :--- |
| 配信者・通話利用者（既定） | 本番帯、ノイズ低減、声を整える機能。外部 VST を使わない人も多い（ゲームセンター配信など） | OBS・Discord の基本操作。仮想ケーブルは「聞いたことがある」程度 |
| 外部 VST で音を作り込む人 | 上に加えて右パネルの VST 構成、外観の「数値の詳細を表示」 | VST、バッファ、サンプルレートの意味 |

表示モード（以前の「配信向け・かんたん」「VST・詳細」）は廃止し、ホームは1種類にしました。多くの利用者は「ノイズを消したい」「声を良くしたい」が目的で、設定項目そのものには関心がありません。作り込む人でも、エンジン内部の計測値（callback、frame、cohort など）は通常の作業に不要です。この文書で「既定の表示」と書くときは、「数値の詳細を表示」が OFF の状態を指します。

### 1.3 使われる場面

- **準備中**：落ち着いて読める。説明はここに置く。
- **本番中**：緊張していて、読む余裕がない。操作は一目で分かり、一度で効く必要がある。

本番中に使う操作（緊急ミュート、VST を外して比較、出力音量）は、文字を読まなくても見分けられ、読んでも誤解しない形にします。

## 2. 情報設計

### 2.1 1画面に主操作は1つ

- 画面・モーダル・カードごとに、最も勧める操作を **1つだけ** 主ボタン（`primary`）にする。
- 選択中の状態（タブ、セグメント、トグル）に主ボタンと同じ見た目を使わない。音調整で ON の行は左端の細い線で示し、ゲーミングでは淡い塗りと発光も残す。スイッチで状態を伝える。声ON・残響OFFを「一部ON」と表示せず、内訳は情報ボタンへ置く。声OFF・残響ONは「残響のみON」と明示する。
- 未設定の状態では機器の設定を主操作にし、ほかの入口（VST 追加、チュートリアルなど）を主ボタンにしない。設定済みの停止中は、本番帯の「音声を開始」を主操作にし、失敗したときは次に取る操作を示す。移行内容の確認待ちは設定から開始する手順を保つ。誤操作防止中は保持済みの機器経路を再開し、古い入力チャンネルを再適用しない。開始自体の失敗は、再接続など別の経路も含め音声が稼働すれば警告を解除する。開始後の設定反映・保存の失敗は区別して残し、設定から正常に開始・保存できたら解除する。
- 音声稼働中で送り先が未選択のときは、本番帯から「送り先を選ぶ」を主操作として音声チェックへ移動し、選択肢へフォーカスを移す。送り先の選択後は音声チェックの次の操作を主操作に戻す。

### 2.2 同じ機能の入口は同じ名前にする

- 1つの機能の入口を複数置く場合、すべて同じ名前・同じアイコン・同じ色にする。
- 入口は「常設の1か所」と「文脈上の近道」に限る。同じ画面内に同じ操作を2つ置かない。
- 案内文やトーストで行き先を示すときは、実在するボタン名をそのまま書く。

### 2.3 ホームは1つ、VST 構成は右パネル

- オーディオ設定の遅延・周波数は「接続方式・音切れの設定」の閉じた折りたたみに置き、現在の接続方式と現在値は見出しに残す。サンプル数は既定の見出しに出さず、中の詳細に置く。接続後に毎回変更する項目ではないため、マイクと出力先の選択を先に見せる。音切れの検出時、「数値の詳細を表示」がONのとき、音切れ案内から移動したときは開く。移動先の操作へフォーカスを移し、推奨値を自動適用しない。

- ホームの骨格と音声設定は共通にし、表示用途で日常操作を出し分ける。外部 VST を使わない人には、音調整の VST 行を「外部 VST 使っていません」の薄い1行と「追加」だけにする。
- VST 構成（並べ替え・ゲイン・削除・表示形式・プロファイル管理・テンプレート）は、音調整の「VST を編集」から開く右パネルに置く。パネルはヘッダーとフッターの間に出し、狭い幅ではホームに重ねる。ホームの文字やボタンを縮小せず、余裕が増えるにつれてパネル用の幅を空ける。1200px 以上では大型メーター併用時も横に並べ、音調整の操作群は残り幅に応じて折り返す。重なる間は背後のホームを操作不可にするが、緊急ミュートと出力音量は操作できる。背景のクリックまたは Escape で閉じ、入れ子のモーダルやメニューの Escape を奪わない。開閉の状態は保存し、以前「VST・詳細」を使っていた人と音楽鑑賞の人は開いた状態から始める。閉じたらフォーカスを「VST を編集」へ戻す。広い窓ではホームとパネルの組を中央へ寄せ、間の空白を外側へ集める。開閉時は組の最大幅と予約幅を同じ240msで変え、キーボード操作と動きを減らす設定では即座に配置する。
- 大型メーターは64pxの細身表示を基本にし、詳細表示でも96pxに収め、ホームの予約幅も実際の表示幅に合わせる。最大化時もホームの右隣へ寄せる。縦バーは通常14px・詳細20pxとし、全体の高さは720pxまでに収める。高さ1100px以上ではホーム下部の横向き表示に切り替え、右側の予約幅を解除する。音声チェックの直下へ寄せ、余白の中央まで離さない。出力メーター内に入力音量を重ねず、本番帯の入力音量から調整する。大型メーターが見えている間は、本番帯の出力メーターを出さず同じ値を重複させない。縦横切替でメーターのボタンにあるフォーカスを引き継ぎ、閉じたら大型メーターの入口へ戻す。目盛りはバーの上下端からはみ出させず、実際の高さで文字間隔を確保できない目盛りは省く。通常のレベル表示中は状態文を重ねず、無音・更新待ち・停止とクリップは伝える。狭い窓でVST編集と競合する間だけ一時的に隠し、パネルを閉じると元に戻す。隠れている間は入口の印と一時的な説明で、VST 構成を閉じれば戻ることを伝える。広い窓ではVSTパネルの左に並べる。
- 初回の使い方案内（VST の追加・カード・エディタ・VST を外して比較）は、右パネルを開いている間だけ進める。
- 遅延などの数値（ヘッダーの遅延、設定の推定遅延、ノイズ低減の強さ %、本番帯・フッターのレベルの dBFS 値、ピーク保護を開いた状態）は、外観の「数値の詳細を表示」1つで出し分ける。保存値は以前の表示モードと同じで、「VST・詳細」を使っていた人はそのまま数値が出る。セットアップで「VST で音を調整したい」を選ぶと、右パネルを開き、数値の詳細も出す。もう一方の選択では右パネルを閉じ、数値の詳細は変更しない。初期選択は現在のパネルの開閉に合わせる。
- 既定の表示では、数値の詳細専用の用語（VST の遅延申告、バッファ要求など）を出さない。設定モーダル内のパネル、フッターの詳細、ボイスチェック内のパネルも既定の表示で見えるものとして扱い、上級機能は「数値の詳細を表示」の条件で隠すか、閉じた折りたたみに入れる。

### 2.4 よく使うものを上に、診断は奥に

- オーディオタブはマイク・出力先、自分用と配信用に分ける設定、配信ミックス（オケ・配信音を仕上げる VST）、接続方式・音切れの設定、入出力の保存、歌・モニターの順に置く。接続方式・周波数・音の途切れにくさは、現在値を見出しに残した共通の折りたたみへ置く。「接続方式」の選択肢WASAPI・ASIOには短い説明を添える。数値の「サンプル」「バッファ」は詳細側と情報ボタンに置く。稼働中の保存は変更があるときだけ有効にし、変更内容と音が途切れることを示す。停止中の開始、移行確認、設定反映失敗後の明示再試行は維持する。

- タブ・カードの中は、利用頻度の高い順に並べる。音づくりでは「ノイズ低減」「声を整える機能」を、歌向けの下書きより先に置く。
- 設定の左メニューは文字ラベルに種別アイコンを添える。通常時のマイク権限案内はオーディオタブの末尾に置き、アクセス拒否時はエラーの近くで開く。ASIO入力ペアの選択は短い案内を残し、監視期間やキーボード操作の詳細を情報ボタンから確認できるようにする。入力が8チャンネルを超える場合は先頭4ペア・選択中・信号ありを表示し、残りは「すべての入力ペアを表示」から開く。信号が途切れてもフォーカス中のペアは隠さない。
- 音づくりの即時反映と歌向け下書きの適用条件は常に伝える。通常のノイズ低減と環境向けの選択は並べて見せ、内蔵処理の詳細な説明は情報ボタンへ置く。
- 歌向け調整は「音を用意する」「聴いて確かめてから適用する」の順に並べる。声・残響の6つの数値入力は閉じた「数値を細かく調整」へまとめ、再取得・リセット・プロファイル保存も必要時に開く。ただし停止・取得失敗・競合時の再取得、実行可能な適用履歴、反映待ち・エラーは隠さない。試聴を閉じると歌向け欄へ表示位置とフォーカスを戻し、下書きを保つ。試聴を開閉しただけで適用・登録・試聴完了にはしない。
- 入口の説明が約束した場所へ直接移動する。例：「声を整える（ノイズ低減・声を整える機能）」から開いたら、その欄を表示する。
- 内部計測・遅延の内訳・統計は「診断情報」として折りたたみにまとめ、既定で閉じる。
- 周囲の音の測定は、既定では入口だけを表示する。「測定値で調整」「会場」を選ぶと詳細を開く。閉じたときは、その欄が開始した測定だけを中止する。
- ボイスチェックは録音前の操作を録音に絞り、波形・試聴先・比較・品質チェックは録音後に表示する。ノイズ比較の詳細は必要時に開く。失敗時の停止・再試行と、前回の変更を戻す操作は録音前でも隠さない。
- 設定移行・初期化など、まれに使う操作は各タブの末尾に置く。
- 毎日は使わない操作（音量チェック、大型メーターなど）を、ホーム上部に文字ボタンで常設しない。関係する部品の横（マイク音量・音量チェック・大型メーターは本番帯のメーター横）に置く。ヘッダーには、ほかの場所と重なる表示（小さなメーター、テーマ切替、大型メーターの切替）を置かない。
- 本番帯のマイク音量・音量チェック・大型メーターはアイコン（マイク音量は値も表示）にし、名前は読み上げとツールチップで伝える。入力機器の名前は送り先の手前に1つだけ出し、押すと機器の設定を開く。音調整の見出しには「録音して聴き比べる」だけを置き、OBS連携と詳しい調整は「その他の操作」メニューにまとめる。
- 歌・雑談が未登録の場合は、本番帯の「歌・雑談の設定」から「モードを登録」を開く。選んだら音づくりの登録欄を開き、その見出しへフォーカスとスクロールを移す。登録ボタンを二重の折りたたみに隠さず、常設の説明は「いまの音を歌・雑談に登録します」の1行にする。登録するのは適用済みの内蔵設定で、VSTプロファイルは各モードへ任意で関連付けることを情報ボタンで確認できるようにする。雑談登録時に残響がONなら「残響をOFFにして登録」を明示的に選び、登録用の設定だけを変える。保存が成功したら、もう片方の音を調整する入口を出す。登録後は同じ入口を編集ボタンにし、設定を閉じたときのフォーカス復帰先を保つ。
- 音声チェックは、問題がなく畳んでいる間は枠を付けない状態の1行（状態の点と「入力 → 出力先」）にする。問題があれば枠付きのカードで開き、必要な操作を見せる。

- 配信ミックスの設定はオーディオタブ内で、オケと配信 VST を並列の1段の折りたたみにする。別タブ案はマイク・分離出力との行き来を増やし、歌・モニターの中へ置く案は機能を発見しにくいため採用しない。オケを使わなくても配信 VST の内容を確認・準備できる。有効化にはオケ設定が必要な現在の制約を、その操作の近くに示す。開いたら状態を一度取得し、以後の取得では編集中の内容を上書きしない。前提が不足する場合は、分離出力または主入力の操作へスクロールとフォーカスを移す。
- オケの経路確認は、主入力、オケの種類・機器・入力ペア、選択中アプリ・原音の出力先が変わった場合に必要とする。音量・ミュート・時間差の変更や同じ経路の再適用では要求しない。アプリの再起動・候補消失・原音出力のミュート解除が確認された場合は再選択する。Windows の経路は自動変更せず、二重再生と循環を防ぐ説明を入力元の近くに残す。
- 保存範囲は声の設定、分離出力まで、歌／雑談モードまで、オケと配信 VST まで、アプリ入力の単一選択にする。範囲の選択だけでチェックボックスを自動変更しない。声のカテゴリ選択は声だけを保存するときに表示し、ほかの範囲は全カテゴリを含むことを対象範囲で説明する。

### 2.5 本番中の操作

- 本番帯は「歌／雑談」の切替と、その枠外の状態「いまの調整」を分ける。「いまの調整」は登録モードを使っていないときだけ、チェックと補足サイズの文字で示し、操作の枠・塗り・ホバーを付けない。登録モードの使用中は同じ場所を空けて配置の跳ねを防ぐ。見出しの「モード切替」を繰り返さない。登録編集と歌配信の準備は、文字付きの「歌・雑談の設定」へまとめる。操作は通常の画面内で展開し、拡大表示で画面外へ固定しない。Tabで項目へ進み、Escapeで閉じられる。閉じてから設定を開き、設定終了後は同じメニューボタンへフォーカスを戻す。
- 誤操作防止は盾のアイコン・文字・ON/OFFを一緒に示す。設定変更やVST付きモード切替の保護範囲を説明し、停止と緊急ミュートは引き続き使える。処理待ち・復旧・失敗の表示はメニューへ隠さない。
- 正常かつ音声チェックを畳んでいる間は、幅1000px以上・高さ720px以上の窓で余った高さを本番帯へ配分し、入力・出力のバーを64〜140pxで表示する。音声チェックを開いた場合、問題がある場合、大型メーター・音量チェック・配信ミックス表示中・重ね表示の操作中はコンパクトへ戻して作業を優先する。表示の変更で音量や音声経路は変えない。
- 大きな本番帯の入力・出力は同じラベル列・バー列で上下に並べ、バーの左右端を揃える。マイク音量・音量チェック・大型メーターは両行にまたがる共通の操作列へ置く。状態文字はバーの直後で左揃えにし、受信待ち・無音・停止・クリップの意味を保つ。
- モード登録の補助操作は、登録済み・誤操作防止中・復旧中の場合だけ置く。正常な未登録状態には下部の常設折りたたみを置かない。取得・操作の失敗時はエラーと再取得を直接表示し、保護解除と復旧への経路を残す。
- モード登録は歌・雑談のカードごとに登録状態・音を調整・設定を登録を先に見せる。一緒に切り替えるVSTと保存済みの組み合わせはカード内の詳細から開く。詳細を開閉したことを保存・適用とみなさず、再取得や保存失敗でも未保存の選択を保持する。

- 保存済みまたは適用中のオケ・配信 VST がある場合だけ、本番帯の歌／雑談の切替の隣に配信ミックスの状態を置く。オケ設定がある場合は音符アイコンと音量（%）からポップオーバーで音量・ミュートを変更できる。歌モードだけに限定するといまの調整でのオケ操作ができず、ホームへ常設の大きな区画を追加すると通常の声だけの利用を妨げるため、この条件付きの小さな操作にする。取得停止・音声待ち・配信 VST 停止を文字で伝え、状態を押したら設定へ移動する。状態を押して音は変更しない。配信 VST の稼働は enabled だけで判断せず、現在の ready・attached・failed も照合する。

- モードへVSTプロファイルを結び付ける場合は、切替中に音が止まること、誤操作防止中は拒否すること、失敗すると手動復旧が必要になる場合があることを保存前に伝える。未指定なら内蔵設定だけを切り替える。プロファイル内の機器・ノイズ低減・音量・内蔵設定は適用しない。登録後のVST内容が変わったら再登録する。新しい明示空ラックだけを全VST削除として解釈し、旧空配列を削除へ読み替えない。
- VST付きモードは、出力callbackの無音ACK後に全件を入れ替え、内蔵処理の完了も確認してから一時的な無音を解除する。停止・緊急ミュートは常に優先する。元へ戻せた失敗は「いまの調整」で再試行でき、結果不明・復旧失敗・未完了の記録がある起動時は自動再開しない。「以前の状態を復旧する」は音声停止中に行い、その後もミュートを保つ。

- 本番帯と音声チェックの「送り先」は配信・通話などの利用目的を示す。実際の出力機器や、受け側への到達確認と混同させない。
- モード登録では保存済みの声処理・残響の状態を要約し、「音を調整」から対応する設定へ進める。歌向けの調整から登録へ戻る操作も用意する。両モードの設定が同じ場合だけ、登録欄に案内を出す。
- 歌・雑談の登録カードは、モード名・登録状態・保存内容・操作・VSTの詳細をそれぞれ共通の行へ置く。横に並ぶ間は行の高さを共有し、日英の名前や説明が折り返しても状態と操作の位置を揃える。片方だけ未登録の場合も、保存内容のない行を保つ。
- 本番帯の「歌・雑談の設定」は、未登録の場合だけ行の右端へ寄せた補助操作にする。送り先が未選択なら「送り先を選ぶ」を主操作として優先する。登録後の切替・誤操作防止・メニューの配置と、設定を閉じたときの同じ入口へのフォーカス復帰を維持する。
- モード登録・歌向け欄のプロファイル保存・プロファイル管理には、共通の情報ボタンで保存方法の比較を用意する。配信中の内蔵処理・残響の切替と、選択した構成の保存・呼び出しを区別し、下書きや試聴候補を保存しないことを伝える。説明を開いても保存対象や適用状態は変えない。歌向けの各数値にも情報ボタンを置き、単位、増減の方向、困ったときの調整方向を必要時だけ確認できるようにする。説明は効果の保証にせず、少しずつ変えて試聴・適用を確認する手順へつなぐ。

- 緊急ミュート、VST を外して比較、出力音量は、どの表示でも同じ位置に常設する。大きな窓でもVST を外して比較と出力音量が離れすぎないよう、フッターの操作はホームと同じ最大幅にまとめる。
- VST復元の異常・保存済み構成の保護は、ホーム先頭で知らせる。警告の見出し・保護理由・再試行の入口は横並びを基本とし、必要な幅がなければ折り返す。復元再試行の入口は折りたたみに置き、開くと現在のラックを外す影響を説明してから実行できる。ファイル不在を確認できたVSTは、名前・保存への影響・バックアップから戻す条件を確認してから、保存済み構成から外せる。ほかの読み込み失敗やラック変更が残る場合は保護を解除しない。出力ミュート・音量ゼロの対処は機器の再設定へ誘導せず、本番操作の確認へ案内する。
- 既定のウィンドウ幅（1024px）以上では、これらのボタンに **文字ラベル** を表示する。アイコンだけにしない。
- 状態が変わったら、ボタンの見た目と文言の両方で示す（例：「緊急ミュート」→「ミュート中」）。
- トーストなどの通知を、これらの操作の上に重ねない。通知はフッターの上（右下）に出す。
- クリップの記録は手動で解除するまで残し、最後の検出から10秒経過すると警告色を弱める。ツールチップで経過秒数を伝える。音切れ表示は最後の回数増加から10秒表示し、押すと音声処理の詳細を開く。表示が消えた後に詳細を閉じても、常設の詳細入口へフォーカスを戻す。
- 停止状態の常設表示はヘッダーに置き、本番帯では開始操作を優先する。音声チェックやメーターの状態は必要な文脈に限り、同じ停止文言を繰り返さない。
- 状態表示（フッターのバッジなど）を押しても音を変えない。押した場合は、その設定を変更できる場所を開く。

## 3. 文言の置き方

### 3.1 見出し・配置・操作名で分かることを、補助文で繰り返さない

補助文（説明文、ツールチップ、カードの下段、注記）は、見出し・ボタン名・置かれた場所から **分からないこと** だけを書きます。

| 種類 | 避ける例 | 直した例 |
| :--- | :--- | :--- |
| 見出しの言い換え | 見出し「マイクを選んでください」＋「お使いのマイクをリストから選択してください。」 | 見出しだけにする |
| 選択肢の言い換え | 「高速／低遅延」「安定／高遅延」 | 下段を用途にする：「高速／楽器演奏向け」「安定／音切れ対策」 |
| 値の読み上げ直し | 数値入力の直下に「下書き：低音 80 Hz ／ 音量差 …」 | 入力欄だけにし、反映済みとの差分があるときだけ示す |
| 同じ条件の繰り返し | 「配信（即時切替）」「低め（即時切替）」「明瞭（即時切替）」 | 各ボタンは「配信」「低め」「明瞭」。グループに「選ぶとすぐ反映します」を1回 |
| 同じ画面での二重説明 | 「あとから変更できます」を見出しと注記の両方に書く | どちらか1か所にする |

### 3.2 小ラベルや右側の説明は、意味を足すときだけ使う

小ラベル（見出し上の分類、値の右側・下側の注記、カード下段）を置いてよいのは、次のどれかを足すときだけです。

- **分類**：何の仲間か（例：「入力（マイク）」「出力（配信へ）」）
- **対象**：何に効くか・どこへ送るか（例：「受け側では CABLE Output を選びます」）
- **範囲**：効く範囲・効かない範囲（例：「効きにくい：周囲の会話・BGM」）
- **単位・基準**：数値の読み方（例：「%」「ms」「1回分の目安」）
- **条件・結果**：押す前に知るべきこと（例：「音が一度途切れます」「元に戻せます」）

どれにも当たらない小ラベルは削除します。

### 3.3 削ってはいけないもの

文言を減らすときも、次は維持します。

- **入力ラベル**：すべての入力欄・選択欄・スライダーに、見える名前を付ける。プレースホルダーをラベルの代わりにしない。
- **操作条件**：押せない理由、押すと起きること（音が途切れる、保存される、元に戻せる／戻せない）。
- **アクセシブルな名前**：アイコンだけのボタンの `aria-label`、状態を表す `aria-pressed`・`role="status"`。`aria-label` は見える文字を含める（「マイク入力」と表示する欄の名前を「マイク入力・ASIOデバイス」にしない、表示「設定を変更」のボタンの名前を「オーディオ設定を開く」にしない）。
- **状態と名前の分担**：切り替えボタンは名前を固定し、状態は `aria-pressed` で伝える。表示を「ミュート解除」に変えたまま名前を「ミュート」にしない。

### 3.4 注意書きは、必要になったときに出す

- 失敗時にだけ役立つ案内（マイクの許可、デバイスの占有など）は、失敗したときに表示する。常設する場合は折りたたみにする。
- 常設してよい注意は、[COPY_GUIDELINES.md](./COPY_GUIDELINES.md) が求める効果範囲（ノイズ低減の効く・効きにくい対象など）と、破壊的な操作の条件だけにする。
- 画面の見出し直下の一文は、その画面の目的にする。範囲の注意を最初の一文にしない（例：ボイスチェックは「録音して、加工前と加工後を聞き比べます。」を先に書く）。
- 内部の計測根拠（「同HPFのdynamics0対照で評価」など）は、結果の箇条書きに混ぜず「根拠と限界」の折りたたみへ入れる。
- 1つの欄に「保証しません」「含みません」を3つ以上並べない。必要なら「対象範囲」の折りたたみにまとめる。

### 3.5 ボタン名

- 「動詞＋対象」で、押した結果が分かる名前にする（例：「マイクの音を流して確認」「OBS に接続」）。
- 名前は実際の動作と一致させる。テスト音を鳴らさない操作を「サウンドテスト」と呼ばない。短さや慣れのために名前が効果の範囲より広くなる場合（VST だけを外す「VST を外して比較」など）は、説明・ツールチップ・状態表示で範囲を必ず示す。
- 押せない理由は、押せない間だけボタンの近くに示す（例：「再生するには、試聴先を選んで確認にチェックしてください」）。
- キー操作を案内するときは、利用者が変更した割り当てを差し込む。既定キーを文言に固定しない。
- 状態の表示と操作を1つのボタンに兼ねない。「接続済み（クリックで切断）」ではなく、状態「接続済み」と操作「切断」を分ける。
- 停止・削除・初期化など音や設定を失う操作は、取得・確認など安全な操作と同じ見た目（下線リンクなど）にしない。並べる場合は区切りと余白を入れる。
- 括弧で操作を補わない（「サウンドテスト (開始)」ではなく「サウンドテストを開始」）。

### 3.6 用語

- 既定の表示では、英語・内部用語・略語を出さない。
- 数値の詳細で専門用語を使う場合は、日本語を先に書き、必要なら括弧で原語を添える（例：「処理の待ち時間（バッファ）」）。
- 内部 ID（`broadcast` などのプリセット名）を画面に出さない。
- 用語は第4章の正規名に揃える。

### 3.7 文言キー

## 5. 視覚ルール

### 5.1 色

- 色は `src/index.css` のトークン（`primary`、`destructive`、`muted` など）を使う。Tailwind の固定色（`red-700`、`amber-500` など）を直接書かない。
- 状態色は次の意味に固定し、ヘッダー・フッター・トーストで同じ色を使う。

| 意味 | 用途 |
| :--- | :--- |
| 危険（`destructive`） | 緊急ミュート、削除、初期化、停止中の異常 |
| 注意（`warning`） | VST を外して比較中、未確認の項目 |
| 正常（`success`） | 音声処理中、接続済み |
| 情報（`muted`） | 補足、ヒント |

警告は `warning`、正常は `success`、案内は `info` を使います。エラーの本文はテーマごとの可読性を保つ `destructive-text`、危険操作の塗りは `destructive` を使います。`destructive` は塗り専用とし、文字・枠・リングには使いません。危険操作の枠・リングは `destructive-text` を使い、緊急ミュートのように操作や状態の識別に必要な印は透過させず、隣接する面と3:1以上を保ちます。装飾だけの枠は透過を使えます。用途違反は `src/__tests__/themeContrast.test.ts` で検出します。メーターの注意域と危険域は文字色や塗りボタンから独立した `meter-warning`・`meter-danger` を使います。ブランドは `brand`・`brand-secondary`、波形の比較は `waveform-raw`・`waveform-processed` として状態色から用途を分けます。定義は `src/index.css` に集約します。

- ブランドの基調色は [BRANDING.md](./BRANDING.md) の「静かな面、一か所の光」に従う。既定のダークテーマ「オーロラ（標準）」（内部 ID は `dark`）とライトは、背景・カード・枠線・文字を彩度の低い段階で作り、面に色相を持たせない。色はメーター、状態色、本番帯の奥のオーロラに集める。ゲーミングは黒に近い地にネオンのマゼンタを主色と選択色にして差し色を1色に絞り、オーロラと見てすぐ区別できるようにする（今回の改訂の対象外）。
- オーロラとライトでは、役割ごとに次の色を使う。どれも状態色と混ぜない。
  - 主色（`primary`・`brand`・`ring`）: 青緑（Aurora Teal）。主ボタンの塗り、スイッチの ON、フォーカスリング、文字リンク、操作の目印に使う。大型メーターなど、機能の ON を示す切り替えも同じ色にする。
  - 選択中のボタン・タブ・プリセット・送り先・VST の有効表示（`selection`）: 文字色に近い無彩色の細枠と淡い塗り。色相は持たせない。
  - 共通セグメントの確定した選択（`segment-accent`）: ブランド色の3px下線と10%の淡い面。ライト・オーロラは青緑、ゲーミングは従来のマゼンタを使う。主ボタンの全面塗りと区別し、`aria-pressed` と下線の形でも伝える。下線は面と3:1以上、文字は4.5:1以上を保つ。
  - 補助色（`brand-secondary`）: Aurora Rose。支援の目印など、ごく小さな飾りにだけ使う。
  - 面（`background`・`card`・`popover`・`secondary`・`muted`・`accent`・`border`・`input`）は彩度15%以下にする。
  - 主ボタンの文字と塗り、主色と背景、選択色とその淡い塗りは 4.5:1 以上を保つ（`src/__tests__/themeContrast.test.ts`。面の彩度も同じテストで確かめる）。
  - 主ボタンは当初 Mist（明るい無彩色）にする案だったが、`primary` は文字リンクや選択の目印として約200か所で使われており、無彩色にすると目印が文字と区別できなくなる。そのため主色にそろえた。
- オーロラは本番帯の奥にだけ置く（`live-aurora`、色は `aurora-green`・`aurora-teal`・`aurora-rose`、強さは `aurora-strength`）。音声処理中（エンジン稼働中）は共有入力メーターの強さに合わせてゆっくり変化し、停止中は消す。到達確認や音質の判定には使わない。オーロラ（標準）とライトで表示し、ライトでは淡くする。ゲーミングでは表示しない。
- オーロラは飾りであり、状態の意味は持たせない。無音や異常はメーターと文言で示す。設定で表示をオフにできるようにし、切り替えはホームに置かない。
- 本番帯と音調整は枠を重ねず、余白と面の明るさの差で区切る。問題がある音声チェックと設定の入力欄には細い枠線を使う。ホームと設定のセクション見出しは20px・太さ600、主な操作は16px・太さ500〜600、補足は13px・通常の太さと控えめな文字色で強弱を付ける。すりガラス、色相のグラデーション、発光、色付きの影は使わない（ゲーミングは改訂の対象外とし、カードの半透明と ON 行の淡い塗り・発光を残す）。音調整で ON の行は、左端の細い線だけで示す。メーターの正常域だけは、緑から青緑への同系色のグラデーションを許す。画面全体の格子模様など、面に重ねる飾りも置かない（ゲーミングは背景の光と格子を残す。5.6）。
- 危険操作の塗り（`destructive`）とその文字（`destructive-foreground`）も、全テーマで 4.5:1 以上を保つ。
- 選択中のタブ・セグメントなど、状態を示す目印は周囲と 3:1 以上の差をつける（WCAG 1.4.11）。背景のわずかな明暗差や文字色だけに頼らず、塗り・枠線・太字のいずれかを併用する。
- 文字サイズは共通の `text-ui-heading`・`text-ui-control`・`text-ui-support` を役割ごとに指定する。セクション見出し・legendは20px、下位見出しと主要な入力ラベル・操作は16px、補足・小さな補助操作は13px。設定内の全button/select/labelなどを要素種別だけで一律指定しない。情報アイコンやリンク風の補助操作まで拡大しない。

### 5.2 ボタンの強さ

| 強さ | 見た目 | 使う場面 |
| :--- | :--- | :--- |
| 主 | 塗り（`primary`） | 画面の主操作1つ |
| 副 | 枠線 | 主操作の代替・補助操作 |
| 弱 | 文字のみ | キャンセル、閉じる、詳細を開く |
| 危険 | 危険色の枠線または塗り | 停止・削除・初期化。確認を挟む |

- 押せないボタンは、どの強さでも見た目で区別する（`disabled:opacity-50` など）。押せない理由は画面に表示する。`sr-only` だけに書かない。
- 角丸はテーマによらず共通にし、通常ボタンは10px、大きな操作は12pxを基準にする。Gamingでも角丸を極端に小さくしない。ネイティブの選択欄と展開した候補にもテーマの背景・文字色を適用する。

### 5.3 文字

- ホームと設定で使う主要な文字は3段階とする。セクション見出しは `text-ui-heading`（20px、太さ600、行高1.4）、主な操作・入力ラベルは `text-ui-control`（16px、太さ500〜600、行高1.5）、補足は `text-ui-support`（13px、通常の太さ、行高1.5）を使う。補足には `muted-foreground` を使う。画面題名とメーターの数値は、その役割に合わせてさらに大きくできる。
- 900×600と150%では主操作を縮小せず、まとまり単位の折り返しと縦スクロールを使う。メーターの状態は「受信待ち」等の短い表示にし、省略記号で切らず必要なら折り返す。完全な状態はメーターの読み上げとツールチップへ残す。
- 補足（`text-ui-support` + `muted-foreground`）を3行以上続けない。続くなら構成を見直す。
- 数値・デバイス名以外に等幅フォントを使わない。

### 5.4 アイコン

- アイコンは `react-icons/md`（Material Design）に揃える。絵文字を使わない。音量チェックは計測用のゲージ、大型メーターは縦のレベルバーで区別し、短いツールチップで目的と対象範囲を示す。
- 意味が一意でないアイコン（例：緊急ミュートの医療記号）は、文字ラベルと組み合わせる。

### 5.5 レイアウトと寸法

- ホームはどの幅でも上から1列（本番帯 → 表示を選んだ配信ミックス → 音調整 → 音声チェック）に並べ、広い画面では最大 1180px で中央に寄せる。左右2列にすると片側だけが詰まって見えるため。主要カードは内側の余白 16〜20px、カード同士の間隔 16px を基準にする。正常時の拡大条件と問題発生時の優先順位は2.5に従い、入出力バーを64〜140pxで調整する。高さ1100px以上で大型メーターを開くと、ホーム下部の余白に横向きで配置する。
- 音調整は、音の流れの順にアイコン・名前・操作・スイッチを揃えた行で並べる。段ごとの枠や発光、分類タグの反復はなくし、行の区切りだけにする。種別と処理範囲は読み上げ・ツールチップ・情報ボタンで確認できるよう残す。実際の作業幅が760px以下のときは、名前とスイッチを先に置き、操作群を次の行へ送る。
- ノイズ低減と声を整える機能のセグメントは、同じ高さ・余白・最小幅の規則を使う。
- ホームのエフェクト量は5%刻みの20段階。ラベル・数値を含む操作欄は最大22remとし、広い窓でもバーだけを伸ばし続けない。狭い窓では操作群を折り返し、数値と操作幅を保つ。
- VST 構成の右パネルは幅420pxとし、重ね表示と横並びは2.3の方針で切り替える。本番帯の歌・雑談の切替は、残り幅が不足すれば次の行へ送る。パネル用の予約幅はホームの操作幅を保てる分だけ空ける。

- 現行実装の最小ウィンドウは配信・通話が960×640、音楽鑑賞が900×600。既定はどちらも1024×768。用途別の寸法は `src/lib/usageWindow.ts` の `WINDOW_POLICY` に従い、実Tauriではリサイズ後に制約が適用された実寸を確認する。
- 用途別の最小サイズで主要操作に到達でき、文字の切れ・重なり・1文字ずつの折り返しが起きないことを確認する。小さい画面では補助情報の折りたたみ・配置変更を併用し、表示領域を超える最小サイズを強制しない。
- 最大化するとラックの表示件数が増え、空き領域があるのに一覧だけが小さな領域に制限されない。用途別にサイズ・位置・最大化状態を記憶し、表示領域とDPIに合わせて復元する。表示用途の切替だけで音声設定・送出・ミュートを変更しない。
- ヘッダー（高さ 64px）の要素は2行までにする。
- 統計などのタイルは、ラベルが2行を超える幅になる場合、表または縦並びに切り替える。

### 5.6 動き

Auralyn は作業の道具です。動きは状態の変化を伝えるときだけ使い、見せるための演出にしません。

**動かすかどうか**

| 対象 | 判断 |
| :--- | :--- |
| 本番中の操作（緊急ミュート、VST を外して比較、出力音量） | 画面内の場所は動かさない。VST を外して比較中は静的な注意色の枠と「VST オフ」で示す。押した瞬間に見た目と文言を切り替える。緊急ミュートは押下中の色も強め、処理を待たせない |
| キーボード・ホットキーで開くもの | 配置の移動を待たせない |
| ノイズ低減の強弱、声の種類、歌・雑談、ミュート | 選択背景を確定したボタンの位置へ200msで移動する。反映待ちは未確定の選択を表示せず、背景の要素と位置だけ保持して、成功後に移動する。ミュートは押下時に2px沈め0.97倍にする。音声操作の完了を待たせない |
| ホバー | 色の変化だけ。短く控えめにする |
| 右パネル、モーダル、ポップオーバー、ツールチップ、トースト | 出入りを短く示してよい |
| 初回セットアップの完了など、まれな場面 | 演出してよい |

ポインターで開く設定画面とメニューは200msで不透明度と0.97→1の拡大を組み合わせる。設定画面の暗幕は拡大しない。動きを減らす設定では拡大を止める。

押下の移動は `press-feedback` を付けた緊急ミュート・オケ/VSTミュートだけに限定する。`aria-pressed` のある全ボタンへ適用しない。セグメントの文字と誤操作防止は動かさず、確定した選択の印だけを移す。動きを減らす設定では押下の移動も停止する。

**書き方**

- 時間と曲線は `src/index.css` のモーショントークンを使う。値を個別に書かない。UI の動きは 300ms 以内にする。
  - 時間：`duration-(--motion-fast)`（150ms：押下・ホバー・ツールチップ）、`duration-(--motion-base)`（200ms：ポップオーバー・モーダル）
  - 曲線：出入りは `ease-out`、画面内の移動は `ease-in-out`（どちらも `index.css` で強めの曲線に上書き済み）。進捗のように一定の速さで進むものは `ease-linear`
- 通常の出入りは `transform` と `opacity` に限定する。幅・高さ・余白を遷移させず、伸び縮みは `scaleX` などで表す。右パネルとホームを連動させる予約幅1要素だけは、下記の理由で例外とする。
- `transition: all`（Tailwind の `transition-all`）を使わない。色だけなら `transition-colors`、影・不透明度・transform も変わるなら `transition`、移動だけなら `transition-transform` を使う。
- 出入りには ease-out 系の曲線を使い、ease-in を使わない。`scale(0)` から出さない。
- 何度も押される要素には、途中から戻れる transition を使う。最初からやり直す keyframes を使わない。
- メーターと波形は計測値の表示であり、この節の対象外とする。値を遅らせたり、補間で実際と違う値に見せたりしない。
- ホームの区画は、状態・文言・ウィンドウ幅で高さや並びが変わっても跳ねさせない（#298）。`useLayoutMotion` が変化の後に前回の位置との差を測り、`--motion-panel` と `--ease-in-out` で transform を 0 へ戻す（FLIP）。幅・高さは遷移させない。
  - 対象はホームの直下の区画と、`data-layout-motion` を付けた部品だけ。部品の位置は外側の区画から測り、区画ごと動いたときに二重に動かさない。
  - 伸び縮みした区画そのものは切り抜かず、後ろの区画の移動で変化を伝える。clip-path で隠した部分は押せないため、開いたばかりのメニューを押し損じさせない。新しく現れた部品は、場所を動かさず `--motion-fast` の不透明度で入れる。
  - 測るのは大きさが変わったときだけにし、メーターの値の更新では測らない。途中で次の変化が来たら、今の位置から動き直す。
  - 設定の反映中に観測が一瞬「反映待ち」になっても、メーターの配置（広い表示）を畳まない。
  - 動きを減らす設定では位置を記録するだけにし、動かさない。

右パネルはポインターで開閉したときだけ `--motion-panel`（240ms）と `--ease-drawer` で出入りさせる。パネル・ホームの予約幅・大型メーターを同時に動かし、退場後のアンマウントでホームの幅を変えない。文字の変形と終了時の跳ねを避けるため、例外として予約幅1要素だけは width を遷移させる。実Tauriでフレーム間隔と閉じ終わりの幅の連続性を確認する。閉じ始めた内容は即座に操作・読み上げの対象から外し、フォーカスを入口へ戻す。初期表示とキーボード操作では移動を待たせず、途中で開き直した場合は現在位置から反転する。

**動きを減らす設定（`prefers-reduced-motion: reduce`）**

- 移動・拡大・回転をやめ、不透明度と色の変化だけを残す。状態が変わったことは伝わるようにする。
- 繰り返し続く動き（脈動、点滅）を止める。読み込み中の表示は、静止した表示と文言に置き換える。

**背景の装飾**

- 画面全体の背景に置いていた、ぼかした光の塊（`aurora-glow`）と格子模様は、ライトとオーロラでは廃止し、本番帯の奥のオーロラ（5.1）に置き換える。ゲーミングでは従来どおり表示し、本番中（音声処理中）と動きを減らす設定では止める。
- 本番帯のオーロラだけは装飾用の `--motion-aurora`（800ms）で不透明度・transformを補間する。入力レベルを5%刻みにし、既存の共有メーターを使う。追加のIPC・タイマー・音声処理は作らない。これは操作の300ms上限とは別の背景表現であり、メーターの表示値は変えない。動きを減らす設定では静止した光にし、表示OFFでは要素を描画しない。
- ぼかしフィルターや `mix-blend-mode` を使わず、グラデーションの重ね合わせで描く。装飾のために本番中の処理負荷を増やさない。

### 5.7 ステージと音の流れ（#301）

ホームとセットアップの構成は、動く試作の3案（A ステージ、B 音の流れ、C タイル）を実アプリのウィンドウで見比べて決めた（2026-11-05）。利用者が選んだのは、**A を基本にし、未設定のホームだけ B の音の流れにする**組み合わせ。試作は開発時だけ `?proto=ab`（Ctrl+Shift+P）で開ける（`src/prototypes/`）。この節は、それ以前の規則と食い違うときに優先する。ゲーミングの装飾は対象外とする。

選んだ理由（利用者の評価）:

- 決め手は未設定のホームの差。A は分かりやすく迷いにくいが、VST ホスト・配信ツールとして並べて使いたくなる見た目ではなかった。B の流れは、その点で選ばれた。
- A のセットアップに異論はなく、B と比べると A の方が好まれた。A を基本にする。
- C はぱっと見て分かりやすいが、使いたくなるものではなかった（子ども向けの携帯電話を見ている印象）。大きなアイコンと少ない文字だけで画面を作る方向は採らない。

**未設定のホーム（B）**

- 最上段に、音の流れを「マイク → 整える（Auralyn）→ 送り方 → 送り先」の4区間で横に並べる。区間は、アイコン・小ラベル（13px）・値（16px、太さ600）で示し、区間の間は細い線でつなぐ。
- 区間の状態は3つに固定し、文字を読まなくても見分けられるようにする。
  - 未決定：破線の枠と、控えめな文字色。値の欄は「—」にする。
  - 次に決める所：主色の2pxの内側線、淡い主色の面、「ここを決める」。この状態は画面に1つだけ置く。
  - 決定済み：`muted` の塗りと、主色のアイコン面。両端の区間が決まると、その間の線を主色にする。
- 流れの下には、主ボタン1つ（次に決める区間の名前。例：「送り先を決める」）と1行の説明だけを置く。区間を押しても同じセットアップが開く。
- 音調整は不透明度40%で操作不可にし、警告を並べない（#297）。

**セットアップ（A）**

- 高さを固定したダイアログ（高さ560px、または画面の高さに収まる値）にする。左の手順レール（幅200px）と右の中身、下の操作欄で構成する（#294）。
- 手順の名前は、ホームの流れの区間名とそろえる（送り先・マイク・送り方・確認。2.2）。
- 現在の手順の印（`accent` の面と、左端3pxの主色の線）はレールの上を縦に滑る。済んだ手順と現在の手順の番号は主色で塗る。
- 手順の見出しは24px・太さ600にする。そのほかの文字は、5.3の3段を守る。

**設定済みのホーム（A）**

- 最上段は本番帯を「舞台」にする。入力機器 → 送り先を1行で示し、右に歌・雑談の切替、その下に声のメーター（高さ18px）を置く。奥にオーロラ（5.1）を灯す。
- 配信ミックスのパネルを表示するときだけ、本番帯の直下、音調整の手前へ置く（#355）。音調整・音声チェックの高さで本番中の入口が押し出されないようにし、表示中は本番帯のメーターを大型化しない。既定では非表示とし、上部に低頻度の設定を常設しない。パネルは音調整と同じく外枠を付けず、面と余白、内部の行の区切りで示す。内部のオケ・配信 VST の詳細設定は折りたたみに保つ。

**アクセント**

- 選択中のカードには、主色の2pxの内側線、主色8%の面、右上の主色の丸いチェックを付ける。線は `box-shadow: inset` で描き、太さが変わってもレイアウトがずれないようにする。カードのアイコン面も主色16%の面と主色の文字に変える。
- 推奨の選択肢には、主色15%の面に主色の文字で小さな「おすすめ」札を付ける。札は1画面に1つまでにする。
- 主ボタンは手順ごとに1つにする（2.1）。押せないときは中立の面と文字にし、理由をボタンの横に書く。

**動き**

| 対象 | 動き |
| :--- | :--- |
| セットアップを開く | 暗幕は不透明度だけ、本体は0.97倍から。どちらも `--motion-base`、`ease-out` |
| 手順の切替 | 進む向きから28pxずれた位置と不透明度0から入る。260ms、`ease-out`。戻るときは逆向きから入る |
| 手順レールの印 | 縦の移動、`--motion-panel`、`ease-in-out` |
| 選択カード | 線と面は150msで変える。チェックは0.6倍から200msで拡大する。押下中は0.98倍にする |
| 次に決める区間 | 外側の波紋を1.8秒ごとに繰り返す。画面内で繰り返してよい動きは、この1か所だけにする |
| パネルの開閉 | 行の高さを `grid-template-rows` の 0fr→1fr で、`--motion-panel` と `--ease-drawer` を使って変える。中身は不透明度を200msで変える |
| 主ボタン | 押下中は0.97倍にする。ホバーでは矢印を4px進める |

- パネルの開閉は、5.6の「高さを遷移させない」の例外とする。中身の読み込みで高さが一度に変わり、下の要素が跳ねる（#298）のを避けるため。対象は、開閉する1つの要素の行の高さだけにする。
- 動きを減らす設定では、移動・拡大・波紋を止める。手順の切替とダイアログは不透明度だけにし、選択の印・レールの印・つまみの移動は瞬時に切り替える。
- 新しい動きの値は、`src/index.css` のトークンから取る。試作の `proto.css` は、採用部分を本体へ移したあとに消す。

**未確定**

- 流れは右端の「送り先」から決め始める。この順のまま案内を工夫するか、決める順を変えるかは、#294・#297の実装で実アプリを見て決める。

## 6. 状態とフィードバック

- 1つの状態は1か所で1回だけ表す。同じ領域に「エンジン停止」と「音声未設定」を並べない。
- 状態は結果を書き、次の操作を1つ示す（例：「音声未設定」＋「マイクと出力先を設定する」）。
- 未設定は中立の点と「音声未設定」、取得できない状態は注意色と未確認の文言、設定済みの停止は危険色と「音声停止中」で区別する。未設定を故障として赤く表示しない。
- 未設定の接続画面は「初回設定」と開始する入出力を示す。画面が自動選択した候補を「変更予定」に数えず、設定済みの場合だけ利用者が操作して保存値と異なる項目を列挙する。
- 未設定時の機器はOS既定のIDを優先し、先頭候補で補わない。既定がない・複数で確定できない・入力の既定が再生音の取り込み系なら未選択として案内する。保存済みの機器が失われた場合も別の既定へ暗黙に切り替えない。
- 送り先は共通定義からOBS・通話・自分で聴く・その他の順と名前・アイコンを使う。「自分で聴く」は入力手順でマイク／PCの音を選ぶ。旧music設定はPCの音を保持し、表示の統合だけで経路を変更しない。
- マイク権限の確認は、セットアップと設定で同じ部品を入力選択の直下に置く。無効な「次へ」は主色の塗りから中立の面と文字へ変え、必要な入力選択を近くで伝える。
- 画面側の音声設定が空・破損の場合も、同じアプリに正常設定が残っていれば起動時に画面へ戻し、未設定と混同しない。起動時の復帰では元データを書き換えず、復帰値を新しい自動開始要求へ渡さず、既存のHost起動gateを維持する。明示読み込みは画面側の選択を保存するが、それだけでは音声開始・移行完了・VST復元を行わない。別の配布形式や一時利用の保存先へ代替しない。
- 明示読み込みの入口は、画面側が空で、検証できたネイティブ保存があるときだけ機器欄の後に補助操作として置く。読取中・不在・読取不能には入口と説明を出さない。接続方式の表示名は共通関数を通し、内部値が`Wasapi`でも画面には`WASAPI`と表示する。
- トーストは操作の結果を知らせるために使い、恒常的な案内に使わない。行き先を示すときは実在するボタン名を書く。
- 音や設定を失う操作は、確認を挟むか、元に戻す手段を示す。
- 読み込み中・確認中は、操作できない理由を表示する。
- 音量変更の通信失敗は表示し、確認できない値を保存済みにしない。入力・出力の小窓に再試行を置く。モードの初回読込失敗も入口ごと消さず、ホームから状態を再取得できるようにする。
- 緊急ミュートの失敗は切替済みと表示せず、配信・通話アプリ側でのミュートを先に案内し、設定を開く入口を残す。技術的なエラー原文は詳細に置き、主な表示は次の操作を示す。

## 7. アクセシビリティ

- 見える名前とアクセシブルな名前を一致させる（WCAG 2.5.3）。
- 切り替えボタンは `aria-pressed`、タブは `role="tab"`、状態の変化は `role="status"` で伝える。
- すべての操作をキーボードで行えるようにし、フォーカスの位置を見える形で示す。
- 色だけで状態を伝えない。文言またはアイコンを併用する。
- 詳細な確認手順は [ACCESSIBILITY_MANUAL_CHECK.md](./ACCESSIBILITY_MANUAL_CHECK.md) を使う。
