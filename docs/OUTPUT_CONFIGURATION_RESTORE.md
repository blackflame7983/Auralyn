# 分離出力を含む配信状態の保存・復帰

#222の最初の実装単位として、声用途・カスタム構成の二系統出力、枝別の内蔵処理、trimを既存の配信状態へ追加する。
後続のschema 3では[歌／雑談モードの登録・選択と関連VST](LIVE_MODE_STATE_RESTORE.md)も扱う。
本書は先行したschema 2の対応範囲と確認記録を残す。プロセス入力の復帰は引き続き対象外とする。
[未保存状態の共通契約](UNSAVED_RUNTIME_RESTORE.md)に従い、ピーク保護・学習結果・録音・外部アプリは復帰しない。

## 保存した項目と復帰する項目を一致させる

旧形式は単一出力の形式として読み続ける。分離出力を含める場合は明示選択し、新形式に主入出力の機器IDと二系統出力の全設定を保存する。
配信出力のID、処理分離、自分用の歌／雑談処理、両枝のtrim、自分用ミュートを含む。
音声機器・音量・NR・内蔵処理・VSTも同時に保存し、一部だけを選んで分離出力を落とす保存は拒否する。
現在の本番保護中と歌／雑談モード中は、この単位では保存・復帰を拒否する。
処理分離中の自分用処理は、登録済みの歌向け設定と同じ状態だけを扱う。
過去の雑談設定や個別復元した設定を保持している場合は、標準設定へ戻したことを「復帰」と表示しないよう拒否する。

取得するのは実Engineの出力構成である。保存ファイルも照合し、取得中の外部編集や、実行中の値と保存値の食い違いを成功へ読み替えない。
差分には配信用機器、処理分離、trim、自分用ミュート、枝別処理を表示し、音声再起動とVST再ロードが必要であることを先に示す。

## 原本を確保し、ミュートのまま両枝を再起動する

適用前に、現在の両枝の全設定とVST stateを既存の非公開原本領域へ退避する。
元の主入出力のIDを現在の選択と照合し、配信用出力もIDで一意に見つかることを必要とする。
既定機器や同名機器に代替しない。利用者が明示開始して全体ミュートし、新しい差分を確認した場合だけ適用する。

再起動中は今回の出力構成をHost内の一時的な指定として使い、古い保存ファイルを再読して上書きしない。
適用後は実Engineの両枝と設定値を照合し、保存ファイルを同期して読み戻す。完了した後だけ成功表示と復旧待ち解除を行う。
Stop・緊急ミュート・世代変更を優先し、VST欠落・出力失敗・書込み失敗では原本を保持する。
VST・出力構成の適用自体に失敗した場合は両枝を停止する。停止の応答を確認できなければ、今回のHostが所有するEngineとの接続を終了する。
反映後の照合で競合した場合は完了とせず、原本を保持する。
出力設定ファイルは適用直前と書込み直前に元のバイト列と照合し、途中の外部編集を上書きしない。

Undoと異常終了後の手動復旧にも同じ形式を使う。自動開始や自動復帰は追加しない。
本番保護・ピーク保護は過去の値から復活させず、現在の全体ミュートとVST全体バイパスを維持する。

## コードの確認とV-04を分ける

旧形式、対象外構成、欠落機器、保存時の外部編集、取得・適用中の変更、空ラック、音量ゼロ、部分失敗、Stop・ミュート、Undoの条件を自動確認する。
分離出力と枝別処理の設定が戻ることと、耳やOBSに届く音が正しいことは別に確認する。
実音声の漏れ・二重音・機器切断・ASIOとWASAPIの混在・長時間運転はV-04の実機受入として残す。

## ミュート中も設定反映を完了させる

実Hostの追加試験で、ミュート中の配信出力が「反映待ち」のままになる不具合を見つけた。
配信sinkが無音を返す際、ピーク保護の係数更新と反映通知を途中で省略していた。
このため、機器や枝別処理を読み戻す前に、復帰の前提条件を満たせなくなっていた。

ピーク保護は補間後の出力に一度だけ通し、ミュート・入力待ち・異常停止で返す無音でも係数更新と反映通知を進めるようにした。
無音の出力から新しいPCMを取得せず、解除後に過去の音を戻さない。
無音の4経路で再現テストが修正前に失敗することを確認し、修正後は出力0とRT割当・解放0を保ったまま反映が完了した。
この確認を実音声の聴感やV-04の合格には読み替えない。

## 遅れて届く音量初期化を実変更へ数えない

実Hostでは、Engineの再起動通知に合わせて画面が保存音量の初期化を再送する。
Engineは明示した開始条件や音量設定を優先して初期化を無視していたが、Hostはこの再送も変更として数えていた。
そのため、実際の復帰値が一致していても、照合の世代が変わって未完了になっていた。

Hostでも同じEngine内の初期化済み状態を区別し、以降の初期化要求は現在値の取得にする。
明示的な音量変更、Stop、Engine交代での失効は維持する。
初回だけ変更を送り、後から届く保存値では実音量と照合の世代を変えないことを、音声を開かない所有fixtureで確認する。

## 実Hostでは設定の復帰と失敗後の原本保持を確認する

実行入口は `scripts/verify-output-configuration-native.mjs`。
Host・Engine・scanner・設定・WebView2・TEMPを専用領域へ分離し、共有MCPドライバーと通常設定を変更せず確認する。
入力はCABLE Output、本人用出力はVoicemeeter Input、配信用出力はCABLE Inputを使用し、48 kHz・512フレームで全体ミュートを維持する。
同じ仮想ケーブルの入出力を使う試験用構成であるため、この試験でミュートは解除しない。実配信の配線や聴感の合格には使わない。

| 条件 | 確認内容 |
| --- | --- |
| 明示保存 | 実UIで分離出力を選び、全カテゴリと主入出力のIDを新形式へ保存する |
| 旧形式の保護 | 分離出力を省略して入出力カテゴリを保存する要求を拒否する |
| 差分と適用 | 実UIで両枝・trim・再起動の差分を確認し、ミュートを維持したまま復帰する |
| 実値の照合 | 配信用sinkと処理分離worker、入出力gain・NR、TDR Novaの件数とcomponent stateを照合する |
| Undo | 直前の出力構成とVSTを戻し、現在の全体ミュートを保持する |
| 外部編集 | 出力設定ファイルがプレビュー後に変われば、同じ意味のJSONでも古い差分を拒否する |
| 機器欠落 | プレビューへ欠落IDを出し、機器を代替せず、変更前に適用を拒否する |
| VST読込失敗 | 所有する非実行ファイルのfixtureで読込を失敗させ、両枝の停止と復旧原本の保持を確認する |
| 明示復旧 | 元の機器を明示開始して新しい差分を取り、失敗前の構成へ戻す |
| OS設定 | 終了後も全出力機器の音量・ミュート・既定の役割が試験前と一致する |

初期試験の「反映待ち」はミュート中のsinkの不具合として再現・修正した。
修正前後の結果と、独立したSoundblaster出力で停止を観測した未確認条件も、ignoredの `test-results/output-restore-20261103/` に残す。
後者の原因は確定しておらず、対応機器全体の合否へ一般化しない。
画面の音量初期化との競合も修正し、実機の失敗記録を成功記録で上書きしない。

この先行対応後、歌／雑談の登録・選択・関連VSTは[schema 3へ拡張](LIVE_MODE_STATE_RESTORE.md)した。
プロセス入力、一時利用前の分離出力退避、V-04の可聴確認は未完了である。
