# VSTスキャン結果を差分で更新する（Issue #451）

2026-11-08、`codex/scan-catalog-451-20261108` でローカル実装した。ベースは `codex/vst3-class-id-450-20261108` の `f6c37e80`。実在の VST3、認証画面、音声機器では確認していない。

スキャン結果の正本は `<app_config_dir>/vst_catalog.json`。成功したクラスは従来どおり `scan_plugins` が `Vec<VstPlugin>` で返す。画面は `scan_plugin_catalog` と `retry_plugin_scan` を使う。`scan_plugin_catalog` の戻りは `plugins`、`failures`、`stats` に加え、`generation`、`recoveredFromCorrupt`、`saveError` を含む。スキャナーの実行ファイルが無いときは、全件を `spawn_failed` にせず、カタログを変えずに「スキャン用のプログラムが見つかりません」を返す。

## カタログ

`schemaVersion` は 1。各 entry は binary の正規化パス、bundle ならそのディレクトリ、`fileId`（`size` と `modifiedNs`）、スキャナー形式、最終試行時刻、結果を持つ。結果は `ok`（クラス一覧）、`noEffects`、`failed` のいずれか。

`ok` には、クラスにメーカーが無いときの表示用 `factoryVendor` と、クラス ID の無い旧スキャナー出力用の `legacy` を任意で入れる。クラス ID を作らずに、#450 の表示と旧1行出力を再利用するためである。

失敗の `kind` は `crashed`、`timed_out`、`load_failed`、`no_factory`、`invalid_output`、`spawn_failed`、`legacy_blacklisted`、`unknown`。子プロセスの JSON に `errorKind` を足し、ホストはその値だけを見る。フィールドが無い旧出力や、知らない語は `unknown` にする。エラー文からの推定はしない。

`crashed` は非0終了で JSON が無いとき。JSON として読めない、または `formatVersion` が 2 でも旧形式でもないときは `invalid_output`。exit 0 で成功せず `errorKind` も無い完了は、対応エフェクトが無い走査完了として `noEffects` に入れ、除外しない。

## 差分

候補は今までと同じ2つのルートから集め、bundle は中の `Contents/x86_64-win` にある binary を1件にする。同一性はその binary のサイズと更新時刻、および `scannerFormatVersion`（現在 2）が一致すること。

一致する entry は再スキャンしない。失敗も自動では再試行しない。サイズか時刻か形式が違うときだけ、その1件を置き換える。候補から消えた entry は削除する。

通常の再スキャンは差分（`incremental`）。「すべて再スキャン」は成功とエフェクトなしを調べ直す。読み込めなかったものを含めるかはチェックで選び、既定は含めない。

この判定は、更新時刻を保ったまま中身だけを置き換えたファイルを見ない。bundle の説明ファイルだけが変わった場合も、binary のサイズと時刻が同じなら再スキャンしない。

## 再試行と並行

`retry_plugin_scan` は指定したパスの1件だけを調べ、ほかの失敗は残す。失敗のままなら `attempts` を1増やす。成功なら `ok` に置き換える。通常のスキャンは30秒、この再試行は120秒。認証画面が出ることがあるためで、ホストはその画面を閉じない。画面には、操作することと、応答がなければ時間切れで失敗になることを書く。実機の認証ウィンドウでは未確認。

スキャン、再試行、除外のリセットは1本のゲートで直列にする。実行中の追加要求は待たせず「スキャン中です」で返す。再試行が認証を待っている間に、別の要求を同じだけ待たせないためである。各実行には世代番号を付け、その世代が現在の世代でなければ結果をカタログへ書かない。

保存は1件更新するたびに一時ファイルへ書き、同じフォルダで置換する。途中で落ちても、置換前のファイルは完全な JSON のまま残る。アプリ再起動で途中の世代を継がない。

## 旧除外と壊れたファイル

カタログが無く `vst_blacklist.json` があるときだけ、今もファイルがあるパスを `legacy_blacklisted` として取り込む。ファイルが無いパスは file id を取れないので取り込まない。以降、スキャンは blacklist を読まない。ファイルは消さない。ダウングレードした版が、移行時点の除外をまだ使えるようにするためである。新しい失敗をこのファイルへは書かない。両方へ書くと、片方の保存失敗で内容がずれる。

「読み込みを止めたVSTをリセット」は、カタログの失敗 entry を消し、blacklist も空にする。次の差分スキャンは、消したファイルだけを新しい候補として調べる。空にするのは、ダウングレード後もリセットの意味を残すためである。

カタログの JSON が読めない、または `schemaVersion` が 1 でないときは `vst_catalog.json.corrupt-<時刻>` へ移し、空から全件スキャンする。このときは blacklist を再取り込みしない。壊れたファイルの直前まで成功していたプラグインを、古い除外で再び止めないためである。読み取りそのものが失敗したときは、ファイルを空にせずエラーを返す。

保存に失敗しても、今回の一覧は返す。画面は、次回は最後に保存できた内容を使うと知らせる。

設定の移行では `vst_catalog.json` を許可リストに入れ、`schemaVersion` が 1 で path が空でないことを確認する。
