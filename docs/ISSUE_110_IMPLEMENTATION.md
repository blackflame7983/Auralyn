# 設定画面とウィンドウ幅（Issue #110）

## 構造の比較

1. 既存の中央モーダルを広くする案は変更が少ないが、小さいウィンドウではタブと本文が同じスクロールに残る。
2. 別ページへ遷移する案は広さを使えるが、既存のダイアログからの戻り先・入れ子を変更する範囲が大きい。
3. 既存のモーダル操作を保った全高シートに、固定タブ・本文・操作バーを置く案は、画面を広く使いながらフォーカスの管理を引き継げる。今回はこの案を採用した。

## 変更内容

- 保存済みテーマを初回描画前に安全に読み、ライト・ダーク・ゲーミングの背景と `color-scheme` を反映する。保存値がない・壊れている・読み出せない場合は OS の配色、取得できなければダークとする。テーマ変更は従来のクラス切替を使う。
- ヘッダーに入力ゲインの入口を常設し、押して開く操作にした。1024px 以上は設定・ヘルプ・入力ゲインの文字も表示する。大型メーターの入力音量スライダーは操作名とリセット説明を区別した。
- 設定を全高シートとし、タブを左に常設して本文と別にスクロールする。オーディオの保存操作は下部に固定し、セットアップの入口はシステムタブへ移した。システムとホットキーは表示モードにかかわらず常設する。
- ホットキーは既存の保存形式を維持し、修飾キーと物理キーを押して入力できる。Escape は入力のみを取り消し、Tab は移動に使える。既存の手動選択も残した。重複と一部の既知の OS 予約キー、未対応キーを知らせ、実登録時の失敗は従来のエラーを表示する。保存と取消はホットキータブの上部に固定する。
- 1440px 以上のホームは左に準備・声、右に VST と音量チェックを並べる。狭い幅では従来どおり1列とし、本番操作はヘッダーとフッターに保持する。

## 検証と残る範囲

- `npm test -- --run`: 成功（116 ファイル・1107 テスト、skip 0件）。初回テーマ選択、ショートカット入力・取消・修飾キー順を含む重複・既知予約・未対応キー、設定画面内の Escape と既存エラー処理を含む。
- `npx tsc --noEmit`、`npx vite build`、`git diff --check`: 成功。Vite は 500 kB 超の chunk、Git は改行変換について警告した。
- 一時的に応答を補った Vite モックで、日英 900×600・1024×768・1280×720・1920×1080・2560×1440 の設定6タブと保存バー、文書の横はみ出しを確認した。英語 1024px では入力ゲイン・設定・ヘルプの文字、入力ゲインのキーボード開閉とフォーカス復帰を確認した。1280px は1列、1920・2560px は2列だった。900px のホットキー入力で Escape の取消、修飾キーを含む入力を確認した。モックはショートカット保存の応答を実装していないため、実登録は確認していない。
- 英語 900×600 のボイスチェックでは録音ボタンがスクロールなしで画面内にあることを確認した。録音は実行していない。モックの試聴応答が不足していたため、エラー時に試聴欄が開く状態だった。
- 英語 1024px の詳細表示で入出力両方がクリップすると、修正前は状態表示が3行となり緊急ミュートの下に重なった。1280px 未満ではヘッダー内の重複メーターを畳み、状態表示の幅を確保した後、900・1024px の通常時と両クリップ時に重なりがないことを確認した。1280px では小メーターとクリップ表示を維持した。入力メーターはホーム、出力メーターはフッターでも確認でき、大型メーターの入口も残る。
- OS・別アプリの全予約キーを事前に列挙するものではない。既知の組み合わせ以外の登録競合は従来の登録エラーで知らせる。
- 実機・実 VST Host・OBS・聴感・実 DPI・Narrator、および Windows 上での実ホットキー登録は未確認。
