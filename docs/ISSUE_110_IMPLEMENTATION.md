# 設定画面とウィンドウ幅（Issue #110）

## 構造の比較

1. 既存の中央モーダルを広くする案は変更が少ないが、小さいウィンドウではタブと本文が同じスクロールに残る。
2. 別ページへ遷移する案は広さを使えるが、既存のダイアログからの戻り先・入れ子を変更する範囲が大きい。
3. 既存のモーダル操作を保った全高シートに、固定タブ・本文・操作バーを置く案は、画面を広く使いながらフォーカスの管理を引き継げる。今回はこの案を採用した。

## 変更内容

- 保存済みテーマを初回描画前に安全に読み、ライト・ダーク・ゲーミングの背景と `color-scheme` を反映する。保存値がない・壊れている・読み出せない場合は OS の配色、取得できなければダークとする。テーマ変更は従来のクラス切替を使う。
- ヘッダーに入力ゲインの入口を常設し、押して開く操作にした。1024px 以上は設定・ヘルプ・入力ゲインの文字も表示する。大型メーターの入力音量スライダーは操作名とリセット説明を区別した。
- 設定を全高シートとし、タブを左に常設して本文と別にスクロールする。オーディオの保存操作は下部に固定し、セットアップの入口はシステムタブへ移した。システムとホットキーは表示モードにかかわらず常設する。
- ホットキーは既存の保存形式を維持し、修飾キーと物理キーを押して入力できる。Escape は入力のみを取り消し、Tab は移動に使える。既存の手動選択も残した。入力待ちの間は登録済みホットキーの操作を停止し、登録済みキーも入力として受け取る。入力終了・フォーカス移動・30秒経過で操作を再開する。重複と一部の既知の OS 予約キー、未対応キーを知らせ、実登録時の失敗は従来のエラーを表示する。保存と取消はホットキータブの上部に固定する。
- 1440px 以上のホームは左に準備・声、右に VST と音量チェックを並べる。狭い幅では従来どおり1列とし、本番操作はヘッダーとフッターに保持する。

- `npx tsc --noEmit`、`npx vite build`、`git diff --check`: 成功。Vite は 500 kB 超の chunk、Git は改行変換について警告した。

- OS・別アプリの全予約キーを事前に列挙するものではない。既知の組み合わせ以外の登録競合は従来の登録エラーで知らせる。
