# プロセス入力を明示選択して配信状態を復帰する

#222の保存・復帰を、声／音楽用途のプロセス単独入力へ拡張する。
単独出力・カスタム構成を対象とし、処理分離と歌／雑談モードの組合せは既存の非対応を維持する。
分離出力の追加設定は標準状態だけを扱い、枝別のtrimや自分用ミュートを変えた構成は保存前に拒否する。通常の入出力音量と全体ミュートは扱う。
プロセス入力の開始条件は[段階1の契約](PROCESS_LOOPBACK_STAGE1.md)に従う。原音用の別出力先と、その出力機器側のミュートが必要である。

## 保存するアプリ設定と、その時点の実行状態を分ける

保存画面の「プロセス入力の設定も保存する」で、アプリの識別情報と表示名、原音用出力、声／音楽の用途、返し先の機器IDを全カテゴリと一緒に保存する。
schema 4を使い、旧schema 1〜3とは混ぜない。プロセス入力を機器入力として保存し、後でマイクへ置き換える経路は拒否する。

PID・プロセス生成時刻・候補一覧の選択IDは保存しない。
現在のHostが明示選択したPIDと生成時刻だけをメモリー内で保持し、差分の取得後に実行状態が変われば再確認を必要とする。
同じ名前の別アプリや再利用されたPIDを、保存した設定だけで選択しない。

## 現在の選択を照合してから再起動する

復帰前に、音声設定で同じアプリ・用途・原音用出力・返し先を明示選択して開始し、全体ミュートして新しい差分を確認する。
差分にはアプリ名・用途・両出力のID、選択の一致と欠落を表示する。選択不一致や欠落では適用ボタンを無効にし、Hostでも変更前に拒否する。
原音用と返し先が同じ機器の場合は拒否し、機器IDを名前や既定の出力で代替しない。

適用直前に現在のプロセスと音声セッションを確認し、PIDと生成時刻・アプリ識別・原音用経路の一致を検証する。
音声再起動には検証した現在の選択だけを渡し、保存したPIDを復活させない。
最初の音声callbackから現在のミュートと全体バイパスを維持し、VST・NR・内蔵設定・音量を復帰する。
出力設定ファイルも適用前後に照合し、途中の経路変更を完了として扱わない。

Undoと失敗後の手動復旧にも同じ形式を使う。
VST・処理設定の適用自体に失敗した場合は停止し、変更前の原本を保持する。停止応答を確認できなければ、所有するEngineを終了する。
反映後の確認で競合や異常があれば完了とせず、原本と現在の全体ミュートを保持する。
Hostの再起動後は自動送出せず、復旧原本があってもアプリの明示選択・開始・ミュート・差分確認を必要とする。
保存時と同じアプリを起動し直した場合も、利用者が選び直した新しい実行状態だけを使う。

## 音楽用途の制約と、実音声の確認を残す

声／音楽の用途は既存の処理経路に従う。音楽用途で声向け測定を有効にする変更は含めない。
学習結果・信号到達の履歴・聴感の合格・ピーク保護・本番保護・録音・外部アプリの設定は復活させない。
プロセス入力の一時利用前の退避、機器入力の音楽用途、処理分離や本番モードとの組合せは、この実装単位の対象外である。

自動試験は通常の再生アプリや物理マイクを操作せず、所有するテスト再生プロセスで確認する。
未使用のCABLE Inputを原音用に一時ミュートし、終了時に元へ戻す。Auralynの返し先は指定済みのVoicemeeter Inputを使い、全体ミュートを維持する。
入口は`scripts/verify-output-configuration-native.mjs`の`--process-input`で、保存・差分・適用の実UIと、終了・再選択・中断・Host再起動後の手動復旧を確認する。
Chrome・音楽プレイヤーの聴感、機器切断、各ドライバーや実OBSでの受入は別に残す。
