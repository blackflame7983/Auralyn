# 競合比較と改善順序：Auralyn・Live Audio Assist・Stream Gear Mixer

確認日：2026-10-27。Auralynの基準は `main` の `e71a1d3fa175614fa5109475da89d0a2ff9a5522`（PR #105マージ後）。

## 方針：環境が変わっても準備・比較・復旧できる体験を強化する

Auralynは既存機能を保持し、自宅・ゲーセンの配信と通話を対象にする。差別化の中心は、入力条件に合った確認、同じ録音でのノイズ低減比較、通常設定を守る一時利用、失敗後の復帰である。機能を削ることや、競合の機能数へ追随することを目的にしない。

現行実装はこの方針の土台を持つ。ただし、音質・遅延・CPU負荷・安定性の比較優位は未確認。他製品の公開ページに記載がないことを、機能が存在しない証拠にはしない。

本書は比較と計画の記録。製品コード・係数・依存・設定、GitHub Issueの本文・状態・依存設定は変更していない。以下の受入条件と試験行列は今後の計画であり、今回の合格記録ではない。

## #97／#98の実装残件と受入条件

### I-97a：未保存状態のsnapshotと復帰契約（#97）

現在の別領域起動と明示import／exportは保持する。現行にない未保存runtimeの退避・復帰を追加する場合、最初に項目ごとの所有者・保存先・復帰可否を定義する。

- [ ] 音声選択・実機ID／ch／gain、NR／FX／VST state・順序、二系統構成・trim、自分用処理、歌／雑談・本番保護・ピーク保護について、保存値と稼働状態、永続とHost寿命を区別した対応表がある。
- [ ] 録音・試聴・進行中適用・OBS／OS／VST外部状態など対象外を開始前に示す。対応していない値を落として「元どおり」と表示しない。
- [ ] 復帰は機器・schema・Engine世代・設定revision・外部／後編集を照合する。取得不能・機器欠落・保存失敗・競合では原本を保持し、別機器や未加工経路へ自動代替しない。
- [ ] 通常終了・異常終了・再起動・旧PID待機失敗・一時領域削除失敗で、未完了の音声／試聴／適用を自動再開しない。通常設定への明示開始後のVST復元、空セッションの保存解除、二重通知・取消の回帰を保持する。
- [ ] 旧schema、同名機器、VST欠落、取得中の変更、途中失敗、Stop／muteとの競合を自動検証し、#98へ共通の範囲・差分・競合契約を提供する。

このチェックの成功は、V-03の共有PC・配布形式・異常終了の実機合格とは別に記録する。

### I-97b：変更差分と選択的な書き戻し（#97）

現行は通常設定へ自動コピーせず、必要な音作りを明示exportする。これは原本を守る代替として維持する。需要確認後に拡張する場合の受入条件は次のとおり。

- [ ] 利用開始前と終了時の対象差分を示し、破棄／export／対象を選んだ書き戻しを区別する。機密値や生音声を差分・復旧マーカーへ含めない。
- [ ] 通常側の後編集・他利用者の変更を検出し、衝突を自動上書きしない。選ばなかったカテゴリは保存値も実設定も変わらない。
- [ ] 原子的保存・バックアップ・中断回復を確認する。変更前から値が変わっている場合は古いsnapshotへ巻き戻さない。
- [ ] 実装を見送る場合は、需要と理由、明示exportで対応できる範囲、残る要件・追跡先を#97に記録する。自動的な全受入完了にはしない。

### I-98a：全対応構成の確認済み保存・復帰（#98）

現在は単一出力・カスタム構成に限定し、対象外構成をnative側でも拒否する。この制限を、拡張完了前に外さない。

- [ ] I-97aの契約を使い、分離出力・枝別処理・trim・歌／雑談・本番保護の対応範囲を保存と復帰で一致させる。ピーク保護のHost内保持／再起動時OFFを変更するなら、互換性と利用者の明示選択を別途定義する。

- [ ] 緊急ミュート・明示Stopを優先し、本番保護中の構成変更を拒否する。保存しただけでは適用せず、復帰時のミュートを勝手に解除しない。

### I-98b：局所Undoと障害の案内（#98）

- [ ] NR候補・内蔵候補・固定gain・profile／bundle・monitor trialの対象と基準revisionを示す。局所Undoを全設定の復帰と呼ばない。

- [ ] 未設定／停止／stream失敗／機器欠落／VST部分復元／OBS未接続／取得不能を、観測できる範囲で区別する。推定原因を断定せず、確認・再選択・有限retry・停止維持を案内する。
- [ ] 内部の復旧成功と相手側の可聴確認を分ける。原因が不明でも無制限retry、別機器への無言切替、未加工音への代替をしない。

## 評価後に判断する強化

### D-01：導線・送り先案内（#92／#94／#74）

V-01／V-05の記録から、次の主操作・接続先の対・二重処理の案内を絞る。通常表示の少数状態と詳細の根拠を両立させ、既存の詳細操作・入力ラベル・アクセス可能な名前を保持する。受入は同じ対象者・条件での成功率／時間／やり直しの比較と、変更後の失効・停止・フォーカスの回帰確認。改善が未測定なら「簡単になった」と断定しない。

### D-02：現行NRとDeepFilterNetの再比較（#93）

#100後の現行controller・モデル・設定を固定し、同じ許諾済み素材をDFN3標準と比較する。#93の旧基準による表を修正後の結果として流用しない。品質・本人の声の保持、信号対応／追加遅延、初回／定常／過負荷、CPU・メモリ、移行／配布コストを同じ境界で報告する。

受入は採用／条件付き採用／保留／不採用と理由・適用条件・未確認を残すこと。採用自体は必須ではない。採用する場合も追加候補から始め、現行NR・旧設定・発声保護を保持する。処理時割当のある推論を音声callbackへ直結せず、有界worker・世代・過負荷・失敗時停止を別の実装で検証する。低遅延モデルを軽量モデルとは扱わず、優先は下げたままとする。

### D-03：新しい送信・操作連携は需要から判断する（#92の将来候補）

専用OBS送信、仮想マイク／driver、専用Stream Deckは現在の必須範囲に加えない。導入時間・送り先選択で残る失敗を示し、仮想ケーブルの案内改善や既存のOBSシーン連動・ホットキーで足りるか比較する。新規方式はOBS版／配布／driver／保守の依存と、OBSなしの通話経路への影響まで評価してから採否を決める。

BGM・セットリスト・Overlay・効果音・汎用ミキサーの拡充も後続。LAA等との共存は有用な候補だが、処理段・二重NR／AGC・重複取り込みを固定して実機確認するまで推奨構成とはしない。
