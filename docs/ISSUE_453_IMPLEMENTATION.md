# Issue #453: VSTの切替・削除・並べ替えで音と遅延の不連続を抑える

## 長さと方式

slot ごとの遷移長は `T = sample_rate / 100`（48 kHz で 480 フレーム、10 ms）。半分は `T / 2`（48 kHz で 240 フレーム、5 ms）。0 除算を避けるため最短 1 フレーム。状態は固定配列で、callback 中に確保・解放しない。

方式は遷移を始める瞬間の申告遅延で決める。

- 申告遅延が 0: クロスフェード。遷移中だけ VST を呼び、その入力（dry）と VST 出力（wet）を線形に混ぜる。完了後の bypass は VST を呼ばない。
- 申告遅延が 1 以上、または不明（`u32::MAX`）: ディップ。今の出力を `T/2` で 0 にし、無音のサンプルで経路を切り替え、`T/2` で次の経路へ戻す。遅延の違う dry と wet を同時に鳴らすと櫛形フィルタや二重発音になるため、重なる区間を作らない。
- 無音との出入り（mute、停止からの復帰、無音の追加）: レベルフェード。`T` で片方の係数だけを動かす。遅延のある VST を無音から立ち上げるときも、dry と遅延 wet は重ねない。

連打と途中取消は、その時点の係数から逆方向へ続ける。同じ目標の再送ではランプを最初からやり直さない。削除待ちの slot は、dry 以外の新しい目標を受け付けない。

## 操作

- Bypass のオン／オフは、上の方式で wet と dry を入れ替える。完了後は従来どおり VST を呼ばない。
- Mute のオン／オフは即ゼロをやめ、`T` のフェードにする。フェードアウト中は VST を呼び、mute が落ち着いたあとは呼ばない。
- 追加は、wet を 0 から立ち上げて音量の谷を作るのをやめる。dry から wet へ、遅延に応じた方式で移る。ゲインの smoother は最初から指定ゲインにいる。追加時点で bypass または mute なら、フェードせずその状態で始まる。
- 削除は、順序に入って処理中の slot を先に dry へフェードし、完了したフレームで既存の retire キューへ渡す。キューが満杯なら従来の `pending_retire` に残し、callback では drop しない。bypass が完了して既に dry の slot と、isolated（#448）の slot は即時に外す。mute が落ち着いて無音の slot は、無音から dry へ `T` で戻す。無音から入力を急に戻す段差を避けるためである。
- 並べ替えは、共通 slot の相対順が変わるときだけチェーン出力をディップする。フェードアウトは全体比較と同じく callback の末尾まで伸ばすので、`T/2` より最大 1 callback 長くなる。無音の時点で、ためた順序の最新だけを適用する。追加や削除だけ（共通 slot の並びが変わらない）ではチェーン全体はディップせず、slot 側のフェードに任せる。Load は追加のあとに並べ替え、Unload は削除のあとに並べ替えを送るので、ここでチェーンもディップすると谷が二重になる。
- 全体 bypass 中はプラグインを通らない。保留中の順序はその場で適用し、途中のチェーンフェードは 1 に戻す。
- isolated の slot は遷移させず無音のままにする。再開は無音から目標の経路へフェードインする。不正値の検査は、VST を呼んだブロックでは遷移中も行う。無効な出力は混ぜる前に無音にする。
- グローバルミュート、ストリーム障害、停止の無音は遷移より優先する。ミュートと障害は処理のあとでデバイスバッファを 0 にする。遷移の状態は進んでよい。Stop はストリームを閉じ、遷移の尾は出さない。

ミックス後 VST の bypass、mute、再開は同じ `PluginControls::process` を使う。稼働中の load、unload、並べ替えは従来どおり拒否する。

## 遅延表示

`plugins.rs` の遅延合計は、制御側が bypass を受けた時点でその slot を除外する。音声のフェード完了より先に、遅延表示とミックスの時間合わせ（`sync_mixing_latency`）が変わる。ずれは `T` 程度、数十 ms である。フェード完了まで表示を遅らせることはしていない。

## 交換条件

遷移中だけ VST を呼ぶ。bypass が完了したあとは呼ばないので、常時すべての VST を動かす方式にはしていない。遅延を保ったまま dry を出すバイパス（VST を動かし続ける、または申告遅延ぶんの遅延線を常設する）は採らなかった。申告遅延は未知のことがあり、長い遅延線は callback の固定バッファと追加遅延を増やす。ディップは遷移の間だけ無音の谷を作り、遅延差の重なりを避ける。

bypass を戻したとき、VST 内部の残響などの履歴は残る。callback から `setProcessing` を呼ばないためである。ディップとフェードインで境目は目立ちにくくなるが、履歴そのものは消えない。

VST の生成と破棄は制御側のままである。callback は既存の retire キューと `pending_retire` へ所有権を移すだけである。

## 検証

合成 VST（ゲイン、申告遅延つきの遅延、減衰する内部状態）で確認した。実 VST の試聴、実機デバイス、OBS は未実施。

隣接サンプル差の上限は `1 / (rate/200) + 0.001`。48 kHz では `1/240 + 0.001 ≈ 0.00517`。44.1 kHz では半分が 220 フレームで約 0.00555、96 kHz では 480 フレームで約 0.00308。

振幅 0.5 の反転クロスフェードは、出力が `-0.5` から `0.5` まで動く。一段の差は `1/T` で、48 kHz では `1/480 ≈ 0.00208`。同じ反転を遷移なしで切り替えると差は 1.0 である。試験はこの差が上限以下で、かつ遷移なしの 1/4 より小さいことを、44.1／48／96 kHz と 32／64／480／1056 フレームで確認した。左右の片側だけが鳴る入力では、無音側は 0 のままである。出力の絶対値は、入力と各経路の最大を超えない。

遅延 8 サンプルの VST はディップを選ぶ。定数入力は無音付近を通り、完了後は dry に戻る。無音から入れたインパルスは 1 回だけ出る。不明な遅延（`u32::MAX`）もディップになる。

追加は dry から立ち上がり、0.5 倍の VST ではサンプルが 0.5 から 1 の範囲に収まる。ゲイン 0.5 指定では smoother が 0.5 から始まり、完了後の出力も 0.5 である。遅延ありの追加はディップで無音付近を通る。

削除はフェードのあと retire キューに入り、callback 中の割当と解放は 0 である。完了後に入力 0.25 を入れると出力は 0.25 で、削除した VST の尾は出ない。bypass 済みの削除は即時、mute 済みの削除はフェード、isolated の削除は即時である。

並べ替えを続けたときは最後の順序だけが無音のあとで効く。チェーン出力は無音付近を通る。連打と途中取消のあと、最後の要求の経路に落ち着く。isolated 中は bypass を変えても VST を呼ばず無音のままである。再開の最初のサンプルは無音に近い。

グローバルミュートとストリーム障害が使う無音化は、遷移中のバッファを 0 にする。Stop は遷移の尾を描かない。
