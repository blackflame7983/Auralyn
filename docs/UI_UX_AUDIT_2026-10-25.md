# UI/UX・デザイン監査（2026-10-25）

対象は `codex/monitor-completion-review` の HEAD（`1880f3f`）時点の画面です。判断基準は [DESIGN.md](./DESIGN.md) と [COPY_GUIDELINES.md](./COPY_GUIDELINES.md) です。

この文書は監査時点の判断材料です。修正の完了や現在の実装を示す証拠として扱わないでください。

## 確認方法と限界

- **実画面**：Vite 開発サーバーの画面をブラウザで開き、Tauri の通信を仮の応答に置き換えて描画しました。表示寸法は既定ウィンドウと同じ 1024×768 です。
- **コード**：`src/components` と `src/i18n/messages.ts` の日本語文言を、画面上で一緒に見える見出し・ボタン名と照らし合わせました。
- **文言の全数点検**：`messages.ts` の日本語文言を名前空間ごとに3つに分けて点検しました。表示条件と動作に関わる主な指摘は、コード（例：`core.rs` のバイパス処理）で確かめてから採用しています。
- **確認していないこと**：実機の音声エンジンと接続した状態、OBS 接続後の画面、VST を読み込んだラック、英語表示、ライトテーマ、900×600、スクリーンリーダーでの読み上げ。
- 仮の応答による見え方（例：OBS 未接続なのに「接続済み」と表示）は、指摘から除くか、設計上の問題に限って記載しています。

## アプリのコンセプトと評価の軸

Auralyn は「いつものマイクの音を整え、聴いて確かめてから、配信や通話へ送る」ための Windows アプリです。主な利用者は音響の専門家ではない配信者・通話利用者で、既定は「配信向け・かんたん」表示です。

評価の軸は次の3点です。

1. **迷わない**：次に何をすればよいかが、画面を見て1つに決まるか。
2. **間違えない**：押した結果が予想どおりか。危険な操作が安全な操作と区別されているか。
3. **本番中に頼れる**：緊張している状況でも、ミュートや比較を一目で見つけて一度で操作できるか。

## 総評

機能の正確さと誇張しない姿勢は、文言の随所に表れています。ノイズ低減の「効きやすい／効きにくい」の明示や、出力先で「受け側では CABLE Output を選びます」と対象を補う書き方は、そのまま規範にできる水準です。

一方で、正確さを求めるあまり、内部の計測条件や免責が利用者向けの画面に積み重なっています。その結果、次の3つが同時に起きています。

- 本番中に使う操作が、既定のウィンドウ幅ではアイコンだけになり、意味を読み取れない。
- 同じ機能の入口が複数あり、名前も揃っていないため、どれを押せばよいか迷う。
- 設定画面の各タブが表示領域の3〜7倍の長さになり、よく使う操作が下に埋もれている。

## 指摘一覧

重要度は、**高**＝誤操作・迷いに直結する、**中**＝理解に時間がかかる・不統一、**低**＝品質・一貫性の問題、です。

### 高

#### H1. 本番中の操作が、既定の幅ではアイコンだけになる

- **根拠**：ヘッダーの文字ラベルは `xl`（1280px）以上でだけ表示されます（`Header.tsx` の `hidden xl:inline-block`）。既定の 1024px では、緊急ミュート・原音比較・セットアップ・設定・ヘルプがすべてアイコンだけでした。
- **問題**：緊急ミュートのアイコン（`MdEmergency`）は医療記号に見え、「音を止める」とは読み取れません。ツールチップはマウスを乗せないと出ないため、本番中の判断には使えません。
- **改善案**：緊急ミュートと原音比較は常に文字ラベルを出す。入りきらない場合は、状態表示（M1）を短くして幅を空ける。

#### H2. 「声を整える」から開く場所が、説明と違う

- **根拠**：かんたん表示のカード「1. 声を整える ノイズ低減・内蔵ボイスチェーン」は、設定の音づくりタブを先頭から開きます（`useUIState.ts` の `openSoundSettings`）。タブの先頭は歌向けの下書き（`SingingControls`）で、ノイズ低減は約 1,400px 下にあります（タブ全体 1,795px、表示領域 443px）。
- **問題**：最初に音を整えたい人が、約束された「ノイズ低減」に辿り着けません。
- **改善案**：音づくりタブを「ノイズ低減 → 内蔵ボイスチェーン → 本番の歌・雑談モード → 歌向けに整える」の順にする。入口から開いたときは該当欄へスクロールする。

#### H3. セットアップを再開する場所の案内が違う

- **根拠**：トースト `guide.copy.244` と中断確認 `wizard.interruptHint` は「『オーディオ設定』からいつでも再開できます」と案内します。実際の入口は、ヘッダーの「かんたん設定」（かんたん表示のみ、1280px 未満ではアイコンだけ）、VST 欄の「かんたん設定」と空状態の「セットアップを開く」、設定画面下部の「セットアップウィザードを再実行」です。画面に「オーディオ設定」という名前のボタンはありません（設定画面の題名は「設定」）。
- **改善案**：入口と案内の名前を「セットアップ」に揃える（[DESIGN.md](./DESIGN.md) 第4章）。案内文は「ヘッダーの『セットアップ』からいつでも再開できます」とする。

#### H4. 安全な操作と音を止める操作が、区切りなしで並んでいる

- **根拠**：オーディオタブの「自分用と配信用の二系統出力」で、「現在の構成・稼働状態を取得」と「両経路の音声を停止」が、同じ下線リンクの見た目で区切りなく続き、「…取得両経路の音声を停止」と1行に読めます（`LiveOutputPanel.tsx` 67行目付近）。
- **改善案**：停止は危険の見た目のボタンにし、取得とは余白で分ける。停止の前に「配信中の音も止まります」を示す。

#### H5. 状態表示と切断操作を1つのボタンが兼ねている

- **根拠**：OBS 連携タブの「接続済み (クリックで切断)」（`settings.ObsConnectionSettings.291`）。大きな緑のボタンで、押すと切断します。
- **問題**：緑は「正常」の印であり、確認のつもりで押すと接続が切れます。
- **改善案**：状態表示「接続済み」と、副ボタン「切断」に分ける。

#### H6. 「原音比較」「原音」は、実際の効果より広い

- **根拠**：比較中のエンジンは、VST の処理ループだけを飛ばします（`core.rs` 3211〜3213行、`rt_global_bypass`）。ノイズ低減・内蔵ボイスチェーン・残響は動き続けます。それでも文言は「原音比較を開始する（エフェクトOFF）」（`header.compareStart`）、状態は「原音比較中（エフェクトOFF）」です。フッターの「原音」（`master.raw`）も、VST とノイズ低減が無効なだけで表示され、内蔵処理を見ていません。
- **問題**：かんたん表示の利用者は VST を使わないことが多く、押しても音が変わらないか、加工が残ったまま「原音」と思い込みます。[COPY_GUIDELINES.md](./COPY_GUIDELINES.md) の「効果を誇張しない」に反します。
- **改善案**：名前は「原音比較」のまま残す（「VST 比較」では VST 同士を比べる機能に読めるため）。範囲は説明側で示す。
  - 開始の説明 `header.compareStart`：「原音比較を開始する（VST をオフ。ノイズ低減・内蔵処理は継続）」
  - 状態 `shell.comparingEffectsOff`：「原音比較中（VST オフ）」
  - フッターの状態 `master.raw`：名前ではなく状態の主張なので、「VST・ノイズ低減なし」に変える
  - 加工前の声そのものと比べたい人は、ボイスチェックへ案内する
- **将来の選択肢**：比較中にノイズ低減と内蔵処理も外せば、名前と動作が一致する。音声処理の変更になるため、文言の修正とは別に検討する。

#### H7. 緊急ミュートの案内が、動作と違う

- **根拠**：トースト `header.muteOn` は「緊急ミュートを有効化しました (音声停止)」です。ミュートは出力を無音にするだけで、音声エンジンは止まりません。「音声停止中」は別の状態（エンジン停止）を指します。OBS ガイドは「**Alt + M** でいつでもマイクをミュートできます」と、キーをコードに直書きしています（`OBSGuideModal.tsx` 261行）。キーは利用者が変更できるうえ、ミュートされるのはマイクではなく Auralyn の出力です。
- **改善案**：トーストは「緊急ミュート中です。Auralyn の出力は無音です」。キーは実際の割り当てを差し込む。

#### H8. ボイスチェックで、歌向けの上級パネルが聞き比べより先に出る

- **根拠**：「録音から比較候補を提案」（`VoiceProposalPanel`）の表示条件は `singingModel &&` だけで、表示モードに関係なく、録音ボタンの直下・加工前／加工後ボタンの上に出ます（`VoiceCheckModal.tsx` 115行）。中の文言には「封印済みの原音」「clamp前ピーク」「同HPFのdynamics0対照」「通常送出」が含まれます。
- **矛盾**：`proposal.parameters` には「・残響OFF」が固定で入っており、残響が有効なときは次の行に「残響候補: ON」が並びます。
- **改善案**：かんたん表示では隠すか、聞き比べの下の閉じた折りたたみ「歌向け：内蔵処理の候補を試す」にする。「・残響OFF」は削る。計測の根拠は「根拠と限界」の折りたたみへ移す。
- **関連**：見出し「ボイスチェック」直下の一文が、目的ではなく範囲の注意（`voice.copy.003`）になっています。目的を書いた `voice.copy.002` は未使用です。

### 中

#### M1. ヘッダーの状態表示が溢れ、同じ状態を二重に表している

- **根拠**：`DeviceStatus.tsx` は高さ 64px のヘッダーに3行（「エンジン停止」「音声未設定」「通過時間は未測定・詳細は設定へ」）を並べ、上端と右端が切れていました。
- **問題**：「エンジン停止」と「音声未設定」は利用者にとって同じ意味です。「エンジン」は内部用語です。
- **改善案**：1行目に状態（「音声未設定」「音声処理中」など）、2行目は必要な場合だけにする。遅延の案内は「音声の詳細」に任せる。

#### M2. 同じ機能の入口が重複し、名前も揃っていない

| 機能 | 入口と名前 |
| :--- | :--- |
| セットアップ | ヘッダー「かんたん設定」、VST 欄「かんたん設定」、空状態「セットアップを開く」、画面題名「セットアップウィザード」、設定「セットアップウィザードを再実行」、案内文「オーディオ設定」 |
| 原音比較 | ヘッダーとフッターの2か所。ヘッダーは琥珀色、フッターは橙色 |
| 表示の切り替え | 本体上部の切り替えと、ヘルプメニューの項目。さらに設定のオーディオタブに、無関係な「かんたん／詳細設定」切り替えがある |
| 音量チェック | かんたん表示ではカードの下、詳細表示では右上 |
| 設定 | ボタン名「オーディオ設定を開く」、画面題名「設定」、空状態の文中「音声設定」 |

- **改善案**：原音比較はフッターに一本化するか、ヘッダーと同じ色・同じ名前にする。表示切り替えは本体上部に一本化する。名前は [DESIGN.md](./DESIGN.md) 第4章の正規名に揃える。

#### M3. 未設定のとき、主操作が競合する

- **根拠**：詳細表示に切り替えると、音声未設定でもチュートリアル「ステップ 1: エフェクトを追加」が出ます。同じ画面に白い塗りのボタンが「マイクと出力先を設定する」「VSTを追加」の2つあり、選択中の表示切り替えも同じ白です。
- **改善案**：音声未設定のあいだはチュートリアルを出さないか、最初の手順を「マイクと出力先を設定する」にする。選択中の表示は塗りの主ボタンと別の見た目にする。

#### M4. 設定画面の各タブが長く、よく使う操作が埋もれている

| タブ | 内容の高さ（表示領域 443px） | 先頭にあるもの |
| :--- | :--- | :--- |
| オーディオ | 1,327px | マイクの許可（折りたたみ）、ドライバ、入出力 |
| 音づくり | 1,795px | 歌向けの下書き |
| OBS 連携 | 1,149px | シーンの連動方式（接続欄より前） |
| システム | 3,087px | 設定移行 |

- **問題**：システムタブには、ホットキー10件、エンジン最適化、遅延の内部診断（callback、frame、cohort、FIR、resampler など）、初期化が1列に並びます。統計タイルは 1024px 幅でラベルが1〜2文字ずつ折り返していました。
- **改善案**：各タブの並びを利用頻度順にする（OBS 連携は「接続 → 確認 → 連動」）。内部診断は「診断情報」の折りたたみにまとめる。統計は表にする。

#### M5. かんたん表示でも内部用語が見える

表示モードに関係なく表示される箇所に、次の用語があります。

| 場所 | 例 |
| :--- | :--- |
| オーディオタブ | 「選択中のバッファ要求（1回分の換算・総遅延ではありません）」 |
| オーディオタブ「歌いながら聴く設定を試す」 | 「同じ機器・rate のまま、取得できた対応 buffer 範囲内で…Default・能力不明では強制しません。NR/VST は…」 |
| オーディオタブ「二系統出力」の詳細 | 「stereo F32」「有界 clock 補正」「配信状態 bundle」 |
| 音づくりタブ | 「現在：broadcast ／ ON」（内部 ID） |
| フッター「音声の詳細」 | 遅延の内訳（VST 申告、NR フレームなど） |

- **改善案**：かんたん表示では、二系統出力と歌いながら聴く設定を「歌・モニター」の詳細へまとめるか、詳細表示に限る。内部 ID は表示名（「配信」など）に置き換える。

#### M6. セットアップ最終画面の情報量が多い

- **根拠**：「設定と接続の確認」に、経路の説明、OBS の手順3つ、WebSocket の説明、接続欄、一時的な接続の注意（5文）、テスト音の注意、状態、保存の注意が1画面に並びます。マイクの許可の案内は入力の画面でも出ています。
- **改善案**：手順と接続欄を「OBS で確認する」の折りたたみにまとめ、既定は「サウンドテストを開始」と「設定を保存して開始」だけを見せる。

#### M7. 音づくりの操作部品が揃っていない

- 残響は数値の入力欄、ほかはスライダー。
- 「下書きを現在値へ戻す」だけ下線リンクで、ほかはボタン。
- ノイズ低減の「学習／会場／弱／強」は、方式と強さを同じ並びに混ぜている。
- 「未学習」は状態なのに、ボタンと同じ枠で表示される。

#### M9. 名前と状態を取り違えるボタン

- VST カード（シンプル表示）：ミュート中は表示が「ミュート解除」なのに、名前は「{名前}をミュート」で `aria-pressed=true` です（`PluginCard.tsx` 117〜121行）。表示を「ミュート」に固定し、状態は `aria-pressed` で伝えます。
- ボイスチェックの「停止」（一時停止アイコン）と「試聴を停止」が隣に並びます。前者は「一時停止」にします。
- 「選んだ試聴先で再生」は、試聴先の選択と安全確認のチェックがそろうまで押せませんが、理由が近くにありません。
- セットアップの「サウンドテスト (開始)」は、テスト音ではなくマイクの音を出力先へ流す操作です。「マイクの音を流して確認」にします。完了トースト「セットアップが完了しました！」は、同時に出る「音声設定を保存しました」や、接続確認は完了していないという案内（`guide.copy.235`）と食い違います。

#### M10. 数値の詳細が判定の横に常設されている

- 音量チェックの「短時間（3秒） {lufs} LUFS ／ true peak推定 {peak} dBTP」と、音量合わせの「測定 → 推定 LUFS ／ 調整後のtrue peak推定」は、かんたん表示でも判定ラベル（小さめ／ちょうどいい／大きすぎ）の隣に常に出ます。「測定値の詳細」の折りたたみへ移します。
- 遅延の選択肢の用途説明（楽器演奏向け・配信・会話向け・ノイズ対策、`settings.AudioSettingsModal.050`／`053`／`056`）は定義されていますが描画されず、代わりに言い換えの小ラベル（L4）が出ています。

#### M8. 設定画面の枠組み

- オーディオタブ内の「かんたん／詳細設定」は表示モードと無関係なローカル切り替えで、外観タブの「詳細設定を表示」はシステムタブを出すボタンです。同じ語が3つの状態を指しています。前者は「おまかせ／数値で指定」、後者は「システム設定タブを表示」にします。外観タブには、同じ目的のボタンが上下に2つあります（`027`＋`028` と `136`＋`137`）。
- 表示言語の選択がタブの外にあり、どのタブでも先頭に出ます。外観タブへ移すと、各タブの先頭が本題になります。
- 「エンジン再起動」が主ボタン「保存して開始」の隣に、ほぼ同じ大きさで並びます。トラブル時の操作なので、システムタブか診断情報へ移します。

### 低

#### L1. 色の使い方

- コンポーネント内に固定色の指定が 216 か所あります（トークン指定は 1,115 か所）。原音比較のヘッダーとフッターで色が違うのはこのためです。
- 既定のダークテーマでは主色がほぼ白で、[BRANDING.md](./BRANDING.md) の Aurora Cyan はゲーミングテーマでしか使われていません。

#### L2. 見える名前とアクセシブルな名前の不一致

- OBS・Discord ガイド：表示「設定を変更」、名前「オーディオ設定を開く」（`guide.copy.035`／`036`、`100`／`101`）。
- 音量チェック・音量合わせ：表示「声用の目標（仮の目安）」、名前「音量の目標」「自動調整の目標」。
- オーディオタブ：表示「マイク入力」、名前「マイク入力・ASIOデバイス」（WASAPI 選択時も同じ）。
- ロゴ見出し：「Aura」と「lyn」を別要素にしているため、「Aura lyn」と区切って読まれます。

#### L3. セットアップ最初の画面

- 「用途を選んで設定する」「OBS向けに設定する」「スキップ（手動設定）」の3つの入口があり、次の画面にも「OBSで配信」「手動で設定」があります。
- 表示モードを、まだ画面を見ていない段階で選ばせています。
- 「設定後の表示（あとから変更できます）」と「表示はあとから切り替えられます」で同じことを2回書いています。

#### L4. 選択肢の言い換えと断定

## 文言管理の課題

`meterBrowser.copy.000`〜`317` は、音量チェック・音量合わせ・メーター・遅延診断・プラグイン追加・VST ラックの6画面の文言を、連番でまとめたものです。キーから画面が分からず、同じ文字列（「閉じる」「不明」など）が重複し、VST カードのシンプル表示と詳細表示は文言が別キーです。画面単位の名前空間（`loudness.*`、`autoGain.*`、`rack.*` など）に分けると、片方だけ直す食い違いを防げます。表示されていない未使用キーもあります（例：`voice.copy.002`、`settings.AudioSettingsModal.131`）。

## 守るべき良い例

| 例 | 理由 |
| :--- | :--- |
| 出力先の下「Auralyn の出力先です。受け側では CABLE Output (VB-Audio Virtual Cable) を選びます。」 | 見出しから分からない **対象**（受け側で選ぶ名前）を足している |
| ノイズ低減の「効きやすい／効きにくい」 | 効果の **範囲** を示し、誇張を防いでいる |
| 「VSTで音を調整する」の右「折りたたんでもエフェクト処理は続きます」 | 折りたたむ前に知るべき **操作条件** |
| 「声を守る」の「声とノイズを完全に判別する機能ではありません」 | 効果の **範囲** の限定 |
| セットアップの入力画面で、マイクの許可を折りたたみにしている | 失敗時だけ必要な案内を、既定で隠している |
| 表示切り替えの `aria-pressed`、状態の `role="status"` | 状態をアクセシブルに伝えている |
| 「「設定を保存して開始」は音声設定の保存です。受け側への接続確認を完了したことにはなりません。」 | ボタンが何をして何をしないかの **範囲** |
| 「…削除後、5秒以内であれば「元に戻す」で復元できます。」 | 取り消せる期間という **条件**（実装の5秒と一致） |
| 「VST チェーンのみ置き換えます（デバイス・ノイズ設定は変更しません）。」 | 影響の **範囲** |
| 「Auralynの最終出力だけの目安です。ゲーム音を含む配信全体は判定しません。」 | 測る **対象** を一文で限定 |
| 「再起動すると一時的に音声が途切れます。読み込み済みのプラグインは自動的に復元されます。」 | 押した **結果** |
| OBS 接続失敗の4種類の案内（認証・時間切れ・拒否・その他） | 原因ごとに確認先が違う、具体的な次の行動 |

## 改善の進め方（提案）

小さく検証できる単位に分けます。音声処理の変更は含みません。

1. **事実と違う文言の修正**（H6、H7、M9、L6 の一部）：原音比較の範囲の明記、緊急ミュート・サウンドテストの名前と案内。文言とキー割り当ての差し込みだけで済む。
2. **用語と案内先の統一**（H3、M2 の名前、L2）：文言と `aria-label` の変更だけで済み、影響が小さい。
3. **本番中の操作の視認性**（H1、M1）：ヘッダーのラベル表示と状態表示の短縮。
4. **危険な操作の区別**（H4、H5）：ボタンの分離と見た目の変更。
5. **音づくりタブとボイスチェックの並び替え**（H2、H8、M7）：入口からのスクロールを含む。
6. **設定タブの再構成と診断情報の折りたたみ**（M4、M5、M8、M10）。
7. **セットアップの簡素化**（M6、L3）。
8. **色トークンの整理**（L1）：状態色トークンを追加し、固定色を置き換える。
9. **文言キーの再編**（文言管理の課題）：画面の変更が落ち着いてから行う。

各段階で、1024×768 と 900×600 の表示、キーボード操作、既存テスト（文言を検証しているテストを含む）を確認します。
