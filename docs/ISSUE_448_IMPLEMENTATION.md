# Issue #448: VSTごとの不正な音声出力の検知と停止

## 対応範囲

主経路の VST チェーン（`PluginControls::process`）で、各 slot の使用チャンネルに NaN または ±Inf があれば、そのブロックを無音にしてから後段へ渡す。ゲインを掛ける前に消す。片側チャンネルだけの異常も無効とする。連続して 100 ms 以上かつ 2 ブロック以上、または 1 秒の窓に入った無効時間の合計が 250 ms 以上になると、その slot だけを停止する。停止中は VST を呼ばず、ミュートと同じく無音を後段へ渡す。未加工の音へは自動で切り替えない。壊れた数値の代わりに元の音を出すと、どの処理が止まったのか利用者から見えなくなるためである。

バイパス中とミュート中の slot は VST を呼ばないので判定しない。追加と削除、サンプルレート変更に伴う再起動では、その slot の判定を初期状態に戻す。再起動では token も振り直す。

共有処理（処理分離がオフ）では、出力デバイスの callback が `process_output` を直接呼ぶ。検査するのは、その中のラック VST 各 slot の使用チャンネルである。止めた slot は、後段のラック VST と、その先の配信シンク・デバイス出力へ無音を渡す。本人が聞く音と配信は同じ処理結果なので、停止は両方に効く。

処理分離がオンのとき、本人用の出力 callback は `Monitor::render_gated`（`split_monitor.rs`）で、ラックの VST は通らない。内蔵の声・残響と本人用の返しだけを出し、非有限のサンプルは 0 に置き換える。これは今回の slot 停止ではない。VST チェーンは配信 worker（`broadcast-dsp` が `process_output` を回す側）にある。検査対象はその worker のラック VST 各 slot で、停止は配信側の後段と配信出力に効く。本人用 callback の音は止まらない。

ミックス後 VST は別エンジンのスレッド `auralyn-post-vst` で、`Rack::process` が同じ slot 判定を使う。検査するのはミックス後チェーン各 slot のステレオ出力である。停止はその slot から後段のミックス後 VST と、worker が返す packet に効く。主経路のラックや、分離時の本人用 callback は止めない。この処理を呼ぶのは `process_output` の `post_renderer` なので、共有処理では共有出力の後段、処理分離では配信 worker の後段になる。1 つの VST の NaN で worker 全体を止めていた経路は、slot 単位の無音化と停止になる。worker へ渡す前のサンプルと、処理後の packet 全体に対する非有限チェックは、取りこぼしを止める安全網として残している。

これは DLL クラッシュ防御とは別である。クラッシュ防御は別 sidecar と Job でプロセスごと切り離す。今回はプロセスを落とさず、非有限の数値だけを slot 単位で止める。

有限の大振幅は対象にしない。最終段のピーク保護が担当する。ここで大振幅を止めると、正常な音まで止まる。

再開は利用者がボタンを押したときだけ行う。VST の内部状態はリセットしない。音声コールバックから `setProcessing` を呼ばない。同じ異常が再発すれば、再び停止する。

## しきい値

ブロック数を固定せず、サンプルレートとブロック長から時間で決める。

- 連続: 無効な音声が 100 ms 以上続き、かつ連続 2 ブロック以上。1 ブロックだけでは停止しない。48 kHz / 256 サンプルなら 100 ms は 4800 フレームで、19 ブロック目に届く。44.1 kHz / 4096 サンプルでも 1 ブロックは 100 ms 未満なので、2 ブロック下限が先に効き、2 ブロック目で停止する。
- 散発: 1 秒の固定窓の中の無効時間合計が 250 ms 以上、かつその窓の無効ブロックが 2 つ以上。48 kHz / 256 サンプルなら 250 ms は 12000 フレームで、約 47 ブロック分。窓をまたぐと無効時間と窓内の件数は 0 に戻る。表示用の累計件数は戻さない。連続カウンタは有効なブロックでのみ戻す。
- 1 ブロックが 1 秒分でも、ブロック数が 1 のままなので停止しない。

## 画面

実行中の統計に、停止中のプラグインだけを載せる。プラグインカードには理由の文章と警告アイコン、再開ボタンを出す。新しく停止したときだけ、一度 toast を出す。通知は統計を購読している常駐側で行い、ラックを閉じている間も出す。統計が一時的に欠けても、同じ停止は知らせ直さない。再開、削除、または token が変わって統計からその停止が消えたときだけ、次の停止を新しいものとして知らせる。バイパスと削除はそのまま使える。

ミックス後 VST は slot 単位で無音化・停止するが、カードごとの表示は付けていない。配信ラックのカードは主経路の統計を見るため、ここに出すと別エンジンの停止と取り違える。ミックス後の状態経路にはプラグイン一覧がない。再開コマンド自体はミックス後エンジンでも受け付ける。

## 検証

合成 VST で確認した。後段の入力に非有限値が届かないこと、停止した slot の出力が無音で後段は処理を続けること、削除して追加し直すと旧状態が戻らないこと、token が一致しない古い停止を採用しないこと、再開で処理が戻ること、これらの音声処理中の割当と解放が 0 であることを確認した。44.1 kHz / 48 kHz / 96 kHz と 64 / 256 / 4096 サンプルのしきい値、ミックス後 VST の slot 単位、カードの表示・再開・toast も確認した。

- `cargo test --locked --lib plugin_health`: 10 件成功。窓をまたいだ散発は、生涯累計が 2 でも新しい窓の 1 件では止めない。
- `cargo test --locked --lib`: 728 件成功、5 件 ignored。主経路とミックス後の slot 試験を含む。
- `cargo clippy --locked --all-targets`: 成功。
- `npm test -- --run --maxWorkers=4`: 166 ファイル、1896 件成功。ラック非表示中の通知、再マウント、欠測、再開後の再停止を含む。
- `npx tsc --noEmit`: 成功。
- `git diff --check`: 成功。

## 未確認

実在の VST プラグインでは未確認。実機の音声デバイスと、耳で聴いた無音の確認はしていない。ミックス後 VST のカードごとの表示は未対応。
