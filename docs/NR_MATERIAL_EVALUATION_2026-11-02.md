# ゲーセン配信の同一音声で現行NRを聞き比べる

利用者が使用可能と確認した[過去のゲーセン配信](https://www.youtube.com/watch?v=UYXGTRB-Dw4)から、約05:00・25:00・50:00の各10秒を採取した。
元配信でのNR設定は不明。今回作るのは現行NRの比較材料であり、NR方式の採用判断や段階1の受入完了は行わない。

## 先に未処理を聞き、同じ位置で候補を切り替える

起動入口はignoredの`test-results/nr-evaluation-20261102/Start-NR-Comparison.cmd`。
専用のChromeで比較画面が開く。再生ボタンを押すまで音は出ない。

1. 返し先のVoicemeeter Inputと、普段のヘッドホンへの経路を確認する。
2. 区間を選んで「再生」を押す。音量は25%から始め、必要に応じて上げる。
3. 「未処理」「現行設定」「抑制を弱めた候補」「抑制を強めた候補」を切り替える。再生位置は維持し、10秒ごとに繰り返す。
4. 声の聞き取りやすさ、小声・語尾の欠け、ゲーム音や周囲の声の変化、金属的な響きを比べる。
5. 停止後、専用Chromeを閉じる。通常のChromeの設定やプロファイルは使わない。

よい／悪いと感じた区間と候補を記録する。3区間とも比較に適した発話とは限らないため、発話が少ない区間は別の時刻へ差し替える。
試聴結果が出るまでは、設定の既定値やモデルを変更しない。

## 現行の処理だけを同じPCMへ適用する

採取には[短区間PCM採取スクリプト](../scripts/collect-youtube-nr-material.mjs)を使った。
専用Chromeで本編を再生し、復号後の音声を48 kHz・ステレオ・float32 WAVで各480,000フレーム保存した。
Chromeの物理再生はミュートし、マイクは開いていない。
これはブラウザから採取したPCMであり、製品のプロセス入力・声の用途による録音試験とは分ける。
実際の開始位置、ピーク、動画IDとSHA-256は`browser-pcm/source.json`に残す。

[明示評価用Rustテスト](../src-tauri/src/audio_engine/core/noise_evaluation.rs)は、そのPCMに既存の`render_candidate`を適用する。
通常のテストではignoredとし、指定した素材と新規保存先がある場合だけ実行する。
製品のNR処理や設定、通常アプリの学習結果は変更しない。

| 候補 | 条件 |
| --- | --- |
| 未処理 | 採取PCMとサンプル単位で一致 |
| 現行設定 | 弱モード、強度0.8、声の保護あり |
| 抑制を弱めた候補 | 同じ方式で強度0.6 |
| 抑制を強めた候補 | 同じ方式で強度1.0 |

学習済みノイズの混合は使わない。backendは`nnnoiseless-0.5.2`、モデルは`bundled-e6de5fbfadf7ec91`。
既存の候補生成と同じ1秒の事前処理と対応位置の補正を使い、各候補の条件・補正量・ピークを`clip-*/variants.json`へ保存する。
再生時は全候補に共通の減衰をかける。候補ごとの音量合わせは行わないため、NRによる音量差も比較に含まれる。

## 聴感とプロセス入力の受入を分ける

素材は声・ゲーム音・周囲の声が混ざった配信音声で、声だけの正解音声がない。
声の保持を保証する数値評価や、新方式との優劣判定は行わない。
今回の比較でマイクの学習状態の実機保護、プロセス入力でのNR切替、歌素材の回帰確認を代用しない。

音声、起動cmd、比較画面の検証記録はすべてignoredの`test-results/nr-evaluation-20261102/`に置く。
Gitには素材を含めず、採取・処理・比較の手順だけを残す。

今回の実行では3区間×4候補の生成が成功し、48 kHz・ステレオ・10秒・有限値と未処理版の一致を確認した。
専用Chromeで全3区間の読込、再生位置を維持した切替、停止、操作前に再生しないことも確認した。
Rustライブラリは608件成功・5件ignored、Clippy全target＋probe feature（`-D warnings`）、Rustfmtとスクリプト構文確認も成功した。

## 今回の素材ではNRありの方が好ましいという聴感結果を得た

2026-11-02、利用者から「現時点のものとしては確実にNRありの方が、周りの環境音も減っていますし、いいと思います」と回答を得た。
今回の素材・試聴条件では、環境音の低減とNRありへの好評価を確認した。
候補の強度ごとの優劣、区間ごとの評価、小声・語尾の保持については個別の回答を得ていない。
現行NRを継続して評価する根拠として扱い、既定の強度・モデルは変更しない。

2026-11-03の[後続検証と修正](PROCESS_INPUT_LEARNING_RETENTION_2026-11-03.md)では、実素材をプロセス入力の声用途で取得し、NRのOFF→ON→OFFを実Engineの録音でも確認した。
機器入力との学習値の分離・保持は制御音で確認した。これは物理マイクでの測定や声の保持の聴感評価とは区別する。
