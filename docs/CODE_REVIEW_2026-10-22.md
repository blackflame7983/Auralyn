10月23日の第4段階では、共有録音バッファの同期とVSTロード失敗時の解放を優先し、所有権と終了手順を修正した。
同日の第5段階では、ノイズ低減の設定反映、定常ノイズ学習、不正入力と停止時の処理を確認・修正した。

## 実行境界と状態の寿命を整理した

起動・トレイ処理と同居していたTauriコマンドを、`src-tauri/src/commands/` の音声・プロファイル・ボイスチェックへ分離した。
既存のinvoke名・引数・返却型を保ち、同期I/OとIPC応答待機を `run_blocking` へ移した。
デバイス一覧取得では、専用スレッドを起動してからUIスレッドで `recv` する処理も解消した。

エンジンのDSP状態は `audio_engine/core/dsp.rs` へ分離した。
プロセスの起動・キュー・コールバック接続を担当する `core.rs` から、ノイズ低減、学習、内蔵FX、ゲイン平滑化の実装を切り離している。
Windows Job Objectの重複実装は `process_job.rs` に集約し、設定途中で失敗しても生成済みHANDLEを解放するようにした。

フロントではセッション保存を `usePluginSessionPersistence`、デバイス復旧を `useAudioRecovery` へ分離した。
設定画面のOBS接続・診断・表示は `ObsConnectionSettings.tsx` に分離し、タブの表示と接続寿命を対応させた。
保存済み音声設定の型と検証は `lib/audioPreferences.ts` に集約した。
実際のAppから使われていなかった旧AudioConfigContext、旧UIContext、イベント処理のデバッグ用複製を削除した。
旧UIContextのテストは実際に使用する `useUIState` のテストへ移し、設定タブの入口も検証する。

## 確認した問題と修正

| 問題が起きる条件 | 影響 | 修正・検証箇所 |
| --- | --- | --- |
| IPC要求がタイムアウトし、その応答が次の要求後に届く | 古い応答を別操作の成功と取り違える | `audio/replies.rs`。古い応答を消費するまで次の送信を拒否するテストを追加 |
| 音声コマンドやファイル処理が応答待ちになる | UIまたはasync executorをブロックする | `commands/` のバックグラウンド実行へ統一 |
| 保存名に `../`、絶対パス、Windows特殊名などを渡す | プリセット領域外のファイル操作、特殊名へのアクセス | `vst_host/presets.rs`。保存・読込・削除で同じ検証を使う |
| ラック変更前の状態取得が遅れて完了する | 削除済みVSTを含む古いセッションを保存する | 保存effectの寿命確認。遅い応答の回帰テストを追加 |
| VST状態の取得に失敗する、前の保存が未完了である | 保存済みパラメーターを欠落させる、取得要求が重複する | 不完全な保存を拒否し、保存中の定期取得を抑制 |
| デバイス復旧要求が失敗し、新しいエラーイベントが来ない | 最大3回のはずが1回で止まる | 失敗処理から次の試行を予約。上限・キャンセル・遅い応答をテスト |
| デバイス復旧でプロセスを再起動する | VSTインスタンスと状態が消える | 既存エンジン内でストリームを再開し、入力ペアを再適用 |
| デバイスキャッシュが壊れている | 設定画面の描画時に例外となる | JSONと要素の型を検証し、再取得可能な空キャッシュへ戻す |
| ボイスチェックの2本目の書き出しや解析が失敗する | 一時音声が残る | 専用ディレクトリの所有者を設け、途中の失敗でもDropで削除 |
| 停止・ミュートのIPCが失敗する | 停止の成功を返す、実際と異なるミュート状態を保持する | 停止のエラーを返し、ミュート状態は成功後に更新 |
| 並べ替えに重複・欠落・不明なIDが含まれる | チェーンからVSTが抜ける、同じVSTを複数回処理する | 全件を一度ずつ含む要求だけを採用するテストを追加 |
| 不明なIDへゲイン・バイパス・ミュートを送る | 無効な操作を成功扱いし、不要な状態を保持する | インデックス確認後に状態を更新 |
| ファイル名のないパスでVSTをロードする | `file_stem().unwrap()` がpanicする | DLLロード前にエラーとして返すテストを追加 |

音声IPCの要求IDは今回追加していない。
応答が永久に戻らない場合は後続操作を拒否し続けるため、エンジン再起動による復旧が必要になる。
通信への書き込み自体が失敗した場合は接続を破棄し、音声エラーを通知する。

## DSPは出力を変えずに固定係数の計算を移した

内蔵ボイスチェーンのハイパス係数はサンプルレートとプリセットで決まるため、毎サンプルの計算から構築時の計算へ移した。
8 / 44.1 / 48 / 96 / 192 kHzの各条件で、4,096フレーム中にプリセットと強度を変更し、変更前の処理との左右出力ビット一致を確認するテストを追加した。
同じ区間でヒープの確保・解放が0回であることも検査する。

これは数値結果と割当の検証であり、実機のCPU使用率や音切れが改善したという測定結果ではない。
速度の改善率は計測していない。

## 第4段階（10月23日）: 共有録音バッファとVSTロードの解放

### 録音の公開を、表示状態から独立した所有権で管理する

従来の `VoiceCheckBuffers` は `UnsafeCell<Box<[f32]>>` から無条件に共有スライスを返していた。
録音完了を示す共有値もRelaxedで更新しており、サンプルの書き込みと読取側の間に同期がなかった。
加えて、音声コールバックが加工後の音声を保存する前に `advance_recording` を呼んでいたため、上限に達したブロックの加工後音声が欠落し、未完成のデータを公開し得た。

バッファの所有と公開は `audio_engine/voice_check/buffers.rs` に分離した。
1回だけ取得できる `RecordingWriter` が書き込みを担当し、完成後は再利用できない構成とした。
`recording()` は完成状態をAcquireで確認した場合だけスライスを返す。
対応するReleaseは、加工前後の全書き込みと完成フレーム数の保存が終わってから行う。
`unsafe impl Sync` はこの所有・公開規則を守る内部実装に限定し、画面用の `state` や `duration_frames` を読取許可として扱わない。

| 修正対象 | 現在の動作 |
| --- | --- |
| 完了通知の順序 | 加工前後を書き込んだ後にフレーム数を進め、上限到達時に公開する |
| 録音中の書出し・波形取得 | 完成したバッファ以外は読まない。書出しはファイル作成前にエラーを返す |
| 次の録音用の共有値が先に変わる場合 | 書き手自身が保持する上限を使い、別録音の上限や長さで処理しない |
| 書出しのレート・長さ | 完成したバッファ自身の不変メタデータを使う |
| コールバック破棄 | 加工前後が揃った最後のブロックまで公開し、途中ブロックは含めない |
| 録音バッファの入れ替え | 制御側の `VoiceCheckBufferStore` が旧バッファを保持し、RT側の参照がなくなってから制御スレッドで回収する |

この変更は録音データの所有と同期を対象とし、音声処理の方式を置き換えるものではない。
録音・再生開始、サンプル保存、録音切替・停止を割当検査に通し、音声コールバック区間の確保・解放が0回であることを確認した。

### ロード途中と通常終了で同じ解放規則を使う

VSTのロード中に取得した参照は、`instance/load_resources.rs` の `InstanceResources` へ直ちに引き渡す。
コンポーネントとコントローラーは初期化成功を記録し、成功した対象だけ `terminate` を呼ぶ。
同じCOMオブジェクトを共有するコンポーネントとコントローラーには、重複した終了処理を行わない。
処理開始・有効化を試みた後に失敗した場合も、停止・無効化してから参照を解放する。

従来はOTT以外のfactory参照や、互換性のため保持していたFUnknown参照に解放先がなかった。
factoryは生成処理の終了時に解放し、FUnknownとOTTで置き換えた元のコントローラー参照はインスタンスの寿命まで保持してから解放する。
ホストコンテキストとDLLは、プラグインの終了・参照解放が完了するまで生存させる。

`setup_processing` や `set_processing` の失敗もエラーとして扱い、準備が完了していないProcessorを音声スレッドへ渡さない。
通常ロードで準備に失敗した場合は、PluginManagerの登録前にインスタンスを破棄し、確保したRT管理番号も返却する。
バス構成の設定失敗は従来どおり警告扱いを維持しており、任意のチャンネル構成への適合まで保証する変更ではない。

## 第5段階（10月23日）: ノイズフィルター
