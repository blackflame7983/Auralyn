# 歌唱・雑談モードとVST構成の一体切替（Issue #151）

2026-10-31、`codex/live-mode-vst-transaction` で[設計案](plans/LIVE_MODE_VST_TRANSACTION.md)をローカル実装した。実機受入・配布完了の記録ではない。

## 利用時の動作

- 歌唱・雑談それぞれに、保存済みプロファイルのVST構成を任意で関連付けられる。関連付けなしは従来の内蔵処理だけの切替になる。機器、NR、入出力ゲイン、プロファイル内の内蔵設定は適用しない。
- 関連付け時にVST内容のSHA-256を保存する。切替前に存在と内容を再確認し、削除・変更されたプロファイルは再登録が必要になる。確認後の内容を切替中に固定する。
- VSTカテゴリーを明示して保存した空ラックは「全VSTを外す」。旧形式の空配列は従来どおり「VSTカテゴリーなし」で、関連付け対象にはしない。旧データの未指定フィールドは互換維持する。
- 切替中は無音とロード待ちが発生する。通常の競合操作は拒否し、停止・緊急ミュートを優先する。ホットキー、OBS連動、画面操作は共通のHost処理へ入る。

## 処理と復旧

Hostの状態機械（`src-tauri/src/audio/mode_vst.rs`）はバックグラウンドで進行し、UIの表示やポーリングを実行条件にしない。既存の稼働中Engineを使い、元ラックの順序・各VSTの内部state・有効/ミュート/ゲイン・内蔵処理を取得して世代とrevisionを照合する。変更前に復旧原本を `live-mode-vst-journal.json` へ永続化する。

Engineの専用無音ゲートは、実際の出力callback末尾のACKを待ってからラック変更を許可する。全VSTの復元と内蔵処理の反映を照合した後も、入力の履歴破棄と停止ACK、monitor/workerの古いキュー排出、物理出力側の排出を順に確認してから解除する。途中に到着した入力callbackは次の履歴破棄済みcallbackのACKを待つ。通常のミュート意図と切替用ゲートは別に保持する。

既知の失敗は無音中に元ラック・元設定へ全件ロールバックする。その場合のモード表示は元の値を持つカスタム状態になる。応答不明・期限超過・Engine交代・復元失敗ではEngineを停止して原本を保持し、明示的な復旧を要求する。復旧は停止・ミュート状態で行い、勝手に音声を再開しない。破損した原本も自動起動を許可しない。

原本の耐久書込みと大きなIPCのシリアライズ・パイプ送信はHostのmutex外で実行する。遅い書込み・詰まったパイプ・古い応答は、中断済み処理を再開できない。プロファイル読込みと内容計算、登録保存、起動時の原本読込み、完了時の原本ファイル削除は同期処理である。

React側は切替開始時に既存のセッション保存原本を保護し、完了後に世代・revisionを再確認して新しいラックIDへ同期する。中断後も古いIDや空ラックで自動保存を上書きしない。復元原本取得前の停止・緊急ミュートでは、保存前のVST内部stateを回収できる保証はない。通常の保存原本を保持して既存の明示復元へ戻れるようにする。

## 実機で残る受入

複数の実VSTでのstate復元、WASAPI/ASIO、実出力録音による旧音の混入と無音区間、実OBS連動、実Tauriの再起動・中断復旧、DPI・キーボード・読み上げの受入は未実施である。使用するVST/ドライバー/サンプルレート/buffer/出力経路を記録して実施する。

VST自身のロード待ち・内部stateの正確さ・音質・クラッシュ耐性は、このローカル自動検証のみで保証しない。復旧原本はVST最大32件、state合計64MiB、JSON最大96MiBに制限し、上限超過は切替前に拒否する。
