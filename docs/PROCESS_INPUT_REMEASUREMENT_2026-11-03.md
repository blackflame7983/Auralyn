# プロセス入力の65分計測を取り直した

2026-11-03、利用者の指示に従い、段階2〜3の前に段階1の自動計測を取り直した。
ChromeとVLCを各3,900秒運転し、取得失敗・不連続・時刻エラー・非有限値は発生しなかった。
これは過去に消失した原データの復元ではなく、今回の新しい計測である。
聴感、機器の物理切断、通常のChromeプロファイル、物理マイク・ASIO・OBSの受入は別に残す。

## 固定したEngineで、原音を抑止して取得した

対象ソースは`fa443eb`時点、固定して複写したEngineのSHA-256は`6c74a7640f0572233918e0d81844f49ac9e67a80a41643e326f55afcbe18252e`。
44.1 kHzの同一の小音量ステレオ素材を、専用Chromeのaudio要素とVLCのリピートで再生した。
ChromeはFS2333、VLCはRealtek Digital Outputを原音用に使い、各出力デバイス側をミュートした。
取得後は製品SRCとTDR Novaを通し、Voicemeeter Inputへ返す経路を全体ミュートして運転した。
通常のChromeプロファイルや通常のアプリ設定は使っていない。

2アプリを同時に動かし、途中でRustビルドと所有する別Chromeの異常系試験も行った。
無負荷時の性能基準や、過去の測定との優劣を示す結果にはしない。

| 観測 | Chrome（出力48 kHz） | VLC（出力44.1 kHz） |
| --- | --- | --- |
| 定常運転 | 3,900秒 | 3,900秒 |
| 不連続／時刻エラー／非有限値の増加 | すべて0 | すべて0 |
| callback遅延の検出数の増加 | 2,971 | 2,962 |
| 最大callback遅延 | 11,536 µs | 11,535 µs |
| 音声待機に伴うresetの増加 | 0 | 242 |
| 待機時に破棄した取得フレームの増加 | 0 | 30,046 |
| キューの観測範囲 | 1,156〜2,204フレーム | 0〜2,256フレーム |
| 速度差補正の観測範囲 | −805〜1,242 ppm | −951〜2,000 ppm |

遅延検出数は呼出し間隔の観測であり、耳に聞こえた音切れの件数ではない。
VLCには素材リピート時の待機と、補正上限への到達が残る。これを「音切れなし」へ読み替えない。
開始前の一時停止・再開、VST経路と原音比較の切替、64回の切替後に最後の要求へ戻ることも確認した。
65分間ずっと比較を連打した試験ではない。
各試験の原音用出力と返し用出力は復元・保持され、全体の試験前後でもミュート・音量・既定ロールが一致した。

## 独立した出力で、終了・再選択・経路変更を確認した

`verify_process_input_faults.py --audio-service-restart`で、所有するChromeの音声サービス終了後の読み直し、
ルート終了、古い対象の拒否、新しい対象の明示選択、別出力への移動、原音用出力のミュート解除を確認した。
マイクや既定出力への自動接続は行っていない。

最初の2試験では、ミュート解除後の停止通知を確認できなかった。
CABLE InputとCABLE In 16chがミュート状態を共有し、別の試験用ガードが元のミュート状態へ戻していたためである。
その組合せを起動準備中に拒否する検証を追加し、Engineを開始する前に止まることと、出力設定の保持を確認した。
CABLE Inputと独立したVoicemeeter In 1へ変更すると、ミュート解除を含む異常系試験が成功した。
失敗時にも取得状態と出力状態を保存し、失敗した記録を残している。

## 自動計測の結果を残し、実音声の受入と分けて後続へ進む

今回の結果から、自動試験で扱ったプロセス取得・停止・再選択と、65分の取得継続を確認した。
利用者が指示した段階2〜3の実装へ進み、上記の未確認条件は継続して追跡する。
マイク＋オケの実機運転、配信側の録音、本人への返しの評価は、この単独入力の成功で代替しない。

原データは`test-results/mixing-stages-2-3-20261103/`に保存する。
`chrome-65m`と`vlc-65m`の`summary.json`・`samples.jsonl`・元のWAVとログ、
`faults-independent/summary.json`、`faults-linked-guard/summary.json`、`stage1-result-summary.json`を参照する。
最初の失敗は`faults`と`faults-unmute-repro`、試験前後の出力設定は`endpoints-before.json`と`endpoints-after-stage1.json`に残す。
