# 配信用 true-peak 制限は、既定 OFF で配信用の最終段に入れる

48 kHz、天井 -1 dBFS で比べると、サンプル間の山が出る信号では既存の sample-peak 保護が天井を 0.6〜3.0 dB 超え、候補は天井の下に収まった。最悪の候補超過は -0.11 dB である。CPU は同じ 1 秒の処理で sample-peak の 3.98 倍（debug の試験バイナリ）だった。この差は採用の目安に収まる。分離した配信用 sink の最終段へ、既定 OFF の独立した設定として組み込んだ。自分用と単一出力には入れていない。

## 主要数値

超過は、リミッターとは別の測定器で見た true-peak が天井 -1 dBFS から何 dB 上か。負の値は天井未満。

| 信号 | 保護なし | sample-peak | 候補 | 候補の超過率 | 候補の平均減衰 | 候補の THD 相当 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 12 kHz（fs/4）/ 45° | +6.11 dB | +3.01 dB | -0.41 dB | 0% | -6.51 dB | 0.000 |
| 11 kHz / 0°・45° | +6.11 dB | +0.03 dB | -0.39 dB | 0% | -6.50 dB | 0.001 |
| 15 kHz / 20°・75° | +6.11 / +6.10 dB | +0.01 / +0.08 dB | -0.38 / -0.37 dB | 0% | -6.49 / -6.48 dB | 0.001 / 0.000 |
| 19 kHz / 10°・45°・90° | +6.11 dB | +0.03 dB | -0.37 dB | 0% | -6.48〜-6.49 dB | 0.001 |
| 帯域制限インパルス | +5.61 dB | +0.64 dB | -0.20 dB | 0% | -5.79 dB | 0.000 |
| 帯域制限雑音 | +5.49 dB | +0.78 dB | -0.31 dB | 0% | -4.88 dB | 0.000 |
| 急な立上り（15 kHz、位相 90°） | +6.39 dB | +0.28 dB | -0.11 dB | 0% | -6.50 dB | 0.000 |
| 左だけの過大音（fs/4、位相 0.3 rad） | +6.98 dB | +0.36 dB | -0.40 dB | 0% | -7.39 dB | 0.000 |

11 / 15 / 19 kHz の長い正弦は、サンプル点が連続波形の山に近い。sample-peak でも超過は 0.1 dB 未満で、ここで候補との差はほぼ出ない。差が出るのは fs/4 の 45°（sample-peak が +3.01 dB 残す）、帯域制限したインパルス、帯域制限した雑音である。左だけの信号でも左右の比は保ったまま、大きい側に合わせて両方を下げる。

候補が定常正弦で天井より約 0.4 dB 深く減衰するのは、検出側だけ天井を 0.40 dB 低く見ているためである。出力の合否は設定した天井で測っている。定常部のゲインは一定なので、正弦に対する残余比は 0.001 以下だった。天井未満の 1 kHz（-20 dB）は、遅延を揃えると誤差 0.0001 未満である。

追加遅延は ON の定常状態で次のとおり。OFF では 0 sample である。すべてのレートで 0.5 ms という保証はしていない。

| レート | 先読み |
| --- | --- |
| 44.1 kHz | 44 sample / 0.998 ms |
| 48 kHz | 48 sample / 1.000 ms |
| 96 kHz | 96 sample / 1.000 ms |
| 192 kHz | 192 sample / 1.000 ms |

44.1 / 96 / 192 kHz の fs/4・45° でも、候補の超過は 0.1 dB 以下、sample-peak は 2 dB を超えることを試験が確認した。保持メモリは 48 kHz で 840 bytes。1 秒分（48 kHz、19 kHz の過大ステレオ）の処理時間は、debug の試験バイナリで候補 51.4 ms、sample-peak 12.9 ms、比 3.98 だった。release 最適化後の実時間は測っていない。

## 測定器

試験専用で、リミッターと係数を共有しない。測定器は 8 倍、64 tap の Blackman 窓 sinc、演算は f64。リミッターは 4 倍、16 tap の Hann 窓 sinc、演算は f32。窓も次数も配列も別である。係数はどちらもこのリポジトリで作った。Unleashing のコードと係数、ITU-R BS.1770-4 Annex 2 の係数表は参照していない。

検証信号は、サンプルレートの 1/4 の正弦を位相 45° で入れたもの。連続波形の山は振幅 1.0、サンプル値の山は √2/2 なので、サンプル間の山は約 +3.01 dB になる。窓を滑らせて測ると、測定器の誤差は 0.05 dB 未満だった。100 Hz の正弦も同じ範囲に入る。1 箇所の窓だけではゼロクロスに当たって 0.707 しか見えないことがある。試験は全サンプルを入れてから、履歴が温まった後の最大値だけを採る。

## 採否と置き場所

採用する。判断の目安は、候補の天井超過が 0.1 dB 以下であること、sample-peak が約 0.3 dB を超える信号でその差が 0.5 dB より大きいこと、CPU が sample-peak の数倍に収まること。上の表はこの範囲に入っている。

置く場所は、分離モードの配信用 sink だけである。`live_output` がドリフト追従の線形補間と配信用トリムと、既存の sample-peak（path 2）を済ませたあと、デバイスへ渡す直前に通す。自分用の経路には先読みを足さない。単一出力にも入れない。単一出力では本人が聞く音と配信用が同じ列なので、先読みが自分の返しに乗る。

天井と復帰時間は sample-peak と独立にした。範囲と既定値は同じで、天井は -12〜-0.1 dB、復帰は 20〜1000 ms、既定は OFF・-1 dB・100 ms である。sample-peak は自分用と主出力にも効く。天井を共有すると、配信用だけ下げたい操作が自分用の制限まで動かす。

設定はアプリの起動中だけ保持し、Engine を作り直したときに同じ値を渡す。アプリを再起動すると OFF に戻る。プロファイルと歌／雑談には保存しない。操作ロック中は変更できない。固定ゲイン提案の測定を止める条件には入れていない。測定タップは配信用 sink ではない。sample-peak が ON のときの既存の停止はそのままである。

ON と OFF の切替は、短いフェードアウト、遅延線の消去、先読み分の無音、フェードインの順で行う。フェードアウトは先読みの半分で終わり、新しく書いたサンプルが遅延の出口に届く前に音を消す。消す前の音は、新しい遅延の先からは出さない。レートの変更と停止からの再開は処理器を作り直すか、同じフェードで遅延を消す。無音に落ちた callback では、遅延に残った音をデバイスへ書かず、状態の反映だけ進める。天井の変更は 5 ms の線形ランプで、隣接サンプル差の試験は 0.05 未満だった。

遅延の内訳には、分離した配信用デバイスがあるときだけ先読みの sample 数と ms を出す。OFF、単一出力、配信デバイス未設定では 0 である。自分用の true-peak 段は 0 sample と表示する。この値は段の計算値であり、観測値と足した実測の総遅延ではない。

## 保証する範囲

保証するのは、配信用出力デバイスへ渡すサンプル列について、この 4 倍補間で見た true-peak が設定した天井を大きく超えないことである。今回の数値試験では、載せた信号の超過は -0.11 dB 以下だった。OBS の中の処理と、デバイス側のサンプルレート変換はこの範囲に入らない。Engine の中に、sink デバイスを経由しない別の OBS 経路はない。固定レートの変換は入力 callback 側で、DSP より前に終わる。peak の後にレートが動くのは、この sink の線形補間だけで、true-peak 制限はその後段にある。

外部の true-peak リミッター VST とは比べていない。プラグインの有無と設定が環境ごとに違うため、このリポジトリの試験では再現できない。

## RT の確認

先読みバッファは、レートが決まったときに確保する。音声 callback の `process`、`report`、`reset_audio` では `allocation_counts` が (0, 0) だった。出力は有限値に収め、過大な定数入力でも絶対値は 1 を超えない。バイパス中は入力をそのまま返し、遅延は 0 sample である。

## 聴感は未実施

許諾済みの声、歌、音楽を人の耳で聴く確認はしていない。上の数値は、決まった試験信号を測定器に通した結果である。音の印象が許容できるかは、この文書の範囲外で別に聴く必要がある。
