# 配信用 true-peak 制限は、既定 OFF で配信用の最終段に入れる

48 kHz、天井 -1 dBFS で比べると、サンプル間の山が出る信号では既存の sample-peak 保護が天井を 0.6〜3.0 dB 超え、候補の最悪超過は +0.08 dB（急な立上り）だった。許容は天井 + 0.1 dB である。単発インパルスは、天井 -12 / -6 / -1 / -0.1 dB、復帰 20 / 100 / 1000 ms、振幅 1〜10、44.1 / 48 / 96 / 192 kHz のすべてで超過 -0.20 dB 以下だった。分離した配信用 sink の最終段へ、既定 OFF の独立した設定として組み込んだ。自分用と単一出力には入れていない。分離を切った配信用 sink にも掛けない。

包絡は、4倍補間で見た左右の大きい方から必要 gain を作り、直近の先読み窓の最小を箱型平均したものである。山が遅延線から出る時点で、この attack は必要 gain 以下になる。下がるときはその包絡へすぐ従い、上がるときだけ指数の復帰を使う。追加のハードクリップは入れていない。

## 主要数値

超過は、リミッターとは別の測定器で見た true-peak が天井 -1 dBFS から何 dB 上か。負の値は天井未満。超過率は、その天井そのものを超えた測定点の割合である。0.1 dB の許容を超えた点はなかった。

THD 相当は正弦だけ測る。過渡は未測定であり、0 とは書かない。天井未満の相対誤差は、遅延を揃えたうえで |入力| が天井未満の区間の |出力 − 入力| を、その入力の RMS で割ったもの。折れ残差は、出力と「遅延入力 × そのサンプルの適用 gain」の差の RMS 比で、ゲイン以外の折れ（ハードクリップを含む）があるかを見る。

11 / 15 / 19 kHz の長い正弦は、サンプル点が連続波形の山に近い。sample-peak でも超過は 0.1 dB 未満で、ここで候補との差はほぼ出ない。差が出るのは fs/4 の 45°（sample-peak が +3.01 dB 残す）、帯域制限したインパルス、帯域制限した雑音である。左だけの信号でも左右の比は保ったまま、大きい側に合わせて両方を下げる。

候補が定常正弦で天井より約 0.2 dB 深く減衰するのは、検出側だけ天井を 0.20 dB 低く見ているためである。余裕なしでは、48 kHz の急な立上りが +0.28 dB 超過した。0.20 dB は、その見落としを許容 0.1 dB の内側へ入れるための値で、以前の 0.40 dB より小さい。出力の合否は設定した天井で測っている。定常部のゲインは一定なので、正弦に対する残余比は 0.000 だった。天井未満の 1 kHz（-20 dB）は、遅延を揃えると誤差 0.0001 未満である。

過渡の THD は未測定。代わりに折れ残差を見た。候補も sample-peak もサンプルへゲインを掛けるだけで、折れ残差は 0.00000 だった。天井未満の相対誤差は、過大な正弦のゼロ付近ではどちらも約 0.5 で、制限そのものが出ている。帯域制限インパルスでは候補 0.471、sample-peak 0.336 で、候補の方が大きい。先読みが山の前後も一緒に下げるためで、波形を折った結果ではない。

追加遅延は、分離が ON で配信用デバイスがあり、設定も ON の定常状態で次のとおり。設定が OFF、分離が OFF、単一出力、配信デバイス未設定では 0 sample である。包絡の長さは約 1 ms で、遅延線はそれに補間フィルタの群遅延 8 sample を足してある。すべてのレートで 0.5 ms という保証はしていない。

| レート | 先読み |
| --- | --- |
| 44.1 kHz | 52 sample / 1.179 ms |
| 48 kHz | 56 sample / 1.167 ms |
| 96 kHz | 104 sample / 1.083 ms |
| 192 kHz | 200 sample / 1.042 ms |

44.1 / 96 / 192 kHz の fs/4・45° でも、候補の超過は 0.1 dB 以下、sample-peak は 2 dB を超えることを試験が確認した。同じ許容は、上の評価信号を天井 -1 dB / 復帰 100 ms、-12 dB / 20 ms、-0.1 dB / 20 ms で 4 レートに通しても守った。保持メモリは 48 kHz で 1600 bytes。

1 秒分（48 kHz、19 kHz の過大ステレオ）を debug の試験バイナリで他の試験と分け、5 回の中央値は候補 95.7 ms、sample-peak 9.1 ms、比 11.82 だった。並列の `cargo test --lib` の中で同時に測ると比が 13 を超えることがあり、単発の 3.98 倍や 11.70 倍とは別の条件である。release ビルドでの実時間は測っていない。

## 測定器

試験専用で、リミッターと係数を共有しない。測定器は 8 倍、64 tap の Blackman 窓 sinc、演算は f64。リミッターは 4 倍、16 tap の Hann 窓 sinc、演算は f32。窓も次数も配列も別である。係数はどちらもこのリポジトリで作った。Unleashing のコードと係数、ITU-R BS.1770-4 Annex 2 の係数表は参照していない。

検証信号は、サンプルレートの 1/4 の正弦を位相 45° で入れたもの。連続波形の山は振幅 1.0、サンプル値の山は √2/2 なので、サンプル間の山は約 +3.01 dB になる。窓を滑らせて測ると、測定器の誤差は 0.05 dB 未満だった。100 Hz の正弦も同じ範囲に入る。1 箇所の窓だけではゼロクロスに当たって 0.707 しか見えないことがある。試験は全サンプルを入れてから、履歴が温まった後の最大値だけを採る。

## 採否と置き場所

採用する。判断の目安は次のとおり。

- 候補の天井超過が 0.1 dB 以下であること。今回の最悪は +0.08 dB。
- 出力サンプルの絶対値が 1.0 を超えないこと。
- 折れ残差が 0.001 未満であること。今回は 0.00000 で、ハードクリップは不要だった。
- 正弦の THD 相当が 0.02 未満であること。今回は 0.000。過渡の THD は未測定のままにし、折れ残差と天井未満の相対誤差で sample-peak と比べる。
- sample-peak が約 0.3 dB を超える信号で、その差が 0.5 dB より大きいこと。
- CPU が、他の試験と分けた debug の中央値で sample-peak の 12 倍未満であること。今回は 11.82 倍。release は未測定。

天井未満の相対誤差が sample-peak より大きいことだけでは不採用にしない。先読みが静かな区間を一緒に下げる仕様だからである。

置く場所は、分離モードの配信用 sink だけである。`live_output` がドリフト追従の線形補間と配信用トリムと、既存の sample-peak（path 2）を済ませたあと、デバイスへ渡す直前に通す。自分用の経路には先読みを足さない。単一出力にも入れない。単一出力では本人が聞く音と配信用が同じ列なので、先読みが自分の返しに乗る。配信用デバイスがあっても分離が OFF なら、sink はあっても true-peak は通さない。

設定の ON（enabled）と、実際に遅延が付く状態（applied）は別である。applied は、分離が ON で、配信用デバイスがあり、かつ enabled のときだけ真になる。DSP、状態応答、遅延の内訳、設定画面はこの同じ判定を使う。ON でも applied でないときは、画面に「分離出力のときだけ配信用に効きます（現在は未適用）」と出す。

天井と復帰時間は sample-peak と独立にした。範囲と既定値は同じで、天井は -12〜-0.1 dB、復帰は 20〜1000 ms、既定は OFF・-1 dB・100 ms である。sample-peak は自分用と主出力にも効く。天井を共有すると、配信用だけ下げたい操作が自分用の制限まで動かす。

設定はアプリの起動中だけ保持し、Engine を作り直したときに同じ値を渡す。アプリを再起動すると OFF に戻る。プロファイルと歌／雑談には保存しない。操作ロック中は変更できない。固定ゲイン提案の測定を止める条件には入れていない。測定タップは配信用 sink ではない。sample-peak が ON のときの既存の停止はそのままである。

ON と OFF の切替は、短いフェードアウト、遅延線の消去、先読み分の無音、フェードインの順で行う。フェードアウトは先読みの半分で終わり、新しく書いたサンプルが遅延の出口に届く前に音を消す。消す前の音は、新しい遅延の先からは出さない。レートの変更と停止からの再開は処理器を作り直すか、同じフェードで遅延を消す。無音に落ちた callback では、遅延に残った音をデバイスへ書かず、状態の反映だけ進める。

天井の変更はフェードも履歴消去もしない。5 ms の線形ランプだけで、遅延線と検出の履歴は残す。ランプの途中も必要 gain は今の天井から計算し直す。隣接サンプル差の試験は 0.05 未満で、ランプ中の true-peak は、測定器の遅れを考慮した時点の天井から 0.1 dB を超えなかった。

遅延の内訳には、applied のときだけ先読みの sample 数と ms を出す。OFF、分離 OFF、単一出力、配信デバイス未設定では 0 である。自分用の true-peak 段は 0 sample と表示する。この値は段の計算値であり、観測値と足した実測の総遅延ではない。

## 保証する範囲

保証するのは、配信用出力デバイスへ渡すサンプル列について、この 4 倍補間で見た true-peak が設定した天井を 0.1 dB を超えて上回らないことである。今回の数値試験では、載せた信号の最悪超過は +0.08 dB だった。OBS の中の処理と、デバイス側のサンプルレート変換はこの範囲に入らない。Engine の中に、sink デバイスを経由しない別の OBS 経路はない。固定レートの変換は入力 callback 側で、DSP より前に終わる。peak の後にレートが動くのは、この sink の線形補間だけで、true-peak 制限はその後段にある。

外部の true-peak リミッター VST とは比べていない。プラグインの有無と設定が環境ごとに違うため、このリポジトリの試験では再現できない。

## RT の確認

先読みバッファと包絡の窓は、レートが決まったときに確保する。音声 callback の `process`、`report`、`reset_audio` では `allocation_counts` が (0, 0) だった。出力は有限値に収め、過大な定数入力でも絶対値は 1 を超えない。バイパス中、および applied でない経路では入力をそのまま返し、遅延は 0 sample である。

## 聴感は未実施

許諾済みの声、歌、音楽を人の耳で聴く確認はしていない。上の数値は、決まった試験信号を測定器に通した結果である。音の印象が許容できるかは、この文書の範囲外で別に聴く必要がある。
