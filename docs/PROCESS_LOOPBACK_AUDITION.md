# プロセス入力をChrome・VLCで試聴する

2026-11-02の未コミット版向け。本人用の返しは、指定された **Voicemeeter Input** を使う。
通常版と設定・WebView2・実行ファイルを分けた試聴環境を用意した。
先に「起動」から「聞き比べ」までを読み、終了時にはWindows側の経路を戻す。
自動検証の条件と結果は[連続運転の記録](PROCESS_LOOPBACK_ACCEPTANCE_2026-11-02.md)を参照する。

## 専用ランチャーから起動する

リポジトリ直下の`test-results/process-input-audition-20261102/Start-Audition.cmd`を実行する。
このPCでは次の場所にある。

```text
D:\Programming\App\VSTHost\test-results\process-input-audition-20261102\Start-Audition.cmd
```

開発サーバーは不要。音声停止中で起動し、前回のアプリには自動接続しない。
通常版の`src-tauri/bin`は差し替えていないため、今回の試聴にはこのランチャーを使う。
試聴環境の`state`内に保存した設定は通常版の設定から独立している。

## 原音と返しを別の出力先へ分ける

この手順の「原音用」は、再生アプリから音を出すための別デバイスを指す。
「返し用」は、Auralynが加工した音を聴くデバイスである。

| 経路 | このPCで試した例 |
| --- | --- |
| Chrome → 原音用 | `1 - FS2333 (AMD High Definition Audio Device)` |
| VLC → 原音用 | `Realtek Digital Output (Realtek(R) Audio)` |
| Auralyn → 返し用 | `Voicemeeter Input (VB-Audio Voicemeeter VAIO)` |

1. 変更前のアプリの出力先と、原音用デバイスのミュート状態を控える。
2. Windowsの音量ミキサーなどで、再生アプリの出力先を原音用へ変更する。Windowsの既定出力は変更しない。VLC等に個別の出力先設定がある場合は、そちらも確認する。
3. **原音用の出力デバイス全体をミュートする。** アプリ側の音量は0にせず、Chromeのタブミュート・VLCのミュート・アプリのセッションミュートも使わない。これらを使うと取得する音まで消える。
4. Auralynをまだ開始せず、再生アプリだけで短く再生する。本人用の返しから原音が聴こえないことを確認する。

自動試験ではChromeの出力先APIとVLCの出力先オプションで割り当てた。
Windows音量ミキサーの手動操作と、現在のVoicemeeterの先で実際に耳へ届く経路は、今回の試聴で確認する。
原音用のデバイスは、ほかの用途で使っていないものを選ぶ。機器やドライバーによってはデバイス側のミュートでも取得できなくなるため、その場合は末尾の仮想ケーブル経路を使う。

## Auralynで再生アプリを選んで開始する

ChromeとVLCを一つずつ試す。対象外のChromeタブやプレイヤーの再生は止める。

1. 対象アプリで音声を再生する。任意の手元の曲を使える。用意した素材は試聴環境内の`samples/Chrome-listen.html`をChromeで開くか、`samples/sample-44100.wav`をVLCで開く。いずれも16秒のステレオ合成音で、Chromeのページは再生ボタンを押すまで無音。
2. Auralynの「設定」→「オーディオ」を開き、接続方式を`Wasapi`、入力元を「アプリの音声（WASAPI）」にする。
3. 「アプリ一覧を更新」から`chrome.exe`または`vlc.exe`を明示選択する。複数候補が出た場合は、先ほど設定した「原音の出力先」を持つものを選ぶ。Chromeはタブ単位の選択には対応しない。
4. 「原音の出力先」が選んだデバイスで、「ミュート済み」であることを確認する。
5. 「入力の用途」を「音楽（VSTを使用、声向けの処理は省略）」、出力先を`Voicemeeter Input`にする。まず48 kHz・バッファ512を使う。
6. 「保存して開始」を押す。入力・出力メーターが動き、Voicemeeter経由で音を聴けるか確認する。Voicemeeterから普段のヘッドホン等への接続は現在の設定を使う。

アプリ再起動やAuralynの次回起動後は、アプリを選び直す。
再生先の移動・原音用のミュート解除・対象終了などを検出すると取得を止めるので、停止後に経路を確認して再選択する。
別のアプリへ切り替えるときもAuralynの音声を停止してから設定する。

## 同じ返し経路でVSTあり／なしを聞き比べる

VSTパネルの「プロファイル管理」に、VST構成だけの「入力試聴 TDR Nova」を用意した。パネルが閉じていれば「VST を編集」で開く。
「音づくりだけを呼び出す（入出力と入出力音量を保持）」を選んだまま適用する。
TDR NovaはこのPCにインストール済みのものを参照する。初期状態はほぼ中立なので、エディターでEQを変更してから比較する。

- フッターの「原音比較」でVSTの処理を切り替える。原音用デバイスのミュートは維持し、両方を同じVoicemeeter経路で聴く。
- Auralynを停止すると音が消えるかを確認する。停止後も聴こえる場合は、WindowsやVoicemeeterに原音の別経路が残っている可能性がある。
- 再生アプリの一時停止・再開、曲の切替、5〜10分の再生で、二重再生・クリック・途切れ・音量変化・遅延の増加を確認する。VSTあり／なしの両方を試す。

「原音比較」はVST段の比較であり、経路全体の遅延をゼロにしたり、遅延差を完全補正したりする機能ではない。
今回は「音楽」の用途なので声向け処理を省略する。「声」でNRを比べる場合は、音作り設定のNRを別に切り替える。

## 終了したらWindows側の経路を戻す

1. Auralynの音声処理を停止する。
2. Chrome・VLCの再生を停止する。
3. 再生アプリの出力先と、原音用デバイスのミュートを控えた状態へ戻す。
4. 試聴用Auralynを閉じる。

Auralynは再生アプリの出力先やWindowsのミュートを自動変更・復元しない。
専用アプリの隔離対象にもWindows・Voicemeeter側の経路設定は含まれない。

## 別の出力先を使えない場合は仮想ケーブルへ切り替える

Auralynを停止し、再生アプリをケーブルの再生側（VB-CABLEなら`CABLE Input`）へ送る。
Auralynの入力元を「マイク・仮想ケーブル」に変更し、ケーブルの録音側（`CABLE Output`）を明示選択する。
用途は「音楽」、Auralynの出力は`Voicemeeter Input`のままとする。
加工後の出力を同じ入力ケーブルへ戻すと音が循環するため、返し先を分ける。

今回の段階1は単独入力の試聴であり、マイク＋伴奏の同時入力やミックス後VSTはまだ含まない。
問題があれば、このチャットで「Chrome/VLC、原音用・返し用の機器名、VSTあり／なし、発生した操作と時刻」を共有する。
