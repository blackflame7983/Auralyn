## #95 測定と適用の契約

測定は入力ゲイン/ch選択後、NR前の音声を対象にする。音声サンプルは共有/保存せず、固定サイズの10ms窓のエネルギー・peak等だけをRT側で集計する。
機械的に声/放送/筐体音の種類を判別したと表現しない。

- 測定の世代、機器の実ID、host、入力名、ch、入力ゲイン、解析rate/backend/model/version、長さ、取得時刻を返す。
- 測定結果と採用済みの固定抑制値を分離する。測定だけではNR設定を変えず、無言/残したい音が混ざっていないことを明示確認して採用する。
- 不正値/ほぼ無音/clip/1秒未満は採用不可。音量の大きさ/変動は不確かとして示し、話者認識の結果にしない。
- 入力/host/ch/gain/rate/stream再開/手動環境変更で失効。出力音量・送り先だけの変更では周囲測定を失効させない。出力変更に伴い入力streamも再構築した場合は再測定する。
- 最大30分で再確認。場所の移動/機器の物理つまみ/周囲の変化は自動検知できないため、#94の環境変更操作から再確認する。
- 失効時は環境由来のgate基準を無効化するが、明示採用した抑制係数とON/OFF・強度・発声保護を保持する。失効したことだけでSmartのmixが強まらないよう、固定値の保持と環境gateの有効性を別に扱う。
- 完了/取消/入力変更は世代で照合し、旧世代のRT完了や開始要求を現在の測定へ採用しない。画面を閉じた後の開始応答は返された世代だけを取り消す。
- 前回の採用条件・時刻・RMS/固定係数は保持できるが、現在有効とは表示しない。通常プロファイルへ環境値を埋め込む変更は行わない。
- デバイスを識別できない場合は測定を開始しない。物理的に同一機器/同一空間の保証ではない。

単体検証、統合/ブラウザー検証、実機確認は区別して記録する。実機・実VST・実DPI・相手側の受信/聴感を自動テストで合格にしない。


## #96 同じ録音のNR比較

- 既存の最大10秒の録音、単一の候補生成worker、固定上限のキュー、別ヘッドホン出力の試聴sessionを再利用する。workerや音声Engineを増やさない。
- 同じ確定録音から「現在」「強度を0.2弱める」「0.2強める」を選ぶ。範囲は現行と同じ0.25〜1.25。現在OFFなら現在候補は原音と一致し、弱め/強めはONにする。モードと発声保護は保持する。
- 同時に保持する候補は1件。次を作ると前候補を破棄する。AはNR前の原音、BはNRだけの候補。既存の歌向け提案・手動候補・録音時の加工後比較・WAV保存を残す。
- 本番と同じNR controllerを独立状態で作り、1秒の共通前置無音、既知の信号対応遅延の補正、末尾のflushで原音と同じ長さへ揃える。対応範囲は8〜192kHz。NRの実行履歴や、callbackごとの判定窓まで本番と同じにはならない。
- 出力gain・VST・内蔵FXを候補へ混ぜない。比較音量合わせは試聴だけを減衰し、本番の音量を変えない。試聴は既存の出力選択・取り込み対象外の明示確認が必要で、主出力へ代替しない。
- 生成・試聴だけでは本番設定を変えない。採用はNRのON/OFF・モード・強度・発声保護だけ。変更前後を表示し、「残る」「声が欠ける」「分からない」の自己申告は自動採用に使わない。
- 録音ID/録音条件/Engine/モデル/NR基準/input・周囲測定の世代が違えば候補は失効する。Undoは採用後のrevision・測定世代・stream・入力条件を照合し、後編集やA→B→Aで過去値を上書きしない。
- 開始/採用自身のHost通知で自分の操作を取消さない。採用後は読み戻し、別の条件変更が重なれば成功表示を止める。Stop/非表示/Engine異常の中断を優先する。
- DeepFilterNetは導入していない。#93の標準モデル追加候補という方針を維持する。

## #97 プロファイルの目的と一時利用

### 保存・適用

プロファイル管理の既定を「音作りだけ」にする。設備設定も保存する場合は従来のカテゴリを使い、Host/入出力/rate/buffer/ch/入出力音量と再開への影響を説明する。
呼出しも既定は音作りだけとし、旧プロファイルに音声設定が含まれていても適用用コピーから除く。保存原本・従来のカテゴリ/schema・プリセット・bundleは変更しない。
周囲測定値は従来どおり保存しない。場所名や似た機器名による同一視を加えない。

### 分離の単位と保存先の棚卸し

途中からlocalStorageを差し替える方式ではなく、再起動前にTauriの全app_*パスとWebView2の領域を専用フォルダへ切り替える。
通常設定をコピーして再保存する処理を作らず、新しい空の領域を使う。音作りはプロファイルを明示importする。

| 対象 | 現行の入口と分離方法 |
| --- | --- |
| 入出力自動保存、live_output、live_modes | AudioHostのconfig rootを分離 |
| プロファイル/適用前backup、bundle/backup | app_config_dirを分離。既存の保存/差分/条件付きUndoを使う |
| VST blacklist/スキャン記録、shortcuts、native表示言語、window-state | app_config_dirのoverrideを使う |
| gain・音声選択・用途・経路・ラック・OBS接続情報・表示・ガイド等のlocalStorage、sessionStorage | WebView2のapp_local_data_dirを分離。各自動保存の原本へ書かない |
| 録音チェックの内部解析WAV | app_cache_dir/voice-analysisへ限定し、一時利用ではこのcacheも分離。通常終了・解析失敗のDropで所有領域だけ削除 |
| 一時利用の中断検出 | OSのユーザーtempにIDと確認待ちだけを記録。生音声/パスワード/設定全体を復旧マーカーへ入れない |
| 自動起動・updater・設定移行の適用 | 一時利用中はnative側でも拒否。自動更新チェックを起動しない |
| OS/OBSの実際の設定、VST自身が外部へ書く状態、明示したexport先 | 対象外。元に戻すと表示しない |

開始/終了は停止を伴う明示操作。未保存のruntime音作り・録音・現在のモードを戻す機能ではないため、必要なら先に既存プロファイルへ保存することを表示する。
通常設定へコピー戻ししないため、別の利用者が原本を変更しても古いsnapshotで上書きしない。
通常設定は確認待ちで開き、HostとUIの両方で自動開始を抑止する。VSTの自動復元と有限自動復旧も明示開始まで抑止する。
復旧マーカーの解除には実際のstream稼働をnative側で確認する。一時利用の途中では通常起動用マーカーを解除しない。

再起動先は旧PIDの終了を最大30秒待ち、同じsingle-instance IDを維持する。待機失敗、作成/権限失敗、既存の一時領域への再開は拒否する。
正常終了は保存したいプロファイルをexportしてから通常設定を開く。旧Host終了後、IDの形式・temp直下・reparse pointでないことを照合し、専用フォルダだけの削除を試す。失敗は画面に残す。
異常終了後の通常起動は確認待ちとなり、残った専用フォルダを表示する。未完了の音声/試聴/適用を再開しない。

**残る実装範囲:** 動作中の未保存状態全体のsnapshot、終了時の詳細な変更差分と選択的な書き戻しは未対応。現段階では自動書き戻しを設けず、明示exportと原本の隔離で保護する。
#97全体の受入完了とは扱わない。

## #98 戻す対象の区別

プロファイル管理に「戻す・復旧する」の入口を追加する。

1. **直前の変更:** NR/内蔵候補・固定gain・bundle・monitor trialにある既存の局所Undoを案内する。適用前backupを「確認済み」と呼ばない。
2. **聞いて確認した構成:** 現在条件の読み取りと明示確認の後、既存bundleへHost/入出力/ch/gain/NR/FX/VSTを保存する。確認時刻・用途・場所と制御条件を履歴として分けて保持する。
3. **障害:** 音声を開始しない既存の状態読取りで、稼働/停止/stream失敗/不明を区別する。出力信号やOBS/相手側の受信とは区別し、既存の有限retryとVST復旧表示へ案内する。

確認済み構成は単一出力・カスタム音作りに限定し、native側で対象外構成を拒否する。モニター分離・歌/雑談・本番保護・ピーク保護・OBS/Windows・環境測定値は復元しない。
保存中の変更を既存control witnessと取得前後の状態で検出する。呼出しは既存bundleの差分/予約/原本保護/読み戻し/条件付きUndoを使い、保存しただけでは適用しない。
呼出しは**緊急ミュートをONにして差分を取得し直してから**行う。native側でもミュートを要求し、失敗やVST不足でも未加工音を送らない。復元後も勝手にミュートを解除しない。
保存した確認履歴は現在の成功を意味しない。復元後は#94の影響する確認を取り直す。受け側の確認を自動で合格にしない。

**残る実装範囲:** 分離出力やモード/保護を含む全構成のsnapshot復元、各局所Undoの履歴を一つに集約する仕組み、機器欠落等の詳細な原因分類は未対応。既存の個別設定/Undo/復旧を保持する。

## #99 出力ピーク保護

- 既定OFF。ceiling -12〜-0.1 dBFS、release 20〜1000ms。stereo共通の減衰で左右の位置を保ち、makeup/AGCは持たない。既存の歌向けコンプは変更しない。
- 主経路は最終output gain/回復fadeの後、monitor trimの前。分離monitorはそのFX/gain/trimの後。配信sinkはキュー/clock補間/trimの後にも保護し、古い未制限のqueued音も天井を超えないようにする。
- lookaheadなし、追加遅延0 sample。過大peakのattackは即時。切替mixと検出ceilingは5msで移り、天井変更中も新しい有効天井で上限を保つ。releaseは指定時間の指数復帰。可聴上の無変化やクリック皆無を保証しない。
- 係数計算は制御側で行う。RT側は固定サイズの値、有限回のatomic読取り、四則演算だけ。変更途中の値を混ぜず、読み取りが競合したblockは前の係数を保持する。RTに割当/ロック/I/Oを入れない。
- 主出力・分離monitor・配信sinkの反映を照合し、確認待ちを表示する。直近の抑制量は大きい出力側を表示する。#94の聴感/送り先確認は保護変更で失効する。
- 設定は現在のHost内で保持する。Engine再生成時は音声開始より先に引き継ぎ、確認できない場合は新Engineを停止する。アプリ再起動時はOFF。プロファイル/歌・雑談へ保存しない。
- 固定gain提案は保護OFFで測定する。ON中の解析開始はnative側で拒否し、保護ONの最終送出は別途確認する。独立した録音試聴の既存安全減衰は別機能として保持する。
- True Peak、入力/処理内部ですでに起きたclip、後段のOBS/通話gainは保護対象外。NRやVSTの失敗を未加工音へ置換する機能でもない。

## 利用場面別の確認手順

- **ゲーセン:** 場所/音声の分離状態を指定 → 実際の入力ch/gainを決める → 話さず周囲測定し内容を確認して採用 → 普通/小声/短い実況/大声を同じ録音で比較 → 最終gain/任意のpeak保護 → 受け側で確認。ゲーム音混合済みではNRが残したい音を削る可能性を確認する。
- **自宅配信:** 自宅設備のプロファイルか音作りだけを選ぶ → 周囲/機器の変化があれば再測定 → NR比較と最終音量 → OBS側の追加処理/重複取り込みを含め録画を確認する。
- **自宅通話:** OBSを起動・接続せず、通話アプリの入力と処理を確認する。同じ録音でNRを選び、最終音量を相手側で確認する。
- **共有PC:** 元の未保存設定は必要なら先に保存 → 一時利用の対象外を確認 → 別領域で開始 → 持ち込む音作りだけをimport → 機器と受け側を再確認 → 保存したいものだけexport → 通常設定を確認待ちで開き、削除失敗の有無を確認する。
