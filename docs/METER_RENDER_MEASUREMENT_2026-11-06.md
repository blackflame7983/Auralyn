# メーターの再描画分離（#331）

2026-11-06、隔離した実 Tauri Host / WebView2 156.0.0.0 で変更前後を計測した。
音声は開始せず、IPC のレベル通知をモックして UI の処理だけを比較した。
通常設定とは別の config / data / WebView2 保存先を使い、計測した Host だけを終了した。

## 条件と再現

```powershell
node scripts/measure-meter-render.mjs a8acddbb418494acbe759788ff91fc87c64a0da8
```

Windows、Rust と既存のビルド依存、Playwright が必要。
runner は専用設定で Host をビルドし、変更前の `src` は上記コミットから、変更後は作業ツリーから取得して別々の Vite 本番ビルドを作る。
計測用ビルドだけで関数入口にカウンターを挿入し、Tauri core の専用ラッパーを通して `tauriFixture` のモック IPC を使う。
窓の観測・配置は隔離 Host 自身へ渡す。製品の内部 API や通常ビルドは変更しない。

- CSS viewport: 1280×768。ダーク・ライト・ゲーミングを確認。
- 負荷計測はダークで、idle → input → output の順に各5秒、1回ずつ実行。
- 通知間隔16ms、各区間313 tick。片側を0.25〜0.44で変化させ、反対側はゼロ。
- 出力区間の冒頭には、直前の入力の減衰・ピーク保持更新が残る。
- `Performance.getMetrics` の区間差分を記録。フレーム観測は826〜827回/区間。
- 再描画回数は関数が呼ばれた回数。React Profiler の commit 時間ではない。

## 再描画回数（変更前 → 変更後）

| 5秒の区間 | LiveStrip | InputGainControl | MasterBar | MeterVisual（全個体の合計） |
| --- | ---: | ---: | ---: | ---: |
| idle | 5 → 5 | 5 → 5 | 13 → 13 | 20 → 0 |
| input | 317 → 5 | 317 → 5 | 327 → 12 | 956 → 314 |
| output | 318 → 8 | 318 → 8 | 324 → 13 | 957 → 644 |

値の通知に伴う高頻度の描画はメーターとオーロラへ限定できた。
実 UI は状態取得や経路確認も行うため、親の回数はゼロにはならない。
別の DOM 試験では、入力・出力の値およびクリップを変えても、本番帯とフッターの操作部品の描画回数が増えないことを確認する。
入力だけの更新が出力の購読者を描画せず、逆方向も同じことを確認する。

## 表示と境界

同じ一定通知（入力0.25、出力0.4）へ収束させたとき、3テーマとも全3メーターの値・x/y・幅・高さが前後で完全一致した。
入力は −12.041199826559248 dBFS、出力は −7.958800173440752 dBFS。
本番帯は高さ32px、フッターは幅28px・高さ28px。
前後のスクリーンショットを `test-results/issue-331/results-before` / `results-after` に保存して比較する。
大型メーター・クリップ・停止・無音・表示切替は通常のブラウザ試験と既存のメーター試験でも確認する。

16ms のタイマー、平滑化係数、ピーク保持・減衰の計算は維持した。
requestAnimationFrame への変更は、同時に値の時間応答を変えないため今回には含めない。
実音声、聴感、OBS・ゲームとの同時負荷、長時間利用、実機でのクリップ操作は未確認。
