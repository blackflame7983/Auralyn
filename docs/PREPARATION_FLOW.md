# 配信・通話の準備導線（#94）

対象は自宅と会場・ゲーセンでのOBS配信、通話、その他のアプリ、ローカル試聴。
既存の機能・音声設定を保持し、条件に応じて既存画面へ案内する。
自動的な設定適用、OBS接続、テスト音、録音、試聴再生は追加しない。

## 表示と操作

[PR #101 のUI/UX監査](https://github.com/blackflame7983/Auralyn/pull/101)のA1・A2を反映する。
詳細表示にも声の簡易調整を残し、通常画面の番号付きセットアップカードを共通の状態帯へ置き換える。
監査全体の解消を意味しない。音量測定、全モーダルの再設計、ホットキーの発見性、音声処理自体の改善は本変更の対象外。

表示順は次のとおり。

1. 入力・音声処理・出力の状態帯、既存の入力メーター、入出力設定への入口。
2. 準備状況、今必要な主操作一つ、現在の段階を利用者が確認するチェック欄。
3. 既存のノイズ低減・ボイスチェーン調整、録音比較への入口。OBS設定はOBS用途で表示する。
4. 既存の音量チェック、歌・雑談の操作、VSTラック等。

900×600のブラウザー表示で次の操作が隠れたため、準備状況を声の調整より前へ配置した。
本文はスクロールし、ミュート・原音比較・出力音量の既存配置を保つ。
原音比較は引き続きVSTのみをOFFにする。

条件と履歴は一つの`details`にまとめる。用途が未選択なら最初から開く。
会場でのテスト音・試聴音の外部送出と停止方法、混合済み入力の分離限界は、折りたたみの外で再生前に示す。
詳細表示は機能を追加して見せる選択とし、通常の声の調整を隠さない。
VST・歌・ASIO・内部診断・モニター分離・プロファイル・ホットキー等の既存入口は保持する。

毎回ウィザードを起動する案は再訪時の操作が多くなるため採らない。
既存リンクの並べ替えだけでは確認状態を共有できないため採らない。
共通の準備状況から既存の設定・ボイスチェック・OBS/通話ガイドへ進む構成を採る。
これらの画面の閉じる/中断・フォーカス復帰は既存のModalを利用する。
準備欄の主操作は読み取り中にも有効にし、復帰時の状態取得でフォーカス先が無効になることを防ぐ。
確認欄が次の段階へ置き換わる場合は、ほかへフォーカスを移していなければ次の操作へ戻す。

## 確認の意味と保存

| 表示・記録 | 保証する範囲 | 保証しない範囲 |
| --- | --- | --- |
| 稼働を確認 | Auralynのプロセス/ストリーム、制御状態、既知の出力障害を読み取れた | 実マイクの内容、ケーブル受信、相手側の聴感 |
| 入力メーター | 既存の入力レベル通知 | 声とゲーム音の識別、送り先の受信 |
| OBSの機械的な確認 | 既存検査の指定ソース・テスト音検出と、現在の条件へのwitness照合 | 実発話、録画トラック、最終録画の品質 |
| 利用者が確認 | 利用者がその段階を確認したと明示した事実と時刻・対象 | アプリが聴感や相手側を自動判定したこと |
| 未確認・非対応・条件変更 | 必要な確認が残っている | 自動的な正常判定 |

「声を整える→加工前後を聴く→受け側」の各確認は利用者の明示操作だけで記録する。
記録時に再取得し、表示時の条件と一致しなければ記録しない。機械的な成功から手動確認を作らない。
通話では選択入力、受け側のNR/AGCとの重複、相手側の聞こえ方を確認するよう案内し、処理設定を一律OFFにしない。
ローカル試聴は「試聴先で確かめる」と表示し、配信・通話への到達と表現しない。
VB-CABLEの既知の対応入力だけを既存関数で案内し、未知のミキサーの入力を推測しない。

場所・用途・混合/別経路・送り先名はローカルの条件設定として保持する。
用途は既存の`vst_host_setup_goal`を共用し、旧`local`も`listening`へ読み替える。
用途が一致しない保存済み送り先は引き継がない。
設定移行には条件だけを含め、受入側で列挙値・長さを検証する。
手動確認の記録とOBS検査の一時共有はメモリー内だけに置き、アプリ再起動後の成功を復元しない。
生音声、OBSの資格情報、相手側アプリの設定は新しい準備機能で保存しない。

## 条件と失効の契約

`EngineRuntimeStats.preparation`は任意の読み取り専用フィールド。
エンジンの識別、既存の処理revision、入力ゲイン/ch、出力revision、出力経路revision、ミュート、反映待ち、現行NR識別を制御スレッドで取得する。
整数revisionは文字列で返し、JavaScriptの整数精度による同一視を避ける。
旧応答でこのフィールドがない場合、準備確認は「不明」とする。既存の操作は引き続き使える。
DSP・モデル・NRの強度や発声保護・音声コールバックは変更しない。

準備欄の状態取得は単一要求にまとめ、2秒ごとに再取得する。
モーダル表示中、画面非表示中、停止/エラー通知後は新しい確認を受け付けない。
状態・統計の前後を照合し、途中で機器や処理が変わった読み取りを捨てる。
購読世代の異なる古い応答は表示に反映しない。

| 変更・状況 | 音作り | 試聴 | 送り先 |
| --- | --- | --- | --- |
| 入力機器/host/ch/rate/buffer、入力ゲイン | 再確認 | 再確認 | 再確認 |
| NRのON/モード/強度/発声保護/学習要求、backend/model | 再確認 | 再確認 | 再確認 |
| 内蔵FX、歌/雑談の適用、VST構成/状態/ゲイン/バイパス | 再確認 | 再確認 | 再確認 |
| 出力機器/音量/ミュート、配信・モニター経路/trim/分離 | 保持 | 再確認 | 再確認 |
| 場所、ゲーム音と声の混合/別経路 | 再確認 | 再確認 | 再確認 |
| 用途、受け側入力/ソース名 | 保持 | 保持 | 再確認 |
| OBSのwitness失効・対象変更・接続世代変更 | 保持 | 保持 | 再確認 |
| 同条件の画面再訪、設定を変えずにモーダルを閉じる | 保持 | 保持 | 保持 |
| ストリーム停止/再開、出力失敗、取得失敗、識別不能 | 再確認 | 再確認 | 再確認 |
| 画面非表示、明示的な環境変更、VST独自GUIを開く | 再確認 | 再確認 | 再確認 |

失効は不可逆とし、設定をA→B→Aへ戻しても古い確認を復活させない。
同じ値を再適用しても制御intentのrevisionが変われば保守的に再確認する。
メーターや録音状態の読み取りだけでは、処理条件の確認を失効させない。
設定が変わらないボイスチェックの実行・中断からは、その段階を自動的に完了させず、元の文脈へ戻す。

機器の物理つまみ、周囲の音、VST独自GUI内の変更すべては自動検知できない。
該当する変更時に使う再確認操作を履歴内に用意し、検知の限界を明示する。
音声の適応処理の瞬間値や受け側のNR/AGCの状態を、固定した設定条件の識別と混同しない。

OBSは既存の検査画面から結果を共有し、指定名とwitnessが一致する場合だけ既存の再検証APIを読む。
準備欄からOBSを接続したり、検査音を再生したりしない。
通話/その他/ローカル用途の準備欄はOBSへ問い合わせない。
既存の明示有効化されたOBSシーン連動は独立した既存機能として維持する。

## 検証と後続の責任分界

自動回帰は条件別失効、A→B→A、用途別案内、旧/不正応答、停止後の遅い応答、非表示、StrictMode購読回収、明示確認時の再取得、OBSの対象照合を扱う。
既存のモード切替/原音比較/ウィザード/設定移行も確認する。
ブラウザー検証はTauri IPCを模擬した画面操作であり、実音声・OBSの検証ではない。

実行結果と実機確認のチェックリストは [PREPARATION_FLOW_VERIFICATION.md](PREPARATION_FLOW_VERIFICATION.md) に記録する。
ノイズ測定の改善（#95）、新NR候補（#96）、DeepFilterNetの採用は実装しない。
これらの後続は処理条件revisionを更新し、候補の試聴と設定適用・利用者確認を引き続き区別する。
既存の実機受入（#72）、遅延（#28）、モニター/配信分離（#73〜#77）を本変更の単体試験で合格にしない。
