# MSIX移行と長時間試験の候補

MSIXを主軸とし、設定移行と数日間の個人試験が完了するまで通常版EXEを維持する。
MSIは新規のビルド・配布・検証から除外し、公開済みファイルは削除しない。
この文書の手順は検証結果ではない。実施済みの結果と未確認事項は末尾に分ける。

## 追加した機能

### 明示的な設定移行

設定の「外観」から、移行元で書き出し、移行先でファイルを選び、内容確認後に取り込む。
通常版のフォルダーをMSIXから探索したり、WebView2内部のファイルをコピーしたりしない。
形式は`auralyn-settings`・version 1のJSONで、全体64MiB、ネイティブ設定512ファイルまで。
取り込み前にデータ形式・ゲイン範囲・デバイス設定・VSTセッション・パスを検証する。

- 対象: テーマ、かんたん表示、用途、導入完了状態、音声デバイス選択・音声プリセット、入出力ゲイン、VSTセッションと状態、お気に入り・最近使ったVST、保存したプロファイル、ブラックリスト、ショートカット。
- 除外: VST本体、ドライバー、OBSの接続情報・パスワード・復元履歴、Windowsの権限、自動起動登録、更新ポリシー、録音途中のデータ、クラッシュ復旧の印、端末固有の詳細チューニング。
- 内蔵FXやノイズ低減は保存済みのフルプロファイルに含まれる。現在の一時的な内蔵処理を移したい場合は、移行元でフルプロファイルを保存し、移行先で確認後に読み込む。
- 同名プロファイルは置き換え、それ以外の移行先のプロファイルは保持する。対象のUI設定は移行ファイルの状態へ置き換える。
- 移行先の`migration-backup.json`に直前の対象設定を保存する。録音・試聴中は拒否し、バックアップ後に音声を停止して取り込む。書き込み失敗時は直前へ戻す。
- 書き込み途中でプロセスが終了した場合も、次回起動時にバックアップへ戻してから確認画面へ進む。バックアップを読み取れない場合は、自動開始と画面の初期化を止めてエラーを示す。
- 再起動後は、入力・出力先とVSTを確認して「保存して開始」を実行するまで、保存音声の自動開始とVSTセッション復元を保留する。権限エラー時も確認要求を残す。
- 「移行前に戻す」は直前のバックアップへ戻す。移行後に行った対象設定の変更も戻る。再度の取り込みは新しい直前バックアップに置き換わる。

移行JSONにはVSTの内部状態・ファイルパスが含まれる。自身で管理し、不特定のファイルを取り込まない。

### MSIX自動起動

試験用manifestに初期OFFの`AuralynStartup` StartupTaskを追加する。
MSIXはStartupTask、通常版は所有するRun登録だけを変更する。
Windowsで無効にされた状態・管理者ポリシーを区別して表示し、アプリ側で強制的に再有効化しない。
両版の自動起動が有効でも二重起動防止を維持するが、先に起動した版が稼働するため、使用する版だけを有効にする。
正式Identityでの更新・ログイン起動は別途実機確認する。

### Stream Deck向けホットキー

設定の「外観」で8操作までキーを割り当てる。
既定はAlt+M（ミュート切替）とAlt+P（原音比較切替）。
追加でミュートON/OFF、原音比較ON/OFF、出力ゲイン1%増減を割り当てられる。
Stream Deckの標準Hotkeyアクションへ同じキーを設定する。
前面と背景で共通のネイティブ操作を使い、画面内の重複キー処理は行わない。
競合・保存失敗は案内し、無効な設定を保存しない。
専用プラグイン、キー画像への状態同期、ローカルAPI、Stream Deck実機の対応確認は今回の範囲外。

### 自動更新

通常版は起動10秒後、その後24時間ごとに確認する。設定でOFFにできる。
更新通知は明示操作まで残し、ダウンロードの自動化は別の任意設定（既定OFF）とする。
自動インストール・無断再起動は行わない。
明示適用時は最新のVST状態を保存し、録音・試聴中でないことを確認し、音声・サイドカーを終了してから署名検証済みの更新を適用する。
通常版のアンインストール登録と現在の実行フォルダーが一致し、Windows Installer（MSI）の登録でない場合に限りアプリ内で適用する。
Portable版・所在不明は配布ページへ案内し、MSIX版はStoreまたは元の配布元に限定する。
オフライン時の自動確認失敗で通常操作を止めず、手動確認と再試行を残す。

## 個人試験の進め方

1. 現在の設定を書き出し、通常版とMSIX版それぞれの自動起動状態を控える。
2. 最終releaseの本体・エンジン・スキャナーの実行パスとSHA-256を固定する。試験途中でバイナリーや設定条件を入れ替えない。通常版では自動確認をOFFにし、自動適用は行わない。
3. 最初に900×600でデバイス選択、移行、再起動、ホットキー、OBS接続、録音・試聴の開始／停止を短時間確認する。
4. 普段の経路で48〜72時間使う。OBS接続と配信用表示のON/OFFを切り替える比較は、各条件の開始時刻・入出力・レート・バッファー・VST構成を記録する。
5. 音切れ、デバイス抜き差し・復帰、スリープ復帰、OBS再接続、終了後の残存プロセスを記録する。ASIOの遅延カウンターだけで可聴の音切れと判断しない。
6. 試験後に元の設定と自動起動状態を復元する。試験パッケージと試験用証明書は、修正・再確認を一通り終えてから削除する。

外部測定はWindows PowerShell 5.1／7から実行できる。
PIDは実行パスを確認した試験ホストのものを指定する。出力先は新しいフォルダーとする。

```powershell
./scripts/measure-release-trial.ps1 -HostProcessId 12345 -OutputDirectory C:/Users/Public/Auralyn-trial-results -DurationSeconds 259200 -IntervalSeconds 30
```

ホストとその時点の子孫プロセス（サイドカー・WebView2等）を記録する。
CPUは各区間のCPU時間差を論理コア数で正規化した値。初回・新規プロセスの最初の値は空欄。
Private BytesとWorking Setは別々の列で、WebView2共有ページの単純合計を実使用物理メモリとは扱わない。
プロセス終了で測定を終了し、設定・優先度・タイマー解像度は変更しない。
音声カウンター、OBS内部の状態、ログ容量、聴感はこのスクリプトだけでは測定しない。

## 実施結果

2026-10-21、Windows 11 x64で以下を確認した。正式Store Identityでの結果ではなく、試験用MSIXと通常版のローカルreleaseによる確認である。

- UI 263件／38ファイル、Rustライブラリー115件とキュー2件・共存2件・メンテナンス1件が成功。最終の`cargo test --locked -j 2`全体実行は成功し、明示実行が必要なOTT寿命テスト1件は既定どおり除外した。配布スクリプト51件、TypeScript、Vite build、clippyも成功。ビルドと並行したUI全体実行では待機時間不足、Rust全体実行ではリンク時のメモリー不足が発生したが、並列数を2に抑えた再実行は成功した。
- 正式のrelease・custom-protocol構成でホスト・エンジン・スキャナーを同時ビルドし、パッケージに含む3本のSHA-256を照合した。Windows PowerShell 5.1でMSIXを作成し、展開・インストール後の実行ファイルも照合した。
- 通常版から書き出し、MSIXでプレビュー・キャンセル・取り込み・再起動・明示確認後の音声開始・直前への復元・再取り込みを確認した。プロファイル2件、ブラックリスト、VST 2件を含む。自動起動のOS登録は移行されず、移行先で有効にしたStartupTaskは取り込み・復元・パッケージ更新でも保持された。
- 移行直後は音声とVSTの自動復元を保留した。実機確認で見つかったASIOの選択チャンネルが0/1になる問題を修正し、確認後の手動開始で6/7が保持されることを修正版MSIXで確認した。通常版→MSIX、MSIX→通常版の両起動順で、後から起動した側が終了し、元のホストとエンジンが継続した。
- マイク未許可でASIOからWASAPIへの再起動を拒否しても、ASIO音声・VST 2件・ホスト／エンジンPIDを保持した。個別許可をONにしただけでは切り替わらず、保持されたWASAPIの選択で明示的に再試行できた。切替後の保存チャンネルは0/1だった。
- 最終パッケージ更新直後の起動では、個別許可がAllowでも一度自動開始が権限案内になった。同じプロセスで設定を変更せず「保存して開始」すると成功し、同じパッケージの次の再起動では自動開始に成功した。発生条件は未特定のため、長時間試験でも更新後の起動を継続観察する。
- WASAPI 48kHz／512、CABLE入力→Steam Streaming出力、VST 2件で合成音声を流し、7.03秒の原音・処理後録音がともに非無音だった（peak 0.354／0.387、RMS 0.0665／0.0722）。音声状態は稼働を維持し、観測中のglitchCountは0。録音の処理後データは出力ゲイン適用前であり、外部出力の聴感を保証するものではない。
- 900×600で移行画面、確認・再試行、音声設定、更新案内、ショートカット設定を操作し、ページの横方向のはみ出しがないことを確認した。8操作のホットキーと前面／背景でのミュート・原音比較を確認し、ゲイン100→101→100を確認した。
- 通常版の手動更新確認は公開フィードへ到達した。PortableのダウンロードとMSIXの確認・ダウンロード・適用はネイティブ側でも拒否した。録音中の中断操作と、停止処理中の重複適用も拒否した。
- 実OBS 32.2.2へ接続し、変更予定を読み取ってから切断した。OBSへの設定適用は行わず、設定7ファイルのハッシュ一致を確認した。OBSは終了要求後も自プロセスが残ったため、試験で起動したPIDと実行パスを照合して終了した。

サンプルレート・画面条件が異なり、後者はビルド作業も並行しているため、ドライバー間の性能比較には使わない。
Working Setは共有ページを含む単純合計で、実使用物理メモリの値ではない。短時間のためリークや数日運用の安定性も判定しない。
初期の測定スクリプトにあったCPU小数の丸めを修正して再測定した値のみを上表に採用した。

個人による48〜72時間の運用、Windowsのログアウト／再ログイン、正式Store配信での更新、署名済み次版NSISインストーラーの取得・実適用、実マイク・Stream Deck実機、スリープやデバイス抜き差しは未実施。

試験パッケージ、専用データ、試験アプリのマイク許可エントリ、ユーザー側の試験用証明書・秘密鍵、公開証明書ファイルは残していない。

### ASIO入力ペア選択時の移行確認保護（2026-10-21）

- 入力ペアの変更は設定の保存だけを行い、移行確認を解除しない。確認チェック後に「保存して開始」または「エンジン再起動」と入力チャンネル設定が成功した場合だけ、移行確認を完了してVSTを復元する。
- 実際の設定画面・音声設定フック・VSTフックを通し、ペア変更後も未確認の開始／再起動が無効でVSTをロードしないこと、確認後の開始／再起動と失敗後の再試行で各VSTを1回だけ復元し、選択した6/7を保持することを自動検証した。
- この追加修正はフロントエンドのみ。コード修正時点では自動検証までとし、その後に以下の実MSIX再確認を行った。前節の.34の実機記録とは区別する。
