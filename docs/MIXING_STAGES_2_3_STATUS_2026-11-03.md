# 二入力とミックス後VSTの実装・確認記録

2026年11月3日時点の作業記録。公開済みの機能を示す文書ではない。

## 段階2の実装

声用途の主入力へ、音楽用途のプロセス入力またはWASAPI機器入力を追加した。
本人用の出力callbackで一度取得して分岐し、配信枝だけで既知の声処理待ち時間と手動オフセットを合わせる。
正の値はオケ側、負の値は声側を追加で待たせる。上限は±2,000 ms。
申告されないVST遅延をゼロと仮定せず、耳やOBSまでの総遅延とは区別する。

独立した入出力クロックは、取得rateとキュー量に基づく可変比変換で扱う。
同じASIO機器の入出力だけは共有クロックとして扱い、ASIO主入力とWASAPIオケの混在は独立したオケのクロックを補正する設計とした。
この環境でASIOの実入力は確認していない。
仮想ケーブル経路も実Engineで取得を確認した。

音量は0〜2倍、トラック別ミュート、本人用のオケ返し、配信側の時間差を操作できる。
オケ終了時はオケを無音にし、声の処理を継続する。
設定変更には世代とrevisionを要求し、保存したPIDやアプリ名だけでは再接続しない。
再起動後は入力元を明示選択する。
壊れた保存設定は明示的な初期化で原本と状態記録を保管し、オケを無効にできる。

## 段階3の実装方針

ミックス後VSTは専用のEngineプロセスへ分離する。
既存の声ラックとインスタンス・順序・状態・エディタ・保存領域を共有しない。
音声は固定容量の共有メモリキューで渡し、本人用callbackで配信VSTを待たない。
OSのマッピングと後始末は制御側で行い、音声callbackでは確保・解放・ロック・I/Oを行わない。
Windowsの共有メモリと生存期間は[Microsoftの公式説明](https://learn.microsoft.com/en-us/windows/win32/memory/sharing-files-and-memory)に従う。

処理順は「声処理・時間合わせ・ミックス・ミックス後VST・最終音量・ピーク保護・配信出力」。
ミックス後ラックの失敗や応答欠落は配信枝を無音停止し、無断で加工前の音へ切り替えない。
旧プリセットの役割は声ラックのままとし、二つのラックを含む保存・復帰が成立するまで既存の全体保存には混在構成を渡さない。
段階3は実装中で、受入完了とは扱わない。
