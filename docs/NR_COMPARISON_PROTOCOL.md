# NR比較の準備（#93・#220）

ゲーセンの実素材で現行NRと将来のDFN3候補を比較するための手順。素材、実測、聴感は未取得であり採否は保留する。採否には実素材比較と #219 の歌枠の守る線の両立が必要。DFN3の実装や動作はここでは前提にしない。

## 素材と条件

[同意・素材記録](templates/nr-material-consent.md)を先に完成させ、用途、公開可否、期限、元のNR・騒音種、長さと同意証跡を確認する。声や周囲の音について必要な許諾がない素材は使わない。素材・加工音・対応表・回答は権限を限定したリポジトリ外に保管し、音声や個人情報をcommitしない。期限満了・撤回時は原本、派生、盲検コピー、配布先の複製と回答の扱いを同意内容に従って確認し、削除対象・各保管先・実施日・確認者を記録する。匿名化した回答の保管も同意の範囲内に限る。削除を自動化したとは扱わない。

同じ素材・区間で、現行NR OFFと ONの low／high／smart／venue、比較する強度（0.25〜1.25）を事前に決める。発声保護、学習状態・設定、機器、実rate／buffer、入力ゲイン・ch、配線、build、モデルと各設定を記録する。内蔵処理・VSTはNR単独比較ではOFFに揃える。DFN3候補を後に追加する場合も、モデル・版・設定・前処理・同一素材・出力条件と実行方法を記録する。異なる条件を揃えられない場合は比較不能とする。

## 録音と安全

1. 許諾済み素材を仮想ケーブルへ再生し、Auralynの入力として明示選択する。配信・OBS・通話を停止または隔離し、二重取り込み、直接モニター、Windowsの「このデバイスを聴く」、ループバックの経路を確認する。低音量で開始し、意図しない送出がないことを確認する。独立した試聴先もOBS等に取り込まれないと実機で確認する。設定変更は試験用環境で行う。
2. 再生開始点を揃え、同一区間を各条件で再生しボイスチェックで録音・停止する。1回最大30秒なので区間ごとに分割し、前後の余裕と開始点を記録する。rawとprocessedをそれぞれWAVへ書き出す。設定が録音中に変わった、取りこぼした、条件を確認できない録音は採用しない。素材の再生経路そのもののレベル・前処理も固定する。
3. rawは入力チャンネル選択・入力ゲイン後のFX前、processedはFX後・出力ゲイン／全体ミュート前。分離時processedは配信用tapで、自分用モニターやOBS最終ミックスではない。ボイスチェックの書出しは32bit float WAV。現行の同一録音NR候補は current／weaker／stronger で、実行中の設定変更とは別である。これを使う場合は候補の条件と生成方法を別記する。
4. 無加工の原本を残し、長さ・レート・ch・形式を揃えた比較用コピーを用意する。音量差が判断を左右しないよう測定した音量と調整量・方法を記録し、クリップを避ける。ボイスチェック内の任意の音量合わせは試聴時のみの減衰で、WAVを変更しない。NR OFF／ON間の時間差やフィルター位相、音声の変形は完全には補正できない。[時間合わせの限界](NR_TIME_ALIGNMENT.md)を確認し、必要な補正の方法・量と未補正を記録する。自動相関の誤りや切り落としを確認し、合わせられなければ判定不能にする。

## 盲検 A/B（A-5）

条件IDは素材や条件を推測できない英数字IDとする。各聞き手・各対比較につき新しい配布先と対応表を作る。Python標準ライブラリのみ、非圧縮PCMまたは32bit floatのWAVに対応する。同一形式・長さが必要で、音声サンプルを変えず付随チャンクを除去する。サンプル内容自体から条件が推測されることは防げない。

```powershell
python scripts/nr_listening_test.py --first cond1 C:/private/one.wav --second cond2 C:/private/two.wav --listener L01 --seed 123 --output C:/private/distribute-L01 --key C:/private/keys/L01.json
```

両親フォルダを先に用意する。出力と対応表は新規のみで、表を配布フォルダ内に置けない。入力パスは例であり実行ログや回答に記載しない。seedと表は主催者が隔離し、聞き手へ `A.wav`・`B.wav` のみ渡す。同じ入力順・seedは同じ順序を再現する。seedは秘密鍵ではなく、各聞き手で事前に変え、提示順の偏りを確認する。途中失敗では新規出力や対応表が残り得るため配布せず中身を確認し、権限を持つ担当者が処理する。

聞き手は[回答CSV](templates/nr-listening-response.csv)に匿名ID、対比較ID、提示順、声の明瞭さ・欠け・騒音・好みと判断不能の理由を記録する。提示順は例えば AB／BA を事前に割り当て、両方を試聴する。人数・順序・判断不能を集計し、回答確定後に主催者だけが対応表で条件を復元する。対比較の順序や疲労、同じ声を繰り返す影響も記録し、選好だけを音質全般の証明としない。

## 別途必要な検証

- A-7：NR強度・ON/OFF・モード切替の瞬間を実録音し、クリックや無音を確認する。静的なA/Bで代用しない。
- B-1：同じ機器・構成・負荷でHostと子プロセスを含むCPUを測る。[性能比較](NATIVE_PERFORMANCE_COMPARE.md)の方法で版と条件を記録する。
- C-6：開始・切替・失敗時の生音や大音量の誤送出を実経路で確認する。試聴先の分離だけで保証しない。
- I-4：上記同意、保管、期限、派生・配布先と削除確認を検証する。
- 候補をリアルタイム導入する設計では、callbackの無割当・非ブロッキングを維持し、有界worker、世代管理、過負荷・失敗時の停止を別途実装・検証する。オフライン音質や処理時間だけでリアルタイム安全性を判断しない。
