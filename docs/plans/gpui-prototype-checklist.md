# GPUI の試作：右の列の合否判定

`audio-session-controller.md` 13.2（J-11）の分岐点のための試作。main は Tauri の構成のまま保ち、この試作は別のブランチだけに置く。

- 試作：`prototypes/gpui-safety-column/`（GPUI Kit 0.11：`gpui-pre` 0.3.14 と `gpui-component` 0.11）
- 範囲：右の列（緊急ミュート、入力メーターとマイク音量、出力のピーク・一言・出力音量、VSTを外して比較）と、実エンジンにつながるメーター。
- 実エンジンとのつなぎ：本体の `AudioHost` をそのまま使う。通知の出口 `AudioEmitter` に、Tauri 以外の受け口（`AudioHost::set_event_listener`）を1つ足した。通知の順序と回数は変えない。Tauri 版の動きは変わらない。
- 試作で行わないこと：プロファイルの復元、VST の列の復元、入力の元（アプリの音声）の復元、マイク音量・出力音量の保存。音量は 100% から始まる。

## 動かし方（Windows）

```powershell
cd src-tauri
cargo build --bin audio_engine
cd ..\prototypes\gpui-safety-column
cargo run -- --plugin "C:\Program Files\Common Files\VST3\<確認に使うVST>.vst3"
```

- ビルドは `src-tauri/target` を共有する（`.cargo/config.toml`）。`audio_engine.exe` と同じ場所に試作の実行ファイルができるので、親が子を見つけられる。
- Tauri 版の Auralyn は閉じてから起動する（同じ機器と Alt+M を取り合うため）。
- `git worktree` で別の作業ツリーを作ったときは、ignored の `src-tauri\bin` に sidecar（`audio_engine-x86_64-pc-windows-msvc.exe` など）が無く、Tauri の build script が止まる。元の作業ツリーからコピーする。
- ビルド領域は大きい。GPUI 一式（debug と release）で `src-tauri/target` が約 20 GB 増えた（2026-11-25 の実測）。
- 設定は Tauri 版と同じフォルダの `last_audio_config.json` を読む。試作の開始で、このファイルが同じ内容で書き直される。
