# 音声セッションの合格の条件の表

状態：F0 の成果物。実装前の期待値で、動作の証拠ではない。
設計は [audio-session-controller.md](audio-session-controller.md)、旧 API の互換は [audio-session-compat-contract.md](audio-session-compat-contract.md)。

#825 と #806 のレビューで再現された順序と、第1版の設計レビューで足された順序を、すべて行にした。
#806 の「5回のレビュー」は、`codex/music-setup-806-v2` の各コミットの説明と、設計レビューの記載から起こした。コミットごとの対応は H 群の「出どころ」に書く。

## 読み方

- 入力の順序：`→` は受信箱での到着順。`‖` は受付順が前後しうる並行。`t=` は仮想の時計。`A`・`B` は別のストリーム。
- 結果：命令の結果（呼び出し側が受け取る値）。
- 残るストリーム：その順序の最後に、動いているストリーム。
- 終了の原因の ID：終了した接続・ストリームに付く `cause_request`。`—` は付かない（自発の障害・クラッシュ）。
- 通知：「状態」は今の状態（稼働、`Conditions`、VST の一覧、再開の予約）への作用。「履歴」は履歴（`occurrence`）への記録。旧の通知は互換の契約に従い、F1a では今のとおりに出る。
- 保存の差分：`last_audio_config.json` の前後のバイト列の差。「なし」は1バイトも変わらない。
- フェーズ：その行を満たす最初のフェーズ。F1a＝互換の固定と所有の移動、F1b＝新しい契約、R1＝自動の再開の制限、F2＝確認のセッション、F3＝購読の移行。以降のフェーズでも維持する。
