# 本番モードと VST ラックの一体切替案（Issue #151）

> **未実装・未検証の設計案。** 現行アプリは本書の原子性、無音確認、復旧を保証しない。この文書は実装や実機受入の証拠ではない。

## 目的と境界

歌唱・雑談の各モードに、任意でプロファイルの VST カテゴリを関連付ける。登録がないモードは従来どおり内蔵処理だけを切り替える。関連付けがある場合、VST と内蔵処理の片方だけを新しい状態で送出しない。機器、NR、入出力ゲイン、プロファイル内の内蔵処理は適用しない。内蔵処理はモード定義の値を使う。

一時的な無音とロード時間が発生する。切替中・復旧中・失敗・手動対応待ちを画面に示し、ホットキーと OBS シーン連動でも同じ Host 側の切替を使う。外部 VST の状態復元・音質・待ち時間はプラグイン依存であり、機器を使わない試験だけでは保証できない。

## 現行コードと、この案を安全とみなせない理由

- [`audio/live_modes.rs`](../../src-tauri/src/audio/live_modes.rs) の `AudioHost::live_modes` は選択・意図・世代を扱い、[`shortcuts.rs`](../../src-tauri/src/shortcuts.rs) のホットキーもここへ入る。OBS のモード連動は [`useLiveSceneRouting.ts`](../../src/hooks/useLiveSceneRouting.ts) から同じ Host コマンドへ入る。一方 `sync_live_modes` は Engine に直接モード復元を送るため、再起動・再同期も新契約に合わせる必要がある。
- [`audio_engine/live_modes.rs`](../../src-tauri/src/audio_engine/live_modes.rs) の定義は内蔵設定のみで未知フィールドを拒否し、`queued`・`transitioning`・`settled` は内蔵処理の状態である。現状の `settled` は VST の適用完了を意味しない。保存形式・IPC・旧データ互換性と状態表示の変更が必要。
- [`profile.rs`](../../src-tauri/src/profile.rs) の既存適用は機器・NR・内蔵処理も扱い、空の `plugins` はラック変更なしである。[`profile/plugin_chain.rs`](../../src-tauri/src/profile/plugin_chain.rs) は復元失敗を欠落として記録して先へ進む。これは部分適用の報告には使えるが、一体切替の全件成功保証ではない。バックアップには呼び出し元から渡された状態を使う。
- [`audio/session_rack.rs`](../../src-tauri/src/audio/session_rack.rs) の Begin は空ラックの復元向けで、ゲインも設定する。[`audio_engine/core/session_rack.rs`](../../src-tauri/src/audio_engine/core/session_rack.rs) のラック情報には VST 内部 state がない。復旧には全インスタンスの state を取得し、取得前後のラック revision と順序を照合する必要がある。
- [`audio_engine/core.rs`](../../src-tauri/src/audio_engine/core.rs) の `SetGlobalMute` 成功応答は、音声コールバックへの通知をキューした時点で返る。実際に無音へ反映済みの確認ではない。出力キューや分岐経路に残る音も含め、切替前後の世代を隔離する仕組みと確認が要る。
- 現行の本番保護はラック置換を拒否する。復元予約は他操作を制限するが、一体切替の安全性や完了を保証しない。長時間 Host の mutex を保持すると停止・緊急ミュート・状態取得も待たせるため、それだけを排他制御に使わない。

## 採用予定の契約

### 登録と互換性

- 各モードに任意のプロファイル参照と、その VST 内容の revision（内容を識別できる値）を保存する。既存保存データの未指定は従来動作とする。既存の名前だけを同一内容の証明にしない。
- VST カテゴリが明示された空ラックは「全 VST を外す」とする。カテゴリ未指定は「ラックを変更しない」。現行の `Preset` は両者を区別できないため、新しい明示的なカテゴリ表現と互換移行が必要。旧データの空配列は従来の「変更なし」として扱い、自動で空ラックと解釈しない。
- 登録後にプロファイルが削除または内容変更された場合、古い参照を自動適用せず再確認を求める。保存時と適用開始時に対象の存在・内容を検証し、適用中は検証済みの内容を固定する。
- 保存・切替 API と snapshot の拡張は旧データと旧呼び出しの動作を維持し、Engine の内蔵処理定義に VST ファイルの操作責務を混ぜない。

### Host 側の一体切替

1. 共通入口でプロファイル内容・モード定義・世代を検証し、切替予約を確保する。UI、ホットキー、OBS に個別の連続 apply を実装しない。実行中は状態を取得でき、停止と緊急ミュートを優先できるようにする。
2. 元のミュート意図、内蔵設定、ラック順序・各 VST の状態・有効／ミュート／ゲインを取得する。ラック revision・Engine 世代が途中で変われば破棄する。取得できない state を成功扱いしない。変更前に、復旧用原本と操作識別子・段階をディスクへ安全に記録し、書込み失敗なら切替を始めない。
3. 切替用の無音を要求し、対象 Engine 世代と送出経路に紐付く RT 適用 ACK を確認する。切替前の出力バッファ・キューが新しい送出に混入しないよう送出世代を隔離する。ACK 欠落・世代変更・経路異常ではラックを変更せず、成功としない。
4. 無音中に旧ラックを外し、検証済み VST を順番と状態を含め全件復元する。1件でも失敗・不明なら部分成功としない。次に内蔵設定を要求し、同一世代・同一 revision の完了を確認する。
5. ラックと内蔵処理の両方が確定した場合だけコミットし、元のミュート意図を維持して無音を解除する。切替前からミュート中ならミュートを維持する。切替中の利用者の緊急ミュートは解除しない。各段階で世代・予約・中断を検証し、古い応答で完了や解除を行わない。
6. 途中失敗時は無音を維持し、ディスク上の原本から元ラックと元の内蔵設定を復元して両方の完了を確認する。復元を確認できない、応答が不明、Engine が交代した場合はミュートを維持し、失敗と手動復旧手順を表示する。後から届く成功応答で自動解除しない。

途中の停止と緊急ミュートは常に優先する。停止後の古い処理は再起動や再ミュート解除を行わない。切替中の通常の新しいモード要求は明示的に拒否し、利用者が完了後に再試行する。保存・通常のラック編集なども予約中は拒否する。緊急ミュートの意図は一時的な切替用無音と別に管理する。

ディスク上に未完了 journal がある起動時は、復旧または送出を自動再開しない。状態不明として通知し、ミュートを保持して利用者が内容を確認し復旧できる導線を設ける。原本や journal の保存・置換の耐障害性、権限、サイズ上限、保管期間と安全な消去条件は実装時に定め、途中で失われた場合も成功扱いしない。

本番保護中の VST 切替は既定で拒否する。許可する拡張を行う場合も、対象プロファイルの内容と無音・失敗時の挙動を事前に明示し、利用者の明示許可を得た対象だけに限定する。既存の保護を一般的に迂回しない。

## 受入テスト

- 旧定義を読み込み、未指定モードで従来の内蔵切替と旧 IPC を維持する。VST カテゴリの不在・明示空・非空を区別し、旧空配列が勝手に全削除とならない。
- UI・ホットキー・OBS の各入口が同じ Host トランザクションへ到達し、同じ結果と状態を示す。保存済みプロファイルの変更・削除・同名置換を検知し、再確認前に適用しない。
- 元ラックと内蔵設定の取得、原本のディスク書込み、無音要求、RT ACK、各 VST 復元、内蔵完了、コミット、無音解除の各段階に失敗・遅延・応答不明を注入する。無音 ACK 前にラックを変更せず、全件と内蔵完了前に送出しない。VST の一部欠落や復旧不完全を成功にしない。
- RT ACK と出力世代隔離を、遅延・満杯のキュー、旧世代の遅い音、複数送出経路、Engine 停止／交代で検証する。古い応答は解除・成功に使わない。RT callback の無割当・非ブロッキング契約を維持する。
- 元がミュート中の場合、新しい緊急ミュートが切替中に来た場合、停止・プロセス異常・再起動が各段階で起きた場合に、勝手に音を再開しない。通常の競合要求を拒否し、状態表示と停止・緊急ミュートが長時間ロックで塞がれない。
- 途中終了・破損・書込み失敗・不完全 journal を再起動時に注入し、自動再開せず、復旧不能ならミュートと手動対応状態を維持する。旧原本を上書きして失わない。
- 自動試験に加え、実 Tauri・実 sidecar と複数の実 VST で状態復元、実出力の無音区間と旧音混入、失敗時の復旧、キーボード操作・状態表示を確認する。使用デバイス、ホスト、サンプルレート、バッファ、VST と送出経路を記録する。OBS 連動は実 OBS でも別途確認する。実機未実施なら未検証として扱う。

## 最小実装順序

1. データ形式・互換性、明示空ラック、内容 revision、保護時の扱い、journal と復旧 UI の契約を確定する。
2. Engine に世代付き無音 ACK と出力世代隔離を追加し、キュー・異常・RT 制約を試験する。
3. Host にラック完全取得・ディスク原本・復旧可能な状態機械を追加し、各段階の失敗と中断を注入する。既存プロファイルの部分適用経路とは区別する。
4. 共通モード入口と再同期を接続し、旧データ・保護・UI／ホットキー／OBS の同一契約を検証する。
5. 任意参照の登録と状態・復旧導線を UI に追加し、ローカル検証後に実機条件を記録して確認する。
