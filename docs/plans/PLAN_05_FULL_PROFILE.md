# プラン5: フルプロファイル保存

## 目的

マイク（入力デバイス）/ 出力先 / AI ノイズ設定 / 内蔵エフェクト / VST チェーンを
**1 つの「プロファイル」として一括保存**し、配信環境をワンクリックで切り替えられるようにする。
（例: 「雑談配信」「ゲーム配信」「会議」「ゲーセン持ち込み」）

## 現状の確認結果

保存対象が現在バラバラに永続化されている:

| 設定 | 現在の保存先 | 現行プリセットに含まれる? |
|------|-------------|------------------------|
| VST チェーン + state chunk | `%APPDATA%/.../presets/*.json` + localStorage セッション | ✅ |
| オーディオデバイス設定 | localStorage `vst_host_audio_config` + `last_audio_config.json` | ❌ |
| AI ノイズ設定（モード/強度/学習プロファイル） | エンジン内 + 一部 localStorage | ❌ |
| 内蔵ボイス FX | localStorage | ❌ |
| 入出力ゲイン・入力チャンネル | localStorage | ❌ |

## 設計方針

### スキーマ: 既存プリセットの v2 拡張（新形式を作らない）

`.auralyn-preset.json` を後方互換のまま拡張する:

```jsonc
{
  "schemaVersion": 2,          // v1 は未定義（=1 扱い）
  "name": "ゲーム配信",
  "plugins": [ /* 既存 v1 と同一 */ ],
  "audioConfig": {             // 追加（任意）
    "host": "WASAPI", "inputDevice": "...", "outputDevice": "...",
    "sampleRate": 48000, "bufferSize": 512,
    "inputChannels": [0, 1], "inputGainDb": 0, "masterGainDb": 0
  },
  "noiseControl": {            // 追加（任意）
    "enabled": true, "mode": "smart", "mix": 0.8, "voiceGuard": true,
    "learnedProfile": { /* NoiseProfile。任意 */ }
  },
  "builtinFx": { "preset": "broadcast", "enabled": true }   // 追加（任意）
}
```

- v1 ファイルの読み込みは従来どおり（追加フィールド欠落 = そのカテゴリを変更しない）。
- 保存時にカテゴリ別チェックボックス（「デバイス設定も含める」等）を用意し、
  **デバイス設定を含めない共有用プリセット**も作れるようにする
  （他人の PC にデバイス名を持ち込むと必ず不一致になるため）。

### 適用（ロード）時の挙動

1. デバイス設定が含まれる場合: 現在の構成と差分があればエンジン再起動を伴う旨を表示して適用。
   **デバイスが見つからない場合は名前を表示して代替選択を促す**（黙って無視しない）。
2. VST が見つからない場合: 既存のプリセット読込と同じ扱い（スキップ + 警告）。
3. ノイズ/内蔵 FX/ゲイン: IPC で即時適用。
4. 適用結果サマリ（「3/4 カテゴリを適用。出力デバイスが見つかりませんでした」）を表示。

### 切替 UX

- `PresetManagerModal` を「プロファイル」概念に改称・拡張:
  - 一覧に含有カテゴリのアイコン表示（🎛 VST / 🎤 デバイス / 🤖 ノイズ / ✨ FX）
  - 「現在の全設定から作成」ボタン
  - ワンクリック適用 + 適用前の現状自動バックアップ（「直前の状態に戻す」）
- 将来拡張（本プラン外）: ヘッダーのクイック切替ドロップダウン、
  OBS シーン連動切替（既存 `obs.rs` のシーンイベントと接続可能）。

### 実装箇所

- `src-tauri/src/vst_host/presets.rs`: スキーマ v2、シリアライズ/デシリアライズ、
  バージョンマイグレーション。
- `src-tauri/src/audio.rs` / `lib.rs`: プロファイル適用コマンド
  （デバイス変更を含む場合の再起動オーケストレーション。既存 restart 経路を再利用）。
- `src/api/presets.ts`: 型拡張 + `saveProfile(categories)` / `applyProfile(name)`。
- `src/hooks/useAudioConfig.ts` / `usePlugins.ts`: プロファイル適用時の状態同期。
- `src/components/features/PresetManager/`: UI 改修。

## テスト

- Rust: v1→v2 読込互換、欠落フィールド、未知フィールド無視のユニットテスト。
- `presets` API のフロントテスト追加（現状テストなし）。
- 手動: デバイス取り外し状態での適用、ASIO⇔WASAPI をまたぐ切替。

## リスク・注意点

- デバイス変更を伴う切替はエンジン再起動で 1〜2 秒の無音が出る → 適用前に明示。
- localStorage と Rust 側 JSON の二重管理が複雑化の元 →
  プロファイル適用時は **Rust 側を正としてフロントに反映**する一方向フローに統一する。
- ノイズ学習プロファイル（環境依存）を含めるかは保存時に選択制（既定 OFF が無難）。
