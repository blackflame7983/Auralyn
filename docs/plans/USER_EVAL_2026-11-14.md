# 利用者目線の画面評価の対応計画（#561）

2026-11-14 の評価（main `404b41fc`）で登録した #539〜#560 を、7つの段階に分けて直す。評価の点数と指摘の一覧は #561 にある。

## 1. 進め方

- 1段階を1つの PR にする。PR は積み上げず、前の段階が main に入ってから、次のブランチを main から作る。
- 設計・依頼文・結果の確認は Claude が行い、実装は Grok 4.7 High に任せる。
- CI が通ったら順にマージする（2026-11-14 に利用者の了解を得た）。
- 音声エンジン、IPC、音声コールバックは変えない。ただし段階 6（#557）は、VST を探す処理（Tauri の本体の `scan_*` コマンドと `vst_host/scanner.rs`）だけを変える。音声エンジンのサイドカーと音声コールバックには触れない。
- 新しい購読・タイマーを足さない。いまのメーターの値・統計・既存の API の範囲で作る（2026-11-14 の利用者の判断：#555 と #541 も既存の仕組みの範囲で実装する）。
- 各段階で、`docs/DESIGN.md` の該当箇所、`user-docs/`（ja・en）、アプリ内の「使い方」を同じ PR で直す。
- 文言キーの規則（`DESIGN_RENEWAL_IMPLEMENTATION.md` 3.7）と、`uiConsistency.test.ts` の上限を守る。

### 調べて分かったこと（2026-11-14）

- **#544**：セットアップの「設定を保存して開始」は、`useSetupWizard.ts` の `finalApply` で必ず `audioApi.start` を呼んでから保存する。評価で停止のままに見えたのは、模擬データ（`?mock=first-run`）の応答による可能性が高い。コードは変えず、#560 で実機で確かめる。
- **#548**：`SoundSettings.tsx` は、ノイズ低減のモードを自分の状態として持ち、初期値が `'smart'`。エンジンの統計が届くまで、弱・強のどちらも選ばれず「詳細で調整中」と出る。ホーム（`VoiceQuickControls.tsx`）は、統計がないとき `'low'` を仮に選ぶ。どちらも、まだ分からない状態を別の値として見せている。
- **#549**：ホームの声の整え具合のスライダーは、OFF のとき無効になっている（評価の記述は誤り）。一方、ホームの声の種類（配信・低め・明瞭）は OFF でも押せ、押すと ON になる。音づくりでは、声を整える機能は OFF のとき全部無効、ノイズ低減は OFF でも変えられる。
- **#550**：「追加」は、配信・通話の用途で、統計が有効で、VST が0個のときだけ出る。音楽鑑賞と、統計がないとき（停止中など）は「VSTを編集」になる。
- **#553**：セットアップには音楽鑑賞の目的（`goal: 'music'`）がすでにある。ただし最初の画面に出ず、「自分で聴く」のあとのマイクの手順で「PCの音」を選んだときだけ選ばれる。
- **#554**：「ホームの表示」（`auralyn_display_purpose`）は表示だけを切り替える。「入力の用途」（プロセス入力の `purpose`）はエンジンに渡り、音楽ではノイズ低減を止め、声の測定を受け付けない。2つは連動していない。
- **#555**：保存した VST の構成は、`presetApi.list()` と `pluginsApi.loadPreset(name)` で、新しい IPC なしで切り替えられる（OBS のシーン連動が同じ方法を使っている）。加工なしとの比較は `audioApi.setGlobalBypass`（右の列の「VSTを外して比較」と同じ）。
- **#556**：音楽鑑賞では、音づくりが「音量の保護」だけになり、配信用 true-peak 制限も同じく出る。
- **#557**：VST を探す場所は `scanner.rs` の `default_roots()` に固定。VST3 だけに対応し、VST2 には対応しない。

## 3. 段階 1：状態の表示と決まりをそろえる

- **#548**：ノイズ低減のモードを、統計から読む関数を1つにし、ホームと音づくりで使う。
  - 値は、小文字にそろえた `'low' | 'high' | 'smart' | 'venue'`。統計がない・知らない値のときは「不明」とする。
  - 不明のときは、弱・強のどちらも選ばず、「詳細で調整中」も出さない。
  - 音づくりで利用者が選んだ直後は、統計が届くまでその選択を見せてよい。
- **#549**：OFF のときの決まりを「OFF でも強さ・種類・整え具合を選べる。選んでも ON にはならず、音には反映しない」にそろえる。
  - ノイズ低減は、いまこの決まり。
  - 声を整える機能（ホームの声の種類と整え具合、音づくりの種類と整え具合）も、この決まりにする。
  - 既存の `builtinApi` で、OFF のまま種類と整え具合を保存できるかを、最初に確かめる。できない場合は止めて、Claude に報告する（決まりを「OFF のときは選べない」に変えるかは、Claude が判断する）。
  - 説明の文（`settings.fxOffHint`、`settings.noiseOffHint`）を、同じ決まりの文にそろえる。
- **#550**：VST が0個と分かっているときは、用途と状態にかかわらず「追加」にする。
  - 個数は、統計がなくても、画面側の VST の一覧から分かる。
  - 個数が分からないときだけ、「VSTを開く」にする（「編集」は使わない）。
  - 「追加」から開いたときは、いまどおり「VSTを追加」へ焦点を移す。
- **#545**：右の列の札（出力のミュートなど）を、212px の列で全文が読めるようにする。折り返すか、意味を保ったまま短い語にする。
- **#556**：音楽鑑賞では、配信用 true-peak 制限の区画を出さない。ただし、すでに ON のときは出し、OFF にできるようにする。

完了の条件：

1. ホームと音づくりで、ノイズ低減と声を整える機能の表示と決まりが一致する（`?mock=live-home` と、統計がないとき）。
2. VST が0個のとき、配信・音楽鑑賞・停止中のどれでも「追加」になる。
3. 右の列の札が、960×640 と 1024×768 で切れない。
4. 音楽鑑賞で、OFF の true-peak 制限が出ない。
5. 試験を足す：モードの読み取りの単体試験、ホームと音づくりの一致の DOM 試験、VST のボタンの名前の DOM 試験。

## 4. 段階 2：名前・見出し・重複を整理する

- **#546**：確かめる機能の名前を、何を確かめるかで分ける。
  - 録音して加工の前後を聴く：「ボイスチェック」（変えない）。
  - 声の流れの音量を測る：「音量チェック」→「音量を測る」。
  - 接続の区画の見出し：「音声チェック」→「接続の確認」。
  - 入口・開いた画面の見出し・ヘルプ・日英で同じ名前にする。英語も同じ考え方で分ける。
- **#547**：音楽鑑賞の上の帯の「聴き比べ」を「再生の確認」にする。開く案内の中に、「VSTを外して聴き比べる」操作を置く。右の列の「VSTを外して比較」と同じ状態を使う（`setGlobalBypass`）。
- **#542**：見出しの形をそろえる。
  - ページの見出しと説明の一文は、接続・音づくり・VST・設定で同じ部品と置き方にする。
  - 接続のページの区画の見出しを、ほかのページの区画と同じ形にする。`fieldset` と `legend` の意味は保ち、見た目だけそろえる。
  - 音づくりで、タブ名と同じ見出し（「基本」の下の「基本」）を重ねない。
  - 歌・雑談の「モード登録」の下の、ⓘ だけの行をなくす。説明が要るなら見出しの横に置く。
  - ヘルプのメニューで、「ガイド & ヘルプ」の見出しの下に「使い方」を置く。
- **#543**：セットアップの確認の手順から、「入力を選び直す」「出力先を選び直す」を外す。戻るのは左の手順の一覧と「戻る」で行う。完了の画面のボタンの間隔を、ほかのダイアログと同じにする。
- **#558**：VST を追加の画面で、検索欄の横の更新ボタンに文字を付けて「更新」にし、「すべて再スキャン」と役目が分かるようにする。件数の行（`pluginBrowser.scanStats`）は「スキャンの詳細」の折りたたみへ移す。
- **#559**：ボイスチェックで、録音と、加工の前後を聴く操作を先に置く。試聴の準備の失敗と、再生できないときの説明は、失敗したときだけ出す。試聴先の注意は折りたたむ。

完了の条件：

1. 「チェック」の付く名前が、役目ごとに1つずつになり、日英とヘルプで一致する。
2. 音楽鑑賞の「再生の確認」から、VST を外した比較に1回で届く。
3. 4つのページの見出しの形が同じになる（ブラウザの試験で、見出しの要素と位置を確かめる）。
4. 960×640 で、ボイスチェックの録音の操作にスクロールなしで届く。

## 5. 段階 3：音量の保護を分かりやすくする（#551）

- 大きな音を抑える機能と、配信用 true-peak 制限のそれぞれで、ON と OFF を見出しの横の1つのスイッチにする。
- 区画の最初に、何を防ぐか（突然の大きな音で耳や配信を傷めない）を一文で書く。
- 天井（dBFS）と復帰時間（ms）は「詳しい設定」の折りたたみへ移す。「数値の詳細を表示」が ON のときは、開いた状態にする。
- 値を変えたあと適用が要るという決まり（`SETTINGS_APPLY_RULES.md`）は変えない。スイッチで ON にしたときは、いまの値で適用する。

完了の条件：ON と OFF の操作が1つになる。数値を開かなくても使える。いまの保存値と適用の決まりが変わらない。

## 6. 段階 4：ホームで、いまの状態がひと目で分かるようにする（#539、#540、#552）

- **#539・#552**：ホームの一番上のカードを「いまの状態」のカードにする。
  - 配信・通話：小さな札「モード」と名前（歌・雑談・いまの調整）、声が届いているか（入力のメーターの状態）、配信へ送っている音の大きさ（出力のメーター）、ミュートかどうか。
  - 音楽鑑賞：再生元 → 出力、音が来ているか、出力の音の大きさ。
  - 音の大きさは、既存のメーターの値（`useSharedMeter`）と部品で横長に出す。2秒で読み取れる大きさにする。新しい購読やタイマーは足さない。
  - 音声を開始、送り先を選ぶ、開始の失敗の知らせは、いまどおり置く。
- **#540**：声の流れで、メーターの状態（`waiting`・`silent`・`stale`・`stopped`）のときは、波形の場所に文字で状態を出す（既存の `meterStatusLabel` の文言を使う）。`live` のときだけ波形を描く。
- 960×640 で、いまのカードの高さを増やしすぎない（音調整の1段目が窓の中に収まる）。

完了の条件：配信と音楽鑑賞で、カードに状態と音の大きさが出る。無音・待機・停止で、声の流れに文字が出る。960×640・1024×768・1920×1080 で崩れない。

## 7. 段階 5：音楽鑑賞を選べ、使える形にする（#553、#554、#555）

- **#553**：セットアップの最初の画面に「音楽を聴く（PCの音にVSTをかける）」を足し、`goal: 'music'` を選ぶ。
  - 「自分で聴く」と音楽鑑賞のときは、確認の手順の「セットアップ後の使い方」と完了の画面に、配信・受け側の文を出さない。
- **#554**：用途の切り替えを、外観から接続のページの先頭（「使い方」）へ移す。
  - 設定の外観には、移った先への案内を1行だけ残す。
  - 音楽鑑賞を選んで、入力がプロセス入力のときは、入力の用途も音楽にするかを、その場で聞く（自動では変えない）。
  - 保存のキー（`auralyn_display_purpose`）と値は変えない。
- **#555**：音楽鑑賞のホームに置く。
  - 保存した VST の構成の切り替え（`presetApi.list()` と `pluginsApi.loadPreset`）。構成がないときは、VST のページの保存への案内。
  - 「VSTを外して聴き比べる」（`setGlobalBypass`、右の列と同じ状態）。
  - 再生の状態：接続方式・周波数（保存済みの音声設定から）。
  - 新しい IPC と保存の形式を足さない。切り替え中は操作を止め、失敗したら理由を出す。

完了の条件：セットアップの最初から音楽鑑賞を選べる。用途は接続のページの先頭で切り替えられる。音楽鑑賞のホームから、構成の切り替えと聴き比べに1回で届く。

## 8. 段階 6：VST を探すフォルダーを足せるようにする（#557）

- VST を追加の画面に「探すフォルダー」の区画を置き、フォルダーを足す・外す。標準の2つは外せない。
- 足したフォルダーは画面側で保存し、スキャンのコマンドに引数として渡す。Rust 側で、存在するフォルダーか、ディレクトリーか、正規化したパスかを確かめ、重複を除く。
- 見つからないフォルダーは、スキャンを止めずに一覧で知らせる。
- 対応は VST3 だけであることを、区画の説明に書く。
- `cargo` の確認（`docs/BUILD_GUIDE.md`）を足す。音声エンジンのサイドカーと音声コールバックには触れない。

完了の条件：足したフォルダーの VST3 が一覧に出る。再起動後も残る。不正なパスで落ちない。Rust の単体試験がある。

## 9. 段階 7：押したときの手応えを決めて入れる（#541）

- `docs/DESIGN.md` に、押す・切り替える・保存する・声が入るときの反応を決める。
- 共通部品（Button、Switch、SegmentedControl）にだけ入れる。押している間はわずかに沈み、切り替えはつまみが滑る、など。時間は既存の `--motion-*` を使う。
- 動きを減らす設定では、動きを止める（色の変化だけにする）。
- 音声と描画の負荷が増えないことを、ブラウザで確かめる。

完了の条件：決まりが文書にあり、3つの部品に入り、動きを減らす設定で止まる。

## 10. 確かめ方（全段階で同じ）

`DESIGN_RENEWAL_IMPLEMENTATION.md` 3.6 の8つと、`npx vite build` のあとの `E2E_PREVIEW=1 npm run test:e2e` を実行し、結果を PR に貼る。段階 6 は `cargo` の確認を足す。画面は `docs/verification/user-eval-<段階>/` に、変えた画面を代表の大きさで撮る（8枚前後まで）。
