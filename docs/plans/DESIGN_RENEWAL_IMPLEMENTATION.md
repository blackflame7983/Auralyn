# デザイン刷新の実装計画（2026-11-12 作成）

[DESIGN.md](../DESIGN.md) 10章の規則を、製品の画面へ段階的に実装する計画です。
この文書は計画であり、実装済みや検証済みの証拠ではありません。

- 規則の正本：`docs/DESIGN.md` 10章
- 経緯と試作：[DESIGN_RENEWAL_2026-11-12.md](../DESIGN_RENEWAL_2026-11-12.md)、`?proto=g2`（開発時だけ）
- 設定項目の置き場所：[settings-inventory.md](../verification/design-renewal-2026-11-12/settings-inventory.md)

## 1. 進め方

- 1段階を1つの PR にする。PR は積み上げず、前の段階が main に入ってから次のブランチを main から作る。
- 設計と依頼文、結果の確認と、実装は、担当を分ける。どの道具に任せるかは利用者の指示に従い、この文書には固定しない。
- 各段階で、規則と食い違う既存の節（`DESIGN.md` 10.11 の表）と、利用者向けドキュメントの該当箇所を同じ PR で直す。
- 音声エンジン、IPC、音声コールバックは変えない。変える必要が出たら、その段階を止めて相談する。
- 試作（`src/prototypes/`）は見本として読む。製品へコピーせず、既存の共通部品（Button、SegmentedControl、Slider など）とトークンで作る。試作のクラス名（`oa-*`、`rn-*`）を製品へ持ち込まない。

**前提**：ブランチ `codex/design-renewal-2026-11-12`（規約と試作）が main に入っていること。

**レールを最初にしない理由**：現行のホームは、音調整の3連モジュールが、音調整の内側の幅で1列に切り替わる。レール（76px）と右の列（212px）を同時に入れると、中央が大きく狭まり、既定の 1024×768 でも3列の余裕がほとんどなくなる。そのため、ホームを先に刷新してから（B）、レールを入れる（C）。

**段階 A の実装で分かったこと（2026-11-12）**：切り替えの境目は、文書では780pxと書かれていたが、実装は内側の幅720pxだった。右の列を入れると、配信・通話の最小 960×640 で内側の幅が666pxになり、1列に切り替わって3つ目が画面の下へ回った。段階 A で境目を660pxに下げ、最小サイズでも3列を保つようにした。この境目のまま C でレールを入れると、1024×768 の内側の幅は約664pxで、余裕は4pxしかない。C の前に B でホームを刷新する順は変えない。

**段階 A で残した点**：幅1200px以上で右パネルをホームの横に並べる境目は変えていない。右の列の分、幅1200〜1411pxでパネルを開くと中央が以前より212px狭く、幅1222〜1374pxでは音調整が1列になる。境目を1412pxへ上げるか、右パネルがなくなる段階 F まで残すかは、利用者の判断を待つ。

**段階 A で残した点の扱い（2026-11-13 決定）**：右パネルを横に並べる境目は1200pxのまま変えず、右パネルをなくす段階 F で解消する。B では、右パネルを開いたときの中央の幅も、新しいカードの構成で確かめる。

### 3.2 配置

- `AppShell.tsx` の `.workspace-body`（ホームと右パネルを入れている行）の右隣に、`<aside aria-label="本番中の操作">` を置く。ヘッダーの直下から窓の下端まで。通知の行は中央の列の中に置き、通知が出ても右の列を動かさない（最初の計画では「通知の行の下」としていたが、緊急ミュートを押すと出る通知で列が下へ動くため、PR 前のレビューを受けて直した）。
- 幅は212pxで固定する。背景は `card`、左に境界線1本。
- 右パネルの重ね表示と暗幕は、これまでどおり中央の作業領域だけを覆う。右の列は覆わず、操作できるままにする。
- 列の中は上から、緊急ミュート、出力（メーターを出す条件のときはメーター、出力音量）、VST を外して比較、余白、状態の表示と詳細の入口。
- 列は縦にスクロールさせない。用途別の最小サイズ（配信・通話 960×640、音楽鑑賞 900×600）で、全部が見えること。
- 出力音量は、ラベルと値の行、スライダーの行の2行に組み替える。「100%へ戻す」と再試行、ミュート中の出力確認の入口は残す。
- 広い窓で中央へ寄せる計算（`index.css` の `.workspace-body` の `max-width`）は、右の列の幅を足して直す。右の列は窓の右端に付ける。

### 3.5 完了の条件

1. 緊急ミュート、出力音量、VST を外して比較が右の列にあり、同じ操作がほかの場所にない。
2. フッターがない。
3. 960×640、900×600（音楽鑑賞）、1024×768、1920×1080 で、右の列の全操作が画面内に見え、文字の切れ・重なりがない。
4. 右パネルを重ねて開いた状態で、右の列の3操作が押せる。
5. 緊急ミュートのホットキー、比較のホットキー、出力音量へのフォーカス移動が、移動前と同じに動く。
6. 3テーマ（オーロラ、ライト、ゲーミング）で、文字4.5:1、状態の目印3:1 を保つ。
7. Tab の順が、ヘッダー → 中央 → 右の列、または合理的に説明できる順になっている。順を PR の説明に書く。

- Rust は変えないので、`cargo` の確認は不要。変えた場合は `docs/BUILD_GUIDE.md` の手順を足す。
- 画面は、開発プレビュー（`?mock=live-home`、`stopped-home`、`first-run`）のスクリーンショットを、完了の条件3の4サイズ × 3テーマのうち代表で撮る。保存先は `docs/verification/` の下に段階ごとのフォルダーを作る。
- 実機（Tauri）の確認は Claude か利用者が行う。**起動すると保存済みの設定で音声処理が自動で始まる**（2026-11-12 に確認）ので、利用者の了解を取ってから、時間を短くして行う。

### 4.2 配置

**いまの状態**（`section`、名前は「いまの状態」）

- 上から、送り先（小さく）、状態の札、見出し、主ボタン、歌／雑談の切替。
- 状態の札は「実行中／音声停止中／音声未設定」（10.3）。札はこの1か所にし、停止中に同じ文言をホームのほかの場所へ重ねない。`HomePanels` の状態文は、札が出ている間は出さない。
- 見出しは、配信・通話ではいまのモード名（未登録は「カスタム」）、音楽鑑賞では出力の機器名（取れないときは「音楽鑑賞」）。
- 主ボタンは、停止中で開始できるときの「音声を開始」、実行中で送り先が未設定のときの「送り先を選ぶ」の、どちらか1つだけ。
- 未設定のときは、この区画を出さず、いまの `UnsetFlow` を先頭に置く。

**音の流れの帯**（`section`、名前は配信・通話で「声の流れ」、音楽鑑賞で「音の流れ」）

- 加工前（入力メーター）と加工後（出力メーター）の音量を、時間の流れで重ねて描く。加工後をオーロラの色、加工前を中立の色にし、凡例の文字を添える。
- 値は `MeterProvider` の共有の読み取り（`useSharedMeter`）だけを使う。新しい IPC・購読・タイマーを作らない。読み取りが変わったときに直近の値を記録して描く。
- 画面が隠れている間は描かない（共有の読み取りが止まる）。動きを減らす設定では、時間の流れを描かず、いまの値だけを静止した形で示す。
- 高さは 72〜120px を目安に、主役の大きさにしない。停止中と未設定では値を描かず、帯の枠と凡例だけにする（状態の文言は重ねない）。
- 見出しの行の右に、音量チェックの入口を置く。押したあとの `LoudnessCheck` の位置と動作は変えない。

**音調整の3枚のカード**

- 見出し「音調整」（音楽鑑賞は「音を整える」）と、ボイスチェック、その他のメニューは、いまの音調整の見出しの行のまま。
- カードは開閉しない。どのカードも、見出しの行（アイコン・名前・状態の点と一言・右端の ON/OFF）と、本体でできている。押すと開く段（`aria-expanded`）、アークゲージ、段をつなぐ信号の線はなくす。

| カード | 1段目（常に出す） | 2段目（`data-home-tier="2"`） |
| :--- | :--- | :--- |
| ノイズ低減 | ON/OFF、強さ（弱・強）。学習・会場のときはその旨の一言 | なし（周囲の音の測定は H） |
| 声を整える | ON/OFF、音色の形、整え具合のスライダーと割合 | 声の種類（配信・あたたかい・明るい） |
| VST | 各 VST の ON/OFF、「VST を編集」または「VST を追加」 | 各 VST の画面を開く |

- 2段目は B では常に出す。窓が低いときに隠すのは H で行う。2段目を区画として分けておき、H で出し分けやすくする。
- 「声を整える」の割合は、スライダーの名前と同じ語（整え具合）で示し、音色の形は「整え具合に合わせた形の目安」であることを、図の読み上げ名と見出しで示す（#517）。効果や音質を保証する語は使わない。
- 音楽鑑賞では、ノイズ低減と声を整えるのカードを出さない（2.7 を維持）。声向けの処理が ON のままのときの注意の一行は残す。
- 1列への切り替えの境目は、新しいカードの中身が収まる幅で決め直す。配信・通話の最小 960×640 と既定の 1024×768 では3列にする。C でレール（76px）が入る分を見込み、中央の内側の幅が約590pxでも3列を保てるかを試算し、結果を PR に書く。

## 6. 段階 D：接続のページと、設定をページにする（#524）

### 6.1 目的と範囲

設定のモーダル（`AudioSettingsModal`、6区分）をなくし、中身を中央のページとして開く（10.4、10.9）。ページを開いている間も、レール・上の帯・右の列は操作できる。

| いまの区分 | D のあと | 中身 |
| :--- | :--- | :--- |
| オーディオ | レール「接続」のページ | いまのまま（入力、出力、接続方式と音切れ、入出力プリセット、保存して開始／再起動）。並びは 6.2 |
| 音づくり | レール「音づくり」のページ | いまのまま。4つの小区分への組み直しは E（#525） |
| 外観・ホットキー・OBS連携・システム | レール「設定」のページの4つの区分 | いまのまま。区分の順は 外観 → ホットキー → OBS連携 → システム（10.4） |

D で動かさないもの：右の列、レール（行き先の判定を「モーダルの区分」から「ページ」に替えるだけ）、上の帯、ホーム、VST 構成（右パネルのまま。F で扱う）、音づくりの中身の並び（E）、セットアップ、ボイスチェック、OBS・Discord の案内（#506 は刷新の後に単独で扱う）。

### 6.2 配置

**ページの切り替え**

- `useUIState` に「いまのページ」（`home`・`sound`・`connect`・`settings`）と、設定の区分（`appearance`・`shortcuts`・`obs`・`system`）を持たせる。いまの `setIsSettingsOpen(open, tab)`、`openObsSettings`、`openSoundSettings`、`openDeviceSettings`、`openAudioSettingsRetry`、`openShortcuts` などの呼び出し元は、同じ名前のまま、対応するページと区分を開くようにする（`audio`→接続、`sound`→音づくり、それ以外→設定の該当区分）。`openDeviceSettings` の入力・出力への移動、`openSoundSettings` の小区分への移動もそのまま効かせる。
- ページは中央の列で、ホームの代わりに出す（上の帯の下）。ホームの中身は、ページを開いている間は描かない。中央は縦にスクロールし、ページを開いたら先頭へ戻す。
- ページを開いたら、ページの見出し（`h1`、「接続」「音づくり」「設定」）へフォーカスを移す。音づくりの小区分を指定して開いたときは、いまと同じ場所へ移す。
- ページには閉じるボタンを置かない。戻るのはレールの「ホーム」。Esc でページを閉じない（ホットキーの入力中の Esc の扱いは、いまのまま）。
- 設定のページの区分は、ページの見出しの下に横並びのタブ（既存の `Tabs`）で示す。区分を替えても URL や履歴は使わない。

**接続のページ**（上から）

1. 見出しと、反映のしかたの一文（保存して開始／再起動が要る、`SETTINGS_APPLY_RULES.md`）
2. 接続の要約（いまの方式・入力・出力・周波数。いまの「要約」）
3. 入力（入力元、用途、マイク、チャンネル）→ 出力（出力先、分ける、チャンネル、配信ミックスをホームに出す）→ 接続方式と音切れ（方式と再検出、途切れにくさ、周波数、歌いながら聴く設定を試す）→ 入出力プリセット
4. 下に固定した行：主ボタン「接続を保存して開始」または「保存して再起動」と、その左に変更の内容（例「変更：マイク、周波数」。`hasConnectionChanges` と、変わった項目の名前）。変更がないときは「変更はありません」。

- 開始の失敗・移行の確認・マイクの許可の案内は、いまと同じ場所と文言で出す。いまモーダルを閉じていた「閉じる」は「ホームへ戻る」にする。保存して開始・再起動に成功したら、いまと同じくホームへ戻る。
- ASIO を選んだときだけ出る項目（チャンネルの選択など）は、いまと同じく入力・出力の中に置く。OBS に接続したときだけ出る項目は、設定 › OBS連携の中のまま。どちらも区分ごと移すので置き場所は変わらない。`settings-inventory.md` の「置き場所が決まっていないもの」と `DESIGN.md` 10.12 の該当行を、そのとおりに直す。
- 長い機器名・長い英語の説明は、枠の中で折り返す（#504 のうち、このページで再現する箇所）。選択欄は、いまの値と選択の手掛かり（矢印）を出し、未選択・読み込み中・未検出を区別する（#505 のうち、接続と外観のページで再現する箇所）。

**保存していない変更**

- 接続のページ（`hasConnectionChanges`）と、ホットキー（`ShortcutsPanel` の `dirty`）に保存していない変更があるまま、ほかのページ・区分へ移ろうとしたら、確認のダイアログを出す：「保存していない変更があります」、主ボタン「このページに戻る」、ほかに「変更を捨てて移動」。黙って捨てない。
- 保存や再起動の処理中（`isApplying`）は、レールの行き先と設定の区分を押せないようにし（`aria-disabled`、理由をツールチップで示す）、処理が終わるまでページを離れない。いまのモーダルが処理中に閉じられなかったのと同じ。
- アプリの終了やリロードの扱いは変えない。

**設定のページのシステム**

- 「診断情報」の折りたたみの中にあった表（稼働統計、遅延の内訳、往復遅延の測定、配信ミックスの診断）を、「診断情報を開く」ボタンから開くダイアログ（既存の `Modal`）へ移す。ダイアログの中身と、測定の処理は変えない。
- #507 のうち、システムの「通常の設定の行 → 影響のある操作（再起動・リセット・初期化）」の順と、OBS連携の「接続 → 適用」の順が読み取れるように、見出しと区切りをそろえる。見た目の強弱の全面的な整理（太字の削減など）は E と同じ基準で行い、D では区分の並びだけを直す。

**大きさ**：960×640、900×600（音楽鑑賞）、1024×768、1920×1080 で、ページの主ボタン（接続の固定した行、ホットキーの保存）と右の列の全操作が画面内に見える。ページの本文が長いときも、固定した行は隠れない。
