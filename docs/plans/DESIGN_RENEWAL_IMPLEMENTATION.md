[DESIGN.md](../DESIGN.md) 10章の規則を、製品の画面へ段階的に実装する計画です。
この文書は計画であり、実装済みや検証済みの証拠ではありません。

- 規則の正本：`docs/DESIGN.md` 10章
- 経緯と試作：[DESIGN_RENEWAL_2026-11-12.md](../DESIGN_RENEWAL_2026-11-12.md)、`?proto=g2`（開発時だけ）
- 設定項目の置き場所：[settings-inventory.md](../verification/design-renewal-2026-11-12/settings-inventory.md)

## 1. 進め方

- 1段階を1つの PR にする。PR は積み上げず、前の段階が main に入ってから次のブランチを main から作る。
- 設計と依頼文、結果の確認と、実装は、担当を分ける。どの道具に任せるかは利用者の指示に従い、この文書には固定しない。
- 各段階で、規則と食い違う既存の節（`DESIGN.md` 10.11 の表）と、利用者向けドキュメントの該当箇所を同じ PR で直す。
- 音声エンジン、IPC、音声コールバックは変えない。変える必要が出たら、その段階を止めて相談する。
- 試作（`src/prototypes/`）は見本として読む。製品へコピーせず、既存の共通部品（Button、SegmentedControl、Slider など）とトークンで作る。試作のクラス名（`oa-*`、`rn-*`）を製品へ持ち込まない。

**前提**：ブランチ `codex/design-renewal-2026-11-12`（規約と試作）が main に入っていること。

**レールを最初にしない理由**：現行のホームは、音調整の3連モジュールが、音調整の内側の幅で1列に切り替わる。レール（76px）と右の列（212px）を同時に入れると、中央が大きく狭まり、既定の 1024×768 でも3列の余裕がほとんどなくなる。そのため、ホームを先に刷新してから（B）、レールを入れる（C）。

**段階 A の実装で分かったこと（2026-11-12）**：切り替えの境目は、文書では780pxと書かれていたが、実装は内側の幅720pxだった。右の列を入れると、配信・通話の最小 960×640 で内側の幅が666pxになり、1列に切り替わって3つ目が画面の下へ回った。段階 A で境目を660pxに下げ、最小サイズでも3列を保つようにした。この境目のまま C でレールを入れると、1024×768 の内側の幅は約664pxで、余裕は4pxしかない。C の前に B でホームを刷新する順は変えない。

**段階 A で残した点の扱い（2026-11-13 決定）**：右パネルを横に並べる境目は1200pxのまま変えず、右パネルをなくす段階 F で解消する。B では、右パネルを開いたときの中央の幅も、新しいカードの構成で確かめる。

### 3.2 配置

- `AppShell.tsx` の `.workspace-body`（ホームと右パネルを入れている行）の右隣に、`<aside aria-label="本番中の操作">` を置く。ヘッダーの直下から窓の下端まで。通知の行は中央の列の中に置き、通知が出ても右の列を動かさない（最初の計画では「通知の行の下」としていたが、緊急ミュートを押すと出る通知で列が下へ動くため、PR 前のレビューを受けて直した）。
- 幅は212pxで固定する。背景は `card`、左に境界線1本。
- 右パネルの重ね表示と暗幕は、これまでどおり中央の作業領域だけを覆う。右の列は覆わず、操作できるままにする。
- 列の中は上から、緊急ミュート、出力（メーターを出す条件のときはメーター、出力音量）、VST を外して比較、余白、状態の表示と詳細の入口。
- 列は縦にスクロールさせない。用途別の最小サイズ（配信・通話 960×640、音楽鑑賞 900×600）で、全部が見えること。
- 出力音量は、ラベルと値の行、スライダーの行の2行に組み替える。「100%へ戻す」と再試行、ミュート中の出力確認の入口は残す。
- 広い窓で中央へ寄せる計算（`index.css` の `.workspace-body` の `max-width`）は、右の列の幅を足して直す。右の列は窓の右端に付ける。

### 3.5 完了の条件

1. 緊急ミュート、出力音量、VST を外して比較が右の列にあり、同じ操作がほかの場所にない。
2. フッターがない。
3. 960×640、900×600（音楽鑑賞）、1024×768、1920×1080 で、右の列の全操作が画面内に見え、文字の切れ・重なりがない。
4. 右パネルを重ねて開いた状態で、右の列の3操作が押せる。
5. 緊急ミュートのホットキー、比較のホットキー、出力音量へのフォーカス移動が、移動前と同じに動く。
6. 3テーマ（オーロラ、ライト、ゲーミング）で、文字4.5:1、状態の目印3:1 を保つ。
7. Tab の順が、ヘッダー → 中央 → 右の列、または合理的に説明できる順になっている。順を PR の説明に書く。

### 4.2 配置

**いまの状態**（`section`、名前は「いまの状態」）

- 上から、送り先（小さく）、状態の札、見出し、主ボタン、歌／雑談の切替。
- 状態の札は「実行中／音声停止中／音声未設定」（10.3）。札はこの1か所にし、停止中に同じ文言をホームのほかの場所へ重ねない。`HomePanels` の状態文は、札が出ている間は出さない。
- 見出しは、配信・通話ではいまのモード名（未登録は「カスタム」）、音楽鑑賞では出力の機器名（取れないときは「音楽鑑賞」）。
- 主ボタンは、停止中で開始できるときの「音声を開始」、実行中で送り先が未設定のときの「送り先を選ぶ」の、どちらか1つだけ。
- 未設定のときは、この区画を出さず、いまの `UnsetFlow` を先頭に置く。

**音の流れの帯**（`section`、名前は配信・通話で「声の流れ」、音楽鑑賞で「音の流れ」）

- 加工前（入力メーター）と加工後（出力メーター）の音量を、時間の流れで重ねて描く。加工後をオーロラの色、加工前を中立の色にし、凡例の文字を添える。
- 値は `MeterProvider` の共有の読み取り（`useSharedMeter`）だけを使う。新しい IPC・購読・タイマーを作らない。読み取りが変わったときに直近の値を記録して描く。
- 画面が隠れている間は描かない（共有の読み取りが止まる）。動きを減らす設定では、時間の流れを描かず、いまの値だけを静止した形で示す。
- 高さは 72〜120px を目安に、主役の大きさにしない。停止中と未設定では値を描かず、帯の枠と凡例だけにする（状態の文言は重ねない）。
- 見出しの行の右に、音量チェックの入口を置く。押したあとの `LoudnessCheck` の位置と動作は変えない。

**音調整の3枚のカード**

- 見出し「音調整」（音楽鑑賞は「音を整える」）と、ボイスチェック、その他のメニューは、いまの音調整の見出しの行のまま。

| カード | 1段目（常に出す） | 2段目（`data-home-tier="2"`） |
| :--- | :--- | :--- |
| ノイズ低減 | ON/OFF、強さ（弱・強）。学習・会場のときはその旨の一言 | なし（周囲の音の測定は H） |
| 声を整える | ON/OFF、音色の形、整え具合のスライダーと割合 | 声の種類（配信・あたたかい・明るい） |
| VST | 各 VST の ON/OFF、「VST を編集」または「VST を追加」 | 各 VST の画面を開く |

- 2段目は B では常に出す。窓が低いときに隠すのは H で行う。2段目を区画として分けておき、H で出し分けやすくする。
- 「声を整える」の割合は、スライダーの名前と同じ語（整え具合）で示し、音色の形は「整え具合に合わせた形の目安」であることを、図の読み上げ名と見出しで示す（#517）。効果や音質を保証する語は使わない。
- 音楽鑑賞では、ノイズ低減と声を整えるのカードを出さない（2.7 を維持）。声向けの処理が ON のままのときの注意の一行は残す。

- 歌・雑談の「歌の調整へ」（いまの `onAdjust`）は、「歌向け」の小区分へ移る。歌向けの「歌・雑談へ戻る」は「歌・雑談」へ移る。

**基本**（すぐ反映）

- 上から ノイズ低減 → 声を整える → 歯擦音 → ボイスチェックと配信ミックスの入口。中身と操作はいまのまま。
- ホームのカードと同じ値を見せる。値を2つ持たない（10.5）。いま、ホームのカードと音づくりのページが同じ状態（`engineStats`、`useSingingDraft` の `snapshot`）から読んでいることを確かめ、ホームで変えた値がページに、ページで変えた値がホームに出ることを試験にする。
- 見出しと操作名は、ホームのカードの語にそろえる（「ノイズ低減」「声を整える」「整え具合」など）。

**歌・雑談**：`LiveModeControls` をいまのまま置く。

**歌向け**（適用が要る）

- `SingingControls` をいまのまま置き、主ボタン（「適用」）を、接続のページと同じくページの下に固定した行へ出す。主ボタンの左に、変更の有無（「適用していない変更があります」／「変更はありません」）を出す。試聴・元に戻す・保存など、ほかのボタンは本文に残す。
- 歌向けの下書きは、いまと同じく `ModalLayer` の `useSingingDraft` に残る。ページを離れても消えないので、離れるときの確認は出さない。代わりに、下書きに適用していない変更があるときは、「歌向け」のタブに印（点と、読み上げ用の「適用していない変更あり」）を付ける。色だけで示さない。

## 9. 段階 G：ゲーミングを形でも見分けられるようにする（#527）

2026-11-14 に、段階 F（PR #535）の結果を見て書いた。

### 9.1 目的と範囲

ゲーミングのテーマは、いまは色（マゼンタ）と、画面全体の背景の光・格子、半透明のカード、所々の発光で見分けている。形はほかのテーマと同じ角丸である。これを、マゼンタ1色の濃淡・角を切り欠いた形・見出しの斜体で見分けられるようにし、画面全体の光と常時の発光をなくす（10.10）。

| いま | G のあと |
| :--- | :--- |
| `AppShell` の `data-gaming-backdrop`（背景の光2つと格子） | なくす |
| ゲーミングだけ半透明のカード（`gaming:bg-card/70` など） | ほかのテーマと同じ不透明の面 |
| 常時の発光（`StatusDot`・`DeviceStatus`・`OBSGuideModal` の光る影、`PluginList` の追加ボタンの光る影と `animate-pulse`） | なくす。発光は「押している間」と「緊急ミュート中」だけ |
| 角丸（`rounded-card` 12px、`rounded-control` 10px） | ゲーミングだけ、角を切り欠いた形（下の 9.2）。ほかのテーマの角丸は変えない |
| 見出しは直立 | ゲーミングだけ、ページの見出し（`h1`）と区画・カードの見出しを斜体 |
| 差し色に青緑（`--brand-secondary: 185 100% 60%`） | マゼンタの濃淡にする。色は足さない（9.2） |
| 外観の注意書き「発光などの視覚的な演出が強くなります」 | 新しい見た目に合わせて書き直す |

**色を足すか（10.12 の未決）を、ここで決める：足さない。** 黄色はすでに注意（`--warning`、メーターの注意域）の意味で使っており、差し色に使うと「注意」と見分けにくくなる。ゲーミングはマゼンタ1色の濃淡と、形・斜体で見分ける。虹色にはしない。

あわせて扱う Issue：

- #512：外観のテーマの色見本（`ThemeSwatch`）は実装済み（PR #515）。G では、ゲーミングの見本にも切り欠いた形を出し、色だけでなく形でも違いが分かるようにする。そのうえで #512 の完了条件を確かめて閉じる。

G で動かさないもの：ページの構成と配置（B〜F）、文言の意味（外観の注意書きを除く）、オーロラとライトの見た目、窓が大きいときの表示（H）、試作（`src/prototypes/`）。

### 9.2 形と色

**切り欠いた形**

- CSS の `corner-shape: bevel` を使う。`border-radius` と組み合わせると、枠線・背景・影・フォーカスの輪が同じ切り欠いた形に沿う。`clip-path` は使わない（フォーカスの輪や影まで切り取ってしまうため）。
- `@supports (corner-shape: bevel)` の中でだけ切り欠く。対応しないときは、小さい角丸（2px）にする。WebView2 と Playwright の Chromium はどちらも対応している（2026-11-14、開発プレビューの Chromium 156 で `CSS.supports('corner-shape', 'bevel')` が真）。
- 切り欠く大きさ（仮）：カード・区画・ダイアログは 10px、ボタン・入力・選択欄などの操作は 6px。小さい印（状態の点、トグルのつまみ、スライダーのつまみ）は切り欠かない。
- 方法：`.gaming` の下で `--radius-card`・`--radius-control` と `corner-shape` を上書きする。部品ごとにクラスを足して回らない。`rounded-full` の部品は丸のまま。

**見出しの斜体**

- `.gaming` の下で、ページの見出し（`h1`）と、区画・カードの見出し（`text-ui-heading` の見出し）を斜体にする。本文・数値・ボタンの文字は直立のまま。
- 日本語は斜体の字形がないので、斜めにした字形になる。960×640 で見出しが欠けたり、隣と重なったりしないことを確かめる。

**発光**

- 常時の発光をなくす（上の表）。
- 押している間：主ボタン（`variant="default"`）の `:active` に、主色の光る影を付ける。
- 緊急ミュート中：右の列の緊急ミュートのボタンに、ミュート中だけ光る影を付ける。
- 動きを減らす設定では、光る影は付けてよいが、明滅・脈打ちはさせない。

**色**

- `--brand-secondary` をマゼンタの濃淡にする（青緑をやめる）。`AppRail` の応援の印など、この色を使う所が読みやすいままであることを確かめる。
- 文字 4.5:1、状態の目印と入力枠 3:1 は、いまの基準と試験（`inputBorderToken.test.ts` などテーマの色の試験）を守る。

### 9.3 変えてはいけないもの

- オーロラとライトの配色・角丸・発光（`aurora-glow` などオーロラのもの）。
- テーマの保存の形式（`useTheme` の値 `light`・`dark`・`gaming`）と切り替えの順。
- 部品の操作・項目・既定値、ページの配置、文言キーの規則（3.7）、`uiConsistency.test.ts` の上限。
