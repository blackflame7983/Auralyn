# プラン2: 音質検証・品質指標

## 目的

実録音サンプル（プラン1 のボイスチェック録音）を分析し、
「劣化」「プツプツ（グリッチ/ドロップアウト）」「音割れ（クリップ）」を数値・可視化で提示する。
ノイズ抑制強度やゲイン調整の**根拠**をユーザーに提供する。

## 前提・依存

- **プラン1 の Raw/Processed 同時録音バッファを分析入力として再利用する**（本プランの核心）。
  録音経路を新設しない。
- リアルタイム系の既存指標（`glitchCount`, クリップ表示, レイテンシ）は継続利用し、
  本プランは「録音後のオフライン分析」を追加する位置づけ。

## 提示する指標（MVP）

| 指標 | 検出対象 | 算出方法 | ユーザー向け表現 |
|------|---------|---------|----------------|
| クリップ率 | 音割れ | \|sample\| ≥ 0.999 の連続サンプル区間数と総時間比 | 「音割れ: なし / N 回検出」+ 発生位置 |
| ドロップアウト | プツプツ | 急峻な不連続（隣接サンプル差分の外れ値）+ 録音中の `glitchCount` 増分 | 「音途切れ: N 回」+ 発生位置 |
| ノイズ床 (dBFS) | 残留ノイズ | 無音区間（簡易 VAD で発話除外）の RMS | 「静かなときのノイズ量」Raw vs Processed |
| SNR 改善量 | ノイズ抑制の効き | (発話 RMS − ノイズ床) の Raw/Processed 差分 | 「ノイズ抑制効果: +X dB」 |
| 帯域バランス | こもり/シャリつき・劣化 | オクターブバンド別エネルギーの Raw/Processed 差分 | 「高音が X dB 減っています（こもり気味）」 |
| ラウドネス | 音量の適正 | RMS / ピーク（簡易。将来 LUFS 化） | 「配信に適した音量です / 小さすぎます」 |

## 判定と推奨アクション

指標を内部で持つだけでなく、**閾値ベースの日本語アドバイス**に変換して表示する。

- クリップ検出 → 「入力ゲインを下げてください（推奨: −X dB）」
- ドロップアウト多発 → 「バッファサイズを上げてください（現在 N → 推奨 M）」
- 高域減衰が大きい（例: 4kHz 以上で −6dB 超） → 「ノイズ抑制が強すぎる可能性。強度を下げるか声優先を ON に」
- ノイズ床が高い → 「ノイズ抑制の強度を上げる / Smart Learn を実行」

総合表示: 「良好 / 要調整 / 問題あり」の 3 段階バッジ + 詳細展開。

## 設計方針

### 分析の実行場所

- **Rust（エンジンではなく Tauri メイン側）でオフライン分析**する。
  - 理由: RT スレッドへの負荷ゼロ、`rustfft`（新規依存・軽量）で FFT 可能、
    フロント JS での大容量 PCM 転送を回避。
  - エンジンが録音完了時に一時 WAV（または IPC 経由の生 PCM ファイル）を書き出し、
    Tauri メインが読み込んで分析 → 結果 JSON をフロントへ返す。
- 新規モジュール `src-tauri/src/audio_analysis.rs`（純関数中心・ユニットテスト可能に）。

### API

```
Tauri command: analyze_voice_check() -> QualityReport
QualityReport {
  clip: { count, ratio, positionsMs[] },
  dropouts: { count, positionsMs[] },
  noiseFloorDb: { raw, processed },
  snrImprovementDb,
  bandDeltaDb: [{ bandHz, deltaDb }],
  loudness: { rmsDb, peakDb },
  verdict: "good" | "warn" | "bad",
  advices: [{ severity, messageKey, params }]
}
```

- `src/api/audio.ts` に `analyzeVoiceCheck()` を追加。

### UI

- プラン1 の `VoiceCheckModal` に「品質チェック」タブ/セクションとして統合する
  （別モーダルにしない。録音→試聴→分析が 1 画面で完結するのが価値）。
  - 総合バッジ + アドバイスリスト（クリックで該当設定モーダルへジャンプ）
  - Raw/Processed のスペクトル比較グラフ（簡易バーで可。Canvas 描画）
  - 問題発生位置を波形上にマーカー表示（プラン1 の波形表示に重畳）

## 実装フェーズ

| フェーズ | 内容 | 完了条件 |
|---------|------|---------|
| 2-a | `audio_analysis.rs`: クリップ/ドロップアウト/ノイズ床/RMS | 合成テスト信号でユニットテストが通る |
| 2-b | SNR 改善量・帯域差分（FFT） | 既知の加工を施したサンプルで期待値どおり |
| 2-c | アドバイス生成 + Tauri command + フロント API | JSON レポートが UI に届く |
| 2-d | UI 統合（バッジ・グラフ・設定ジャンプ） | 録音→分析→調整の導線が完結 |

## テスト

- Rust ユニットテスト: 合成信号（クリップ入り正弦波、無音+ホワイトノイズ、
  ドロップアウト挿入済み信号）で各指標の検出精度を検証。**本プランはここが最重要**。
- `audio.test.ts`: command 呼び出しとレポート型の検証。
- 手動: 実マイクで「わざと音割れ」「わざと爆音ファン」等の再現ケースを `docs/TESTING.md` に追記。

## リスク・注意点

- 指標の閾値は初期値を仮置きし、実測で調整する前提（閾値は 1 箇所の定数モジュールに集約）。
- 「劣化」の完全な自動判定は不可能 → アドバイスは断定調を避け、最終判断は試聴
  （プラン1）に委ねる文言にする。プラン6 の表現ガイドラインと整合させる。
- 将来拡張: ITU-R BS.1770 準拠 LUFS、PESQ/STOI 系の知覚品質指標は本 MVP のスコープ外。
