## 実行した検証

- Vitest：147ファイル・1560件成功。起動時の音楽鑑賞で、保護・復旧・snapshot errorを初回取得し、正常時には歌／雑談の操作を出さない試験を含む。
- 最終の表示名・保存範囲・ホーム開始操作に関する重点確認は12ファイル・138件成功。
- 関連ブラウザ57ケースを確認。`ui255-regression-final.log`のうち最終再実行対象を除く45件と、`ui255-browser-fix-check.log`の12件の成功を採用する。初回の旧配置を前提とする試験を更新し、実際のモード登録へのフォーカスも修正した。試験中のソース更新による開発用HMRの失敗と、詳細ボタン名の競合は、ソースを固定した対象12件の再実行で解消を確認した。1280×800の本番操作、3テーマ、900×600以上の窓、英語、125%／150%拡大、キーボード、動きを減らす設定を含む。
- TypeScript、Viteのフロントビルド、配布スクリプト59件、release:checkが成功。フロントビルドはNSIS生成・配布を含まない。
- 隔離した現行Host・engine・scannerのビルドと実Tauri試験1件が成功。実WebView2でTDR Novaの追加・キーボード並べ替え・初期化・日本語／英語・150%表示を確認。通常設定を使わず、音声を開始していない。
- 独立レビューで、音楽鑑賞起動時の安全状態取得、経路図の分岐、自動起動・再起動の説明を修正し、再レビューで追加の不具合指摘なし。
- デザイン検出は既存のreduced-motion規則内の `animate-bounce` という名前にadvisoryを1件返した。今回追加した跳ねる動きではなく、停止対象の既存セレクターなので変更していない。
- 追加レビューで次の3点を修正した。修正後にTypeScript、Vitest 1,560件、関連ブラウザ23件が成功。native試験は見出しの検索文字だけを更新し、実行していない。
  - #261：オーロラの強さを直線値ではなくdBFS（−48〜−6 dBFSを0〜1）から作り、普通の話し声（約−20 dBFS）でも反応が見えるようにした。
  - #265：音づくりタブ先頭の情報ボタンに「反映のしかた」の文字を添えた。
  - #258・#264：見出しを「接続方式・音切れの設定」にし、ASIO専用に読めないよう現在の接続方式を見出しに出した。サンプル数は中の詳細へ移した。

テスト証拠はignoredの `test-results/ui255-*` と、native runnerが記録する実行ごとの一時領域に保持する。通常の保存先、既存の `.claude/`・`target/`、別ブランチ・別worktreeは変更・削除しない。検証ログや過去の計画を現行実装の証拠に読み替えない。

## 残る受入条件

- **#261**：同じ機器・処理条件で、演出のON/OFFによる描画負荷と実音声への影響を比較する。今回の共有メーター利用とモック試験は、その実測の代わりにはならない。
- **#269**：話し声・大きな声・歌のピークを実際に入力して色を記録し、必要な場合だけ閾値の変更を検討する。
- **#270**：実音声、本当の初回セットアップから配信まで、実DPI、スクリーンリーダーを含む全体評価と同じ条件での再採点。[Issue #270の追記](https://github.com/blackflame7983/Auralyn/issues/270#issuecomment-6624278467)でモック画面の再採点56→65点が記録された。実音声等を含む同Issueの全体受入は引き続き未完了。

利用者による名称の理解、聴感、実ASIO／WASAPI、OBS受信、長時間運転を合格扱いにしない。Issueのクローズ、push、PR作成、公開は実施していない。
