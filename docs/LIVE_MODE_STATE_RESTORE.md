# 歌／雑談モードと関連VSTを配信状態から復帰する

#222の[分離出力の保存・復帰](OUTPUT_CONFIGURATION_RESTORE.md)を拡張し、歌／雑談の登録内容、選択中モード、関連VSTの内容、現在の自分用処理を一緒に保存する。
声用途の機器入力を対象とする。[プロセス単独入力の復帰](PROCESS_STATE_RESTORE.md)は別の形式で扱い、処理分離・モードとの組合せは非対応を維持する。
[一時利用前の退避](EXTENDED_TEMPORARY_RESTORE.md)にも同じ保存形式を使う。V-04の聴感・実機受入は別に残す。

## 選択中の構成と、次の切替で使う内容を両方残す

現在のVSTラックと、歌／雑談に関連付けたVSTの登録内容は別に保持する。
登録後に現在のラックを調整していても、現在の状態と次回の切替先を混同しない。
関連付けなしは「VSTを変更しない」、関連付けた空ラックは「全VSTを外す」という既存の意味を維持する。

保存画面の「歌／雑談モードと関連VSTも保存する」を選ぶと、出力構成と全カテゴリも選択する。
新形式schema 3に、内蔵設定の登録内容、選択中モード、歌／雑談それぞれのVST内容、本人用の実際の処理を含める。
旧schema 1・2は従来の範囲で読み続け、モードまで復帰できる形式へ読み替えない。
旧形式で選択中モードを落とす保存・復帰は拒否する。

差分には、現在と保存値のモード、両モードの内蔵設定、関連VST名と件数、現在の自分用処理を示す。
VST内部stateは画面やログへ返さない。欠落VSTは現在のラックと両モードの登録内容の全件を確認する。

## 通常プロファイルを上書きせず、保存したVST内容を使う

名前だけの参照では、保存後に同名のプロファイルが変わると元の構成を呼び戻せない。
配信状態には関連VSTの内容も埋め込み、復帰時は設定領域の`mode-profile-snapshots/<内容のSHA-256>.json`へ新規保存する。
本番モードの参照には元の表示名と内容識別子、専用保存先の参照だけを持たせる。
通常の`presets/`は置換しない。同じ識別子の専用ファイルが既にある場合は内容を照合し、破損や不一致では上書きせず中断する。

本番モードの通常操作・ホットキー・OBS連動は既存のHost入口を使い、復帰後の参照も同じVST一体切替へ渡す。
通常プロファイルを後編集しても、復帰した参照には反映しない。登録画面にもこの違いを表示する。
利用者が関連付けを保存し直すと、通常プロファイルの最新内容を参照する既存の登録へ戻る。
専用ファイルは復帰原本として保持し、自動整理や公開・exportは追加しない。

## ミュート中に全件を復帰し、実値を照合する

機器の明示開始・全体ミュート・新しい差分を必要とし、現在のモードと出力構成を変更前の原本へ退避する。
本番保護中・切替途中・VST復旧待ち・入力が未対応の場合は拒否する。
設定ファイルとHost・Engineの値、登録したVST内容の識別子を照合し、未取得・改変・読込不能を成功へ読み替えない。

再起動前に今回のモード定義をHostの一時指定へ置き、本人用の実処理も音声開始前にEngineへ渡す。
現在のVSTラック・NR・内蔵設定・音量を戻し、その後に保存されたモードを選択する。
本人用と配信用の反映完了を有限に待ち、実値・機器・VST stateを照合する。
モード定義ファイルは適用前と書込み直前の元バイト列を照合し、外部編集を上書きしない。

Undoと失敗後の手動復旧にも同じ形式を使う。
再起動を伴う適用に入った後の失敗では両枝を停止し、原本を保持する。停止応答を確認できなければ、所有するEngineを終了する。
停止・ミュートの意図はHostのロックを待つ前に記録し、復帰処理が次に接続条件を確認した時点で中断する。
実行中のVST呼出し自体の即時中断や応答時間は保証しない。
本番保護・ピーク保護・学習結果は過去の保存値から復活させず、現在の全体ミュートとVST全体バイパスを維持する。

## 自動確認と実音声の受入を分ける

schemaの互換性、空ラック、参照と内容の不一致、通常プロファイルの保護、専用原本の改変、モニター処理、外部編集、停止・ミュートの中断をコードと実Hostで確認する。
実Hostの入口は`scripts/verify-output-configuration-native.mjs`の`--live-modes`で、専用アプリ・設定・WebView2・TEMPを使用する。
同じ仮想ケーブルの入出力を使うため、全体ミュートを解除しない。聴感やOBS録音の合格には使わない。

実音声の漏れ・二重音、ASIO混在、機器切断、長時間運転と聴感はV-04で別に確認する。
旧実装でSoundblasterの独立出力に停止を観測した条件も未解決として保持する。

## カスタム構成の完了世代を、モード切替中と混同しない

実Hostの追加試験で、カスタム構成に戻った後も「切替中」となり、モード登録が拒否される不具合を確認した。
配信用の個別編集でモード側の世代が進んでも、自分用処理は保持される。その完了世代まで新しいモードと一致するよう求めていたことが原因である。

選択中モードがある場合だけ、配信用と本人用の完了世代を合わせるよう修正した。
カスタム構成の本人用処理は別のsnapshotで確認し、処理失敗は引き続き未完了として扱う。
修正前に再現テストが失敗することを確認し、失敗記録も`test-results/live-mode-restore-custom-phase-before.log`へ残した。

## 適用結果の表示同期から音量変更を再送しない

実HostではモードとVSTの復帰完了後、画面の入力音量表示が同じ値をEngineへ再送していた。
値が同じでも変更世代が進むため、直後の差分やUndoが競合になっていた。

表示同期は表示だけを更新し、Engineへの変更と保存は実際に操作した側が応答確認後に行う。
復帰結果が届いたら、送信待ちの古いスライダー操作も取り消す。同じ値への同期でも取り消すが、自分が出した通知では自分の送信を取り消さない。
修正前に2件の再現テストが失敗することを確認した。記録は`test-results/live-mode-restore-input-sync-before.log`に残す。
