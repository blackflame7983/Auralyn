# モノラル専用 VST3 の入出力を変換する（Issue #456）

2026-11-08、`codex/mono-vst3-456-20261108`（ベース `codex/vst3-class-id-450-20261108`、`f6c37e80`）でローカル実装した。実在のモノラル専用 VST3、音声機器、OBS では確認していない。

## 交渉

対象は VST3 エフェクトの main bus 1 本。VST2、楽器、MIDI、sidechain は変えない。多チャンネルの機器でも、プラグインへ渡す候補はステレオかモノラルである。

音声の準備は、コンポーネントが非アクティブの間に行う。順番は `getBusInfo`、`setBusArrangements`、`setupProcessing`、`setActive`、`setProcessing`。VST3 の処理開始順では配置の決定が `setupProcessing` より前にある。`setupProcessing` で現在の ch 数に合わせて内部バッファを確保する実装があるため、以前の「先に setup し、配置に失敗しても警告だけで続ける」順は使わない。どちらも `setActive` より前である。

`getBusInfo` で main bus の既定 ch 数を読む。失敗、または 1 でも 2 でもない値は不明として、次の試行は止めない。試す順は次のとおり。ホストのチェーンが 2ch 以上のときだけこの順にする。

1. ステレオ入力 / ステレオ出力。`setBusArrangements` が成功するか、失敗しても `getBusArrangement` の現在値が同じなら採用する。配置の更新を拒否しても、もともとステレオで動いていた VST をここで残す。
2. モノラル入力 / モノラル出力。同じ条件で採用する。
3. モノラル入力 / ステレオ出力。同じ条件で採用する。
4. どれも違うときはロードを失敗させる。メッセージは「入出力の構成（モノラル/ステレオ）に対応していません」。未対応の形のまま音声を始めない。

スピーカー配置は `SpeakerArr::kMono = 1`、`SpeakerArr::kStereo = 3`。`activateBus` は呼ばない。main bus の有効状態はプラグインの既定のままにする。

出力デバイスが 1ch のときは、従来どおりモノラルを要求し、拒否されてもロードは失敗させない。

決めた構成はインスタンスの `bus_layout` に持つ。保存データには書かない。ロードと `prepare_processing` のたびに同じ手順で決める。レートを変えて準備し直しても、プラグインの受理規則が同じなら結果は同じになる。

画面へ渡す値は `channelLayout`。`mono`、`monoToStereo`、ステレオは省略する。旧 JSON に項目が無くても読め、そのときはステレオとして扱う。

## 変換

チェーンは従来どおりステレオの planar。変換は `process_planar` の中だけで、scratch とポインタ配列は `create_processor` が bus の ch 数で先に確保する。音声コールバックでは確保しない。

- ステレオ入出力は、ポインタをそのまま渡す。混ぜない。
- モノラル入力は `0.5 × (L + R)`。同じ音を左右に入れているときは元の大きさのままになる。片側だけに音があるときは半分になり、約 -6 dB 小さくなる。左右が逆相だと打ち消す。
- モノラル出力は、その 1ch を左右の両方へ同じ大きさで複製する。
- モノラル入力からステレオ出力のときは、入力だけを混ぜる。左右の出力はプラグインが書く。
- `ProcessData` の `num_channels` は、入力 bus と出力 bus でそれぞれの実 ch 数にする。
- bypass はチェーンが入力を出力へコピーする既存の経路のままにする。

## 画面

プラグインカードに文字のバッジを出す。`mono` は「モノラル」、`monoToStereo` は「モノラル入力」。ステレオには出さない。色だけにはしない。説明はツールチップと読み上げ用の文に置く。モノラルは「左右を混ぜて1chで処理し、両側に同じ音を出します」に続けて、片側だけが約 -6 dB 小さくなることと、逆相が打ち消えることを書く。モノラル入力は、出力の左右をプラグインが出すことを分けて書く。ホームのチェーン列にも同じ文字を出す。

## 対応範囲と未確認

モックで、ステレオだけ、モノラルだけ、モノラル入力からステレオ出力、すべて拒否、配置の更新は失敗するが既定がステレオ、の各受理を確認した。実在のモノラル専用 VST3 製品では未確認。確認できた製品はまだない。

既存のステレオ VST は、ステレオの配置を受理するか、更新に失敗しても現在値がステレオなら、変換せず従来の planar 経路を通る。回帰は、モックのステレオ恒等処理で左右が変わらないことと、既存の planar 試験でプラグインの係数がそのまま残ることで見る。

`getBusInfo` の ch 数はログに残すだけで、試す順は変えない。ステレオの VST が既定 1ch と返しても、先にステレオを試す。停止中の追加でも、その時点の出力 ch 数（未設定なら 2）で一度交渉し、未対応ならその場で失敗させる。あとから 1ch の出力で準備し直すときは、従来の 1ch 経路へ戻る。構成はプリセットにもセッションにも保存しない。
