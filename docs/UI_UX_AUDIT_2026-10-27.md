# UI/UX・デザイン監査（2026-10-27）

対象は `main`（`526242a`）時点の画面です。前回の [UI_UX_AUDIT_2026-10-25.md](./UI_UX_AUDIT_2026-10-25.md) の修正（#84〜#89）が入った後の状態を、利用者の立場から見直しました。判断基準は [DESIGN.md](./DESIGN.md) と [COPY_GUIDELINES.md](./COPY_GUIDELINES.md) です。

この文書は監査時点の判断材料です。修正の完了や現在の実装を示す証拠として扱わないでください。

## 確認方法と限界

- **実画面**：Vite 開発サーバーの画面をブラウザで開き、Tauri の通信を仮の応答に置き換えて描画しました（WASAPI、入力「マイク (Shure MV7)」、出力「CABLE Input」、VST 3 本を保存済み構成から復元した状態）。寸法は既定ウィンドウと同じ 1024×768、テーマは既定のオーロラです。
- **見た画面**：ホーム（かんたん／詳細）、VST ラック（カード／1行）、大型レベルメーター、音声の詳細、設定（オーディオ・音づくり・OBS 連携・外観・システム）、ボイスチェック、VST 追加、音量チェック、セットアップ（目的・入力）。
- **画面サイズ**：F 章のため、900×600（最小）、1024×768（既定）、1280×720（1920×1080 を 150% 拡大で使う場合に相当）、1920×1080、2560×1440 でも確認しました。各サイズで、ヘッダー・フッターの高さ、本文のスクロール量、横はみ出し、文字ラベルが消えるボタンを計測しています。
- **確認していないこと**：実機の音声エンジン、OBS 接続後の画面、VST の独自 GUI、英語表示、ライト／ゲーミングテーマ、スクリーンリーダー、Windows の文字サイズ拡大、実ウィンドウの最大化・スナップ。仮の応答に起因する表示（試聴先の取得失敗など）は指摘から除いています。

## 想定する利用者

| 利用者 | したいこと | 画面に求めるもの |
| :--- | :--- | :--- |
| 配信者（雑談・ゲーム・歌） | 毎日すぐ配信を始め、本番中は事故を止める | 今の状態が一目で分かる。よく使う操作が近い。読まずに押せる |
| 音楽鑑賞ユーザー | PC の再生音（音楽・動画）に EQ などの VST をかけて聴く | マイク前提でない導線。ラックとプリセット切り替えが主役 |
| VST で作り込む人 | 複数の VST を並べ、遅延とレベルを管理する | 信号の流れ、メーター、各段の状態が見える |

[DESIGN.md](./DESIGN.md) 1.2 の利用者表には、音楽鑑賞ユーザーがいません。現状のアプリはすべての文言・既定値がマイク前提です（後述 A4）。

## 総評

前回の監査から、入口の名前・原音比較の範囲・設定タブの長さ（オーディオ 1,327px → 992px）は改善しています。誤解を招く断定も減りました。

一方で、次の3点は構造の問題として残っています。

1. **ホームが毎回「セットアップ手順」の形をしている。** 「1 マイクと送り先」「2 声を整える」「3 聴いて確かめる」の番号付きカードは初回には合いますが、毎日の配信では「今どうなっているか」「すぐ触りたい操作」が見えにくくなります。
2. **詳細表示がかんたん表示の上位互換になっていない。** 「VST・詳細」に切り替えると、ノイズ低減と内蔵ボイスチェーンの操作がホームから消えます（[DESIGN.md](./DESIGN.md) 2.3 に反する）。
3. **VST ホストとしての見た目の芯（信号の流れとメーター）が弱い。** ラックは VST だけの縦リストで、入力・ノイズ低減・内蔵処理・出力との関係が画面から分かりません。メーターは場所ごとに形・目盛り・色の意味が違います。

文章量については、「ボタン名の言い換え」「状態表示の言い換え」「常に出ている注意書き」が各所に残っており、[DESIGN.md](./DESIGN.md) 3.1・3.4 の規則で削れるものが多くあります。

## 指摘一覧

重要度は、**高**＝迷い・誤操作・離脱に直結する、**中**＝理解に時間がかかる・見た目の信頼を損なう、**低**＝一貫性・磨き込み、です。

### A. 導線と画面構成

#### A1.【高】詳細表示に切り替えると「声を整える」が消える

- **根拠**：かんたん表示のホームにある「2 声を整える」（ノイズ低減の ON/OFF・弱／強、内蔵ボイスチェーンのプリセット・かかり具合）は、「VST・詳細」では表示されません。残る入口はフッターの小さなバッジ「ノイズ強 声」（押すと設定の音づくりを開く）だけです。
- **問題**：VST を使い始めた配信者ほど、ノイズ低減と VST の組み合わせを頻繁に調整します。表示を切り替えただけで操作が奥へ移るのは、[DESIGN.md](./DESIGN.md) 2.3「詳細表示は、かんたん表示に追加するもの」に反します。
- **改善案**：B1 の「信号の流れ」表示に、ノイズ低減と内蔵ボイスチェーンを固定の段として置く。最低限、詳細表示でも「声を整える」カードを残す。

#### A2.【高】毎日のホームが、初回セットアップの手順形式になっている

- **根拠**：ホームは番号付きの3枚のカードです。「3 聴いて確かめる」はボタン1つ（「録音して聴き比べる」）と、その言い換えの説明文だけのカードです。
- **問題**：2回目以降の利用者にとって、番号は「まだ終わっていない手順」に見えます。毎日見たいのは、入力→処理→出力の状態と、ミュート・出力音量・ノイズ低減などの即時操作です。
- **改善案**：
  - 上段に「入力 ▸ 処理 ▸ 出力」の状態帯（機器名・メーター・問題があれば警告）を置く。
  - 中段に「声を整える」（ノイズ低減・内蔵ボイスチェーン）。
  - 確認系（ボイスチェック・音量チェック）はカードではなく、状態帯または中段のツールボタンにする。
  - 番号付きの手順表示は、未設定時と #94 の準備導線でだけ使う。

#### A3.【高】音楽鑑賞ユーザーの入口がない

- **根拠**：セットアップの目的は「OBSで配信」「ボイスチャット」「ヘッドホンで試す」「その他の用途」です。入力の画面は「マイクを選んでください」「入力デバイス (マイク)」、ホームは「声を整える」です。オーディオ設定のサンプルレートは「音質設定：標準 (48kHz) 配信・動画用／音楽 (44.1kHz) CD制作など」と表示されています。
- **問題**：PC の再生音に VST をかけたい人は「その他」を選び、入力に `CABLE Output` を自分で選ぶ必要があります。その後もマイク前提の文言が続き、配信用にノイズ低減や内蔵ボイスチェーンを有効にしている人は、音楽にもそれがかかったまま気付かない恐れがあります（エンジンの既定値はどちらも OFF）。44.1kHz を「音楽」と呼ぶと、高音質の選択肢に見えます。
- **改善案**：
  - 目的に「PC の音にエフェクトをかける（音楽・動画）」を追加する。経路（Windows の出力 → CABLE Input → Auralyn → ヘッドホン）を図で示し、ノイズ低減と内蔵ボイスチェーンを既定 OFF にする。
  - この目的のときは「マイク」「声」の文言を「入力」「音」に切り替える。
  - サンプルレートは「サンプルレート：48kHz（推奨）／44.1kHz」とし、用途の説明はツールチップへ移す。

#### A4.【中】入力ゲインの場所が、ウィンドウ幅で変わる（詳細表示）

- **根拠**：詳細表示の入力ゲインは、幅 1280px 以上ではヘッダーにスライダーとして出ます（`Header.tsx` の `hidden xl:flex`）。既定の 1024px を含む 1280px 未満では、ヘッダー右の「大型レベルメーターを開く」で開くサイドパネルの中にしかありません。
- **問題**：入力ゲインは音作りの最初に触る基本操作です。既定のウィンドウでは、メーターを見るボタンの中にあるとは予想できません。幅を変えると場所が変わる点も F2 と同じ問題です。
- **改善案**：B1 の信号の流れの「入力」段、または A2 の状態帯の入力欄に置く。

#### A5.【中】ホットキー設定が隠しタブにあり、入力方式も古い

- **根拠**：システムタブは外観タブの「システム設定タブを表示」を押すまで出ません。ホットキーは11操作 × 2つのプルダウン（修飾キー9種、通常キー約70種）＋「登録を解除：〜」リンクで、タブ全体が 1,830px（表示領域 574px）あります。ミュートと原音比較は「切り替え／ON／OFF」の3行ずつです。
- **問題**：配信者にとってホットキー・Stream Deck は必須機能です。隠しタブに置く理由がありません。プルダウン2つで組み合わせを作る方式は、一般的な「欄を押してキーを押す」入力より手間がかかります。
- **改善案**：
  - システムタブを常に表示し、ホットキーを独立したタブ（「ショートカット」）にする。
  - キー入力は「欄を押して組み合わせを押す」方式にする。既存の衝突検査・保存契約は維持する。
  - 一覧は登録済みだけを表示し、「＋ 操作を追加」から選ぶ。切り替え／ON／OFF は1行の「動作」選択にまとめる。

#### A6.【中】セットアップの入力画面で、マイクの音が見えない

- **根拠**：「マイクを選んでください」の下に「このマイクの入力レベルは、『確認』で『マイクの音を流して確認』を押すと表示されます。」とあり、選んだ時点ではメーターがありません。
- **問題**：複数のマイクやオーディオインターフェースがあると、どれが正しいかを選ぶ時点で確かめられません。
- **改善案**：選択欄の下に入力メーターを置き、選んだ機器の音が動くことを見せる（出力へは流さない）。説明文はメーターで不要になる。

#### A7.【低】音量チェックが「開く」と「測定する」の2段階

- **根拠**：ヘッダー下の「音量チェック」はパネルを開くだけで、「測定は停止中です」と「測定する」ボタンが出ます。
- **改善案**：開いたら測定を始め、閉じたら止める（現在の「非表示にすると測定を停止します」と対称にする）。

### B. VST ホストとしての見た目と操作

#### B1.【高】信号の流れが見えない

- **根拠**：ラック（「VST 構成」）は VST だけの縦リストです。入力・ノイズ低減・内蔵ボイスチェーン・出力ゲインは別の場所（カード、設定、フッター）にあります。カード間の細い縦線だけが「順につながる」ことを示しています。
- **問題**：処理順はエンジンで固定（入力ゲイン → ノイズ低減 → 内蔵処理 → VST → 出力ゲイン）なのに、画面からは読み取れません。「どこで音が変わったか」「ノイズ低減は VST の前か後か」を利用者が推測することになります。VST ホストとして最も期待される「チェーンが見える」表示がありません。
- **改善案**：横または縦の1本のチェーンで、`入力 ▸ ノイズ低減 ▸ 内蔵ボイスチェーン ▸ VST… ▸ 出力` を表示する。
  - 各段に ON/OFF と小さなメーターを置く。固定段（ノイズ低減・内蔵）は並べ替え不可の見た目にする。
  - 原音比較中は、外れる段（VST）だけを薄くする。比較の範囲を文章で説明しなくても分かるようになる。

#### B2.【高】メーターの形と意味が場所ごとに違う

| 場所 | 現状 |
| :--- | :--- |
| ホーム「マイクと送り先」 | 横長の緑一色バー。目盛り・ピーク・クリップ表示なし。進捗バーに見える |
| ヘッダー（詳細表示） | 「IN」「OUT」の下に丸い粒が2つずつ。量が読み取れない |
| 大型レベルメーター | 縦バー。-12〜-3dB で黄、-3dB 以上で赤（`LargeLevelMeter.tsx`）。目盛り（0 / -12 / -24 / -∞）はメーター下に横並び |
| フッター | 「マスター -6.9 dB」と幅数 px の縦バー2本 |

- **問題**：同じ音量が場所によって「緑」「黄」「読めない」になります。ホームの緑一色のバーで問題なく見えた声が、大型メーターでは黄色になります。どちらを信じればよいか分かりません。
- **改善案**：メーター部品を1つに統一する。
  - 目盛りはメーターに沿って付ける（-60〜0dBFS）。
  - ピーク保持と、クリップの点灯（押して解除）を付ける。
  - 色の閾値は1か所で定義し、すべてのメーターで同じにする。
  - ヘッダーの粒表示は細い横メーター2本（IN／OUT）に置き換える。

#### B3.【中】ラックのカードが、VST ホストとして情報が少なく、余白が多い

- **根拠**：カード表示は「有効」の小ラベル、名前、メーカー、ゲインのスライダー、「ミュート」「編集」です。名前とスライダーの間に大きな空白があります。カード表示と1行表示の差は、小ラベルとメーカーの有無だけです。
- **問題**：
  - トグル（有効）の隣の「有効／無効」の文字は、トグルの言い換えです。
  - トグルは実装上バイパスの切り替え（`enabled = !bypassed`）ですが、画面では「有効」と表示されます。隣の「ミュート」との違いも画面から分かりません。
  - VST ごとの遅延申告や、入出力のレベルが見えません。
  - 無効の VST は「編集」も押せません。設定を確かめてから有効にする、という操作ができません。
- **改善案**：
  - 1行表示に一本化する。名前の横に小さなメーターを置き、空白をなくす。
  - トグルは「バイパス」として見せる（電源アイコン）。「ミュート」が何を止めるかを ⓘ で示す。
  - 遅延申告があれば「3.2 ms」などの小バッジで示す。
  - 無効中も「編集」を押せるようにする（プラグイン側で可能な範囲で）。

#### B4.【中】フッターに意味の違うものが混在している

- **根拠**：フッターは左から「原音比較」、「マスター -6.9 dB」と小さなメーター、マイクのアイコンボタン（＝ボイスチェック）、「出力音量」スライダー、「ノイズ強 声」、「音声の詳細」、「VST有効」の順です。
- **問題**：
  - マイクのアイコンは一般に「マイクのミュート」を表します。ボイスチェックの入口として使うと、本番中に押し間違えます。
  - 「ノイズ強 声」の「声」は「声を守る」を指しますが、読み取れません。
  - 「VST有効」は押せない状態表示ですが、隣の「ノイズ強 声」は押すと設定が開きます。同じ見た目で振る舞いが違います。
- **改善案**：
  - フッターは本番中の操作に絞る：`原音比較｜出力メーター＋dB｜出力音量`（緊急ミュートは [DESIGN.md](./DESIGN.md) 2.5 に従いヘッダーの位置を維持）。
  - 状態（ノイズ低減・VST）は B1 のチェーン表示か、ヘッダーの状態表示に移す。
  - ボイスチェックの入口は、波形または「聴き比べ」のアイコンにする。

#### B5.【中】設定が狭いモーダルの中で長くスクロールする

- **根拠**：設定は幅約 520px のモーダルです。各タブの内容の高さは、オーディオ 992px、音づくり 1,094px、OBS 連携 852px、システム 1,830px（表示領域 443〜574px）でした。
- **問題**：設定項目が多いアプリで、ウィンドウの半分の幅のモーダルに閉じ込めると、見出しと操作の位置関係が把握しにくくなります。
- **改善案**：設定を全高のシート（左にタブの縦並び、右に内容）にする。各タブは「よく使う → まれに使う → 診断」の順を維持する。

#### B6.【低】ヘッダーの状態表示に内部用語

- **根拠**：「音声処理中」の下に「WASAPI」と表示されます。
- **改善案**：かんたん表示では表示しない。詳細表示では「48kHz · 5.3ms」のように、利用者が気にする値（サンプルレートとバッファの時間）を出す。WASAPI／ASIO は「音声の詳細」に任せる。

#### B7.【低】見出し「•• VST 構成」

- 見出しの前の「••」が、隣のドラッグハンドル（⠿）と似ていて、動かせる要素に見えます。装飾を外すか、セクションの見出しと同じ形式にします。

### D. 常時表示せず、ツールチップ（ⓘ）で出すべきもの

条件や限界の説明（[DESIGN.md](./DESIGN.md) 3.3 で「削ってはいけない」とされる範囲・条件）は、消さずに **ⓘ ボタンのポップオーバー** へ移すことを提案します。マウスを乗せるだけのツールチップはキーボードやタッチで読めないため、押して開く方式にし、既存のアクセシブルな名前の方針を守ります。

| 設定・音づくり | 「効きやすい／効きにくい」の黄色い枠（3行） |

### E. 不具合・事実との不一致（今回見つかったもの）

#### E1.【中】「内蔵ボイスチェーン」の説明の「リミッター」が、実装と合わない

- **根拠**：設定の説明は「ローカット、軽いコンプ、リミッターをその場で適用します。」です。実装（`src-tauri/src/audio_engine/core/dsp.rs` の `RtBuiltInVoiceChain::process_sample`）は、ハイパス → コンプレッサー（makeup gain あり）→ トーン補正 → **±0.98 での値の切り詰め（ハードクリップ）** です。先読みや release を持つリミッターではありません。
- **問題**：[COPY_GUIDELINES.md](./COPY_GUIDELINES.md) の「効果を誇張しない」に反します。叫び声などで歪みが出ても、利用者は「リミッターがあるから大丈夫」と考えます。
- **改善案**：文言を「ローカット・軽いコンプ・クリップ防止（音割れを完全には防げません）」に直す。本来のピーク保護は #99 で扱う。
- **関連**：#99 の本文は「内蔵処理に最終出力直前の専用ピークリミッターは見当たらない」としていますが、内蔵ボイスチェーン内のハードクリップに触れていません。#99 への補足が必要です。

#### E2.【中】保存済み構成の保護中、VST 追加画面が「一覧を取得できませんでした」になる

- **根拠**：エンジンに残っている VST 構成を引き継いだ状態（保存済み構成の保護中）で「VST を追加」を開くと、カテゴリ数（「すべて (4)」）は出ているのに、本文が「プラグイン一覧を取得できませんでした。元の詳細を確認し、再スキャンしてください。」になりました。「元の詳細（未翻訳）」を開くと、中身は日本語の保護中の通知（「保存済みVST構成を保護中です。…」）でした。
- **問題**：保護中の通知が、プラグイン一覧の取得エラーとして表示されています。再スキャンしても解決しません。
- **確認の限界**：仮の応答で再現した状態です。実機で同じ状態になるかは未確認です。
- **改善案**：ラックの保護状態と一覧の取得結果を別々に扱い、保護中は「追加すると自動保存の保護が解除されます」など、実際に起きることを示す。

#### E3.【低】「音量チェック」ボタンのアクセシブルな名前が違う

- **根拠**：表示は「音量チェック」ですが、名前は「開始は手動です。非表示にすると測定を停止します。」でした。
- **改善案**：名前を「音量チェック」にし、説明は `aria-describedby` に移す（A7 を採用するなら説明自体が不要）。

### F. 画面サイズを変えたときの表示

ウィンドウの最小は 900×600、既定は 1024×768 です（`src-tauri/tauri.conf.json`）。横方向のはみ出しや文字の切れは、どのサイズでもありませんでした。問題は「小さいと縦が足りない」「大きいと広さを使わない」「幅で操作の場所が変わる」の3つです。

#### 計測結果（かんたん表示のホーム）

| サイズ | ヘッダー＋フッター | 本文の表示域 / 内容の高さ | 本文の幅（画面比） | 文字が消えて記号だけになるボタン |
| :--- | :--- | :--- | :--- | :--- |
| 900×600 | 64＋83px（画面の 25%） | 453 / 707px | 858px | 設定、ヘルプ、ボイスチェック、（詳細表示で）大型メーター。ロゴ文字も消える |
| 1024×768 | 64＋64px | （未計測。内容がスクロールする） | 896px | 設定、ヘルプ、ボイスチェック、（詳細表示で）大型メーター |
| 1280×720 | 64＋64px | 592 / 723px | 896px（70%） | ボイスチェック |
| 1920×1080 | 64＋64px | スクロールなし | 896px（47%） | ボイスチェック、大型メーター、テーマ |
| 2560×1440 | 64＋64px | スクロールなし | 896px（35%） | 同上 |

#### F1.【高】最小サイズで、設定とボイスチェックの操作部分がほとんど見えない

- **根拠**（900×600）：
  - 設定モーダルは画面いっぱいの高さになりますが、内容のスクロール域は **300px**（オーディオタブの内容 992px の 30%）です。タブの帯もスクロール域の中にあり、下にスクロールするとタブが見えなくなります。下部の「保存して開始」「セットアップを開く」が約 120px を占めます。
  - ボイスチェックは、スクロール域 437px に対して内容が 1,154px あります。録音した後に必要な「試聴先」と「再生」は、最初の表示では見えません。
  - ホームはヘッダーとフッターで画面の 25% を使い、「声を整える」カードは途中で切れます。
- **問題**：ノートPCで小さいウィンドウを OBS の横に並べる配信者は、この状態で設定を変えることになります。タブを切り替えるたびに上へ戻る必要があります。
- **改善案**：
  - 設定は B5 の全高シートにし、タブを左の縦並び（スクロールしても固定）にする。
  - 主ボタン（「保存して開始」）は1行の固定バーにし、「セットアップを開く」はシステムタブなどへ移す。
  - ボイスチェックは「録音」と「聴き比べ」を1画面に収める。注意書き（C 章）を閉じれば、多くは収まる。

#### F2.【高】ウィンドウ幅で、操作の場所と名前の有無が変わる

- **根拠**：
  - ヘッダーの「設定」「ヘルプ」の文字、テーマ切り替え、入力ゲインのスライダーは 1280px 以上でだけ表示されます（`Header.tsx` の `xl:`）。**既定の 1024px はこの境目より狭い** ため、既定のウィンドウでは記号だけ・入力ゲインなしです。
  - ロゴの文字は 1024px 未満で消えます（`lg:`）。
  - フッターは 1024px 未満で2行に折り返し、2行目に「VST有効」だけが置かれます（フッター 64px → 83px）。「ノイズ強 声」は 1024px 未満で「ノイズ強」になり、「声（声を守る）」の情報が消えます（`MasterBar.tsx` の `lg:`）。
- **問題**：
  - [DESIGN.md](./DESIGN.md) 2.5「本番中の操作は、どの表示でも同じ位置に常設する」の考え方からすると、ウィンドウを少し狭めただけで入力ゲインが別の場所へ移るのは避けるべきです。
  - 最も多く使われる既定サイズが、最も情報の少ない側に入っています。
- **改善案**：
  - 境目を既定サイズに合わせる。「既定の 1024px で全部の文字ラベルが出る」ことを基準にし、それより狭いときだけ縮める。
  - 縮めるときも、操作は消さずに「…」メニューにまとめる（入力ゲインはメニューの中に残す）。
  - フッターは折り返さない設計にする（B4 の整理で項目を減らせば、900px でも1行に収まる）。

#### F3.【中】大きい画面で、本文が中央の細い列に固定される

- **根拠**：本文は最大幅 896px（`AppShell.tsx` の `max-w-4xl`）で中央寄せです。1920px では画面の 47%、2560px では 35% しか使いません。設定モーダルも 1920×1080 で幅約 670px のまま、内容がスクロールします（表示 708px / 内容 992px）。
- **問題**：
  - VST を何本も並べる人や、大型メーターを常時出したい人にとって、左右の余白が使われません。
  - 「原音比較」（左下）と「出力音量」（右下）が、2560px では約 2,400px 離れます。本番中に視線と手を大きく動かすことになります。
  - 文字は 12px 中心のままで、2560×1440（100%）では小さく見えます。
- **改善案**：
  - 1440px 以上では2列にする。例：左にホームの状態帯と「声を整える」、右に VST チェーン（B1）。大型メーターは右端に常設できるようにする。
  - フッターの本番中の操作（B4）は中央または左にまとめ、画面の両端に分けない。
  - 設定シート（B5）は大きい画面で高さいっぱいまで伸ばし、スクロールを減らす。

#### F4.【低】起動直後の読み込み画面が、テーマと違う明るい色で出る

- **根拠**：既定テーマ（オーロラ・暗い配色）なのに、起動中の「音声エンジンを起動しています…」の画面は明るい背景で表示され、その後に暗い画面へ切り替わりました。
- **問題**：暗い部屋で配信前に起動すると、一瞬まぶしく光ります。
- **改善案**：保存済みのテーマを、最初の描画より前（`index.html` の背景色、または起動スクリプト）で適用する。
- **確認の限界**：開発サーバーでの観察です。配布版の起動時に同じ色になるかは未確認です。

## 守るべき良い点

| 例 | 理由 |
| :--- | :--- |
| VST 追加画面（検索・カテゴリ・最近・お気に入り） | 一般的なプラグインブラウザの形で、迷わない |
| 「音声処理の詳細」の要約＋「診断情報」の折りたたみ | 必要な値だけを先に出し、内部計測を奥に置いている |
| セットアップ1画面目の4択カード | 用途から入る形で、専門用語がない |
| 緊急ミュートの常時の文字ラベル | 前回 H1 の改善。本番中に読まずに押せる |
| ノイズ低減の「効きやすい／効きにくい」 | 範囲の説明として正確（置き場所だけ D で移す） |

## 改善の進め方（提案）

小さく検証できる単位に分けます。音声処理の変更は含みません（E1 の文言修正を除く）。

1. **事実と違う文言・名前の修正**（E1、E3）と、#99 への補足。
2. **言い換え・常時の注意書きの削減**（C の表）と、**ⓘ ポップオーバーへの移動**（D の表）。共通の ⓘ 部品を先に作る。
3. **メーター部品の統一**（B2）。ホーム・ヘッダー・大型メーター・フッターを1つの部品に置き換える。
4. **フッターの整理と状態表示の移動**（B4、B6）。
5. **ラックの1行化とバイパス表現**（B3、B7）。
6. **信号の流れの表示と、詳細表示での「声を整える」**（B1、A1、A4）。ホームの再構成（A2）と合わせて設計する。#94 の準備導線と画面の位置を調整する。
7. **ホットキーの独立タブとキー入力方式**（A5）。
8. **設定のシート化と画面サイズ対応**（B5、F1、F2、F3）。表示が切り替わる幅を既定サイズ基準で決め直し、大きい画面の2列表示を合わせて設計する。F4 は単独で直せる。
9. **音楽鑑賞ユーザーの目的追加**（A3）。セットアップ・既定値・文言の切り替えを含むため、別 Issue で設計する。
10. **小さな導線の改善**（A6、A7）と **E2 の調査**。

各段階で、900×600・1024×768・1280×720・1920×1080 の表示、キーボード操作、日本語／英語、既存テスト（文言を検証しているテストを含む）を確認します。
