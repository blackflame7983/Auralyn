# GPUI 移行の決定

GPUI で画面を作り直すときの、理由つきの決定。新しい決定は上に足し、取り消すときは消さずに取り消しの理由を書く。
書き方の知見は [knowledge.md](knowledge.md)。移行の分岐点は [audio-session-controller.md](../plans/audio-session-controller.md) 13.2（J-11）。

| 日付 | 決定 | 理由 |
| :--- | :--- | :--- |
| 2026-11-25 | VST の画面は、並び（上から音が通る順）と追加だけにする。1つずつ ON/OFF・上へ／下へ・編集・削除。追加は、スキャンした候補を検索できる選択で選んで「VSTを追加」。並べ替えはドラッグではなく上下のボタン。並びはエンジンの命令のスレッドが持ち、変わるたびに全体を画面へ送る。子が落ちたあとの開始では、同じ順・同じ ON/OFF で読み直す。並びはまだ保存しない | GPUI 版だけで VST を使える最小の形。Tauri 版の並びの保存は webview の `localStorage` にあり、GPUI 版からは読めない。保存（VST の中の設定を含む）・音量・ミュート・プロファイル・テンプレートは次に足す |
| 2026-11-25 | 接続の画面は、接続方式・マイク・出力先の3つだけを選ばせ、「音声を開始」で開始する（開始できると Tauri 版と同じ `last_audio_config.json` に保存される）。周波数とバッファは同じ接続方式なら保存した値、チャンネルの割り当ては同じ機器のときだけ引き継ぐ。ASIO はドライバー1つを選び、出力は同じドライバーにする。動いている間は機器を替えさせない（先に止める） | GPUI 版だけで設定から使い始められる最小の形。周波数・バッファ・チャンネル・アプリの音声・再検出は、必要になった順に足す |
| 2026-11-25 | 窓の外枠は Tauri 版と同じ並び（左のレール・中央の先頭の帯と行き先の画面・右の本番中の操作の列）にする。まだ作っていない行き先は、名前と「今までの版で設定する」案内だけを出す。開始・停止は帯の右のボタンにし、状態の札は色の点と文字で示す。保存した設定が無いときも、ボタンは「音声を開始」（押すと設定を読み直す。接続の画面を作るまでは、今までの版で設定する） | 行き先を先に揃えると、画面を1つずつ移しても利用者の道筋が変わらない。Tauri 版の開始と停止は状態の札のメニューの中にあるが、GPUI 版では帯に直接置く（メニューは、ヘルプ・終了などを移すときに決める）。確認用の欄は右の列から設定の画面へ移した。レールは `gpui-component` の `Sidebar` を使わず `Button` で組む（`Sidebar` を畳むとアイコンだけになり、アイコンの下に短い名前を出す 76px の形にならない） |
| 2026-11-25 | 音声の開始・停止の状態（未設定・停止中・開始中・実行中・停止中）は `auralyn-ui-model` の `session` で決める。結果を待つあいだはボタンを押せなくする。起動時は保存した設定で自動で開始する（試作と同じ） | 状態の移り方を GPUI なしの試験で確かめるため。重ねて押しても同じ命令を送らない |
| 2026-11-25 | 音の流れの帯の「加工後」は、レベル通知の `processed`（出力音量・ピーク保護・ミュートの前）で描く。子が送らないとき（テスト音など）は出力で代える | 出力のメーターは出力音量とミュートで変わり、加工の前後の比較にならない（PR #865 で `processed` を足した理由）。Tauri 版の帯は出力のままで、変えない |
| 2026-11-25 | 音の流れの帯とメーターのオーロラの塗りは、横の緑→青緑の2色にする。Tauri 版の帯は縦の青緑→緑→青緑 | GPUI の `linear_gradient` は2色までで、グラデーションはパスの外接矩形に掛かる。上下を別のパスに分ければ近づけられるが、見た目を決める段階で判断する |
| 2026-11-25 | ピークは最後に上がった時刻から2秒保持し、そのあと毎秒 20 dB で下げる（0 dBFS から目盛りの下端まで3秒）。Tauri 版（`useMeterLevels.ts`）は変えない | 写した規則（2秒ごとに0.9倍）は −60 dB まで約2分かかり、無音にしても数字が下がらないと利用者が指摘した（試作の判定の項目1）。Tauri 版は置き換えるので、同じ修正をしない |
| 2026-11-25 | GPUI 版を `src-gpui/` として main に入れ、本実装を始める。振る舞いの規則は `src-tauri/crates/auralyn-ui-model` へ移す。`src-gpui` は `src-tauri` と別のワークスペースのまま、ビルド領域は `src-tauri/target` を共有する | 試作の判定（[gpui-prototype-checklist](../plans/gpui-prototype-checklist.md)）で13項目中 合格10・条件付き3・不合格0。利用者が作る方向へ進めると決めた。別のワークスペースにするのは、GPUI の依存で Tauri 版の `Cargo.lock` とビルドを変えないため |
| 2026-11-25 | 色・角丸は `design/tokens.json` を `auralyn-core` 経由で読み、GPUI の側に値を書かない | 手で写すとトークンとのずれを検出できない。正本を JSON 側へ移すか（`index.css` を生成物にするか）は未決 |
| 2026-11-25 | 画面の振る舞いの規則（メーターの読み・一言の判定など）は、GPUI に依存しない `auralyn-ui-model` に置く。部品はその結果を描くだけにする | GPUI なしの `cargo test` で確かめられ、AI や人が部品を直すときに読む範囲が小さくなる。GPUI の判定が通ったら `src-tauri/crates/` へ移す（2026-11-25 に移した） |
| 2026-11-25 | 依存の向きは アプリ → 部品（GPUI）→ 振る舞い・トークン → `auralyn-core` の一方向にし、クレートの境界で守る | 逆向きの依存を Lint ではなく `cargo` で防げる |
| 2026-11-25 | （取り消し：同日、上の `src-gpui/` の決定で置き換えた）試作は main に入れず、別のブランチだけに置く。main は Tauri の構成のまま | J-11 の分岐点の方針。判定が済んだので取り消した |
| 2026-11-25 | GPUI の判定が通れば Tauri は捨てる。TypeScript 側との共存は、GPUI の動作や検証にどうしても必要な箇所だけ考える | 利用者の方針 |
