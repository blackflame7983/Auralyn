# 歌向け内蔵処理の設計・検証境界

Issue #34 の設計。2026-10-23時点では実装・検証を進めているため、この文書だけを完了の証拠にしない。実行結果は [ISSUE_BACKLOG_PROGRESS.md](ISSUE_BACKLOG_PROGRESS.md) に記録する。

## 操作と処理

既存のBroadcast／Warm／Brightと、歌向けの下書き・適用を分ける。歌向け初期値は、利用者が選んだときだけ下書きへ入れる。画面を開いたことを理由に現在値を初期化しない。

| 操作 | 範囲・初期値 | 処理上の意味 |
| --- | --- | --- |
| 低音の整理 | 40〜160Hz、80Hz | ハイパスの周波数。低い声の基音も影響を受けるため、上げれば常に良いとは扱わない |
| 音量差を整える量 | 0〜100%、35% | 左右の絶対値の大きい側で検出する連動コンプレッション。逆相で検出を打ち消さず、自動の音量持ち上げを加えない |
| 声の明るさ | −3〜+3dB、0dB | 高域シェルフ。旧プリセットのトーン調整へ名前だけを付け替えない |

HPFは2次、Qは1/√2。明るさは3kHzを基準とする高域シェルフ（低いレートではNyquist近傍を避けてレートの40%以下）で調整する。
音量差の量をd（0〜1）とすると、比率は1+2d、しきい値は−12−12d dBFS、検出のattack／releaseは12／120ms。係数は時定数20msで平滑化し、有効・無効の混合は約20msのランプを使う。これらは実装上の初期設定であり、個人の歌声に最適と検証した値ではない。

通常経路は入力チャンネル選択・入力ゲイン、ノイズ低減、内蔵処理、既存VST、出力ゲイン・ミュートの順序を維持する。内蔵処理の選択でVSTの追加・削除・並べ替え・再ロードを呼ばない。ノイズ低減やVSTのコンプレッサーを併用すると、音色や音量変化が重なる。

処理係数と固定領域は制御側で準備し、音声callbackでは確保・待機・ログ出力を行わない。設定値を平滑化する。既存3プリセットの処理と旧設定の既定OFF・amount 0.7を維持する。内蔵リバーブは #35 の別段階とする。

歌向けフィルターはIIR方式で、固定長の音声ブロックを貯めてから返す処理を追加しない。追加の蓄積遅延0framesは、周波数に依存する位相変化や群遅延まで0という意味ではない。

## 下書き、試聴、適用、保存

1. 適用済み設定と世代を取得し、下書きの変更予定を示す。
2. 封印済み録音の原音から、候補の内蔵処理だけを別workerで生成する。生成・試聴で通常送出の設定を変えない。
3. 独立した試聴先で原音と候補を比較する。試聴の音量合わせと、通常の送出音量確認を区別する。
4. 取得した世代が現在値と一致するときだけ適用する。受理とRT反映を区別し、反映待ちを成功表示で埋めない。
5. 直前の適用は1回戻せる。ほかの手動変更・プロファイル適用・エンジン再起動を越えて古いundoを使用しない。
6. 保存対象はbackendの適用済み設定。下書きや試聴バッファは既存プロファイルへ保存しない。

候補は録音ID、設定世代、下書き変更、試聴sessionへ結び付ける。編集・録り直し・条件変更・画面終了では取消し、遅れて完了した候補で新しい状態を巻き戻さない。設定とボイスチェックを往復しても下書きは保持するが、終了した試聴sessionのcandidate IDは再利用しない。

候補へは入力ゲイン適用後・音声処理前の録音を使用し、ノイズ低減・外部VST・出力ゲインを含めない。通常送出や録音済みprocessedと同じ音とは案内しない。候補作成完了は「聴いた」「音質が良くなった」の証拠ではない。

## ピークと評価

出力ゲインの平滑化を含め、実際にデバイスへ渡すsample値からピークを取る。sample clampやsample peakはtrue peak保証ではなく、入力過大・後段の音量増加・機器側の飽和まで防げるとは扱わない。

既知信号では有限性、DC・周波数応答、ステレオ逆相・片チャンネル、初回・reset、過大入力、RT割当、取消・世代競合・旧設定互換を確認する。CPU・保持メモリはDSP単体とエンジン全体を分ける。debugでの短時間実機成功からreleaseの最悪時間や長時間の安定性を保証しない。

今回は利用者の指定により歌唱ファイルを用意しない。小声・息・ロングトーン・サ行・大声などへの聴感、初期値の好ましさ、音量をそろえた歌唱比較は未確認として残す。


## 独立した軽量残響（#35）

`active` は声の音作りだけのスイッチで、`reverb.enabled` は独立する。残響だけをONにしてもBroadcastのコンプやmakeupは有効にならない。旧APIの声設定変更では残響を保持する。旧プロファイルで内蔵FXカテゴリがあり残響項目がない場合はOFFへ戻し、カテゴリ自体がない場合は現在値を維持する。

処理順はNR→声の音作り→残響→VST→出力ゲイン／全体ミュート。全体bypassは従来どおりVSTだけに作用する。独自4本FDNを使い、第三者コード・IR・素材は取り込まない。既定はOFF、量8%、減衰時間1.2秒、高域減衰0.5。範囲は量0～25%、減衰0.3～2.5秒、高域減衰0～1。

各delayは約29.7／37.1／41.1／43.7ms、帰還行列は直交Hadamard、帰還係数は `10^(-3*delaySeconds/decaySeconds)`。係数とringを非RT側で準備し、操作では再確保しない。ringだけの保持量は192kHzで約114KiB、384kHzで約228KiB。DSPは384kHzまで扱うが、既存録音経路の対応上限192kHzを拡張するものではない。

残響入力は80Hz DC除去と±1保護、固定inject係数0.125、ring書込は±4、wet出力は符号付き4線和×1/16。dryを変えず `dry + mix*wet` とする。追加分は各ch±0.25以内、dryが±1以内なら合成は±1.25以内というsample値の境界を設ける。内部保護に当たる入力では歪み得る。makeup、出力リミッター、true peak保証、音量一致としては案内しない。非有限値は残響へ入れず、有限巨大dryとの加算も有限範囲へ収める。

送入量と既存tailの出力は内部で分ける。通常OFFは約20msのwet出力フェード後にtailを消去する。全体ミュートは直ちに最終出力を無音にしてtailを消去し、ミュート中の入力で新しいtailを生成しない。processed録音は出力ゲイン／ミュート前だが、ミュート中の内蔵残響はこのため含まれない。解除後に以前のtailを再生しない。停止・レート変更ではringを持ち越さない。resetはvalid-countを戻し、RTで巨大バッファを埋め直さない。外部VSTのtail処理はこの保証の対象外。

候補では同じDSPを使い、原音の後に `2*decaySeconds+100ms` の有限tail窓を追加し、末尾20msをフェードする。元の録音は不変で、候補A側だけ同じ長さのゼロを追記する。試聴音量合わせはこのゼロ延長とtailを含む共通全長で算定し、減衰だけを許す。`sourceFrames` は原音、`renderedFrames` は実際に封印した総frame数。64MiBは候補1組（raw/processed、各stereo f32）のpayload上限で、原本や旧worker結果を含むプロセス総量ではない。時間／レートclampによる切詰めはせず、超過は生成前に拒否する。

先読みの追加遅延は0 samples。最初の反射までの時間、減衰設定、候補の有限tail窓は別の量で、減衰設定が厳密な聴感上の残響長を保証するものではない。歌唱での聴感・操作時クリック・CPU最悪時間・実機連続運転は、単体テストや設計だけで完了扱いにしない。
