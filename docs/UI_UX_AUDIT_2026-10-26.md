# UI/UX・デザイン監査（2026-10-26）

対象は `main` の HEAD（`c668598`、PR #80〜#87 の UI 修正を含む）時点の画面です。判断基準は [DESIGN.md](./DESIGN.md)、[COPY_GUIDELINES.md](./COPY_GUIDELINES.md)、[BRANDING.md](./BRANDING.md) です。前回の監査は [UI_UX_AUDIT_2026-10-25.md](./UI_UX_AUDIT_2026-10-25.md) です。

この文書は監査時点の判断材料です。修正の完了や現在の実装を示す証拠として扱わないでください。

## 確認方法と限界

- **実画面**：Vite の画面を内蔵ブラウザで開き、Tauri の通信を仮の応答に置き換えて描画しました（仮応答の仕組みはリポジトリ外に置き、コードは変更していません）。寸法は 1024×768 と 900×600、テーマはダーク・ライト・ゲーミング、表示は「配信向け・かんたん」と「VST・詳細」の両方を確認しました。
- **操作して確認した画面**：メイン、設定の全タブ、セットアップの全4ステップ、ボイスチェック、接続診断、ヘルプメニュー、音量チェック、大型メーター、VST ラック（3件読み込み）。
- **コードだけで確認した画面**：OBS ガイド、プラグインブラウザ、プロファイル管理。
- **確認していないこと**：実機の音声エンジンと OBS に接続した状態、英語表示、スクリーンリーダーでの読み上げ。
- 仮の応答による見え方（OBS 未接続なのに「接続済み」、ホットキー取得エラーなど）は指摘から除いています。

## 総評

前回監査の指摘は、短期間でかなり解消されています。

- 本番中の操作（緊急ミュート・原音比較）に文字ラベルが付いた。
- 音づくりタブがノイズ低減から始まるようになった。
- 設定の各タブの長さは半分程度になった（システムタブは 3,087px → 1,807px）。
- コンポーネント内の固定色の直書きがなくなった。
- 用語の統一が進んでいる。

文言のレベルでは、[DESIGN.md](./DESIGN.md) の方針がほぼ実装に届いています。

一方で、**画面構成のレベル**に課題が残っています。機能を足すたびに「設定モーダルのタブ」や「メイン画面の折りたたみ」へ積んできたため、次の状態になっています。

1. **かんたん表示のメイン画面は、案内カード2枚と空白だけ。** 主な作業（整える・聴く・音量を確かめる）は、すべてモーダルの中にあります。
2. **「確かめる」の要であるレベルメーターが、メイン画面にほぼありません。** フッターに幅 12px のバーがあるだけです。
3. **既定テーマが shadcn の標準色のままで、ブランドの世界観（Aurora / Ethereal）が出ていません。** ブランドの配色は「ゲーミング」という別名のテーマに閉じ込められています。

ターゲットは音響の専門家ではない配信者です。最も効くのは文言の調整ではなく、**メイン画面を「つなぐ → 整える → 確かめる → 本番」の操作盤にすること**です。

## 指摘一覧

重要度は、**高**＝迷い・誤操作・本番事故に直結する、**中**＝理解に時間がかかる・不統一、**低**＝品質・一貫性の問題、です。

### 高

#### A1. かんたん表示のメイン画面が、主な作業を担っていない

- **根拠**：かんたん表示のメインにあるのは、カード「1. 声を整える」「2. 録音して聴く」と、折りたたみ「本番の歌・雑談モード」「VSTで音を調整する」だけです。1024×768 では画面の約6割が空白でした。ノイズ低減と内蔵ボイスチェーンは設定モーダルの「音づくり」タブ、聞き比べはボイスチェックのモーダルにあり、調整しながら確かめるにはモーダルを開閉して行き来する必要があります。
- **改善案**：かんたん表示のメインを3段のパネル構成にする。
  1. **入力パネル**：マイク名、リアルタイムの入力メーター、「声が届いています」の状態表示、マイク音量。
  2. **声を整えるパネル**：ノイズ低減の ON/OFF と強さ（弱／強）、内蔵ボイスチェーンのプリセット（配信／低め／明瞭）と「かかり具合」。学習・会場・声を守るなどは「詳しく調整」から設定タブへ移動する。
  3. **確かめるパネル**：「録音して聴き比べる」（ボイスチェックを開く）と、出力メーター・音量チェックを1枚にまとめる。
- 設定モーダルの音づくりタブは残し、メインと同じ部品を共有する。機能は重複しない。

#### A2. 入力レベルを確認できる場所がない

- **根拠**：
  - セットアップの「入力」ステップにはメーターがありません。入力レベルが見えるのは、4ステップ目の「マイクの音を流して確認」の間だけです。
  - メイン画面のメーターは、フッターの出力メーターだけです。
  - 詳細表示のヘッダーの入力ゲインとミニメーターは `hidden 2xl:flex` のため、1536px 未満では出ません（`Header.tsx` 199行）。既定の 1024px では表示されません。
- **問題**：「マイクを選んだのに音が来ているか分からない」は、配信初心者がつまずく典型的な場面です。ヘルプメニューの説明「VST ラック・入力ゲイン・メーターを表示」（`header.advancedHint`）は、既定の幅では事実と違います。
- **改善案**：
  - セットアップの入力ステップに、入力メーターと「話してみてください」の表示を常時出す。
  - A1 の入力パネルに入力メーターを常設する。
  - 詳細表示のヘッダーのゲインとメーターは `xl`（1280px）以下でも出す。入りきらない場合はメーターだけを残す。

#### A3. トーストがヘッダーの本番操作に重なる

- **根拠**：`<Toaster position="top-right">`（`App.tsx` 262行）のため、900px 幅でトーストが「緊急ミュート」「セットアップ」の上に重なりました。トーストは最大10秒表示される箇所があります。
- **改善案**：トーストを `bottom-right` へ移し、フッターの高さ（64px）分を `offset` で空ける。「本番中の操作の上に通知を出さない」ことを [DESIGN.md](./DESIGN.md) 2.5 に追記する。

#### A4. フッターの「ノイズ弱」が、状態表示に見えるモード切替ボタン

- **根拠**：フッターの小さなバッジは、押すたびにノイズ低減のモードを 弱 → 学習 → 会場 → 強 → OFF の順で切り替えます（`MasterBar.tsx` 648〜666行）。順序の説明はツールチップ（`master.nrHint`）にしかありません。「学習」は学習を終えるまで効果が薄く、「OFF」はノイズ低減が止まります。
- **問題**：状態を確認するつもりで押すと、本番中の音が変わります。前回監査 H5（状態表示と操作の兼用）と同じ型の問題です。
- **改善案**：フッターは状態表示だけにし、クリックで音づくりの欄（A1 のパネル）へ移動する。循環切替は廃止する。素早く切り替えたい需要には、ホットキー「ノイズ低減 ON/OFF」を用意する。

#### A5. 「本番の歌・雑談モード」が、未整理のままメイン上部にある

- **根拠**：かんたん表示でもメインの2番目に常設されています。開くと、次のような説明文と、装飾のないボタン・チェックボックス・下線リンクが並びます。
  - 「デバイス・VST・NR・ゲイン・ミュートを変えず、登録した内蔵処理と残響だけを切り替えます」（`settings.LiveModeControls.215`）
  - 「現在は個別設定（Custom）です」
  - 「本番保護を有効にする（外すと解除）」（`settings.LiveModeControls.229`）
  - 「モードの状態を再取得」

  同じ部品が設定の音づくりタブにもあります。
- **問題**：かんたん表示に「NR」「Custom」が出ています（[DESIGN.md](./DESIGN.md) 3.6）。モード未登録でも「歌にする」が押せるように見えます。「本番保護」という重要な状態が、チェックボックス1つで見た目に表れません。
- **改善案**：
  - モードを登録するまでは、メインに出さない（設定の音づくりタブで登録するとメインに出る）。
  - 登録後は、ヘッダー近くに「歌／雑談」のセグメント切替と「本番保護中」のバッジとして出す。本番中に使う操作として、緊急ミュートと同じ「常設の本番操作」の扱いにする。
  - 「再取得」は診断用の操作として折りたたみへ移す。

### 中

#### B1. 既定テーマがブランドを表現していない

- **根拠**：
  - 既定はダークテーマ（`useTheme.tsx`）で、`index.css` の `.dark` は shadcn の標準 slate そのものです（主色はほぼ白）。
  - [BRANDING.md](./BRANDING.md) の Deep Abyss Blue / Aurora Cyan / Mystic Purple が主役になるのは「ゲーミング（ハイコントラスト・発光）」だけです。README の実画面もゲーミングテーマで撮影されています。
  - 既定テーマでブランド色が見えるのは、ロゴの「lyn」と背景のぼかしだけです。
- **改善案**：
  - 既定のダークを「Aurora」テーマへ置き換える。背景は Deep Abyss Blue 系、主色（`primary`）は Aurora Cyan、補助に Mystic Purple。
  - 現在の「ゲーミング」は、発光を強めたバリエーションとして残すか Aurora に統合する。
  - 状態色（`warning`・`success`・`destructive`）は分けたまま維持する（[DESIGN.md](./DESIGN.md) 5.1）。
- README・配布ページ・アプリの見た目が揃い、「Ethereal Clarity」の約束が初回起動から伝わる。

#### B2. 状態色の意味が揃っていない

- **根拠**：
  - フッターの「VST有効」（`master.vst`）は `warning`（琥珀色）です（`MasterBar.tsx` 732〜736行）。VST が効いているのは正常な状態です。
  - 音量チェックの「測定は停止中です」も琥珀色でした。
  - [DESIGN.md](./DESIGN.md) 5.1 は、`warning` を「原音比較中、未確認の項目」と定めています。
- **改善案**：正常系は `success` か中立色、「原音比較中」だけを `warning` にする。待機中は `muted`。フッターのラベル「ノイズ低減ON（設定）」（`master.nr`）の「（設定）」は意味を足していないので削る。

#### B3. 同じ領域への入口が、名前違いで散らばっている

| 機能 | 入口 |
| :--- | :--- |
| OBS | メイン「OBSを整える」（設定の OBS 連携タブを開く）、ヘルプ「OBS連携ガイド」（別モーダル）、設定「OBS連携」、セットアップ「OBSで確認する」、接続診断「OBS（配信・録画）」 |
| 音量 | フッターの出力音量（アイコンだけ）、「音量チェックを表示」のチェック → パネル → 「測定する」「音量を合わせる」 |

- **改善案**：
  - OBS は「OBS 連携」に名前を統一し、ガイドとタブを1つにする（ガイドはタブ内の「手順を見る」）。
  - 「OBSを整える」は表示切替の行から外し、A1 の構成の中で「つなぐ」の段に置く。
  - 音量チェックは、チェックボックスでパネルを出す二段階をやめる。A1 の「確かめる」パネルに「音量をチェック」ボタンとして置く。

#### B4. ボイスチェックで、録音する前に試聴先の設定を迫られる

- **根拠**：
  - モーダルを開くと、「録音開始」の直下に「通常のマイク送出を続けながら、別の出力で聴く」の枠が出ます。中には試聴先の選択、安全確認のチェック、再準備・取得の2ボタン、注意文2つがあります。
  - 波形の表示欄と「加工前（Raw）／加工後（Processed）」はその下にあります。中身の高さは 1,159px、表示領域は 588px でした。
  - 「Raw／Processed」「通常送出」は、[DESIGN.md](./DESIGN.md) 第4章で使わない表記です。
- **改善案**：
  - 順序を「録音 → 波形 → 加工前／加工後を再生」にする。試聴先は再生ボタンの横に「試聴先：ヘッドホン（Realtek）▼」として置く。
  - 既定の試聴先には、仮想ケーブルでない既定の出力機器を自動で選ぶ（仮想ケーブルの判定は `useVoiceCheck.ts` 107行に既にある）。
  - 安全確認のチェックは、仮想ケーブルらしい機器や不明な機器を選んだときだけ求める。
  - 表記を「加工前／加工後」「マイクの音」に揃える。

#### B5. VST ラックの「シンプル／詳細」が、表示モードと逆に感じられる

- **根拠**：
  - ラック内の切り替えで「詳細」（`rack.detailed`）にすると、1行の密なリストになります。「シンプル」（`rack.simple`）は縦に大きなカードで、ゲインのラベルと ON/OFF の位置も変わります。
  - ボタンには、今の状態ではなく切り替え先の名前が出ます。
  - かんたん表示では見出しが「かんたんエフェクト」（`rack.simpleTitle`）です。用語集の正規名は「VST 構成」です。
  - 追加ボタンは、空のときは「VSTを追加」、1件以上では「エフェクトを追加」です。
- **改善案**：切り替えを「カード／リスト」の2択のセグメントにし、今の状態を `aria-pressed` で示す。ON/OFF・ゲイン・ミュート・編集の並び順をどちらの表示でも同じにする。見出しは「VST 構成」、追加ボタンは「VSTを追加」に統一する。

#### B6. OBS 連携タブの構成

- **根拠**：
  - 先頭は接続先の入力欄3つと、4文の注記（「入力欄は保存済みの次回接続先です。既存の接続先を確認した値ではありません…」）です。
  - 見出し「OBS の設定を確認・変更」が、その操作ボタン（「変更予定を確認する」）より後に出ます。
  - その下に、番号付きのボタン「2. 接続テスト」が単独であります（「1.」はありません）。
  - 「OBS WebSocket v5 (OBS 28+) が必要です」は、接続済みでも常に表示されます。
- **改善案**：
  - 「接続（状態＋接続／切断）→ 確認（接続テスト）→ 変更（変更予定を確認・適用）→ 連動（シーン）」の順にカードを分ける。
  - 接続先の入力欄と注記は、未接続のときだけ開く折りたたみにする。
  - WebSocket の要件は、接続に失敗したときだけ出す（[DESIGN.md](./DESIGN.md) 3.4）。

#### B7. 接続診断が、セットアップで選んだ用途をもう一度聞く

- **根拠**：接続診断の最初の画面は「まず用途を選んでください」（Discord／OBS／その他アプリ／とりあえず聴きたい）です。セットアップの1ステップ目でも同じ質問に答えています。
- **改善案**：セットアップで選んだ用途を初期値にし、「用途を変える」は小さなリンクにする。

#### C2. 視覚的な一貫性

- **絵文字**：`TroubleshootModal.tsx` に ✅ ⚠ が残っています（[DESIGN.md](./DESIGN.md) 5.4）。
- **極小文字**：`text-[8px]` などの任意サイズが22か所あります。フッターの L/R ラベルは 8px です。最小を `text-xs` に揃えます。
- **装飾のない操作部品**：`LiveModeControls` などで、`className="underline"` だけのボタンが15か所あります。`Button` の `variant="link"`／`ghost` に寄せます。
- **フォント**：`--font-sans` は "Inter", "Noto Sans JP" を指定していますが、フォントを同梱していません。Windows では別のフォントで表示され、英数字と和文の印象が揃いません。同梱するか、システムフォント（"Segoe UI", "Yu Gothic UI"）を明示します。
- **メインの幅**：`max-w-4xl mr-auto ml-0` で左寄せのため、1280px 以上では右側が大きく空きます。A1 で2列にするか中央に寄せます。
