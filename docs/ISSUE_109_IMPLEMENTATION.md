# ホームと VST ラックの整理（Issue #109）

## 設計の比較

再訪時の主目的は、今の状態と次の確認を見てから、音づくりや VST を操作すること。初回の入出力選択は既存のセットアップが担当する。

1. 準備・入力・処理を別カードに分ける案は、各項目を詳しく説明しやすいが、状態と主操作が縦に分散する。
2. すべてを信号チェーンの各段に移す案は順序を理解しやすいが、準備確認の条件と既存操作の大きな組み替えが必要になる。
3. 準備状態と入出力を一つの領域にまとめ、その下に固定の5段と既存の調整・1行ラックを置く案は、既存の準備判定と操作を維持しながら順序を示せる。今回はこの案を採用する。

## 実装と判断

- 既存の `usePreparation` と準備段階の判定・確認・主操作を変更せず、重複していた入出力帯を準備領域にまとめた。初回は既存のセットアップ、再訪時は準備状態と次の操作を使う。
- かんたん／詳細の両方に、入力 → ノイズ低減 → 内蔵ボイスチェーン → VST → 出力の固定段を表示する。NR・内蔵処理・VST は既存 stats の現在の世代に結び付く設定状態のみを示し、未取得や停止を OFF にしない。設定状態と稼働・受け側への到達を区別する。自分用と配信側の処理を分ける場合は経路が分岐する旨を併記する。
- 既存の MasterBar の stats を参照し、新しい poll や音声処理を追加していない。既存の声の調整、ミュート、原音比較、ラック操作、本番保護の入口を維持する。
- ラックの表示選択を保存済みの場合は保持し、未選択時は1行表示を既定にした。詳細表示も手動で選べる。既存のドラッグ、ON/OFF、ゲイン、ミュート、編集、削除を残す。VST の申告遅延は、現在の世代と VST ID が一意に一致した値のみを表示し、未取得と申告ゼロを分ける。見出しの装飾点を外した。

## 残件

- 5段は現在の状態を示す要約で、ゲインや各調整の操作自体を各段に移してはいない。入力ゲインの幅による位置とラベルの課題は #110 の対応対象として残る。
- フッター整理（B4）と音量チェックの1操作開始（A7）は未対応。入力画面の既存メーター（A6）は、すでに実装されている表示を維持した。
- ラックの詳細表示を既に選んだ人の設定を上書きしないため、その場合は自動的に1行へ変わらない。

## 検証と未確認

- `npm test -- --run`: 成功（115 ファイル・1102 テスト）。日英の5段の順序、世代不一致・停止時の未確認、VST の申告ゼロと未取得の区別を含む。
- `npx tsc --noEmit`、`npx vite build`、`git diff --check`: 成功。Vite は 500 kB 超の chunk、Git は改行変換について警告した。
- 一時的に応答を補った Vite モックで、日英の 900×600・1024×768・1280×720・1920×1080 における文書の横はみ出しがないことを確認した。英語 900×600 では用途を選び、準備帯・主操作・5段・声の調整を両表示で確認した。VST 3件は1行で表示され、申告値のないものは未取得となった。キーボードでドラッグ開始・移動・Escape 中止を行い、順序を変えない通知とフォーカス復帰を確認した。モックでは準備情報が不足しており状態は未確認で、実機や全操作の保証ではない。
- 実機・実 VST Host・OBS・聴感・実 DPI・Narrator は未確認。画面と自動テストは実音声や受信確認を代替しない。
