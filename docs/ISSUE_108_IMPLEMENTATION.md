# メーターと内部観測の表示（Issue #108）

## 変更内容と判断

- ホーム、ヘッダー、大型メーター、フッター、セットアップのレベル表示を `MeterVisual` へ統一した。表示は sample peak の線形値を dBFS に換算し、保持中のピークが −6 dBFS 以上で注意色、1.0（0 dBFS）以上で危険色とクリップ表示になる。−3 dBFS はクリップではない。大型とホームには目盛り、各表示には読み上げ用の名前・値・状態を付ける。
- 入力と出力それぞれでピークを保持し、クリップした後はボタンで消せる。同じ入力／出力の全表示で解除を共有する。停止・エラー・不正値・更新切れではレベルとピークを消し、クリップ記録は消さない。新しいストリームの開始または手動操作でクリップ記録を消す。無音についてはゼロ通知が省略される既存仕様に従い無音状態を保持する。
- 既存 `audio-level` 通知を共有し、表示更新は既存と同じ16 ms間隔とした。音声 callback・RT イベント・音声処理は変更していない。セットアップの既存の音声操作も変更していない。
- ヘッダーは方式・サンプルレートと、直近30秒の入力 cohort 到着から出力バッファ完了までの観測値の p50 区間を表示する。未取得時は数値を出さず「未取得」とする。値は耳や OBS までの遅延ではない。
- MasterBar の既存1秒 stats poll を共有し、新しい stats poll は追加しない。schema、queue の稼働・epoch、条件窓と revision、通常出力、分布、時刻の進行を確認する。最初の読取後は次の窓の進行を確認してから数値を出し、2.5秒進行しない場合、停止、取得失敗、非表示、古い応答、条件変更中や不正値では値を隠す。故障・封印後の同 epoch は復活させず、過去32 epoch の再来を拒否する。
- 段別の NR・VST・バッファの申告／計算値を観測値に加算しない。従来の「音声の詳細」への入口は維持する。
- 監査 B6 の「方式は詳細へ」という案と Issue #108 の「方式を常時表示」は一致しないため、今回の明示された受入条件に合わせて方式を常時表示した。

## 検証

- `npm test -- --run`: 初回は並列ビルド等と重なり、AudioSettingsLifecycle の hook 10秒 timeout と ShortcutsPanel の1件が5秒 timeout（112 suite成功、2 suite失敗、7件skip）。単独再実行では全114ファイル・1096テスト成功。その後、共有クリップ解除と境界色のテストを追加した最終状態でも全114ファイル・1098テスト成功。
- `npx tsc --noEmit`: 成功。途中、型で到達不能と判定された重複判定を取り除いて再実行した。
- `npx vite build`: 成功。500 kB 超の chunk に関する Vite の警告あり。
- `git diff --check`: 成功。Windows の改行変換に関する Git の警告あり。
- クリップ境界、手動解除、停止・異常・更新切れ、共有解除と、直近観測の欠測、条件変更、順序逆転、進行停止、epoch・故障を自動テストで確認した。
- 一時的な応答を補った Vite モックで、900×600・1024×768・1280×720・1920×1080 の日英表示、大型メーター開閉、文書とヘッダーの横はみ出しを確認した。モックに periods がない状態では「未取得」を表示し、0 ms を表示しない。別のクリップ用モックでは 1.0 以上で表示と解除ボタンが現れることを確認した。実デバイスの信号や有効な periods の受信を再現した確認ではない。

## 未確認

実機、実 VST Host、OBS、聴感、実 DPI、Narrator は未確認。クリップと内部観測の自動テスト・ブラウザモックは、実音声や実環境の遅延保証ではない。

## PR前レビューの追加対応（2026-10-28）

- 900×600・日本語・クリップ中の大型表示で、バー・数値・解除ボタン・目盛りが横一列に縮み、バー全体が約0.91px幅になる問題を確認した。数値と解除操作をバーの下へ置き、目盛りはバーと同じ高さの領域へ移した。
