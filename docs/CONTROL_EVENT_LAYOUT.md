# 制御イベントの保持方式

2026-11-01、Issue #195 の比較結果に基づき、`UserEvent::Command(Command)` を維持する。
Box化は採用しない。単に警告を消すための変更にはせず、比較試験を `core/user_event_tests.rs` に残す。

同じ現在のCommand型で、イベントのサイズは現行216バイト、Box候補16バイトだった。
一方、値だけのコマンド1件の確保・解放は現行0/0回、Box候補1/1回となる。
Timerとコマンドを各50,000件、最後にShutdownを入れて排出するVecDequeのローカルdebug試験では、現行8.1565ms、Box候補14.5811msだった。

この比較は実winitの待ち時間・最大メモリ・実機の音声負荷を測っていない。
常に大量のイベントが滞留する条件も確認していないため、イベント単体の小ささだけで本番の改善を断定しない。
現時点では追加確保を避け、既存の制御経路を維持する。イベント滞留の実測が得られた場合に再評価する。

比較試験は同じコマンド内容、配送順序、確保・解放回数、サイズを確認する。
時間比較は次の明示実行に限定する。

```powershell
cargo test --locked --lib user_event_tests -- --include-ignored --nocapture
```

音声コールバックのメッセージやRTの無割当方針は変更していない。
