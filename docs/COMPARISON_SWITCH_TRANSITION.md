# 原音比較の切替時に波形の段差を抑える

2026-11-02。プロセス単独入力までを`74a3aba`でコミットし、その後の改善として実装。
利用者から、入力とVSTあり／なしの切替は確認できた一方、切替時に小さな「プツッ」という音が入ると報告を受けた。
この報告は、全素材・全経路の聴感確認を完了したという意味には広げない。

## 無音の境界で経路を変える

従来はcallbackの先頭で全体bypassのboolを変更し、そのblockからVSTの通過／省略を切り替えていた。
処理前後のレベルや位相、VSTの遅延が異なると、境界のサンプル値が急に変わり得る。
実際の聴感ノイズの原因をすべて確定したわけではないが、この段差を抑える処理を加えた。

新しい処理は[comparison.rs](../src-tauri/src/audio_engine/comparison.rs)で状態を持つ。

1. 元の経路を維持したまま、5 ms以上かけて音量を0へ下げる。終端はcallbackの末尾に揃える。
2. 次のcallbackで、無音からVST通過／省略の経路を変更する。
3. 5 msかけて音量を元に戻す。

48 kHzで実callbackが480フレームの場合、fade-outは10 ms、fade-inは5 msとなる。
要求バッファ512と実callbackの長さは同じとは限らない。切替時には短い音量の谷が生じる。
遅延の異なるdry/wetを重ねない方式であり、遅延差の完全補正や完全に無音のない切替を保証しない。

連打・取消はその時点の音量から追従し、同じ要求の再送ではfadeを再開始しない。
空ラックでは音量を下げず、開始時に既にbypassされている場合も初期fadeを行わない。
状態と演算だけを持ち、callback内の新規確保・解放・ロック・待機・I/Oは増やさない。

## 測定に切替途中の音を入れない

ボイスチェック録音・音量測定の開始要求は、切替が安定するまで既存のFIFO内に残す。
処理callback自体は継続する。遷移中のblockは通常音声の遅延計測条件から除外する。
NR・内蔵処理の設定と、全体bypassがVST段だけを切り替える契約は維持する。
個別VSTのbypass操作の平滑化は今回の対象に含めない。

## 波形・実Engine・聴感を分けて確認する

追加のRust試験は、逆極性のdry/wetで瞬時切替なら2.0となる段差を作り、fadeによるサンプル間変化を確認する。
44.1／48／96／192 kHz、32〜1,056フレーム、可変長block、往復・連打・取消・空ラック・起動状態を扱う。
RTの確保・解放0も計測する。

実Engineでは、`scripts/verify_process_app_soak.py --comparison-switches`で実VSTのラック音量を0.25とし、bypass時の1.0との違いと、64回連打後に最後の要求へ戻ることを確認する。
これは小音量素材の経路確認であり、クリックが耳で消えた証拠にはしない。
以前の各65分の試験は改善前のEngineによる記録なので、改善版の長時間合格へ読み替えない。

試聴用の改善版は`test-results/process-input-audition-clickfix-20261102/Start-Audition.cmd`から起動する。
以前の`process-input-audition-20261102`は保持し、設定も分ける。
同じ再生素材・TDR Novaの設定で原音比較を往復し、切替ノイズと音量の谷を耳で確認する。
最終の検証結果と実行ファイルの識別は、`test-results/comparison-transition-20261102`に保存する。

確認結果:

- Rust全target＋probe featureは成功。ライブラリ608件成功・4件ignored、probeは8件成功。追加した比較遷移の6件を含む。
- Clippy全target＋probe feature（`-D warnings`）、Rustfmt、TypeScript・Vite、スクリプトの構文確認は成功。
- Chrome→実Engine→TDR Nova→Voicemeeter Inputで、安定後の出力／入力ピーク比0.25と1.0を確認。64回の連打後も0.25へ復帰し、原音用デバイスの状態を復元。
- 改善版の埋込みフロントを実起動し、TDR Novaの実UIでの適用と、音声停止中であることを確認。試聴用EngineのSHA-256は`cc761f106d12ee94255a725d497fd5dbb7b8ad0259b4b96273ecb79e5327dec5`。
- 初回の並行ビルド・全体テストはメモリ不足（OS error 1455等）で失敗。並行実行をやめ、`CARGO_BUILD_JOBS=1`・デバッグ情報なしで順次再実行して成功した。
