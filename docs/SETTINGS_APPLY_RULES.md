# 設定の反映・保存ルール

設定画面では、**何を変え、いつ反映され、どこに残るか**を、操作する場所で示す。
全項目を一つの保存ボタンへ集めず、即時調整・明示適用・音声処理再起動時の反映を使い分ける。

対象は設定UIの設計・実装・レビュー担当者。1〜2節を共通ルールとし、区画ごとの判断には3節、確認には6節を使う。
この文書は[DESIGN.md 2.8](./DESIGN.md#28-設定は反映時点と保存範囲を操作の近くに示す)の詳細。文言は[COPY_GUIDELINES.md](./COPY_GUIDELINES.md)、検証方法は[TESTING.md](./TESTING.md)に従う。

## 1. 反映の時点と、保存して残る範囲を分ける

反映方式は次の3種類とする。今後のUI改修では、この分類に沿って反映時点を示す。
今回の文書整理では、音声処理・保存形式・既存の適用手順は変更しない。

| 反映方式 | 画面に示す内容 | 操作名の例 |
| --- | --- | --- |
| 変更するとすぐ反映 | 対象と、選択・操作確定後に反映すること。OFFなら設定だけを更新する場合も区別 | ON／OFF、種類の選択、音量調整 |
| 明示操作で適用 | 編集中は未適用であること、押した後の対象と影響。停止中は音声開始も含むかを示す | 接続設定を適用、調整を適用、キー設定を保存 |
| 登録後、音声処理の再起動で反映 | 登録先、まだ今の処理には反映していないこと、必要な開始・再起動 | 処理設定を登録 |

保存は反映方式と別に扱う。「保存済み」は、示した対象を保存先が受け入れた範囲に限る。
アプリ内で値を保持しただけなら「設定を登録しました」などとし、アプリ再起動後も残るファイル保存と区別する。
プリセットの保存は名前付きの記録であり、現在の音への適用を意味しない。

| 状態 | 意味 | 示す文言の例 |
| --- | --- | --- |
| 編集中 | 画面上の変更。処理や登録先への適用は未完了 | 接続設定を編集中です |
| 登録・保存済み | 対象の値を登録先が受理した。今の音声処理への反映は別 | 処理設定を登録しました。音声処理の再起動で反映します |
| 適用済み | 対象処理の値を確認できた。可聴品質やOBS到達の確認とは別 | 声の調整を適用しました |
| 反映未確認・一部反映 | 成功を確認できない、または処理と保存の一方だけが成功 | 接続は開始しましたが、設定の保存を確認できませんでした |

「設定全体に変更なし」「すべて保存済み」は、区画ごとに異なる結果があり得る画面では使わない。
接続設定だけの状態なら「接続設定に変更はありません」と書く。

## 2. 表示は操作群ごとに1回、取消は対象を限定する

### 操作する前に、反映時点が分かるようにする

反映方式が同じ操作群の見出し直下へ、短い説明を1回置く。
各ボタンへ同じ説明を繰り返さず、詳しい仕組みは情報ボタンへ置く。
音声停止・再起動・保存範囲・変更対象・OFF時の編集可否は、情報ボタンを開かなくても分かるようにする。

音づくりは、即時調整の群に「変更するとすぐ反映します」、歌向けの下書きに「適用するまで現在の音は変わりません」と表示する。
停止中・OFF時は、処理へ送ったことを「音が変わった」と言い換えない。
スライダーを確定する時点は既存の実装に従い、ドラッグ中の毎フレーム送信へ変更しない。

ページ下部に固定するボタンは、そのページの対象設定だけに作用する。
オーディオ下部には「接続設定」を示し、稼働中は音声再起動で途切れること、停止中は音声開始を伴うことを伝える。
区画に独立した保存がある場合は、区画名とボタン名で対象を対応させる。

### 取消と再取得で、現在の処理を黙って戻さない

- 下書きの取消は、その区画の未適用分を戻す。即時反映や他の区画で保存済みの変更は戻さない。
- 現在の処理を戻す操作は「適用前に戻す」など別の名前にし、既存の復元条件を守る。復旧原本を消す操作と同一視しない。
- 再取得は現在値の読み込み。編集中の内容を置き換える場合は対象と結果を伝え、定期取得で下書きを上書きしない。
- タブ移動は保存・適用の契機にしない。閉じると失う下書きは対象を挙げて保持・破棄を判断できるようにする。既存の共有下書きを閉じるだけで消す変更はしない。
- キー入力の取得中のEscapeは入力取得の中止として扱い、設定画面全体の破棄と混同しない。

OFF時は「保存値だけ編集できる」と「編集できない」を分ける。
編集可能な値には現在の音へ効かないことを短く示し、無効な値はラベル・数値・つまみも無効と見分けられるようにする。
見た目の統一を理由に、独立したエフェクトのON/OFFを親のON/OFFへ結び付けない。

## 3. 区画別の現行挙動と、画面へ示す範囲

以下は2026-11-09、HEAD `492213424d90e1f4006377a899015c2650028e95` のコード調査で確認した境界。
監査した配布版との完全一致、実際の再起動・失敗・聴感は未確認。
保持期間をコードから確定できない項目は、永続保存を保証しない。
表の文言は設計例で、画面へ反映済みではない。

| 区画・操作 | 現行の反映境界 | 保存・取消の範囲と表示方針 |
| --- | --- | --- |
| 接続方式・入力元・機器・チャンネル・出力・バッファ・レート | 画面の選択後、接続の明示操作で開始／再起動する | 「接続設定」の操作としてまとめる。処理開始と設定保存の結果を分け、一部成功ならそれぞれを示す |
| 入出力プリセットの保存 | 選択中の接続値を名前付きでローカル保存する | 現在稼働中の値の保存とは限らない。「編集中の接続設定をプリセットに保存」。音声を開始しない |
| 入出力プリセットの選択 | 接続の選択値へ読み込み、変更項目として扱う | 読み込むだけでは接続を適用しない。開始／再起動の入口へつなぐ |
| 本人用・配信用の分離出力 | 区画内の下書きを、確認後に専用の要求で反映する | 接続設定の下部ボタンと分け、「出力構成」の範囲を示す。取消はこの下書きだけ。停止・処理分離の制約は操作の近くに残す |
| モニター設定の試行 | 候補準備と実際の試行は別。試行では開始処理があり、元の設定を復旧用に保持する | 「候補を作る」「試す」「採用する」「元に戻す」を分ける。試行前に処理が変わることを示し、原本を残す条件を維持する |
| ノイズ低減・基本の声の調整・ディエッサー | 確定した操作を個別APIへ送り、現在の処理設定を更新する | 「変更するとすぐ反映」。OFF時の設定変更と処理ONを分ける。現在値への反映をプリセット保存や再起動後の復元と呼ばない |
| 歌向けの調整 | 下書きを編集し、試聴・明示適用へ進む | 未適用であることと適用対象を示す。下書き破棄、現在値の再取得、適用済みへのUndoは別操作として扱う |
| 歌・雑談への登録 | 適用済みの音の設定をモードへ登録する | 未適用の歌向け下書きの適用とは別。任意のVST関連付けと登録対象を示す |
| ピーク保護・配信用true-peak制限 | 数値編集は下書き。各区画の適用・有効化・無効化で対象の保護設定を反映する | 本人用／配信用の作用先を分ける。OFFで編集した数値を、保護が効いている表示にしない |
| OBSへの接続 | 接続の明示操作。資格情報の保持は専用の仕組みで扱う | 接続成功と音声到達を分ける。ホスト・ポート・パスワードを一般設定の一括保存へ混ぜず、資格情報を状態文に含めない |
| OBSのシーン連動方式 | 区画内で方式・有効状態・対応を編集し、明示保存する | 「シーン連動設定を保存」。VST再読み込み等の影響と有効状態を示す。保存成功をOBSでの動作確認と呼ばない |
| 外観・言語・ホームの表示 | 操作に応じて表示を更新し、各設定の保存処理を使う | 「表示の変更はすぐ反映」。接続・音量・ミュートを適用しない。ホーム表示の用途と入力の用途は分ける |
| ホットキー | キー取得・候補選択・解除は下書き。保存要求後に返った登録結果を表示する | 「キー設定を保存」。保存とOSの登録失敗を分ける。「キー設定の変更を破棄」は未保存分だけを戻す |
| Windows起動時の実行・更新方針 | 個別の操作でOS登録または方針保存を要求する | 操作対象と結果を示す。接続設定の取消では戻さない。配布形態で利用不能なら、その版の理由を示す |
| 高度な処理設定 | 登録要求はHost内の設定値を更新し、音声エンジンの新規起動時に使う | 現行setterはファイル保存ではない。「処理設定を登録」。アプリ終了後も残る保存と案内しない |
| 設定の移行・初期化・測定 | 専用の確認・実行手順を持つ | 設定の通常保存と分ける。音声停止・アプリ再起動・復元・録音やテスト音の条件を各操作で明示する |

通常の停止後の再開では既存エンジンを再利用するため、登録値の反映を保証しない。登録後はシステムの音声処理再起動を使う。アプリ自体を再起動すると登録値は失われる。

## 4. 成功・失敗・競合を対象ごとに示す

成功表示は、対象の応答・読み戻しで確認した範囲に限定する。
画面の選択値やトーストだけを根拠に、処理・保存・受け側到達の全てを成功にしない。
状態通知は操作群の近くに残し、トーストだけで必要な再試行先を消さない。

| 状況 | 表示と次の操作 |
| --- | --- |
| 接続開始は成功、設定保存は失敗 | 接続の稼働を保ち、保存未確認と保存の再試行を示す。再試行だけで不要な再起動を繰り返さない |
| 登録・適用の結果が取得できない | 「反映を確認できません」。下書きを残し、再取得して現在値を確認する入口を示す |
| 処理停止中 | 設定値の登録と音声開始を区別する。設定更新を理由に音声を自動開始しない |
| 別の画面・モード操作で現在値が変わった | 古い値で上書きせず、変更競合を示す。現在値と下書きを確認して再試行する |
| キー設定の保存後にOS登録が失敗 | 該当キーと登録失敗を示す。保存済みでも利用可能とは表示しない |
| アプリ内の再起動時の設定を登録 | 今の処理には未反映と示す。アプリ再起動後の保持を保証しない |

エラー原文は詳細に置き、通常表示では対象と次の操作を示す。
値の再取得は新しい世代の応答を使い、保存中・適用中の二重操作と古い非同期応答による上書きを防ぐ。
これらの表示を実装するときは、既存APIの結果・復旧契約を使う。表示だけで判別できない結果を推定しない。

## 5. 今回のUI反映範囲

設定画面では、接続の保存・開始／再起動、入出力プリセット、出力構成、シーン連動、キー設定、高度な処理設定の操作名を対象別に整理した。
音づくり・外観の即時反映と、出力構成・保護設定・キー設定の明示適用は、操作群の近くに説明を表示する。
高度な処理設定は「登録」と表記し、音声処理の再起動で反映することと、アプリ終了後は保持されないことを案内する。
利用者向け設定ガイドも日英で合わせた。

今回の変更は文言と案内の表示に限る。
API・保存形式・音声処理・取消の処理は変更していない。
OFF表示の統一、未保存変更の移動時確認、保存結果・競合表示の拡充は、別の実装範囲として残る。

## 6. 画面へ反映するときの確認条件

この文書の追加だけではUI改善や実機受入を完了にしない。実装時は次を確認し、結果を分けて記録する。

- [ ] 即時調整・明示適用・音声処理再起動時反映を、操作前に対象と一緒に判別できる。
- [ ] プリセット保存、接続の適用、モード登録、高度な設定の登録を混同しない。
- [ ] OFFで編集可能、OFFで無効、処理停止、未取得を区別し、無効なスライダーも操作不可と見分けられる。
- [ ] 接続の未設定／稼働中／停止中で、対象・開始／再起動・音切れ・保存結果の表示が対応する。
- [ ] 下書きのある区画からタブ移動・閉じる・再取得を行い、保存・破棄される範囲が表示と一致する。別区画の即時変更は巻き戻さない。
- [ ] 保存失敗、処理だけ成功、登録だけ成功、読み戻し失敗、別操作との競合、古い応答、二重実行を確認する。
- [ ] 高度な処理設定について、登録直後・音声再起動後・アプリ再起動後の値と説明を照合する。永続化の追加が必要なら別の実装範囲として扱う。
- [ ] 日英・各テーマ・狭い窓・拡大表示で、説明と操作対象の対応を保つ。キーボード・読み上げでも反映方式と状態を追える。
- [ ] モニター試行・復元、歌向け試聴、OBS連動、音声再起動は実Tauri・実機で確認し、自動テストや画面の成功表示と区別する。

今回の文書整理では、API・音声処理・保存形式・自動開始・復元の挙動は変更しない。
画面の並べ替え、用語全体の短縮、プリセット統合、MSIX更新案内の改修は、それぞれの実装範囲を決めて進める。
UIへ反映する際に現行コードとルールが矛盾した場合は、保存先・適用対象・失敗結果を確認し、この文書とDESIGN.mdを合わせて更新する。

## 用語

| 用語 | この文書での意味 |
| --- | --- |
| 下書き | まだ対象へ適用・登録していない編集値 |
| 登録 | 対象の仕組みへ値を渡し、受理を確認する操作。保持期間は登録先に従う |
| 保存 | 示した保存先へ値を記録する操作。現在の音への反映とは別 |
| 適用 | 対象処理へ設定を渡し、受理された現在値を確認する操作 |
| 再取得 | 対象が持つ現在値を読み直す操作 |
| 復元 | 以前の設定へ戻す操作。未適用の下書き破棄とは別 |
