# スイープによる往復遅延の測定（#455）

この文書は、利用者が開始した往復測定の意味と限界を残す。実装は `audio_engine/latency_measure.rs` と遅延表示の「実際の往復遅延を測る」である。

## 測るもの

測るのは、出力機器から配線または音響経路を通り、入力機器へ戻るまでの往復時間である。アプリが出力へ出した指数正弦スイープと、入力機器から取得した音の相互相関で、スイープの到着位置を求める。

声とパソコンの音の相対的な時間差は測っていない。往復の半分を片道遅延と呼ばない。ミックスの時間合わせ `offsetMs` へは入れない。適用ボタンもない。往復値は、声がマイクに入ってから処理を通り出力へ出る時間とは別の経路だからである。

## 基準時刻

入力コールバックは、測定を始めてから書き終えた入力フレーム数を atomic で公開する。出力コールバックは、スイープの先頭サンプルを出すブロックで、その値を一度だけ読む。遅延は「取得バッファの中でスイープが始まる位置」から「その開始フレーム」を引いた値である。

コールバックの境界では、入力ブロック長と出力ブロック長の和くらいの不確かさが残る。結果の `resolution_ms` がその幅で、画面は `± x ms` と示す。この幅は誤差の保証区間ではなく、ブロック境界から見た分解能である。

取得は、開始フレームにスイープ長と探索上限（1000 ms）を足したところまで続ける。スイープを出し終えたあとも、その取得が終わるまで出力は無音のままにし、マイクは配信と本人用の後段へ流さない。ハウリングと、遅れての到着の取りこぼしを避けるためである。

入力の選び方は、ゲインを掛ける前の選択チャンネルである。左右が同じ番号ならその1チャンネル、違う番号なら二つを等分に足してモノラルにする。範囲外や非有限は 0 とする。クリップは平均する前の選択サンプルで数え、片側のクリップを平均で隠さない。

`buffer_size` が 0 の結果は、固定フレーム数を指定していないデバイス既定である。内部の 512 仮値は条件にしない。

## 信頼性

解析は音声コールバックの外で行う。相互相関は FFT で計算し、主ピークを放物線補間してサブサンプルの位置を出す。

- 取得の RMS が雑音床未満なら失敗（`no_signal`）。
- 絶対値が 0.999 以上のサンプルが 8 個以上なら失敗（`clipped`）。
- 取得が短い、または開始位置が残っていないなら失敗（`truncated`）。
- 遅延が 0 から 1000 ms の外なら失敗（`out_of_range`）。
- 主ピークの ±1 ms を除いた二番目の山が、主ピークの 1.25 倍未満に収まらないなら不確か（`multiple_peaks`）。
- ピークの絶対値を、その除外範囲の外の相関 RMS で割った値が 8 未満なら不確か（`low_snr`）。
- 主ピークが負なら逆相として成功し、極性を報告する。

不確かと失敗には遅延の数値を付けない。成功の信頼度は、山の比とピーク対雑音のそれぞれを閾値との比で 0 から 1 に収め、小さい方を使う。閾値そのものは、この実装の判定であり、実機の音響経路で較正した値ではない。

## 安全と実行できるとき

通常の入出力ストリームが動いているときだけ開始できる。停止、ストリーム異常、ミュート、テスト音、ボイスチェックの再生、録音、ラウドネス測定、音量の自動調整、プロセス入力、分離出力、入力と出力のサンプルレート不一致では、理由のコードを返して拒否する。

スイープはテスト音と同じ上限 −12 dBFS、既定 −20 dBFS で、約 1.25 秒、100 Hz から `min(12 kHz, 0.45 × レート)` まで動く。前後 10 ms はフェードする。再生は `rt_output_gain` とピーク保護を通り、VST とノイズ低減は通さない。配信の `live_sender` へは送らない。グローバルミュートが優先で、そのブロックは無音にする。

取消、タイムアウト（スイープ長 + 2 秒）、停止、入力チャンネルの変更、デバイスの切替、エラーではスイープを止める。取消は短いフェードの次のブロックから無音にする。ミュートとストリームの異常は、信号を残さず止める。

スイープと取得バッファは、測定の開始前に制御側で確保する。音声コールバックは、そのバッファを読む・書くだけで、確保も解放もしない。入力と出力は別スレッドのため、片方のコールバックから retire キューへ渡すと、もう片方が使っている途中で解放され得る。公開は制御側の `AtomicPtr` とし、各コールバックは触る前に自分の busy を増やす。制御側は終了を書いてから両方の busy が 0 になるのを待ち、そのあと制御側で所有を戻して解放する。ストリーム破棄でコールバックが戻ったあとの回収も制御側である。これは `deferred_drop` の「RT で drop しない」と同じ目的で、二つのコールバックが同時に触るための持ち方である。

## 条件と古い値

結果には、出力機器、入力機器、入力チャンネル、サンプルレート、バッファ要求、エンジンの queue 世代、測定時刻を付ける。いまの条件と一つでも違えば、画面は「条件が変わったため、この数値はいまの遅延ではありません」と示し、その数値を現在の遅延として扱わない。条件を確認できないときも、現在値にはしない。保存はセッション内だけで、設定ファイルへは残さない。

画面では、この実測（往復）と、既存の申告値の合計を並べても、足したり、同じものとは呼ばない。申告値の合計は VST の申告と古いノイズ低減の計算だけであり、測定値ではない。

## 声とパソコンの音の時間差（今回はやらない）

往復は、出力を出てから入力へ戻る時間である。声はマイクに入り、処理を通って出力へ向かう。パソコンの音は、その出力側のどこかを聴いている。この二つがずれる量は、往復の半分でも、往復そのものでもない。処理の中の遅延、出力バッファ、聴いている場所（配信タップ、モニター、スピーカー）が別に入る。

次に測るなら、同じフレーム時計の上で、定義したタップのパソコン音と、ゲイン前のマイクを同時に取り、その二つの相関を RT の外で求める。タップの位置、処理を含むか、モニターの音を含むかを結果の条件に残し、往復値からの換算や `offsetMs` への自動適用は、その測定が説明する範囲に限る。今回の往復値を、その相対差の初期値にもしない。

## まだ確認していないこと

#211 の外部実測（物理ループバック配線と発声）とは比較していない。実機の ASIO / WASAPI、音響経路、ハウリング、実際のコールバック長による誤差は未確認である。自動テストは、既知の遅延を入れた信号と、コールバックがバッファを確保・解放しないことの確認であり、聴感や実機の誤差の代わりではない。
