# 入力レートの選択と再試行（#46）

WASAPIの起動時は、入力の既定チャンネル数・サンプル形式・有効バッファを保ったまま、出力と同じレートを使えるか確認する。
既定入力の形式がF32で、対応一覧にも同じチャンネル数・F32・出力レートを含む範囲がある場合だけ同率を優先する。
一覧の取得失敗、別チャンネル数、別形式、範囲外を対応と推測しない。既に同率なら追加の試行をしない。

同率入力のbuildをデバイスが拒否した場合は、出力レートと有効バッファを保ち、既定入力へ一度だけ戻す。
これも拒否された場合は従来の出力既定レート・Defaultバッファへの再試行を使う。
出力が先に拒否された場合にも、出力既定値への再試行と入力だけ戻す再試行は各一度までで、全体は最大3試行とする。
各試行では能力を取り直す。再試行前にローカルstreamとcallbackを回収し、processorを停止してから準備し直す。
入力・出力のplayが両方成功した場合だけStartedを通知し、UIへは最終的な出力レートとバッファを返す。

ASIOはdriverのレートを入出力で共有するため、この独立した入力選択・追加再試行の対象にしない。
ASIOのDevice共有・rate整合は [ASIO_DUPLEX.md](ASIO_DUPLEX.md) に分け、チャンネル設定と出力fallback予算・ASIOのみ入力先行buildとし、WASAPIの出力先行build／両Hostの出力先行play順を維持する。
異なるレートでの変換は引き続きrubatoの標準target chunk 1024を使い、必須変換の準備に失敗した場合は開始失敗とする。
変換失敗を無変換へ置き換えない。

同率選択の条件、再試行予算、stream・callback回収順はデバイスを起動しない自動テストで確認する。
実機での対応レート受理、デバイス内変換、音質・CPU・クリック・長時間運転・総遅延削減量は、この選択ロジックのテストだけでは確認できない。
小さいrubato chunkへの変更や、クロック差補償・queueの自動切り捨ては含めない。
