# 分離出力・モード・プロセス入力を一時利用前に退避する

#221の[未保存状態の退避・手動復帰](UNSAVED_RUNTIME_RESTORE.md)を、#222で実装した保存形式へ広げる。
声用途の機器入力では、分離出力・枝別処理・現在の本人用処理・歌／雑談の登録と選択・関連VSTも退避する。
プロセス入力では、標準の単独出力で声／音楽の用途とアプリ設定を退避する。
プロセス入力と処理分離・モードの組合せ、機器入力の音楽用途は引き続き拒否する。

## 元の状態を止める前に、全内容を読み戻す

一時利用の画面で「対応する未保存設定を退避してから開始する」を選ぶと、停止・再起動より前に現在の範囲を確認する。
取得中の変更、測定・録音・試聴、VST復旧待ち、本番保護、未解決の原本は従来どおり拒否する。
取得・書込み・読み戻し・照合を完了できなければ、一時利用へ進まない。未完了情報や原本は残す。

従来の単一出力・カスタム構成はschema 1を維持する。
分離出力やモードの登録内容を含む機器入力はschema 3、プロセス入力はschema 4を使い、明示保存・復帰と同じデータを取得する。
VST内部state、両枝とモードの内容は非公開の原本だけへ保存し、画面や復旧マーカーに出さない。

## 復旧情報の版と、原本の入力・出力を照合する

復旧マーカーの外側は従来のversion 1のまま、`runtime.version`で退避範囲を区別する。
従来原本のschema 1はruntime 1、拡張したschema 3・4はruntime 2を使う。
runtime 2では、機器入力の原本内の機器IDとマーカーのIDを一致させる。プロセス入力へ機器入力のIDを混ぜた場合も拒否する。
未知の版、原本と範囲が異なる情報、原本全体のSHA-256の不一致は、読み取り可能な退避として表示しない。

プロセス入力はアプリの識別情報・用途・原音用出力・返し先だけを保存する。
PIDと生成時刻・候補IDは退避原本へ含めず、取得元のHost世代も再開の権限には使わない。

## 通常設定へ戻っても、自動では音を再開しない

一時領域は新しい設定・WebView・TEMPで開き、通常設定へコピーし戻さない。
通常設定へ戻った場合も、元の機器または起動中のアプリを利用者が明示選択して開始し、全体ミュートして原本との差分を確認する。
プロセスを起動し直した場合は、同じアプリの新しい実行状態を選び直す。保存したPIDの再利用やマイクへの代替は行わない。

復帰には[分離出力](OUTPUT_CONFIGURATION_RESTORE.md)、[モードと関連VST](LIVE_MODE_STATE_RESTORE.md)、[プロセス単独入力](PROCESS_STATE_RESTORE.md)の既存処理を使う。
停止・ミュートの要求を優先し、外部編集・欠落・部分失敗では原本を保持する。
学習結果・録音・聴感の合格・信号到達の履歴・本番保護・ピーク保護・外部アプリは復活させない。

## 一時領域の隔離と、実音声の受入を分ける

機器入力の試験は`scripts/verify-unsaved-runtime-native.mjs`の`--split-modes`で行う。
未使用のCABLE Output入力とCABLE Inputへの配信出力を組み合わせるため、全体ミュートは解除しない。
通常設定の保持、モードと関連VSTの退避・復帰、欠落・後編集、空ラック・音量ゼロも確認する。

プロセス入力は`scripts/verify-output-configuration-native.mjs`の`--process-input`で、所有する再生プロセスだけを使う。
一時利用中に元のプロセスを終了し、起動し直したアプリを通常設定側で明示選択して復帰する。
各試験で原本と失敗記録を保持し、OSの出力設定は元へ戻す。
これらは全体ミュート中の制御と状態の確認であり、共有PCの運用・実OBS・聴感を含むV-03／V-04の受入は別に残す。

## 検証記録の消失と再作成を区別する

2026-11-03の追加のブラウザ試験で、Playwrightの既定の出力先が`test-results`全体だったため、過去の内容（ログ・専用試験環境など）を消去した。
コードとGit履歴は残っているが、消失した記録を復元できたとは扱わない。
設定の`outputDir`を`test-results/browser-output`へ限定し、同じ親フォルダーの確認用ファイルが試験後も変わらないことを確認した。
以降の確認結果は`reverified`を含む新しいファイルへ記録し、消失前の記録とは区別する。

## 2026-11-03の再検証結果

- Rustの全target試験は成功。ライブラリは642件成功・5件ignoreで、実機を要するignoreは合格へ含めない。厳格Clippy、fmt、TypeScriptと専用Host・Engineのビルドも成功した。
- 関連コンポーネント30件と、IPCを模擬するブラウザ6件が成功した。
- 実Hostと実Engineで、schema 1の従来構成、schema 3の分離出力・歌／雑談の登録・関連VST、schema 4の音楽用途のプロセス入力を確認した。
  3構成とも、停止状態での起動・明示復帰・原本保持・一時領域の削除と、試験前後のOS出力設定の保持が成功した。
- 機器入力ではVST欠落・機器ID不一致・原本変更・Stopによる差分無効化・空ラックと完全な音量ゼロを確認した。
  プロセス入力では、元アプリの終了・再起動後に古い選択を拒否し、明示再選択して復帰できることを確認した。
- 削除処理は短い排他的ファイルロックの解放後に再試行し、ロックが続く場合は失敗として残す。隣のフォルダーを変更しないこともRust試験で確認した。

記録は`test-results/extended-temporary-{device,process,legacy}-reverified/summary.json`と、同じ親フォルダーの`extended-temporary-*-reverified.log`に保存する。
`test-results/extended-temporary-verification.json`にソース・バイナリ・ログのSHA-256と、各構成の確認範囲をまとめる。
通常アプリの設定と共有MCPドライバーは変更せず、物理マイクは開かない。
実音声・OBS・共有PC・ASIO機器の受入や、過去の消失した原データの復元を、この再検証の成功に含めない。
