# 未保存状態を退避し、差分を確認して復帰する

#221（I-97a）の契約と初期実装。通常設定を分離する既存の一時利用と、#98の配信状態の原本保護・手動復旧を共通の土台にする。
初期対応は、単一出力・カスタム構成・声用途の機器入力の未保存設定を、一時利用へ切り替える前に任意で退避する範囲とする。
通常設定へ戻っても自動適用せず、明示開始・機器照合・ミュート・差分確認を経て復帰する。
プロセス入力と分離出力への拡張は、この初期対応の完了と区別する。

## 項目ごとの所有者と復帰範囲を固定する

| 項目 | 稼働状態の所有者／保存値 | 初期対応の退避と復帰 |
| --- | --- | --- |
| host・入力／出力のIDと名前 | HostのActiveAudioConfig／last_audio_config.json、画面の設定 | 実際の選択を退避。復帰前に同じ機器ID・名前・hostの一致を要求。既定機器や同名機器へ代替しない |
| rate・buffer・ch・出力ペア | Engineの開始条件／音声設定・プロファイル | 実際の固定要求値を保存。Defaultや未取得を512等へ読み替えない |
| 入出力gain | Engineの制御値／画面保存値 | Engineの値を線形で退避。完全な0も保持する |
| NR・声の保護・強度 | Engine／プロファイル・画面保存値 | 取得した設定を退避・復帰する |
| 内蔵処理・歌のパラメーター・残響設定 | Engineのbuiltin／プロファイル・画面保存値 | 設定のみ退避。残響やフィルターの過去の音は再開しない |
| VSTの順序・有効・ミュート・gain・component state | Engine／画面session・プロファイル | 実Engineから取得し、欠落・取得失敗・準備中は成功扱いしない。明示した空ラックも復帰対象 |
| プロセス指定入力 | Hostの候補・PID＋生成時刻／保存にはアプリ識別と原音用出力だけ | 一時利用前の退避は未対応。#222で[単独入力の明示保存・復帰](PROCESS_STATE_RESTORE.md)に対応。PIDは復帰権限として保存せず、明示再選択が必要 |
| 入力の用途 | HostのInputSource／音声設定 | 初期対応は既定の声用途だけ。音楽用途は停止前に拒否し、将来の形式で明示的に保存する |
| 二系統出力・枝別処理・trim・本人用処理 | Host・Engine／live_output.json | 一時利用前の退避は未対応。#222で[配信状態の明示保存・手動復帰](OUTPUT_CONFIGURATION_RESTORE.md)を先行実装し、未対応のモードや自分用処理の保持状態は拒否する |
| 歌／雑談モード・本番保護 | Host＋Engine／live_modes.json・本番保護はHost寿命 | 一時利用前の退避はカスタム構成だけ。#222の[明示保存・手動復帰](LIVE_MODE_STATE_RESTORE.md)でモード・関連VSTを拡張。本番保護を解除してから操作し、保護を自動で復活させない |
| ピーク保護 | EngineとHostの意図／アプリ再起動時は既存どおりOFF | 今回の退避には含めない。復帰対象を増やす場合は互換性と明示選択を別途定義する |
| 全体ミュート・VST全体bypass | Engine＋Host／Host寿命 | 退避した過去値を再適用せず、復帰操作時の現在値を優先。復帰時はミュートを必要とする |
| ノイズ学習・各種確認履歴 | Engineの入力別状態・各測定世代／一部履歴は別管理 | 対象外。過去の学習・信号到達・聴感確認を、復帰後の現在の合格として再利用しない |
| 録音・試聴・測定・適用途中・キュー・プラグインGUI | Engine・Host・外部ウィンドウ／進行中の状態 | 対象外。進行中の処理を終えてから退避し、自動再開しない |
| OS・OBS・VST自身の外部保存・明示export先 | 各外部アプリ・利用者指定先 | 対象外。通常設定への自動コピー戻しも行わない |

画面の未適用の下書きと、Engineへ反映済みだが未保存の状態は別物とする。
この退避は後者を取得する。下書き・保存原文・通常プロファイルは勝手に置き換えない。

## 退避は元の状態を止める前に完了させる

一時利用の開始前に対応範囲・対象外を表示し、利用者が退避を選べるようにする。
退避しない既存の経路では、未保存状態が戻らないことの確認を維持する。
退避を選んだ場合、未対応構成・録音や試聴・復元途中・未解決原本があれば、停止・再起動より前に拒否する。

取得は既存Engineだけを使い、取得のために音声やEngineを自動開始しない。
Hostの制御世代・revisionを束縛し、VST stateも含めて再取得した値が一致することを確認する。
取得中の変更や読み取り不能では元の動作状態を保持し、退避したという表示を出さない。

保存先は通常設定側の既存`broadcast-bundle-backups`配下。component stateは機密扱いとし、UI・ログ・復旧マーカーには出さない。
既存のサイズ制限・新規作成・同期書き込み・読み戻しを使う。原本の検証値、取得元世代・revisionと機器IDだけを復旧情報に持たせる。
別の原本が残っていれば上書きしない。失敗時に通常設定や既存原本を削除しない。

## 復帰は現在の条件で取り直した差分だけを適用する

通常設定へ戻ったときや異常終了後は、既存の確認待ちで開き、音声・録音・試聴・VST適用を自動再開しない。
残った原本は配信状態の復旧画面から確認する。

1. 利用者が元の機器を明示選択して開始し、ミュートする。
2. 原本のschema・検証値と現在の機器IDを照合する。
3. 現在のEngine世代・制御revisionに差分を束縛する。元のEngine世代は新しい世代への適用許可にしない。
4. 利用者が差分を確認して適用する。後編集、世代交代、Stop・ミュート等で条件が変われば、再確認を必要とする。
5. 取得不能・VST欠落・保存失敗・部分適用では原本を保持し、成功表示・確認済み表示にしない。

復帰しない場合も、現在の設定を採用する明示確認後に復旧待ちだけを解除する。原本ファイルは自動削除しない。
旧schemaの復旧情報は既存の契約を維持し、未知の新形式を成功へ読み替えない。

## 実装・検証の完了を段階ごとに記録する

この契約を#221と#222で共有する。初期対応の完了は、プロセス入力・分離出力・物理マイク・ASIO・共有PCの全受入完了を意味しない。
旧schema、入力の誤代替、原本の変更、取得中の変更、空ラック、途中失敗、Stop・ミュート・世代交代との競合を自動確認する。
一時利用の通常終了・異常終了・親待機失敗・削除失敗と、実機のV-03は確認範囲を分けて追跡する。

2026-11-03時点で、初期範囲の退避・手動復帰をローカル実装した。
実施条件と失敗を含む結果は[先行対応の確認記録](UNSAVED_RUNTIME_ACCEPTANCE_2026-11-03.md)、再実行方法は[検証手順](TESTING.md#未保存設定の退避と手動復帰issue-221)に記録する。
対応範囲外は停止前に拒否し、#222ではこの表の未対応項目から保存と復帰の契約を広げる。

## #221の5条件を今回の改修範囲へ対応付ける

| #221の完了条件 | 実装・確認先 |
| --- | --- |
| 項目の所有者・保存先・復帰可否 | 本文の対応表で、保存値と稼働状態、永続とHost寿命を区別した |
| 対象外の事前表示 | 一時利用の開始前に範囲を表示し、退避を選ぶと再確認を要求。未対応構成はHostでも停止前に拒否する |
| 復帰時の照合 | schema・原本全内容・機器ID／名前・現在のEngine世代と制御revisionを照合し、後編集と競合で再確認を要求する |
| 異常終了時に自動再開しない | 取得前の未完了情報と起動時の確認待ちを使う。音声・VSTは自動復帰せず、親の終了を確認できなければ起動処理を止める |
| 自動検証と#98への共通契約 | 保存・原本保護・差分・世代照合・手動復旧を既存bundleへ統合し、単体・画面・実Hostで確認した |

この5条件に対する契約と、上記初期範囲のコード改修を今回の対象とする。
全構成への拡張は#222、共有PC・配布形式・聴感を含む実機受入は#72のV-03で継続する。
GitHub Issueのクローズや公開は、このローカル改修の完了に含めない。
