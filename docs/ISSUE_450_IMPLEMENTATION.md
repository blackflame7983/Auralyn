# VST3 の複数エフェクトをクラス ID で扱う（Issue #450）

2026-11-08、`codex/vst3-class-id-450-20261108` でローカル実装した。実在の複数クラス入り VST3、音声機器、OBS、インストーラでは確認していない。

## 列挙対象と除外

スキャナーはプラグインを子プロセスで調べ、`createInstance` は呼ばない。列挙に成功しても、そのクラスを音声処理できる保証にはならない。

対象は category がちょうど `Audio Module Class` のクラスだけ。`IPluginFactory2` が使えるときは `getClassInfo2` の `subCategories` を `|` で区切り、トークンが `Instrument` で始まり `Fx` で始まらないものを楽器として除外する。`Fx|Instrument` は残す。`IPluginFactory2` が無く v1 の `getClassInfo` だけしかない場合は、楽器かどうかを決められないので残し、`kindKnown` を false にする。

同じ CID は最初の1件だけを残す。同じ表示名で CID が違うクラスは、そのまま別項目にする。

## 取得元と不明な値

`infoSource` は `classInfo2` または `classInfo`。固定長の文字列は NUL 終端までを読む。NUL が無い、または UTF-8 として不正な場合は lossy 変換し、取得元の区別は残す。空文字は JSON に出さない。`"0.0.0"` や `"Unknown"` は作らない。

画面では、メーカーまたはバージョンが空のとき「不明」と表示する。クラス名が無くファイル名を使った項目は「名前は取得できませんでした」と添える。

## スキャナー出力

成功時の1行 JSON は `formatVersion: 2`。項目は `path`、`success`、`error`、`factoryVendor`、`classes`。クラスが0件のときは `success: false` と `error: "対応するエフェクトがありません"`。この完了は exit 0 で返し、ホストはブラックリストへ入れない。ファイル不存在、DLL のロード失敗、factory 不在など、結果を読めない失敗は従来どおり exit 1 でブラックリスト対象にする。#451 が失敗理由を種別化する前提なので、今回の理由は文字列のままである。

`formatVersion` の無い旧1行出力も読む。そのときの名前はファイル名、`nameSource` は `file`、クラス ID は無い。旧出力の vendor `"Unknown"` と version `"0.0.0"` は不明として空にする。

ホストの一覧は1クラスを1件にする。識別子は path と classId。

## ロードと移行

`VstInstance::load` は `load_with_class(path, None, Legacy)`。classId があるときは、その CID のクラスだけを `createInstance` する。見つからない、または生成できないときは別クラスへ移らず失敗する。classId が無い旧データは、従来どおり category に `audio module` または `fx` を含み、最初に生成できたクラスを開く。どちらの成功でも、実際に開いた CID をインスタンスと IPC 応答へ載せる。

通常追加と互換復元で、指定 CID の許容を分ける。

- 通常追加は `load_plugin`（ブラウザからの追加、配信VSTの追加）で、エンジンは `ClassLoadPolicy::Catalog` を使う。指定 CID は `list_effect_classes` と同じ判定の対象だけを開く。カタログで除外した楽器や、category が `Audio Module Class` ちょうどではないクラスは開かず、別クラスへも移らない。列挙できないときも、指定 CID は開かない。
- 互換復元は `restore_plugin`（保存セッション、プリセット、プロファイル、bundle、配信VSTの復元）で、`ClassLoadPolicy::Legacy` を使う。従来ロードと同じ category の部分一致で、その CID を持つクラスを探す。カタログでは出さない楽器や、category がちょうどではない旧クラスでも、一度開けた CID は次回もそのクラスだけを開く。

従来規則の対象外（例: Component Class）も、カタログ対象外の通常追加も、「保存されたエフェクトがこのファイルにありません」で失敗し、別のクラスへは移らない。

旧データで、新しい列挙規則のエフェクト候補が2つ以上あるときは `legacyClassAmbiguous: true` を返す。画面は同じパスにつき1回、「このファイルには複数のエフェクトがあります。以前と同じ規則で最初のものを開きました」と表示する。この告知は追加、プリセット読込、セッション復元で同じ規則にする。別の製品へ置き換えない。列挙自体に失敗した未指定ロードは、従来の選択を続け、曖昧フラグは付けない。

保存した CID がそのファイルに無い、または従来規則の対象外のときは「保存されたエフェクトがこのファイルにありません」。指定クラスの生成失敗は「指定したエフェクトを開けませんでした」。形式が違う ID は「VSTのクラスIDが不正です」。

`classId` は Preset、bundle、live-mode journal、post-mix、ラック、復元要求、プロファイル適用結果の任意項目。schema_version は上げていない。無い旧 JSON は読める。保存時、値が無い項目は出さない。`missing_vst_paths` はパスの存在確認のままで、CID がそのファイルにあるかは実ロードまで分からない。

プリセット保存、プロファイル保存、切替前のバックアップは、画面の `classId` を path だけに落とさない。プリセット読込は要求に CID を渡し、応答の CID と名前を画面に採用する。プロファイルと bundle の適用結果も、実際に開いた CID を Rust の `LoadedPluginInstance` から画面のラックへ渡す。

エンジン再起動後にラック全体を開き直すときは、再読込前の並びで新しい id に付け替える。同じファイルの別クラスや、同じクラスの複数インスタンスを path だけでは選ばない。

一覧でクラス名・ファイル名・メーカー・バージョンがすべて同じ項目は、その重複グループの中で一意になる最短の CID を表示と読み上げ名に足す。最短は8桁、最長は32桁。先頭8桁で分かれる組は8桁のままである。お気に入りと履歴の path だけの旧キーは、そのパスの候補が1つなら `path::CID` へ移して保存する。複数あるときはどれか一方へ割り当てず、path のまま候補を出して選ばせる。選んだクラスだけを新しいキーにする。お気に入りと履歴の移行保存は、両方書けたときだけ完了にする。片方の保存が失敗したときは書いた側を元のキーへ戻し、画面は維持して次の表示で再試行する。

欠落 VST を除いてセッションを保存するとき、保存側に CID がある項目は実ラックの path と CID の両方が一致するときだけ残す。一致しない場合は保存せず、保護を維持する。保存側に CID が無い旧データは path の一致で残し、実ラックの CID を保存結果へ引き継ぐ。
