# 未保存設定の退避・復帰：先行対応の確認記録

単一出力・カスタム構成・声用途の機器入力について、一時利用前の退避と通常設定へ戻った後の手動復帰をローカル実装した。
実Host・実Engine・TDR Novaで一連の操作を確認した。音は全体ミュートし、物理マイクは開いていない。
#221の[5条件に対する契約と初期範囲のコード改修](UNSAVED_RUNTIME_RESTORE.md#221の5条件を今回の改修範囲へ対応付ける)を今回の対象として完了した。
全構成保存の#222、聴感、ASIO、共有PCのV-03の合格とは分ける。

## 通常設定を保ち、停止状態から明示復帰する

プロファイル管理の「共有PCで今回だけ使う」に、任意の未保存設定退避を追加した。
選択を変えると確認チェックを解除し、退避範囲を確認してから再起動する。
実Engineの機器・固定レート／バッファ・音量・NR設定・内蔵処理・VST順序と状態を取得する。
プロセス入力・音楽用途・分離出力・歌／雑談モードなど、初期範囲外の構成は退避指定時に停止前に拒否する。

退避は既存の非公開復旧領域に保存し、未解決の原本を上書きしない。
取得前に未完了情報を作成するため、取得中に終了しても次回は確認待ちになる。
取得・保存・読み戻しが失敗した場合も、元の音声を止めず、復旧情報を保持する。
component stateは原本だけに保存し、画面や検証ログへ出さない。

通常設定へ戻ると音声・VSTを自動再開しない。
元の機器を明示開始してミュートし、配信状態の復旧画面で差分を取り直してから復帰する。
過去のミュート・全体バイパスを再適用せず、復帰操作時の値を維持する。
ノイズ学習、確認履歴、録音、ピーク保護、OBSなどは復帰対象外である。

## 実Hostで確認した条件を限定する

実行入口は `scripts/verify-unsaved-runtime-native.mjs`。
アプリ・設定・WebView2に加え、子プロセスも含むOS一時領域を専用フォルダーへ分離した。
共有MCPドライバーには接続せず、所有するHostのWebView2へCDPで接続した。
WASAPIのCABLE Output入力からVoicemeeter Inputへ、48 kHz・512フレームで開始した。
ケーブルの再生側が未使用であることを確認し、ソースを再生せず、全体ミュートで操作した。

| 条件 | 確認内容 |
| --- | --- |
| 取得途中の終了を想定 | 未完了の復旧情報を置き、確認待ち引数なしで起動しても実ストリーム停止・空ラックになる |
| 一時利用への再起動 | 実UIの退避・確認操作から再起動し、停止・空ラック・専用領域を確認する |
| 退避した値 | 入力0.7・出力0.25・NR強度0.6・TDR Nova 1件とgain 0.4を実Engineから取得する |
| 通常設定への復帰 | 通常設定ファイルの内容が不変で、確認待ち・停止・空ラックのまま開く |
| 古い差分の拒否 | 原本変更、原本と検証値を同じrevisionのまま変更した後の古い差分、プレビュー後のStop、ミュートなしでの適用を拒否する |
| 明示復帰 | 新しい差分から4カテゴリを復帰し、ミュート・音量・NR・VST件数とcomponent stateの一致を確認する |
| 原本保護 | 完了後も原本ファイルを保持し、復旧待ちだけを解除する |
| 対象外入力 | 音楽用途の機器入力で退避を要求すると、再起動せず実ストリームを維持し、復旧情報も新規作成しない |
| 機器・VST欠落 | 機器ID不一致を適用前に拒否。VST欠落は未完了とし、復旧原本と全体ミュートを保持する |
| 空ラック・音量ゼロ | 独立した試験で空ラックと入力／出力の完全な0を退避。別のVSTと音量1がある状態から、空ラックと0へ復帰する |
| 現在の全体バイパス | 退避時ONでも復帰操作時OFFならOFFを維持し、過去の値を自動復活させない |
| OS設定 | 終了後も各出力機器のミュート・音量・既定の役割が試験前と一致する |

試験用の停止判定は `session_rack` の実ストリーム状態を使う。
`get_audio_state.is_running` はsidecarの存在も含むため、停止確認へ代用しない。

一時利用終了時、WebView2がファイルを使用していて専用領域を削除できないケースを観測した。
製品は削除待ちの専用パスを表示し、通常設定・退避原本を保持した。
削除成功へ読み替えず、この試験でも手動の一括削除は行っていない。

## 復帰後の照合で見つかった不一致を修正する

初期の実機試験では、処理自体は復帰しても内蔵残響の省略値と明示的な既定値の違いで未完了になった。
適用処理と同じ既定値で比較するよう修正し、実機で完了とTDR Novaの状態一致を確認した。
無効な処理でも既定値と異なる保持パラメーターは一致扱いしない。再現する失敗テストを先に確認した。

保存内容の照合はrevisionだけに依存せず、プレビュー時の全内容と比較する。
同じrevisionでの外部編集も再確認を必要とする。
これは従来の配信状態の適用にも共通で使い、旧形式の復旧情報の読み取りは維持する。

最終実行は `native-12/summary.json` の `passed: true` である。

製品コードは`22fd14e`と同じであり、追加試験のための再ビルドや同じ全体テストの再実行は行っていない。

`temporary-runtime.spec.ts` は900×600のブラウザで、範囲確認・確認チェックの解除・退避拒否後の画面と保存値の保持を確認する。
原本の保存失敗・未知形式・後編集、機器ID違い、古い制御世代、空ラック、全体ミュート、opaque stateの照合は単体試験でも確認する。

証拠はignoredの `test-results/unsaved-runtime-20261103/` に保持する。
初回の全体テストと実行ファイルのSHA-256は同フォルダーの `verification.json` に記録した。

試験途中の失敗記録も残し、退避したVST stateを公開文書へ転載しない。
ブラウザ試験は音楽用途の対象外表示を追加した後に期待文言を更新して再実行した。
隔離ビルドの初回再実行は作業ディレクトリを誤って失敗したため、リポジトリ直下で実行し直して成功した。
追加試験では、音楽用途から声用途への明示的な選び直し、反映の安定待ちを試験手順へ加えた。
削除待ちが残ると次の一時利用を拒否するため、空ラックのケースは前の領域を残したまま独立した試験用TEMPで実行した。
古いプレビューや適用の競合拒否は自動で再試行せず、明示した拒否理由も照合した。

物理マイク、ASIO、実音声・聴感、機器切断、複数VSTでの異常終了、共有PCでの親待機・削除成功を含むV-03は未確認である。
プロセス入力・分離出力・モードを含む全構成の保存は#222で範囲と形式から設計する。
