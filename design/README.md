# デザイン管理（pen.dev）

`auralyn-screens.pen` は、実装した画面を見渡し、変更案を比べるための作業台です。
**正本はコードです。** 色は `src/index.css`、部品は `src/components/`、文言は `src/i18n/messages.ts` を正とします。
デザインの原則・判断基準は [docs/DESIGN.md](../docs/DESIGN.md) にあり、ここでは繰り返しません。

## 区画

| 区画 | 中身 | 更新のしかた |
|---|---|---|
| ① 現状の写し | 名前が `Home /`・`Settings /`・`Dialog /` などで始まる最上位フレーム | 手で直さない。下の「取り込み直し」で入れ替える |
| ② Components | 写しから切り出した部品（reusable）。各部品の `metadata.file` と「Source」欄に元のファイルを記す | 部品の見た目がコードで変わったら、新しい写しから切り出し直す |
| ③ Proposals | 変更案。①を複製し、`#Issue番号 対象 案A` の形で名付ける | 自由に編集してよい。採用した案はコードへ実装して閉じる |
| 遷移の行（`Flow /`） | ①を画面の遷移順に並べる4行の見出しと矢印。A はじめて使う→ホーム、B 音調整から開く画面、C 接続・困ったとき、D 設定（タブ順） | 画面を足したら、入口に合う行の遷移順の位置に置き、実際に移る箇所だけに操作名入りの矢印を付ける |
| ⑤ 比較 | 修正前のレイヤーの写しと修正後の画像の対。PR #515（Issue #514）の分 | 記録として残す。レイヤーで取り込み直したら、対の画像は消してよい |

- **色は変数で持つ:** `$primary` などの変数は、`index.css` から作ります。テーマ（`dark` / `light` / `gaming`）は、フレームの `theme` で切り替えます。
- **半透明の色:** Tailwind の `/50` のような半透明は、`border-a50` のような派生変数になります。
- **変数の値を .pen 側で決めない:** 色を変えたいときは、③で値を試します。採用したら `index.css` を直し、下の「変数の更新」で .pen へ戻します。

## 変数の更新（index.css を変えたとき）

1. 次を実行して、`design/tokens.json` を作り直します。

   ```bash
   node scripts/design-tokens.mjs
   ```

2. 次を実行して出たコードを、Pencil MCP の `execute` で .pen に適用します。

   ```bash
   node scripts/design-tokens.mjs --snippet vars
   ```

   既にある派生変数（`-aNN`）も作り直されます。

## 取り込み直し（①の写しを最新にする）

> **画像の写し:** 名前が「（画像・PR #515 後）」で終わる最上位フレームは、レイヤーで取り込めなかった画面の代わりに、開発プレビューの画像（`design/screens/*.png`、1280×800、ダーク）を貼ったものです。変数や部品とはつながっていません。レイヤーで取り込み直したら同じ位置へ置き、画像のフレームを削除します。画像を撮り直すときは、`colorScheme: dark` のブラウザで `?mock=` と `?screen=` を付けて撮ります。

1. **開く:** 開発サーバーで `?mock=` と `?screen=` を付けて対象の画面を開き（状態の一覧は [docs/TESTING.md](../docs/TESTING.md)）、CDP の `Emulation.setDeviceMetricsOverride` で表示を 1280×800 にします。
2. **取り込む:** `html` の `data-auralyn-preview` に画面名が付くまで待ちます。ホームは `#root` を、モーダルは `body` を取り込み、古い写しと同じ名前を付けてから古いほうを削除します。③と②は消しません。
3. **色を変数に戻す:** 次のコードを `execute` で適用し、色を変数へ置き換えます。

   ```bash
   node scripts/design-tokens.mjs --snippet bind 0 6
   ```

   1回で処理する画面は6枚程度にします。大きく取ると時間切れになります。次は `6 12`、`12 18` のように続けます。
4. **確認する:** 結果の `unmatched` に、トークンにない色が並びます。新しい色がコードに増えていないかを確かめます。

取り込みは、その時点の静的な写しです。オーロラのような描画中の要素は、1コマの画像として入ります。

## 変更案の流れ

1. ③で、現状（①の複製）と案A／案Bを並べて決めます。
2. 決めた案を、コードに実装します。
3. 取り込み直した①と③の案を見比べて、確かめます。
4. レビューには、③の該当フレームをPNGに書き出して添えます。
