# User Docs

作業入口はルート `AGENTS.md`。利用者向けドキュメントの正本は `docs/USER_DOCS.md`。
この手順より正本が優先する。古い記憶ではなく、必ず現行の正本・原稿・実装を確認する。

1. 説明をどの層に置くかを決める。画面で示せることは画面で示し、アプリの「使い方」は要約だけにして、細かい説明は `user-docs/` に書く。
2. 原稿は `user-docs/ja/` と `user-docs/en/` の両方を同じ構成で直す。見出しの印（`{#...}`）は明示し、公開済みの印とページ名は変えない。
3. アプリから飛ぶ先を足す・変えるときは `user-docs/links.json` を更新し、アプリは名前で参照する。URL を直書きしない。
4. 原稿で「」に入れるボタン名は `src/i18n/messages.ts` に実在する文字列にする。用語の説明は `glossary.md` だけに書く。
5. 挙動や画面の名前を変える PR では、同じ PR で原稿とリンク一覧も直す。
6. 原稿とリンクの試験、型検査、関係する単体試験を実行する。
7. 公式サイト（`blackflame7983/tech-trend-site`）へは同期 PR で反映する。サイトのリポジトリでは、その `AGENTS.md` と設計文書に従い、原稿を書き換えない。

push・PR・公開・サイトのデプロイは、ユーザーが許可した対象と範囲でのみ行う。
